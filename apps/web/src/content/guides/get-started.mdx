## What Veli gives you

Veli is a shared foundation for Maldivian government digital services. It gives your team reusable building blocks and page layouts, so you can spend less time rebuilding the basics and more time on the service itself.

- [**Foundations**](/docs/foundations/)

  Colour, typography, spacing, and the other values every layer depends on.

- [**Components**](/docs/components/)

  Buttons, inputs, alerts, and other interface elements, ready to use.

- [**Patterns**](/docs/patterns/)

  Reusable solutions for signing in, filling in forms, and other tasks.

- [**Blocks**](/docs/blocks/)

  Editable page sections you can copy into your application.

Veli's packages are available on public npm. Hosted resources and the Blocks registry may require separate access.

Want to know how and why Veli was made? Read [Designing Veli →](/design/).

## Develop

This short setup assumes an existing React 19 application. For a complete Vite walkthrough and framework notes, use the [React package setup guide](https://www.npmjs.com/package/@veli-design/react).

### 1. Install Veli

Install the React components, tokens, and React Aria peer dependency. Your application also needs React 19 and React DOM 19.

```bash
pnpm add @veli-design/react @veli-design/tokens react-aria-components
```

### 2. Set up tokens and theming

Use Tailwind CSS 4 with its framework integration, then import these styles in order. Veli's React adapter registers the component sources with Tailwind. See the [Tailwind Vite guide](https://tailwindcss.com/docs/installation/using-vite) for plugin setup.

```css title="src/index.css"
@import 'tailwindcss';
@import '@veli-design/tokens/tailwind';
@import '@veli-design/react/tailwind';
```

### 3. Configure language and direction

Wrap your app in `VeliProvider`. Use `language="en"` for English and LTR, or `language="dv"` for Dhivehi and RTL. `colorScheme="system"` follows the saved Veli theme or system preference. Your app supplies translations and loads its fonts. [Language and direction →](/docs/foundations/language-direction/)

### 4. Use your first component

Import components from their package subpaths. This example renders a Veli Button inside the provider.

<div className="preview">
  <ButtonUsageDemo client:visible />
</div>

```tsx title="src/App.tsx"
import { Button } from '@veli-design/react/button';
import { VeliProvider } from '@veli-design/react/provider';

export default function App() {
  return (
    <VeliProvider language="en" colorScheme="system">
      <Button>Continue</Button>
    </VeliProvider>
  );
}
```

## Build in both languages

Build a complete experience in each language. Veli handles the supported language and direction context; your team owns the content and translations.

- Switch the whole interface between Dhivehi and English, rather than showing both side by side.
- Check layouts, content length, keyboard navigation, and service flows in both directions.
- Write content that reads naturally in each language.

## Before you launch

Check accessibility, language, and responsive behaviour in the service you have built:

- Test against [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/), including keyboard and screen reader use.
- Review the complete service in both Dhivehi and English.
- Test on mobile and desktop, including zoom, validation, and error states.

Veli components provide a foundation; using them alone does not establish conformance. [Read the accessibility guidance →](/docs/foundations/accessibility/)

## Get help and contribute
