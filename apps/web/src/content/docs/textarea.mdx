# TextArea

<DocsTab id="overview">

A text area lets people write longer answers over several lines, such as a message or a description. Use it when the answer may run past one line. For short answers, use Input. Like Input, it has a visible label, helper text and a validation message, and it adds an optional character counter and vertical resizing.

## When to use

### Use a text area when

- A form needs free-form text that may span several lines, such as a message, a reason or a description.
- People write in their own words rather than pick from options.
- People benefit from a maximum-length counter or bounded vertical resizing.

### Don't use a text area when

- The answer is a short single line. Use [Input](/docs/components/input/).
- People choose from a fixed list. Use [Select](/docs/components/select/).
- The value is a date or a number. Use [Date picker](/docs/components/date-picker/) for a date, or [Input](/docs/components/input/) with inputMode numeric for a number. Veli has no number input.

<DocsAnatomy>

1. **Label**

   names the field. In code it is label.

2. **Info icon**

   a 16 button that opens a tooltip with extra help. In code it is infoTooltip.

3. **Optional**

   the localised word Optional after the label, in `text/base/subtle`. In code it is isOptional.

4. **Required indicator**

   an asterisk in `text/danger/muted`. In code it is isRequired. In code, Optional is hidden when the field is required.

5. **Character counter**

   the count and limit, such as 50/100, with a 14 progress ring that fills as people type. It sits at the end of the label row and shows when you set maxLength. In code it is showCharacterCounter.

6. **Field**

   the typing area, at least 120, 146 or 173 high, with a 10 corner radius. The default appearance has an underline; outline has a border. In code it is appearance.

7. **Text**

   starts at the top of the field. The placeholder in `text/base/inactive` until people type, then the value in `text/base/strong`. In code it is placeholder and value.

8. **Resize handle**

   16, placed 4 from the bottom and end corner. Drag it to make the field taller. It is hidden when the field is disabled, read only or not resizable. In code it is isResizable.

9. **Helper text**

   one sentence below the field. The error message replaces it while the field is invalid. In code it is description.

</DocsAnatomy>

## Content guidelines

### Labels

Name the value, not the action, in sentence case with no colon.

| Do                    | Don't                                                                                 |
| :-------------------- | :------------------------------------------------------------------------------------ |
| Message               | Please write your message here: (says please, names the action and ends with a colon) |
| Reason for the change |                                                                                       |

### Placeholder

Use a placeholder, if at all, for a short prompt, in sentence case with no end punctuation. Never put instructions people need in the placeholder; put them in the description.

| Do                      | Don't                                                                                                                      |
| :---------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| Tell us how we can help | Include your passport number, the date you applied and the office (instructions people need, which disappear as they type) |

### Helper text

Say what to include in the answer, in one sentence with no full stop. Don't put links in helper text.

| Do                                                   | Don't                                                                                                        |
| :--------------------------------------------------- | :----------------------------------------------------------------------------------------------------------- |
| Include your application reference, such as PR-20418 | Please enter a detailed description of your issue. (says please, adds a full stop and says nothing specific) |
| Do not include card or bank details                  |                                                                                                              |

### Character limits

Set maxLength only when the service needs a limit. When there is one, say it in the helper text before people type, and pair it with the counter.

| Do                                 | Don't                                                  |
| :--------------------------------- | :----------------------------------------------------- |
| You can enter up to 500 characters | Max 500 (abbreviated, and doesn't say what is limited) |

### Error messages

Say what is wrong and how to fix it, with no full stop on a one-sentence message. For length errors, give the limit.

| Do                                          | Don't                                                                                  |
| :------------------------------------------ | :------------------------------------------------------------------------------------- |
| Write at least 20 characters so we can help | Invalid input (doesn't say what to change)                                             |
| Message must be 500 characters or less      | Write at least 20 characters so we can help. (a one-sentence error takes no full stop) |

### Built-in strings

| String                        | English          | Dhivehi           |
| :---------------------------- | :--------------- | :---------------- |
| Optional, shown by isOptional | Optional         | އިޚްތިޔާރީ        |
| Info button name              | More information | އިތުރު މަޢުލޫމާތު |
| Counter                       | 86/500           | 86/500            |

Optional can't be reworded. Override the info button name with infoTooltipAriaLabel so it names the topic. The counter shows numbers only, left to right in both languages, with no words to translate.

### Dhivehi copy

Write Dhivehi labels, helper text and errors natively rather than translating word for word, and keep them as short as the English.

## Behaviour

- **Typing**: control the value with value and onChange, or start with defaultValue.
- **Enter**: Enter adds a new line. Let Ctrl or Command with Enter submit the form.
- **Counter**: with maxLength, the counter shows the count and fills its ring. Code stops typing at the limit, although the guidelines say never to silently block keystrokes. The counter is the only live feedback before submit; errors wait until people submit.
- **Resize**: people drag the handle to resize the field vertically, within minHeight and maxHeight when you set them. Resizing is vertical only and works by pointer only.
- **Click target**: clicking anywhere in the field moves focus to the text.
- **Paste**: never block pasting, and never silently block or strip keystrokes.
- **Width**: the field fills its container and can grow vertically. Constrain the width in the surrounding layout.
- **Text size on phones**: field text should be at least 16px on phones so iOS Safari doesn't zoom the page on focus. Sizes sm and md use 14px text, so use lg on phones.

## Usage

<div className="preview mb-4 rounded-lg border p-4">
  <TextAreaUsageDemo client:visible />
</div>

```tsx
<TextArea
  label="Message"
  isOptional
  placeholder="Tell us how we can help"
  description="Helper text"
  maxLength={280}
/>
```

Setting `maxLength` shows a live character counter. Pass `showCharacterCounter={false}` to hide it. The field resizes vertically by default; use `isResizable={false}` to lock the height, or `minHeight` / `maxHeight` to bound it.

## Appearances

`default` uses the underline shell. `outline` draws a bordered field. Size the field with `sm`, `md`, or `lg`.

<div className="preview mb-4 rounded-lg border p-4">
  <TextAreaAppearancesDemo client:visible />
</div>

```tsx
<TextArea label="Default" placeholder="Write a note" />
<TextArea appearance="outline" label="Outline" placeholder="Write a note" />
```

## API Reference

TextArea is a Veli field on React Aria [`TextField`](https://react-spectrum.adobe.com/react-aria/TextField.html), which wraps a native `<textarea>`. Props below follow that stack.

### TextArea

Veli-specific props for the composed field.

| Prop                    | Type                       | Default          | Description                                                          |
| :---------------------- | :------------------------- | :--------------- | :------------------------------------------------------------------- |
| `appearance`            | `'default' \| 'outline'`   | `'default'`      | Underline or bordered field.                                         |
| `size`                  | `'sm' \| 'md' \| 'lg'`     | `'md'`           | Field size.                                                          |
| `label`                 | `ReactNode`                | -                | Visible label.                                                       |
| `isOptional`            | `boolean`                  | `false`          | Shows localized Optional beside the label. Hidden when `isRequired`. |

## Accessibility

- Give the field a visible `label`, or pass `aria-label` / `aria-labelledby` when the label is hidden.
- `description` is the accessible helper. On error, `errorMessage` replaces it.
- Resize is pointer-drag only, same as a native textarea. The handle is not in the tab order, and it is hidden when the field is disabled or read-only.

## RTL and Language

On `lang="dv"` pages, entered text uses `MV_Faseyha`, same as Input. In RTL, the label row and resize handle follow `dir`. The character counter stays left-to-right so the count does not reverse.

How the text area works with keyboards and screen readers, and what you still need to do. It is built on the React Aria TextField with a native textarea.

## Keyboard

| Key         | Action                                               |
| :---------- | :--------------------------------------------------- |
| Tab         | Moves focus into the field, then to the next control |
| Shift + Tab | Moves focus back                                     |
| Enter       | Adds a new line                                      |

The info button is a separate Tab stop. The resize handle is not in the tab order. A disabled field is skipped by Tab.

## Screen readers

- **Label**: give every field a visible label. Set aria-label only when there is no visible label.
- **Description and error**: description and errorMessage are linked to the field, so people hear the help and the error.
- **States**: required, disabled, read-only and invalid states are exposed to assistive technology.
- **Optional and required**: Optional and the asterisk sit outside the label element, so neither is part of the accessible name. isRequired still tells screen readers the field is required.
- **Counter**: the counter is not announced and is not linked to the field. Say the limit in the description, and announce the characters left in a polite live region near the limit, such as 20 characters left, not on every keystroke.

## Resizing

The resize handle is decorative: it has no accessible name and works by pointer drag only. Keyboard and screen reader users can still scroll inside the field, so set a size or minHeight that shows enough lines for the expected answer.

## Focus

Keyboard focus shows a 2px ring in `border/focus`, offset 2, around the field. It appears for keyboard focus only (focus-visible). A click shows the active state instead: the pressed fill and a 2px underline or border. With the ring, the outline appearance drops its border, so the two never stack.

## Errors

Errors show a message as well as the red line, so they never rely on colour alone.

## Contrast

Placeholder text uses `text/base/inactive`, about 2.1:1 to 2.7:1, below the 4.5:1 text minimum. Never put information people need in the placeholder.

## Right to left

Set the language with VeliProvider (language dv). The layout and resize handle mirror; the counter stays left to right. Set dir to auto on free-text fields and pass Dhivehi labels, helper text and errors yourself.
