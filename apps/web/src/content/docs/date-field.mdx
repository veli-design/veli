# DateField

<DocsTab id="overview">

A date field lets people type a date, and a time when needed, into separate day, month and year segments, with no calendar. Use it for dates people know without looking at a calendar, such as a date of birth or a date printed on a document.

## When to use

### Use a date field when

- People should type a date directly, segment by segment, and the form needs no calendar popover.
- The date is one people know by heart, such as a date of birth. Prefill it from the National Registry when you can.
- People copy the date from a document, such as the date of issue on a passport or the expiry date on a work permit.
- A time is typed freely, such as an arrival time. Add time segments in 24-hour form.
- The value must reach the service through a form as an ISO string. Give the field a name.

### Don't use a date field when

- People need to browse dates or see which dates are available. Use a date picker or an embedded calendar.
- The field should open a calendar from a compact trigger. Use a date picker.
- The form is in Dhivehi. Under language dv the segments read month, day, year, so a person who types 3 for the day and 4 for the month would give 4 March instead of 3 April. Use three Inputs labelled Day, Month and Year, in that order, grouped with FieldSet and FieldLegend.
- Browser autofill matters. The segments can't take the bday-day, bday-month and bday-year autocomplete tokens, so use three Inputs.
- You need a date range. Use two date fields labelled Start date and End date.
- Only some times are open. List them as Radio options instead.

<DocsAnatomy>

1. **Label**

   names the date. It also names the field group for screen readers. In code it is label.

2. **Info icon**

   a 16px icon button that opens a tooltip with extra detail. Screen readers announce it as More information. Put where to find the date in the description, not here. In code it is infoTooltip.

3. **Optional**

   Optional after the label, shown with isOptional and hidden while isRequired is on. The required asterisk sits in the same place. Neither is part of the accessible name.

4. **Field**

   the input container, one group named by the label. It is 36, 44 or 52 high and fills its container. In code it is set by appearance and size.

5. **Date segments**

   day, month and year, separated by a slash. Each segment is a spinbutton people type into or step with the arrow keys. Placeholders show dd, mm and yyyy until a value is set. granularity adds time segments.

6. **Error icon**

   a 16px filled info icon, 20px at lg. It shows while isInvalid is on and is hidden from screen readers.

7. **Helper or error text**

   a hint below the field. While isInvalid is on, errorMessage replaces it, so the error itself must say which dates are allowed. In code it is description and errorMessage.

</DocsAnatomy>

## Content guidelines

### Label

Name what the date or time is for, as a short noun phrase in sentence case. Don't add a format, a colon or an abbreviation.

| Do            | Don't                                             |
| :------------ | :------------------------------------------------ |
| Date of birth | DOB (abbreviation)                                |
| Date of issue | Enter Date: (instruction, title case and a colon) |
| Arrival time  | Date (dd/mm/yyyy) (bare label with a format)      |

### Helper text

Add helper text only when the label needs context, in one short sentence: where to find the date or which dates are allowed. Don't write the format, because the segments already show it. Helper text wraps below the field; never truncate it.

| Do                          | Don't                                                                                       |
| :-------------------------- | :------------------------------------------------------------------------------------------ |
| As printed on your passport | For example, 27 3 1990 (a format example belongs to three separate Inputs, not to segments) |

### Error messages

Say which rule failed, in the words of the label:

- Empty: Enter &#123;date name&#125;.
- Incomplete: &#123;date name&#125; must include a &#123;day, month or year&#125;.
- Year the wrong length: Year must include 4 numbers.
- Impossible date: &#123;date name&#125; must be a real date.
- Wrong side of today: &#123;date name&#125; must be in the past, must be today or in the past, or must be in the future.
- Outside a range: &#123;date name&#125; must be after, before or between &#123;date&#125;, with the date written as 21 October 2026.
- Time: Enter &#123;time name&#125; in 24-hour format, like 14:30.

Show missing and incomplete errors first, then impossible dates, then the rest. Don't use valid, invalid or other generic words, and leave the full stop off a one-sentence error.

| Do                                | Don't                                                                |
| :-------------------------------- | :------------------------------------------------------------------- |
| Enter your date of birth          | Enter a valid service date. (valid, and a full stop on one sentence) |
| Date of birth must include a year |                                                                      |
| Date of birth must be a real date |                                                                      |
| Date of birth must be in the past |                                                                      |

### Optional or required

Mark whichever is rarer in the form: Optional with isOptional when most fields are required, or the asterisk with isRequired when most are optional. Never mark one field both ways.

### Service messages

Supply error messages from the service in English and Dhivehi instead of the browser's built-in validation messages.

### Dhivehi copy

Write Dhivehi the way a Dhivehi speaker would say it, rather than translating word for word, and keep it as short as the English, because Dhivehi lines are taller.

## Sizes

Size sets the field height, the padding and the text styles. In code, size defaults to md.

- Use **sm** (36 high) in dense layouts such as filters and table toolbars.
- Use **md** (44 high) in most forms.
- Use **lg** (52 high) on touch-first and kiosk forms.

Match the size of the other fields in the form. On phones, segment text should be at least 16px so iOS Safari doesn't zoom when the field gets focus: lg gives 16.

- **Date people know by heart**: such as Date of birth. Prefill it from the National Registry when you can. No info icon and no helper text.
- **Date copied from a document**: such as Date of issue. The description says where to find it: As printed on your passport.
- **Date and time**: such as Arrival time, typed freely in 24-hour form. Set granularity to minute and hourCycle to 24.

Set granularity only when time segments are needed; it defaults to day. Use placeholderValue to set the segment shape and the calendar or time zone context. Set minValue and maxValue only for real limits, such as a date of birth that must be in the past, and say the limit in the error message. Put where to find the date in the description, not in the info tooltip.

## Behaviour

- **Typing**: each segment takes digits and moves to the next one when full. Up and Down change the focused segment, and Backspace clears it.
- **Checking**: inside a Veli Form, errors show while people type, because the Form uses validationBehavior aria. Set validationBehavior="native" on the Form to check dates when people submit. An error that appears while people are still typing interrupts them.
- **Keeps answers**: the field keeps the value people typed when it shows an error, so they can correct it rather than start again.
- **Limits**: minValue, maxValue, isRequired and validate set the rules. A value outside minValue and maxValue is invalid, and the error replaces the description, so the error must say which dates are allowed.
- **Form value**: control it with value and onChange, or leave it uncontrolled with defaultValue. With name it submits as an ISO string. Convert with isoDateToDateValue and dateValueToIsoDate from @tradenetcorp/veli-ui/form, so the service stores dates such as 1994-03-14.
- **Time zones**: time zone entry depends on the date value you supply and on hideTimeZone.
- **Width**: the field fills its container. Set the width on the form column, not on the field.
- **No calendar**: the field never shows a calendar or which dates are available.

- In code, wrap the app in VeliProvider with language set to dv. It gives the field its direction and Veli strings.
- Under dv the segments read mm, dd, yyyy from the right, with English placeholders. Date picker differs: it forces its segments left to right with lang=en, so they read dd / mm / yyyy from the left. Date fields should read day, month, year in both languages, so use three Inputs for typed dates in Dhivehi forms until this is fixed. The segment names stay in English in both components.
- The label, Optional (އިޚްތިޔާރީ), description and error read from the right in the Dhivehi text styles. The field keeps its English height, but the label row grows with the taller lines: in Storybook it is 36 high at sm and md and 40 at lg, against 28, 28 and 32 in English (the label line is 28 or 32, plus 8 below). See Missing or unverified.
- Digits stay Latin. Left and Right arrows are mirrored, so Left always moves to the segment on the left.
- Segment names, Empty and the placeholders stay in English. The info button name switches to Dhivehi on its own (More information, އިތުރު މަޢުލޫމާތު); override it with infoTooltipAriaLabel.
- In Figma, design Dhivehi screens with dateFieldDv.

Example configuration: a Dhivehi date field is not recommended for typed dates, so show the English field and, beside it, the three Inputs pattern. No Dhivehi label copy for a date field exists yet; see Missing or unverified.

## API Reference

DateField is a Veli field on React Aria [`DateField`](https://react-spectrum.adobe.com/react-aria/DateField.html). Props below follow that stack.

| Prop                    | Type                     | Default          | Description                                                          |
| :---------------------- | :----------------------- | :--------------- | :------------------------------------------------------------------- |
| `appearance`            | `'default' \| 'outline'` | `'default'`      | Underline or bordered field.                                         |
| `size`                  | `'sm' \| 'md' \| 'lg'`   | `'md'`           | Field size.                                                          |
| `label`                 | `ReactNode`              | -                | Visible label.                                                       |
| `isOptional`            | `boolean`                | `false`          | Shows localized Optional beside the label. Hidden when `isRequired`. |

| `infoTooltipAriaLabel`  | `string`                 | Localized string | Accessible name for the info tooltip trigger.                        |
| `description`           | `ReactNode`              | -                | Helper text beneath the field.                                       |
| `errorMessage`          | `ReactNode`              | -                | Error text shown when `isInvalid`.                                   |
| `showRequiredIndicator` | `boolean`                | `true`           | Shows the required asterisk when `isRequired`.                       |

### React Aria DateField

React Aria’s headless [`DateField`](https://react-spectrum.adobe.com/react-aria/DateField.html#props). These props pass through. The React Aria docs cover the rest, except the exclusions below.

| Prop                      | Type                                      | Default | Description                                        |
| :------------------------ | :---------------------------------------- | :------ | :------------------------------------------------- |
| `value`                   | `DateValue \| null`                       | -       | Controlled value.                                  |
| `defaultValue`            | `DateValue`                               | -       | Uncontrolled initial value.                        |
| `onChange`                | `(value: DateValue \| null) => void`      | -       | Called when the value changes.                     |
| `placeholderValue`        | `DateValue`                               | -       | Placeholder shape and default calendar context.    |
| `granularity`             | `'day' \| 'hour' \| 'minute' \| 'second'` | -       | Smallest editable segment.                         |
| `hourCycle`               | `12 \| 24`                                | -       | Forces 12-hour or 24-hour time when time is shown. |
| `hideTimeZone`            | `boolean`                                 | -       | Hides the time zone segment for zoned values.      |
| `shouldForceLeadingZeros` | `boolean`                                 | -       | Keeps segment values zero-padded where applicable. |
| `minValue`                | `DateValue`                               | -       | Lowest allowed date/time.                          |
| `maxValue`                | `DateValue`                               | -       | Highest allowed date/time.                         |
| `isDisabled`              | `boolean`                                 | `false` | Disables the field.                                |
| `isInvalid`               | `boolean`                                 | `false` | Marks the field invalid.                           |
| `isReadOnly`              | `boolean`                                 | `false` | Prevents editing.                                  |
| `isRequired`              | `boolean`                                 | `false` | Marks the field required.                          |
| `name`                    | `string`                                  | -       | Submits the value in forms as an ISO string.       |
| `validate`                | `function`                                | -       | Custom validation.                                 |
| `autoFocus`               | `boolean`                                 | `false` | Focuses the field on mount.                        |

Not forwarded from React Aria `DateField`:

| Prop        | Why                                                |
| :---------- | :------------------------------------------------- |
| `children`  | Veli owns the field composition.                   |
| `style`     | Not supported.                                     |
| `className` | Replaced by Veli’s layout `className` on the root. |

## Accessibility

- Give the field a visible `label`, or pass `aria-label` / `aria-labelledby` when the label is hidden.
- `description` is the accessible helper. On error, `errorMessage` replaces it.
- Date segments are individually focusable; arrow keys and typing edit each segment in place.

## RTL and Language

Date segment order and formatting follow the locale from `VeliProvider`. Set `language` on the provider rather than passing a separate locale prop. See [VeliProvider](/docs/components/provider/). In RTL, the label row follows `dir`.

How the date field works with keyboards, screen readers and assistive technology, and what you still need to do. It is built on the React Aria date field.

## Keyboard

| Key                   | Action                                                                                      |
| :-------------------- | :------------------------------------------------------------------------------------------ |
| Tab                   | Moves to the next segment, then out of the field                                            |
| Shift + Tab           | Moves to the previous segment                                                               |
| Left and Right arrows | Move between segments, mirrored in Dhivehi so Left always moves to the segment on the left  |
| Up and Down arrows    | Increase or decrease the focused segment. On an empty segment, Up starts from today's value |
| Page Up and Page Down | Change the focused segment by a larger step                                                 |
| Home and End          | Set the focused segment to its lowest or highest value                                      |
| Digits                | Type a value. Focus moves to the next segment when the segment is full                      |
| Backspace or Delete   | Clear the focused segment                                                                   |

## Screen readers

- The visible label names the field group. Every date field needs one; never hide it.
- Each segment is a spinbutton named day, month or year with the label, and is read as Empty when blank. On iOS VoiceOver it falls back to a text box, because VoiceOver can't focus spinbuttons there.
- When a date is set, the field adds a hidden description such as "Selected Date: 18 April 2026".
- The description, or the error while invalid, is linked to the field and read on focus.
- isRequired and isInvalid reach screen readers on every segment. Optional and the asterisk sit outside the label, so neither is part of the accessible name.
- The slash separators and the error icon are hidden from assistive technology.

- Keyboard focus shows a 2px gap in `bg/surface/raised`, then a 2px ring in `border/focus`, around the whole field. The focused segment fills with the primary colour.
- The ring shows for keyboard focus only. A click selects a segment without the ring.
- The ring sits outside the field, so focus doesn't change its size or move the label or helper text.

## Disabled and read only

A disabled field can't be edited or focused, and is skipped by Tab. A read-only field stays in the tab order and keeps its value readable but can't be changed. Use read only for prefilled dates.

## Errors

An error shows errorMessage in text below the field as well as the red line and icon, so colour is not the only signal. The error replaces the description, so write the rule into the error.

## Target size

The field is at least 36 high. The info icon button is 16 x 16, below the 24 x 24 minimum target size; see Missing or unverified.

## Contrast

Placeholder text uses `text/base/inactive`, which falls below 4.5:1. Never rely on the placeholder: the label and helper text carry the meaning. Helper text in `text/base/muted` measures 4.96:1 in light and 5.23:1 in dark in Storybook, which meets 4.5:1. Optional, in `text/base/subtle`, stays below 4.5:1.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction and the language, and mirrors the label row, field and helper text. Segment names, Empty, Selected Date and the placeholders stay in English, because React Aria and the browser have no Dhivehi date data and no prop can change them. Pass Dhivehi labels, descriptions and errors yourself.
