# VeliProvider

<DocsTab id="overview">

VeliProvider sets the language, direction and colour scheme for every Veli component inside it, and connects Veli links to your app's router. It renders no visible UI. Wrap the whole app once, choose en or dv with the language prop, and set lang and dir on the html element to match.

<DocsResources source="https://github.com/veli-design/veli/blob/main/packages/react/src/provider.ts" />

## When to use

### Use VeliProvider when

- You build any app that uses Veli, English-only ones too. Put it at the root and always pass language. Without a provider, components fall back to English and left to right, and a later Dhivehi launch has to touch every screen.
- You need the system, light or dark colour scheme. Set colorScheme.
- Links in Link, Tabs, Menu or Breadcrumbs should change pages through your app's router. Pass navigate, and useHref if your router needs it.

### Don't use VeliProvider when

- You only need to change the language of a passage or block. Set lang and dir on that element instead. Nest a provider only at a real app boundary, such as a separately built part of the page.
- A framework theme runtime, such as next-themes, already owns the theme on the html element. Pass the resolved light or dark value from that runtime to colorScheme, or leave the theme to the runtime.
- You want to theme one region dark. Adding the dark class to a wrapper doesn't change the components inside. Theme the whole page at html, and use the high contrast Button for Buttons on coloured surfaces.

## Content guidelines

### What the language prop translates

VeliProvider has no text of its own. Its language prop decides the language of Veli's built-in strings. Veli's own strings switch to Dhivehi, React Aria strings and dates formatted by Intl stay English under dv, and some Veli defaults are English in both languages, such as Calendar Previous month and Table Select all.

### Your own strings

Supply every string your app writes in English and Dhivehi, and pick it with useVeliLanguage. VeliProvider translates only Veli's built-in strings. When a translation is missing, show the English string, never the raw key or an empty space.

### Theme choice

When a service lets people choose a theme, offer the three values VeliProvider supports and name them in plain words in the page language.

| Do             | Don't                                                         |
| :------------- | :------------------------------------------------------------ |
| Light          | System (technical; people may not know which system is meant) |
| Dark           | Auto (doesn't say what it follows)                            |
| Device setting |                                                               |

### Language switch

Offer a visible language switch on every page, in the same place, with each option written in its own language: ދިވެހި on an English page and English on a Dhivehi page. Mark each option with its lang.

VeliProvider has no visual design of its own. This tab covers what it sets for the components inside it: language, direction, typography and colour scheme.

## Behaviour

- **Wrapper**: VeliProvider renders a div that carries lang, dir, data-theme (the resolved theme), `data-color-scheme` (the requested one) and the dark class when the theme is dark.
- **Routing**: with navigate, Veli links change pages through your router without a full reload. Without it, href falls back to the browser's normal navigation.
- **Hooks**: useVeliLanguage returns the active language, locale and direction. useVeliColorScheme returns the requested colour scheme and the resolved light or dark mode.
- **Without a provider**: components use English and left to right, and Veli links navigate with a full page load.

## Language and direction

| language | Content language | Locale | Direction |
| :------- | :--------------- | :----- | :-------- |
| en       | English          | en-GB  | ltr       |
| dv       | Dhivehi          | dv-MV  | rtl       |

- language defaults to en in code, but that is only a fallback. Always pass the language the person chose.
- Don't pass locale and direction separately. Veli owns the mapping, so unsupported combinations can't happen.
- VeliProvider supports only English and Dhivehi.
- Under language dv, Veli shows numbers in Latin digits. Intl has no dv-MV data, so dates formatted by React Aria fall back to English and US order, except Calendar month and weekday names, which Veli supplies in Dhivehi.
- React Aria resolves dv to right to left, so arrow keys in Tabs, Menus, Tags, Tables and Calendars mirror.

## Typography

VeliProvider sets the lang that the type utilities read. Keep using the same type utilities in both languages: font family, size, line height, weight and letter spacing switch to the Dhivehi values under lang dv. dir rtl alone doesn't switch typography.

Load MV Faseyha, MV A Waheed and MV Aaamu FK in your app and preload the font of the page language. VeliProvider and the type utilities switch to these fonts but don't download them.

## Colour scheme

| colorScheme      | Behaviour                                                                                                                        |
| :--------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| system (default) | Follows the device's light or dark setting. A light or dark value stored under `veli-color-scheme` wins over the device setting. |
| light            | Forces light mode.                                                                                                               |
| dark             | Forces dark mode.                                                                                                                |

- VeliProvider renders an inline script that sets the dark class, data-theme and `color-scheme` on html before the first paint, so the page never flashes the wrong theme.
- It keeps the dark class, data-theme and `color-scheme` on html in step with the theme, follows device changes, and keeps open tabs in step.
- When people switch theme, turn on disableTransitionOnChange so colours switch at once instead of animating.
- When a framework owns the theme instead, set the dark class, data-theme and `color-scheme` on html yourself, so scrollbars and native controls match. With next-themes, set attribute="class" and use its script for the first paint.
- Set the `theme-color` meta tag to the page background for each theme, so the browser toolbar matches the page.

## Supported Language Modes

| `language` | Content language | Locale  | Direction |
| :--------- | :--------------- | :------ | :-------- |
| `en`       | English          | `en-GB` | `ltr`     |
| `dv`       | Dhivehi          | `dv-MV` | `rtl`     |

Consumers should not pass `locale` and `dir` separately. Veli owns that mapping so unsupported combinations cannot be created by accident.

## Supported Color Schemes

| `colorScheme` | Behavior                                                        |
| :------------ | :-------------------------------------------------------------- |
| `system`      | Resolves to the user's `prefers-color-scheme` media preference. |
| `light`       | Forces light mode for the provider subtree.                     |
| `dark`        | Forces dark mode for the provider subtree.                      |

The provider applies `data-theme`, `data-color-scheme`, the `.dark` class when resolved dark, and the CSS `color-scheme` utility to its wrapper element. App shells that render portaled UI should also keep `document.documentElement` in sync with the same `.dark` class so overlays inherit the active token mode.

## Framework Theme Runtimes

Veli is compatible with framework-level theme runtimes that toggle `.dark` on the document root. In Next.js apps, especially shadcn/ui-style apps, prefer `next-themes` as the app-level theme manager and configure it with `attribute="class"` so Veli token CSS can respond to `<html class="dark">`.

`VeliProvider colorScheme` is optional in that setup. Use it when Veli components need context awareness, but do not let it compete with the app shell for document-level theme state.

## Integration Examples

All examples should import Veli's Tailwind theme CSS after Tailwind so semantic utilities can resolve to Veli tokens:

```css
@import 'tailwindcss';
@import '@veli-design/tokens/tailwind';
@import '@veli-design/react/tailwind';
```

### Next.js with next-themes

Use `next-themes` as the document-level theme runtime and configure it to write a class to `<html>`.

```tsx
// app/layout.tsx
import { ThemeProvider } from '@/components/theme-provider';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider
          attribute="class"
          defaultTheme="system"
          enableSystem
          disableTransitionOnChange
        >
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

`VeliProvider` can wrap the application for language and component context. It does not need to own document-level theme switching when `next-themes` already owns `<html class="dark">`.

```tsx
'use client';

import { useTheme } from 'next-themes';
import { VeliProvider, type VeliColorScheme } from '@veli-design/react/provider';

function toVeliColorScheme(theme: string | undefined): VeliColorScheme {
  return theme === 'light' || theme === 'dark' ? theme : 'system';
}

export function VeliThemeBridge({ children }: { children: React.ReactNode }) {
  const { theme } = useTheme();

  return <VeliProvider colorScheme={toVeliColorScheme(theme)}>{children}</VeliProvider>;
}
```

### Astro

Astro apps should set the root `.dark` class before first paint, then keep it in sync when the user changes modes. Put the inline script in the shared layout `<head>`.

```astro
---
import '../styles/global.css';
---

<!doctype html>
<html lang="en" data-color-scheme="system">
  <head>
    <script is:inline>
      (() => {
        const storageKey = 'veli-color-scheme';
        const root = document.documentElement;
        const stored = window.localStorage.getItem(storageKey);
        const colorScheme =
          stored === 'light' || stored === 'dark' || stored === 'system' ? stored : 'system';
        const isDark =
          colorScheme === 'dark' ||
          (colorScheme === 'system' && window.matchMedia('(prefers-color-scheme: dark)').matches);
        const resolvedColorScheme = isDark ? 'dark' : 'light';

        root.classList.toggle('dark', isDark);
        root.dataset.theme = resolvedColorScheme;
        root.dataset.colorScheme = colorScheme;
        root.style.colorScheme = resolvedColorScheme;
      })();
    </script>
  </head>
  <body class="bg-surface-base text-base">
    <slot />
  </body>
</html>
```

Toggle controls should update the same root contract and persist the requested mode:

```html
<button type="button" data-theme-choice="system">System</button>
<button type="button" data-theme-choice="light">Light</button>
<button type="button" data-theme-choice="dark">Dark</button>

<script>
  const storageKey = 'veli-color-scheme';
  const media = window.matchMedia('(prefers-color-scheme: dark)');

  function applyColorScheme(colorScheme) {
    const isDark = colorScheme === 'dark' || (colorScheme === 'system' && media.matches);
    const resolvedColorScheme = isDark ? 'dark' : 'light';

    document.documentElement.classList.toggle('dark', isDark);
    document.documentElement.dataset.theme = resolvedColorScheme;
    document.documentElement.dataset.colorScheme = colorScheme;
    document.documentElement.style.colorScheme = resolvedColorScheme;
    window.localStorage.setItem(storageKey, colorScheme);
  }

  for (const button of document.querySelectorAll('[data-theme-choice]')) {
    button.addEventListener('click', () => {
      applyColorScheme(button.dataset.themeChoice);
    });
  }
  media.addEventListener('change', () => {
    if (document.documentElement.dataset.colorScheme === 'system') {
      applyColorScheme('system');
    }
  });
</script>
```

### Vite, React Router, and TanStack Router

Client-rendered React apps can use a small app-shell theme provider. The important part is that the app shell writes `.dark` to `document.documentElement`; Veli components will inherit token values from that class.

```tsx
import * as React from 'react';
import { VeliProvider, type VeliColorScheme } from '@veli-design/react/provider';

const storageKey = 'veli-color-scheme';

function resolveColorScheme(colorScheme: VeliColorScheme) {
  return colorScheme === 'system'
    ? window.matchMedia('(prefers-color-scheme: dark)').matches
      ? 'dark'
      : 'light'
    : colorScheme;
}

export function AppThemeProvider({ children }: { children: React.ReactNode }) {
  const [colorScheme, setColorScheme] = React.useState<VeliColorScheme>(() => {
    const stored = window.localStorage.getItem(storageKey);
    return stored === 'light' || stored === 'dark' || stored === 'system' ? stored : 'system';
  });

  React.useEffect(() => {
    const applyColorScheme = () => {
      const resolvedColorScheme = resolveColorScheme(colorScheme);
      document.documentElement.classList.toggle('dark', resolvedColorScheme === 'dark');
      document.documentElement.dataset.theme = resolvedColorScheme;
      document.documentElement.dataset.colorScheme = colorScheme;
      document.documentElement.style.colorScheme = resolvedColorScheme;
    };

    window.localStorage.setItem(storageKey, colorScheme);
    applyColorScheme();

    const media = window.matchMedia('(prefers-color-scheme: dark)');
    media.addEventListener('change', applyColorScheme);

    return () => {
      media.removeEventListener('change', applyColorScheme);
    };
  }, [colorScheme]);

  return (
    <VeliProvider colorScheme={colorScheme}>
      <button type="button" onClick={() => setColorScheme('system')}>
        System
      </button>
      <button type="button" onClick={() => setColorScheme('light')}>
        Light
      </button>
      <button type="button" onClick={() => setColorScheme('dark')}>
        Dark
      </button>
      {children}
    </VeliProvider>
  );
}
```

## Client-side routing

Pass `navigate` (and optionally `useHref`) to wrap the subtree in React Aria's `RouterProvider`. Every Veli component that accepts `href` — including Tabs, Link, MenuItem, and Breadcrumb — then uses client-side navigation instead of a full page load.

```tsx
'use client';

import { useRouter } from 'next/navigation';
import { VeliProvider } from '@veli-design/react/provider';

export function AppProviders({ children }: { children: React.ReactNode }) {
  const router = useRouter();

  return (
    <VeliProvider navigate={(href, options) => router.push(href, options)}>{children}</VeliProvider>
  );
}
```

```tsx
'use client';

import { useRouter } from '@tanstack/react-router';
import { VeliProvider } from '@veli-design/react/provider';

export function AppProviders({ children }: { children: React.ReactNode }) {
  const router = useRouter();

  return (
    <VeliProvider
      navigate={(to, options) => router.navigate({ to, ...options })}
      useHref={(to) => router.buildLocation({ to }).href}
    >
      {children}
    </VeliProvider>
  );
}
```

To type `routerOptions` on individual links, augment React Aria's `RouterConfig`:

```ts
declare module 'react-aria-components' {
  interface RouterConfig {
    routerOptions: NonNullable<Parameters<ReturnType<typeof useRouter>['push']>[1]>;
  }
}
```

`navigate` is optional. When omitted, `href` falls back to the browser's default navigation.

## Helpers

```tsx
import {
  getVeliLanguageConfig,
  useVeliColorScheme,
  useVeliLanguage,
} from '@veli-design/react/provider';
```

`useVeliLanguage` returns the active Veli language config inside a provider subtree. `getVeliLanguageConfig` returns the same mapping without reading React context.

`useVeliColorScheme` returns both the requested `colorScheme` and the resolved `light` or `dark` mode for the current provider subtree.

## Direction Contract

The provider applies `lang` and `dir` to its wrapper element. Veli components that need language or direction awareness should read those attributes from the provider contract instead of deriving direction from a browser locale fallback.

React Aria still receives the mapped locale for i18n behavior. Direction-sensitive Veli component behavior is handled separately by the component implementation.

## Typography

English and Dhivehi typography styles are distinct in design. `VeliProvider` applies the inherited `lang` value that Veli's generated `type-*` utilities use to switch to exported Dhivehi typography values.

Consumers should keep using the same semantic `type-*` classes in both languages. Font family, size, line height, weight, and letter spacing switch automatically when `language="dv"` is active.

## API Reference

| Prop                        | Type                            | Default    | Description                                                                 |
| :-------------------------- | :------------------------------ | :--------- | :-------------------------------------------------------------------------- |
| `language`                  | `'en' \| 'dv'`                  | `'en'`     | Selects Veli's supported language and direction mode.                       |
| `colorScheme`               | `'system' \| 'light' \| 'dark'` | `'system'` | Selects Veli's requested color scheme mode.                                 |
| `navigate`                  | `(path, options?) => void`      | -          | Client-side navigate function; enables React Aria `RouterProvider`.         |
| `useHref`                   | `(path) => string`              | -          | Optional href resolver for the configured client-side router.               |
| `disableTransitionOnChange` | `boolean`                       | `false`    | Suppresses CSS transitions for one frame while the theme changes.           |
| `className`                 | `string`                        | -          | Adds classes to the provider wrapper.                                       |
| `children`                  | `ReactNode`                     | -          | Application or component subtree that should inherit the provider contract. |

<DocsTab id="accessibility">

What VeliProvider does for language and direction, and what you still need to set yourself.

## Page language

- VeliProvider sets lang and dir only on its own wrapper. Set lang and dir on the html element yourself: lang="dv" dir="rtl" for Dhivehi pages and lang="en" dir="ltr" for English pages.
- Render html lang and dir on the server in the first HTML, from the same value you pass to language, so the page never paints in the wrong direction.
- Overlays such as Modal and Popover render outside the wrapper, so they take their direction and theme from html.

## Screen readers

- The lang that VeliProvider sets lets screen readers switch to a Dhivehi voice. Screen reader and text to speech support for Dhivehi is limited, so test Dhivehi pages on the devices people use.
- VeliProvider passes the mapped locale to React Aria, so built-in names and keyboard direction follow the language.
- Mark any phrase in a different language from the page with lang, and dir when the direction differs. On bilingual pages, give each block its own lang and dir.

## Reduced motion

disableTransitionOnChange turns off transitions and animations for one frame while the theme changes, so the whole page doesn't animate between colours.

## Contrast

Check contrast for every text and control colour in Light and Dark separately, because Veli colours change value between themes. Design and review every screen in both themes together.

## Testing

- Test every service by hand before release: with the keyboard only, at 400% zoom, at 200% text size, with text spacing overrides, with reduced motion, in forced colours and in Dark.
- Check every template at widths 320, 375, 768 and 1280 and at an ultra-wide width, in English and in Dhivehi. Zoom out to 50% to fake the ultra-wide width.

## Right to left

Set language="dv". Direction-aware Veli components read the provider or the inherited direction, and use logical properties so layouts mirror. Use logical properties in your own layout too.
