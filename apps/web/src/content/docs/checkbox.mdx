# Checkbox

<DocsTab id="overview">

A checkbox lets people choose one or more options from a set, or turn a single option on or off. Use it when any number of choices can be selected, including none, and the choice takes effect when the form is submitted. A checkbox can be off, on or indeterminate, which shows that some, not all, of the items it controls are selected.

## When to use

### Use a checkbox when

- People can choose any number of options, including none, and opt in or out of each one on its own.
- One option is turned on or off and takes effect when the form is submitted, such as accepting terms. Ask for consent with a checkbox whose label states exactly what people agree to.
- A parent option needs to show that only some of its children are selected. Use the indeterminate value on the parent.
- People need to see every option at once to compare them.
- Several checkboxes need a shared label, description or error message. Put them in a CheckboxGroup.

### Don't use a checkbox when

- People must choose exactly one option from a set. Use a [radio](/docs/radio/) group.
- The setting changes straight away and reads as on or off, such as turning notifications on. Use a [switch](/docs/switch/).
- The list is long and people would rather search or type into it. Use a [combobox](/docs/combobox/).
- The choice is an action, such as Save. Use a [button](/docs/button/).

1. **Control**

   the square box, 16 at size md, 20 at lg and 24 at xl. It has a border when off and is filled when on or indeterminate. In code it is Checkbox.

2. **Indicator**

   a check when on and a dash when indeterminate. It is decorative, so screen readers skip it; the state comes from the input. In code isSelected shows the check and isIndeterminate the dash.

3. **Label**

   names the choice. Clicking it toggles the box. In code it is the Checkbox children.

4. **Description**

   optional helper text below the label. In code it is description.

5. **Error message**

   shown only while the checkbox is invalid. In code it is errorMessage, shown when isInvalid is true.

## Content guidelines

### Labels

Name the thing being chosen, in sentence case and without a full stop. Keep a label to one line where you can. Write options as short, parallel phrases that don't overlap, in a logical order such as alphabetical, by size or by frequency.

| Do                    | Don't                           |
| :-------------------- | :------------------------------ |
| Email me a receipt    | Receipt. (full stop on a label) |
| Send me SMS reminders | EMAIL ME A RECEIPT (all caps)   |

### Positive wording

Word labels so that selected means yes.

| Do                                    | Don't                                               |
| :------------------------------------ | :-------------------------------------------------- |
| Send me SMS reminders                 | Don't send me SMS reminders (selecting it means no) |
| Email me updates about my application | Do not email me (selected means no)                 |

### Descriptions

Add one short sentence only when the label needs context. Leave off the full stop, and don't put links in it.

| Do                                        | Don't                                                                                   |
| :---------------------------------------- | :-------------------------------------------------------------------------------------- |
| We send it to the address on your account | Please read this carefully before you continue. (please, adds nothing, and a full stop) |

### Error messages

Say what is wrong and how to fix it, in one sentence without a full stop. For a missing answer, use Choose. Never show only Required or Invalid, don't blame people and don't say please. Show the same words in the error summary at the top of the page, and mark the checkbox or group invalid with isInvalid.

| Do                                    | Don't                                                          |
| :------------------------------------ | :------------------------------------------------------------- |
| You must accept the terms to continue | Invalid input (generic)                                        |
| Choose at least 1 way to contact you  | Please tick the box. (please, sensory wording and a full stop) |
|                                       | Required (does not say what to do)                             |

### Group labels

Write the group label as the question you are asking, ending with a question mark and with no colon. Add the description Choose all that apply. CheckboxGroup has no label prop, so put FieldLabel inside it; use aria-labelledby only when a visible heading already asks the question. On a page that asks one question, the question is also the page heading.

| Do                         | Don't                                                              |
| :------------------------- | :----------------------------------------------------------------- |
| How should we contact you? | Notification channels: (a colon, and it does not ask the question) |

### Consent

Say exactly what people agree to, in the first person. Ask for each purpose in its own checkbox, and summarise the key terms in plain words beside it. People must be able to open the full terms without losing their answers.

| Do                                                                                      | Don't                                                                     |
| :-------------------------------------------------------------------------------------- | :------------------------------------------------------------------------ |
| I confirm these details are correct                                                     | I agree (does not say to what)                                            |
| I agree to Maldives Immigration sharing my passport details with the Ministry of Health | I agree to the terms and to receive newsletters (two purposes in one box) |

### None of these

When none of the options may apply, add None of these as the last checkbox in the group, and clear the other options when people select it. Without it, people can't tell a skipped question from a real answer of none.

### No links

Don't put links in labels, descriptions or error messages.

### Dhivehi copy

Checkbox has no built-in text. Pass every label, description, error and accessible name in English and Dhivehi. Write Dhivehi natively rather than translating word for word, and keep it as short as the English, because Dhivehi lines are taller.

| Value         | When                                                 | In code                                          |
| :------------ | :--------------------------------------------------- | :----------------------------------------------- |
| Off           | Not selected. The default                            | isSelected false                                 |
| On            | Selected                                             | isSelected, or defaultSelected when uncontrolled |
| Indeterminate | Some, not all, of the items it controls are selected | isIndeterminate                                  |

- A click toggles between off and on.
- Use indeterminate only on a parent checkbox that controls a group of children. It shows partial selection; it is not a third submitted value.
- The dash replaces the check whatever isSelected is.
- Code does not clear isIndeterminate on click. Set it from the children's state in your handler, or the parent shows the wrong summary.

## Sizes

Checkbox has three sizes: md, lg and xl. The box, the label style, and the description and error style change with size. In code, size defaults to md.

- Use **md** (box 16) in most forms, next to md inputs.
- Use **lg** (box 20) next to lg fields, so label sizes match.
- Use **xl** (box 24) when the checkbox is the main thing on the screen, such as a single consent step.
- Keep one size within a group.

- **Required consent**: one checkbox before people submit. Set isRequired, and isInvalid with errorMessage when it is not selected. Leave out the description.
- **Option with detail**: a choice that needs one line of context. Set description.
- **Group with parent**: set isIndeterminate on the parent and put the children in a CheckboxGroup, indented 24 under the parent and 12 apart.
- Group related checkboxes in a CheckboxGroup. It holds one list of selected values and stacks the checkboxes 12 apart.
- Put the error on a single checkbox only when it stands alone, as with consent. For a group, set errorMessage on the CheckboxGroup.

| State    | When                              | Visual change                                                                   |
| :------- | :-------------------------------- | :------------------------------------------------------------------------------ |
| Default  | No interaction                    | Off shows the border; on and indeterminate fill the box                         |
| Hover    | Pointer over the box or the label | The border darkens; a filled box turns `components/checkbox/container-bg-hover` |
| Pressed  | While pressing                    | The border thickens by 1. A filled box uses the hover fill                      |

| Disabled | isDisabled                        | Muted box and text; removed from the tab order                                  |
| Invalid  | isInvalid                         | The error message shows below; the box does not change                          |

Code also has isReadOnly. A read-only checkbox keeps focus and its value but blocks changes, and it looks the same as default.

## Behaviour

- **Toggling**: clicking the box or its label toggles it, and so does Space. The whole row is the target. onChange receives the new value as a boolean.
- **Controlled or uncontrolled**: pass isSelected with onChange to control it, or defaultSelected to leave it uncontrolled.
- **Groups**: CheckboxGroup holds the selected values as a list of strings. Give each Checkbox a unique value. The group's value and onChange work with form libraries.
- **Validation**: isInvalid shows errorMessage below the label. isRequired marks the input as required; on a CheckboxGroup it means at least one must be selected.
- **Validate on submit**: Veli Form shows errors without blocking submission, so check a required Checkbox or CheckboxGroup in the submit handler and set isInvalid and your own errorMessage there. Browser messages are in English and don't follow the language you set.
- **Group errors**: a CheckboxGroup replaces its description with the error while invalid, so the error must make sense on its own. A single checkbox keeps its description beside its error.
- **Consent starts unticked**: never pre-tick a checkbox that gives consent, accepts terms or agrees to data sharing. Leave out defaultSelected, and set isRequired when the service can't go ahead without it. Don't tick Remember me by default, and never offer it on kiosks.
- **No surprises**: changing a checkbox never navigates or submits. Showing a related follow-up question directly below it is fine.
- **Wrapping**: labels and messages wrap to the space they have. A CheckboxGroup stacks, or wraps when it must.
- **Styling**: Checkbox takes no style overrides. Its className only sets the outer layout.

## Descriptions and validation

`description` sits below the label. `errorMessage` appears when `isInvalid` is true. Both describe the input without becoming part of its accessible name. A newly shown error is announced.

```tsx
import { Checkbox } from '@veli-design/react/checkbox';
```

## Group

`CheckboxGroup` manages several checkboxes as one `string[]` value. Give each `Checkbox` a unique `value`. Put `FieldLabel` inside the group for a visible group name, or use `aria-label` or `aria-labelledby`. Group `description` provides shared guidance; an invalid group's `errorMessage` replaces that description. The group's `value` / `onChange` accept a form library field directly (see [Forms](/docs/patterns/forms/)).

<div className="preview p-4 border border-base-subtle rounded-lg bg-surface-raised mb-4">
  <CheckboxGroupDemo client:visible />
</div>

```tsx
'use client';

import { useState } from 'react';
import { Checkbox, CheckboxGroup } from '@veli-design/react/checkbox';
import { FieldLabel } from '@veli-design/react/field';

export function CheckboxGroupDemo() {
  const [channels, setChannels] = useState<string[]>(['email']);

  return (
    <div className="grid w-full max-w-sm gap-4">
      <CheckboxGroup
        name="channels"
        value={channels}
        onChange={setChannels}
        isRequired
        description="Where should we send updates?"
      >
        {({ isDisabled, isRequired }) => (
          <>
            <FieldLabel isDisabled={isDisabled} isRequired={isRequired}>
              Notification channels
            </FieldLabel>
            <Checkbox value="email">Email</Checkbox>
            <Checkbox value="sms">SMS</Checkbox>
            <Checkbox value="push">Push notifications</Checkbox>
          </>
        )}
      </CheckboxGroup>
      <p className="type-body-sm-regular text-base-muted" role="status">
        Selected: {channels.length ? channels.join(', ') : 'None'}
      </p>
    </div>
  );
}
```

For required or disabled groups, pass the group's render-state flags to `FieldLabel` as shown above. These explicit props keep the required indicator and label color aligned with the group, including when it is nested inside a `Field` with different state. `FieldLabel` is a group heading; use plain visible children for each checkbox's inline label.

For one controlled checkbox, pass `isSelected` and `onChange`. For an uncontrolled checkbox, use `defaultSelected`.

## Language, direction, and motion

Use `VeliProvider language="dv"` for Dhivehi. It places the box at the right in RTL and applies Dhivehi text styles; the check and dash keep their direction. Labels and messages wrap in narrow layouts. Color and indicator transitions are disabled when the user requests reduced motion.

## API Reference

Checkbox composes React Aria's checkbox behavior with a native `<input type="checkbox">` inside a label. CheckboxGroup composes React Aria's [CheckboxGroup](https://react-aria.adobe.com/CheckboxGroup) around several Checkbox inputs. Props below follow that stack.

### Checkbox

Veli-specific props and composition for the individual control.

| Prop           | Type                   | Default | Description                                                                  |
| :------------- | :--------------------- | :------ | :--------------------------------------------------------------------------- |
| `size`         | `'md' \| 'lg' \| 'xl'` | `'md'`  | 16px, 20px, or 24px control with matching label and message typography.      |
| `children`     | `ReactNode`            | -       | Visible inline label. Render-function children are not supported.            |
| `description`  | `ReactNode`            | -       | Helper text beneath the label, linked to the input's accessible description. |
| `errorMessage` | `ReactNode`            | -       | Error text displayed and announced when `isInvalid` is explicitly true.      |
| `className`    | `string`               | -       | Layout class merged onto the outer label.                                    |

An invalid individual checkbox keeps its description alongside its error. For application-managed errors, pass both `isInvalid` and `errorMessage`; this component does not render generated React Aria `FieldError` messages automatically.

### React Aria Checkbox

Selection, interaction, validation, and accessible-label props pass through to React Aria. The [React Aria Checkbox documentation](https://react-aria.adobe.com/Checkbox) covers its behavior; Veli's differences and exclusions are listed below.

| Prop                 | Type                                                                  | Default                                   | Description                                                         |
| :------------------- | :-------------------------------------------------------------------- | :---------------------------------------- | :------------------------------------------------------------------ |
| `isSelected`         | `boolean`                                                             | -                                         | Controlled checked state outside a group.                           |
| `defaultSelected`    | `boolean`                                                             | `false`                                   | Initial uncontrolled checked state outside a group.                 |
| `onChange`           | `(selected: boolean) => void`                                         | -                                         | Receives a boolean when selection changes, rather than a DOM event. |
| `isIndeterminate`    | `boolean`                                                             | `false`                                   | Displays the mixed dash until the application clears this prop.     |
| `isDisabled`         | `boolean`                                                             | `false`                                   | Prevents focus, interaction, and native submission of this input.   |
| `isReadOnly`         | `boolean`                                                             | `false`                                   | Allows focus but prevents selection changes.                        |
| `isRequired`         | `boolean`                                                             | `false`                                   | Requires this checkbox to be selected outside a group.              |
| `isInvalid`          | `boolean`                                                             | `false`                                   | Marks the input invalid; enables Veli's explicit inline error.      |
| `validate`           | `(selected: boolean) => ValidationError \| true \| null \| undefined` | -                                         | Custom validation of the selection state.                           |
| `validationBehavior` | `'native' \| 'aria'`                                                  | Inherited from Form, otherwise `'native'` | Browser constraint validation or ARIA-only feedback.                |
| `autoFocus`          | `boolean`                                                             | `false`                                   | Focuses the input on mount.                                         |
| `inputRef`           | `RefObject<HTMLInputElement \| null>`                                 | -                                         | Ref to the native checkbox input for focus or inspection.           |
| `aria-label`         | `string`                                                              | -                                         | Accessible name when no visible label is provided.                  |
| `aria-labelledby`    | `string`                                                              | -                                         | IDs of elements supplying the accessible name.                      |
| `aria-describedby`   | `string`                                                              | -                                         | Extra description IDs, combined with Veli's helper/error IDs.       |

`ValidationError` is a string or string array. `validate` returns `true`, `null`, or `undefined` when valid. Veli `Form` defaults to `validationBehavior="aria"`; opt into `"native"` when browser validation should block submission. Inside a group, drive selection with the group's `value` / `onChange` and each checkbox's unique `value`.

React Aria differences and exclusions:

| Prop           | Veli behavior                                                                    |
| :------------- | :------------------------------------------------------------------------------- |
| `children`     | Replaced by visible `ReactNode` label content; no render function.               |
| `className`    | Replaced by a string layout class on the root; no state function.                |
| `style`        | Not supported.                                                                   |
| `errorMessage` | Accepts `ReactNode`; validation-message render functions are not supported.      |
| `ref`          | A root ref is not declared in Veli's public props; use `inputRef` for the input. |

### Native checkbox input

These attributes reach the native input. The type is fixed to `checkbox`. Use `isSelected` / `defaultSelected`, `isDisabled`, and `isReadOnly` instead of native `checked` / `defaultChecked`, `disabled`, and `readOnly` props.

| Prop    | Type     | Default                           | Description                                                  |
| :------ | :------- | :-------------------------------- | :----------------------------------------------------------- |
| `value` | `string` | Native `'on'` outside a group     | Submitted value when checked; must be unique inside a group. |
| `name`  | `string` | Inherited from group, otherwise - | Native form field name.                                      |
| `form`  | `string` | Inherited from group, otherwise - | ID of the associated form.                                   |

Veli-specific props for the group container and its shared message.

| Prop           | Type        | Default | Description                                                               |
| :------------- | :---------- | :------ | :------------------------------------------------------------------------ |
| `description`  | `ReactNode` | -       | Shared helper text below the group.                                       |
| `errorMessage` | `ReactNode` | -       | Replaces the helper when invalid; generated errors are used when omitted. |
| `className`    | `string`    | -       | Layout class merged onto the outer group element.                         |

React Aria's [CheckboxGroup props](https://react-aria.adobe.com/CheckboxGroup#api) pass through, subject to the exclusions below. The container has `role="group"`; native form values come from its child checkbox inputs.

| `validate`           | `(value: string[]) => ValidationError \| true \| null \| undefined` | -                                         | Custom validation of the group's selected values.                   |
| `validationBehavior` | `'native' \| 'aria'`                                                | Inherited from Form, otherwise `'native'` | Browser constraint validation or ARIA-only feedback.                |
| `name`               | `string`                                                            | -                                         | Default native form field name for child checkboxes.                |
| `form`               | `string`                                                            | -                                         | Default associated form ID for child checkboxes.                    |

<DocsTab id="accessibility">

How the checkbox works with keyboards, screen readers and touch, and what you still need to do. Each checkbox is a native checkbox input inside its label, built on React Aria.

## Keyboard

| Key         | Action                                                                         |
| :---------- | :----------------------------------------------------------------------------- |
| Tab         | Moves focus to the next checkbox. Each checkbox in a group is its own tab stop |
| Shift + Tab | Moves focus to the previous checkbox                                           |
| Space       | Toggles the focused checkbox                                                   |

Enter does not toggle a checkbox, and there is no arrow key navigation in a CheckboxGroup. Disabled checkboxes are skipped.

## Screen readers

- A native checkbox input sits inside the label, visually hidden, so the label text is the accessible name. Pass aria-label only when there is no visible text, and make sure any accessible name contains the visible label.
- The state is read as checked, not checked, or mixed for indeterminate.
- The description and error are linked to the input with aria-describedby, so they are read after the label. A newly shown error is announced.
- The check and dash are decorative and hidden from assistive technology.
- A CheckboxGroup is a group named by the FieldLabel placed inside it. Every group of checkboxes needs a group label.

## Focus

- Keyboard focus shows the focus ring around the box. It appears for keyboard focus only, not on click.
- The ring sits outside the box, so focusing doesn't change its size or move the label.
- State is never shown by colour alone: the check, the dash and the border show it, and errors also show a message.

## Disabled

Disabled checkboxes can't be focused or changed, and are left out of form submission. When people need to see a value they can't change here, use isReadOnly instead: a read-only checkbox keeps focus and its value.

## Target size

The label is part of the control, so the whole row toggles the checkbox. At size md the row is 20 high, under the 24 minimum, so it passes only through spacing: keep checkboxes at least 12 apart, as CheckboxGroup does, or use size lg on touch screens. Keep the label inside the control.

## Contrast

Use the checkbox's text, border and fill tokens as they are. Don't override them with custom colours.

## Reduced motion

When the user prefers reduced motion, the box colours and the check change without a transition. Nothing extra is needed from you.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction and the language, places the box on the right and applies the Dhivehi text styles. Pass Dhivehi labels, descriptions and errors yourself: Checkbox has no built-in text.
