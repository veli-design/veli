# Dropzone

<DocsTab id="overview">

A drop zone lets people attach files to a form, by dragging them in or browsing, and shows each file's upload status. It checks each file against the limits you set and lists accepted files with their progress and a remove button. Use it when a service needs documents from the applicant, such as a passport copy or a signed contract.

## When to use

### Use a drop zone when

- People need to attach one or more files by dropping or browsing.
- The form must show accepted files, rejection feedback, upload progress, previews or remove buttons.
- People may have the file open on their desktop and want to drag it in.

### Don't use a drop zone when

- The question doesn't take a file. Use the control that matches the value, such as Input for a reference number or Text area for an explanation.
- The file is optional and rarely needed.
- A problem affects the whole form. Use Alert, not the drop zone's message.

A drop zone field holds a drop area, and each chosen file shows as a file row.

<DocsAnatomy>

1. **Label**

   names what to upload. Body md regular at labelSize md, body sm regular at sm, in `text/base/DEFAULT`. In code it is label.

2. **Info icon**

   a 16px icon that opens a tooltip with more help. Never put the limits only here. In code it is infoTooltip.

3. **Optional**

   the localised word Optional after the label. Code hides it when isRequired is set. In code it is isOptional.

4. **Required indicator**

   an asterisk in `text/danger/muted`. Turn it off with showRequiredIndicator. In code it is isRequired.

5. **Drop area**

   the drop target. In single mode it becomes a file row once a file is chosen; in multiple mode the list sits below it. In code it is DropzoneArea.

6. **Description**

   helper text below the field, caption regular in `text/base/subtle`. The error message replaces it while invalid. In code it is description.

</DocsAnatomy>

<DocsAnatomy>

1. **Icon**

   a decorative 24px upload icon in a 40 box, in `icon/base/muted`.

2. **Title**

   what to do, body sm medium. It defaults to Drag and drop files here written with an ampersand; set it to Drag and drop files here, written out. In code it is title.

3. **Hint**

   caption regular in `text/base/subtle`. It defaults to Or click to browse; set it to what to upload, such as Front and back of your ID card. In code it is hint.

4. **Secondary text**

   optional, after a short divider: limits such as Up to 10 MB. Caption regular in `text/base/muted`. In code it is secondaryText.

5. **Trigger**

   the Browse files button, a secondary, transparent, sm Veli Button. Turn it off with showTrigger, but keep it for people who can't drag. In code it is DropzoneTrigger.

</DocsAnatomy>

<DocsAnatomy>

1. **Preview**

   a 40 box with radius 6, showing an image thumbnail with imagePreview, or a file type icon. In code it is DropzoneItemPreview.

2. **File name**

   body sm medium, shortened to one line. In code it comes from the File.

3. **File size**

   caption regular in `text/base/subtle`, formatted from the File, such as 1.2 MB.

4. **Status**

   the percentage while uploading, Uploaded on success, or the reason on error. In code it is DropzoneItemMetadata.

5. **Remove button**

   an sm icon button, named Remove with the file name. A cross while uploading, on error and idle; a danger trash icon once uploaded. In code it is DropzoneItemDelete.

6. **Progress bar**

   a 4 high bar along the bottom while uploading and after success, hidden on error. In code it is DropzoneItemProgress.

</DocsAnatomy>

Rows sit in DropzoneList, a list under the area in multiple mode. It can run vertically or wrap horizontally; choose the direction for the space available. It is a building block, not a separate component to place.

## Content guidelines

### Label

Name the document, in sentence case, without a full stop.

| Do                  | Don't                                    |
| :------------------ | :--------------------------------------- |
| Passport copy       | Upload file (names the action)           |
| Employment contract | Attachment (does not say which document) |

### Title and hint

Replace the built-in title and hint. Set the title to Drag and drop files here, and the hint to what to upload, in English and Dhivehi. The built-in title uses an ampersand and the built-in hint says click.

| Do                             | Don't                                         |
| :----------------------------- | :-------------------------------------------- |
| Drag and drop files here       | The built-in title, written with an ampersand |
| Front and back of your ID card | Or click to browse (says click)               |

### Limits

Write the description as what is accepted, in this order: file types, size per file, then the count when there is a limit. Put the limits in secondaryText and the description, never only in the info tooltip.

| Do                                         | Don't                                                                                     |
| :----------------------------------------- | :---------------------------------------------------------------------------------------- |
| PDF, PNG or JPG, up to 10 MB each          | PDF, PNG or JPG with a middle dot before "up to 10 MB each" (a middle dot as a separator) |
| PDF or JPG, up to 5 MB each, up to 5 files | pdf/png/jpg &lt;10MB (symbols, no spaces, lower case types)                               |

### Rejection messages

Replace the built-in rejection reasons (File type not accepted, File too large, Only one file allowed, Maximum &#123;count&#125; files allowed) with messages that say what to do. Pass them from onFileValidate or onFileReject in English and Dhivehi.

For single-file fields write:

- Choose &#123;file&#125;, when none is chosen.
- The selected file must be a &#123;types&#125;.
- The selected file must be smaller than &#123;size&#125;.
- The selected file is empty.
- The selected file contains a virus.
- The selected file is password protected.

In file rows, where the file name already shows, use the short form: File type not supported. Upload a PDF, PNG or JPG.

| Do                                                        | Don't                                      |
| :-------------------------------------------------------- | :----------------------------------------- |
| The selected file must be a PDF, PNG or JPG               | File too large (no limit and no fix)       |
| The selected file must be smaller than 10 MB              | Invalid file. (says nothing about the fix) |
| You can upload up to 5 files. Remove 2 files to continue. |                                            |
| Choose a passport copy                                    |                                            |

### Upload failures and duplicates

When an upload fails for reasons outside the file, write The selected file could not be uploaded. Try again. and offer a Try again action. Keep files that did upload. When a file is added twice, write This file has already been added.

### Percentages

Write percentages as a numeral and the sign with no space: 19%.

### Built-in strings

The drop zone has 20 built-in strings, all with Dhivehi values. You can override the title (title), hint (hint), Browse files (DropzoneTrigger children), Clear all (DropzoneClear children), More information (infoTooltipAriaLabel), the fallback area name File upload (label or aria-label) and the rejection reasons. The row statuses (Ready to upload, Uploading with the percentage, Uploaded, Upload complete, Upload failed, Error with the message), the progress bar name, the remove button name and Optional have no override. Keep them.

### Dhivehi copy

Pass a Dhivehi value for every prop you override, such as title, hint and your rejection messages. Write Dhivehi natively and keep it as short as the English.

## Behaviour

- **Adding files**: people drag files onto the area, press the area or Browse files to open the system picker, or paste files into the focused area. Pasted files go through the same checks as dropped ones.
- **Checks**: files are checked by type, size, count or a custom rule (acceptedFileTypes, maxSize, maxFiles, onFileValidate) after the drop. Files that fail are not added, and the other files stay.
- **Upload**: the drop zone doesn't upload files itself. Supply the transport through onUpload and report progress, success and error for each file.
- **Rejected files**: show rejection messages outside the drop target, next to the file, when people need the detail to stay.
- **Dragging**: while people drag, turn off text selection and mark the dragged item inert.
- **Removing**: people remove a file at once with its remove button, without a confirmation, because they can add it again. Offer Clear all (DropzoneClear) only when many files are listed.
- **Focus after changes**: in single mode, focus moves to the remove button when a file is chosen, and back to Browse files when it is removed. In multiple mode, after a removal, move focus to the next remove button, or to Browse files when none is left.
- **Keep uploads**: keep uploaded files when other fields on the page have errors, and when people come back to the page.
- **Phone photos**: accept the formats phones produce, and resize or compress large images on the device where possible rather than rejecting them.
- **Files**: control the files with value and onValueChange, or leave them uncontrolled with defaultValue. With name, a hidden native file input submits the files.
- **Long names**: when a file name is shortened, keep the end visible so the extension shows, such as passport-co….pdf. Truncation sits at the inline end, which is the left in Dhivehi.

## Composition

Use DropzoneField for a labelled drop zone. For a custom layout, compose Dropzone with DropzoneArea and, optionally, DropzoneList, the item parts (DropzoneItemPreview, DropzoneItemMetadata, DropzoneItemDelete, DropzoneItemProgress) and DropzoneClear. Keep the parts inside Dropzone, and the item parts inside DropzoneItem.

## Usage

```tsx
<DropzoneField
  label="Attachment"
  isOptional
  description="PDF, PNG or JPG · up to 10 MB each"
  secondaryText="Up to 10 MB"
  acceptedFileTypes={['application/pdf', 'image/png', 'image/jpeg']}
  maxSize={10 * 1024 * 1024}
  onUpload={upload}
/>
```

A single-file field is one row. The chosen file replaces it until the file is removed. With `onUpload`, each file shows its progress, then Uploaded or the error message.

## Validation

Files that fail `acceptedFileTypes`, `maxSize`, `maxFiles`, or `onFileValidate` are not added. `onFileReject` receives the file and a localized reason; pass it to `errorMessage` to show it under the field.

<div className="preview mb-4 rounded-lg border p-4">
  <DropzoneValidationDemo client:visible />
</div>

```tsx
const [error, setError] = useState<string>();

<DropzoneField
  multiple
  label="Documents"
  description="PDF only · up to 2 MB each"
  errorMessage={error}
  acceptedFileTypes={['application/pdf']}
  maxSize={2 * 1024 * 1024}
  onAccept={() => setError(undefined)}
  onFileReject={(file, message) => setError(`${file.name}: ${message}`)}
/>;
```

## API Reference

DropzoneField is a Veli field on React Aria [`DropZone`](https://react-spectrum.adobe.com/react-aria/DropZone.html), with a hidden native `<input type="file">` for browsing and form submission.

### DropzoneField

| Prop                    | Type                         | Default          | Description                                                            |
| :---------------------- | :--------------------------- | :--------------- | :--------------------------------------------------------------------- |
| `label`                 | `ReactNode`                  | -                | Visible label.                                                         |
| `labelSize`             | `'sm' \| 'md'`               | `'md'`           | Label type scale.                                                      |
| `isOptional`            | `boolean`                    | `false`          | Shows localized Optional. Hidden when `isRequired`.                    |
| `isRequired`            | `boolean`                    | `false`          | Shows the required asterisk.                                           |
| `showRequiredIndicator` | `boolean`                    | `true`           | Shows the asterisk when `isRequired`.                                  |
| `infoTooltip`           | `ReactNode`                  | -                | Content for the header info tooltip.                                   |
| `infoTooltipAriaLabel`  | `string`                     | Localized string | Accessible name for the info tooltip trigger.                          |
| `multiple`              | `boolean`                    | `false`          | Accepts several files and stacks the area above the list.              |
| `title`                 | `ReactNode`                  | Localized string | Drop area title.                                                       |
| `hint`                  | `ReactNode`                  | Localized string | Drop area hint under the title.                                        |
| `secondaryText`         | `ReactNode`                  | -                | Text after the divider, such as upload limits.                         |
| `showTrigger`           | `boolean`                    | `true`           | Shows the Browse files button.                                         |
| `description`           | `ReactNode`                  | -                | Helper text beneath the field.                                         |
| `errorMessage`          | `ReactNode`                  | -                | Replaces the description when invalid.                                 |
| `isInvalid`             | `boolean`                    | with message     | Shows the invalid border and `errorMessage`.                           |
| `isDisabled`            | `boolean`                    | `false`          | Disables dropping, browsing, and removing files.                       |
| `acceptedFileTypes`     | `string[]`                   | -                | MIME types, wildcards such as `image/*`, or extensions such as `.pdf`. |
| `maxFiles`              | `number`                     | -                | Maximum number of files when `multiple`.                               |
| `maxSize`               | `number`                     | -                | Maximum size per file, in bytes.                                       |
| `value`                 | `File[]`                     | -                | Controlled files.                                                      |
| `defaultValue`          | `File[]`                     | -                | Uncontrolled initial files.                                            |
| `onValueChange`         | `(files: File[]) => void`    | -                | Called when files are added or removed.                                |
| `onAccept`              | `(files: File[]) => void`    | -                | Called with each batch of accepted files.                              |
| `onFileAccept`          | `(file: File) => void`       | -                | Called for each accepted file.                                         |
| `onFileReject`          | `(file, message) => void`    | -                | Called for each rejected file with a localized reason.                 |
| `onFileValidate`        | `(file) => string \| null`   | -                | Return a message to reject a file.                                     |
| `onUpload`              | `(files, callbacks) => void` | -                | Upload handler. Report `onProgress`, `onSuccess`, and `onError`.       |
| `name`                  | `string`                     | -                | Native form field name for the file input.                             |
| `required`              | `boolean`                    | `false`          | Requires a file on native form submission.                             |
| `aria-label`            | `string`                     | -                | Accessible name when there is no visible label.                        |
| `className`             | `string`                     | -                | Layout class on the root (width, margin, flex/grid).                   |

### DropZone

`DropzoneField` renders React Aria’s [`DropZone`](https://react-spectrum.adobe.com/react-aria/DropZone.html#props) but does not forward its props. Compose `DropzoneArea` to reach them; it passes these through:

| Prop               | Type                            | Description                                                 |
| :----------------- | :------------------------------ | :---------------------------------------------------------- |
| `onDrop`           | `(event: DropEvent) => void`    | Called before dropped files are added.                      |
| `getDropOperation` | `(types, operations) => string` | Drop operation to allow. Veli defaults to `copy`.           |
| `onDropEnter`      | `(event) => void`               | Called when a drag enters the area.                         |
| `onDropExit`       | `(event) => void`               | Called when a drag leaves the area.                         |
| `onDropActivate`   | `(event) => void`               | Called when a drag hovers the area long enough to activate. |

Not forwarded from `DropZone`:

| Prop         | Why                                                           |
| :----------- | :------------------------------------------------------------ |
| `children`   | Replaced by Veli content; custom `children` replace it.       |
| `className`  | Replaced by a string `className` on the area.                 |
| `isDisabled` | Set from the root `disabled` or `DropzoneField` `isDisabled`. |

### Native file input

The hidden `<input type="file">` that opens the picker and submits files.

| Prop       | Type      | Description                                                         |
| :--------- | :-------- | :------------------------------------------------------------------ |
| `name`     | `string`  | Native form field name. The input stays in sync with dropped files. |
| `required` | `boolean` | Requires a selected file on native form submission.                 |
| `multiple` | `boolean` | Set from `multiple`.                                                |
| `accept`   | `string`  | Set from `acceptedFileTypes`.                                       |

### Composition

Build a custom layout from the parts `DropzoneField` uses. `Dropzone` takes the same file, validation, and callback props, plus `accept` (comma-separated), `label` (accessible name), `disabled`, `invalid`, `dir`, and `lang`.

```tsx
<Dropzone multiple label="Upload files" onUpload={upload}>
  <DropzoneArea title="Drop files to upload" />
  <DropzoneList>
    <Items />
  </DropzoneList>
  <DropzoneClear />
</Dropzone>;

function Items() {
  const files = useDropzone((state) => Array.from(state.files.keys()));

  return files.map((file) => (
    <DropzoneItem key={file.name} value={file}>
      <DropzoneItemPreview />
      <DropzoneItemMetadata />
      <DropzoneItemDelete />
      <DropzoneItemProgress />
    </DropzoneItem>
  ));
}
```

| Part                   | Description                                                                                            |
| :--------------------- | :----------------------------------------------------------------------------------------------------- |
| `DropzoneArea`         | Drop target. Takes `title`, `hint`, `secondaryText`, `showTrigger`, `isInvalid`, or custom `children`. |
| `DropzoneTrigger`      | Button that opens the file picker. Accepts Veli `Button` props.                                        |
| `DropzoneList`         | Vertical list of items. `forceMount` renders it while empty.                                           |
| `DropzoneItem`         | One file row. Takes `value: File`.                                                                     |
| `DropzoneItemPreview`  | Image thumbnail or file icon. `render(file, fallback)` replaces it.                                    |
| `DropzoneItemMetadata` | File name, size, and status.                                                                           |
| `DropzoneItemProgress` | Progress bar while uploading and after success. `forceMount` keeps it visible.                         |
| `DropzoneItemDelete`   | Removes the file.                                                                                      |
| `DropzoneClear`        | Removes every file. Accepts Veli `Button` props.                                                       |
| `useDropzone`          | Selects from the file store.                                                                           |

## Accessibility

- Give the field a visible `label`, or pass `aria-label`. `description` or `errorMessage` describes the drop area.
- The drop area is focusable. Enter or Space opens the file picker, and pasting files adds them. **Browse files** is a separate button.
- Each file is a list item that announces its name, size, and status. Remove buttons are named “Remove _file name_”.
- In single-file mode, focus moves to the remove button when a file is chosen, and back to **Browse files** when it is removed.
- Border and progress transitions honor reduced motion.

## RTL and Language

On `lang="dv"` pages, built-in strings — title, hint, Browse files, Optional, Uploaded, and rejection reasons — are Dhivehi. In RTL the single-file row mirrors and progress fills from the inline start. File sizes and percentages stay left-to-right, and file names keep their own direction.

How the drop zone works with keyboards and screen readers, and what you still need to do. It is built on the React Aria drop zone, button and progress bar, with a hidden native file input.

## Keyboard

The area, Browse files and each remove button are separate focus stops.

| Key                                        | Action                                                        |
| :----------------------------------------- | :------------------------------------------------------------ |
| Tab                                        | Moves to the drop area, Browse files, then each remove button |
| Enter or Space on the area                 | Opens the system file picker                                  |
| Enter or Space on Browse files             | Opens the system file picker                                  |
| Paste, Ctrl + V or Command + V on the area | Adds the pasted files                                         |
| Enter or Space on a remove button          | Removes that file                                             |

Dragging is never the only way to add a file: keep the Browse files button and don't turn it off with showTrigger false. If your service lets people reorder files by dragging, offer a keyboard way too, with named buttons such as Move passport-copy.pdf up.

## Screen readers

- Give the field a visible label, or aria-label when there is none. The area is named from the label and the title.
- The file list is a list. Each row announces the file name, size and status.
- Each progress bar is named Upload progress for and the file name, with the percentage as its value.
- Each remove button is named Remove with the file name.
- Announce upload start, completion and failure through a polite live region, not every percentage step.
- Optional and the asterisk sit outside the label, so neither is part of the accessible name. The required state is still exposed.

## Focus

The area shows a 2px ring in `border/focus`, offset 2, on keyboard focus only, never on hover or click. The label size doesn't change it. In forced colours mode the browser draws its own outline.
