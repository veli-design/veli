# Tooltip

<DocsTab id="overview">

A tooltip shows a short, non-interactive hint when people hover over or focus a control. Use it to name icon buttons or add a line of help that people can do without. Tooltips never show on touch screens, so never put anything people need in one.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/tooltip.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-tooltip--docs"
/>

## When to use

### Use a tooltip when

- An icon-only button needs a visible name on hover or focus.
- A control has a keyboard shortcut people may not know.
- A short hint helps, but people can do the task without it.
- A field needs a sentence of help, such as where to find an ID card number. Use size lg.

### Don't use a tooltip when

- The content has links, buttons or fields. Use Popover.
- People need the information to finish the task, such as requirements, fees, deadlines or warnings. Show it on the page, for example as helper text.
- The message reports a result or an error. Use Alert or Toast.
- The help explains a disabled control. A native disabled control may not show its tooltip, so show the reason on the page as helper text.
- It would be the only way to read text that is cut off. Show the full text; a tooltip may only repeat it.

## Content guidelines

### Length

Write a few words at size sm, and one or two short sentences at size lg. Don't explain what the label already makes obvious.

| Do                                                            | Don't                                                                                                          |
| :------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------- |
| Print                                                         | Click this button to print a copy of your birth certificate on any printer. (says the obvious, and uses click) |
| Download receipt                                              | Use this button to download a PDF copy of your payment receipt for MVR 250 (a sentence in a small tooltip)     |
| Your ID card number is on the front of your National ID card. | A long paragraph about eligibility (too long for a tooltip)                                                    |

### Icon buttons

Start with a verb, and name the object when there are several. Use the same words as the button's aria-label, with no role word such as button.

| Do                    | Don't                                   |
| :-------------------- | :-------------------------------------- |
| Download receipt      | Receipt (not an action)                 |
| Copy reference number | Download button (role word in the name) |

### Case and punctuation

Write in sentence case. No full stop after a short label; end sentences with a full stop.

| Do    | Don't                                      |
| :---- | :----------------------------------------- |
| Print | PRINT DOCUMENT. (all caps and a full stop) |

### Shortcuts

Write the action first, then each key as a Kbd, with the keys of the platform: Ctrl on Windows, ⌘ on macOS. Never mix platforms with a slash. Build shortcuts on a modifier key, test them with the Dhivehi keyboard, and never make a shortcut the only way to do something.

| Do              | Don't                                           |
| :-------------- | :---------------------------------------------- |
| Search Ctrl + K | Ctrl/Cmd + K (two platforms mixed with a slash) |

### No interaction

A tooltip is text only. No links, buttons or fields: people can't reach them. Use Popover instead.

| Do                                                     | Don't                                                       |
| :----------------------------------------------------- | :---------------------------------------------------------- |
| A Popover with More information and a link to guidance | A tooltip containing a Read the guidance link (unreachable) |

### Dhivehi copy

Tooltip has no built-in strings: pass every text in English and Dhivehi. Write Dhivehi natively rather than transliterating, and keep it as short as the English, because Thaana lines are taller.

## Behaviour

- **Opening**: hover opens the tooltip after delay (1500ms by default). Keyboard focus opens it at once. A mouse click that focuses the trigger doesn't open it.
- **Closing**: moving away closes it after closeDelay (500ms by default). Escape and pressing the trigger close it straight away. It never closes on a timer while people hover or focus it.
- **Next tooltip**: while one tooltip is open, moving to another trigger opens the next one at once.
- **Position**: code keeps the tooltip on screen and flips it when there is no room.
- **Disabled**: set isDisabled on TooltipTrigger to stop the tooltip; the trigger still works.
- **Controlled**: wrap one focusable trigger and the tooltip in TooltipTrigger. Use isOpen with onOpenChange, or defaultOpen, and delay and closeDelay for timing. Set trigger to focus to open it for keyboard focus only.
- **Touch**: tooltips never show on touch screens; a tap activates the trigger instead. Design kiosks the same way.

## Motion

| Phase       | What changes                                                                                                 | Timing                       | Easing   |
| :---------- | :----------------------------------------------------------------------------------------------------------- | :--------------------------- | :------- |
| Hover delay | Waits before opening on hover. Keyboard focus skips it                                                       | delay, 1500ms by default     | None     |
| Open        | Opacity 0 to 100%, scale 95% to 100% and a 4 slide away from the trigger, from the point nearest the trigger | Normal, 200ms                | Ease out |
| Close delay | Waits before closing once the pointer leaves                                                                 | closeDelay, 500ms by default | None     |
| Close       | Opacity 100% to 0, scale 100% to 95% and a 4 slide back toward the trigger                                   | Fast, 80ms                   | Ease in  |

The slide follows the placement: a tooltip above the trigger rises 4 as it opens, one below drops 4, and one to the side moves 4 sideways. The same timing applies to both sizes and both tones.

With reduced motion turned on, there is no transition: the tooltip appears and disappears at once, without fading or moving.

## Usage

<div className="preview mb-4 rounded-lg border p-4">
  <TooltipUsageDemo client:load />
</div>

```tsx
<TooltipTrigger delay={0}>
  <Button intent="secondary">Hover or focus me</Button>
  <Tooltip>Short help text for this action.</Tooltip>
</TooltipTrigger>
```

Keyboard focus opens immediately. Hover uses `delay`; moving away uses `closeDelay`. `trigger="focus"` opens only for keyboard focus. Escape dismisses the tooltip and leaves focus on its trigger. A disabled tooltip trigger leaves the underlying control available but suppresses the help.

## Sizes and tones

`sm` is a compact surface with no arrow. `lg` has a maximum width of 221px and an arrow. Small tooltips use a neutral background and emphasized text in both themes and have no tone variants. Large tooltips use `primary` or `secondary` background and text colors. Text wraps when available space is narrow.

<div className="preview mb-4 rounded-lg border p-4">
  <TooltipVariantsDemo client:load />
</div>

```tsx
<Tooltip size="lg" tone="secondary">
  Keep this help short and non-interactive.
</Tooltip>
```

## Placement

Use `top`, `bottom`, `left`, or `right` for physical sides. `start` and `end`, and aligned placements such as `top start`, follow the locale's direction. React Aria flips the tooltip when its preferred side does not fit.

<div className="preview mb-4 rounded-lg border p-4">
  <TooltipPlacementsDemo client:load />
</div>

```tsx
<Tooltip placement="top start" offset={16} crossOffset={0}>
  Aligned help
</Tooltip>
```

The default gap is 8px for small and 12px for large. An explicit `offset`, including zero, overrides it. `arrowBoundaryOffset` keeps the large caret away from rounded tooltip corners; its default is 20px.

## Shortcuts

Compose existing [Kbd](/docs/components/kbd/) primitives beside small help text. Apply a row layout to the shortcut composition to keep its 8px gap; ordinary Tooltip content keeps inline text flow. No shortcut prop is needed.

<div className="preview mb-4 rounded-lg border p-4">
  <TooltipShortcutDemo client:load />
</div>

```tsx
<Tooltip className="flex items-center gap-2">
  <span>Copy</span>
  <KbdGroup>
    <Kbd>⌘</Kbd>
    <Kbd>C</Kbd>
  </KbdGroup>
</Tooltip>
```

## Language and direction

Use `VeliProvider language="dv"` for a Dhivehi subtree. Portaled tooltips receive its language and direction and logical placements follow its locale. Explicit Tooltip `lang` and `dir` override its text direction; set the provider locale as well when changing logical positioning.

## Controlled state

```tsx
const [isOpen, setOpen] = useState(false);

<TooltipTrigger isOpen={isOpen} onOpenChange={setOpen}>
  <Button>Help</Button>
  <Tooltip>Brief help</Tooltip>
</TooltipTrigger>;
```

Use `defaultOpen` for an uncontrolled initial state. Tooltips remain associated with their trigger through `aria-describedby`; icon-only controls still need their own accessible name.

## Motion and accessibility

Entry and exit move a short distance from the resolved side and fade with Veli motion tokens. Reduced motion removes the movement and transitions. Collision flipping uses the resulting placement for both motion and caret orientation. Forced colors preserve readable text, surface boundaries, and the caret.

Do not make the tooltip focusable, put interactive controls inside it, or use it as the control's only accessible name. For native disabled controls, expose essential help outside the tooltip.

## API Reference

Tooltip is a Veli surface on React Aria [`Tooltip`](https://react-spectrum.adobe.com/react-aria/Tooltip.html#tooltip), which renders a native `<div>`. `TooltipTrigger` handles hover, focus, and open state. Props below follow that stack.

### Tooltip

Veli-specific props for the composed surface.

| Prop        | Type                        | Default              | Description                                                      |
| :---------- | :-------------------------- | :------------------- | :--------------------------------------------------------------- |
| `size`      | `'sm' \| 'lg'`              | `'sm'`               | Surface size; only large has a caret.                            |
| `tone`      | `'primary' \| 'secondary'`  | `'primary'` for `lg` | Available only with `size="lg"`; omit for small tooltips.        |
| `children`  | `ReactNode`                 | -                    | Non-interactive content.                                         |
| `className` | `string` or render function | -                    | Classes merged with the Veli surface; receives React Aria state. |
| `ref`       | `Ref<HTMLDivElement>`       | -                    | Forwarded to the tooltip surface.                                |

### React Aria Tooltip

React Aria’s headless [`Tooltip`](https://react-spectrum.adobe.com/react-aria/Tooltip.html#tooltip). These props pass through, with Veli defaults for `offset` and `arrowBoundaryOffset`. The React Aria docs cover the rest, except the exclusion below.

| Prop                  | Type                               | Default               | Description                                                   |
| :-------------------- | :--------------------------------- | :-------------------- | :------------------------------------------------------------ |
| `placement`           | `Placement`                        | `'top'`               | Preferred physical or logical side/alignment.                 |
| `offset`              | `number`                           | `8` SM / `12` LG      | Gap from the trigger; explicit zero is respected.             |
| `crossOffset`         | `number`                           | `0`                   | Offset along the other axis.                                  |
| `shouldFlip`          | `boolean`                          | `true`                | Flip when the preferred side lacks space.                     |
| `containerPadding`    | `number`                           | `12`                  | Minimum distance from the container boundary.                 |
| `arrowBoundaryOffset` | `number`                           | `20` LG               | Minimum caret inset; unused for SM.                           |
| `triggerRef`          | `RefObject<Element \| null>`       | from `TooltipTrigger` | Anchor ref; supply it for standalone positioning.             |
| `style`               | `CSSProperties` or render function | -                     | Surface styles; receives resolved placement and motion state. |

Not forwarded from React Aria `Tooltip`:

| Prop       | Why                                                                                                     |
| :--------- | :------------------------------------------------------------------------------------------------------ |
| `children` | Replaced by Veli content. Children render functions are not supported; Veli owns the caret composition. |

### TooltipTrigger

React Aria’s headless [`TooltipTrigger`](https://react-spectrum.adobe.com/react-aria/Tooltip.html#tooltiptrigger). Veli forwards its props unchanged. Open-state props belong here when composing a trigger and tooltip.

| Prop                 | Type                        | Default   | Description                                          |
| :------------------- | :-------------------------- | :-------- | :--------------------------------------------------- |
| `delay`              | `number`                    | `1500`    | Hover opening delay in milliseconds.                 |
| `closeDelay`         | `number`                    | `500`     | Hover closing delay in milliseconds.                 |
| `trigger`            | `'hover' \| 'focus'`        | `'hover'` | Hover and keyboard focus, or keyboard focus only.    |
| `isDisabled`         | `boolean`                   | `false`   | Suppress the tooltip independently from its trigger. |
| `shouldCloseOnPress` | `boolean`                   | `true`    | Dismiss when the trigger is pressed.                 |
| `isOpen`             | `boolean`                   | -         | Controlled open state.                               |
| `defaultOpen`        | `boolean`                   | `false`   | Uncontrolled initial open state.                     |
| `onOpenChange`       | `(isOpen: boolean) => void` | -         | Called when the open state changes.                  |
| `children`           | `ReactNode`                 | -         | A focusable trigger followed by the tooltip.         |

### Native tooltip element

The native `<div>` that React Aria renders. These attributes are applied to that surface. Veli defaults `lang` and `dir` to the provider values so the portaled content keeps its language and direction.

| Prop              | Type     | Description                                              |
| :---------------- | :------- | :------------------------------------------------------- |
| `lang`            | `string` | Text language; defaults to the Veli provider language.   |
| `dir`             | `string` | Text direction; defaults to the Veli provider direction. |
| `aria-label`      | `string` | Accessible label for the tooltip surface.                |
| `aria-labelledby` | `string` | IDs of elements that label the tooltip surface.          |

## Release guidance

Explicit offsets now take effect, small surfaces use one neutral appearance, and motion respects reduced-motion preferences. Inline text keeps its normal flow; use the row classes shown above for shortcut composition. Large tone names and caret geometry remain compatible. TypeScript now requires `size="lg"` when passing `tone`; remove `tone` from small or default-size tooltips. Legacy JavaScript small-tone inputs are ignored and remain neutral. `TooltipProps` is now a size-discriminated type alias; compose it with an intersection rather than extending it in an interface.

<DocsTab id="accessibility">

How the tooltip works with keyboards, screen readers and touch, and what you still need to do.

## Keyboard

Attach every tooltip to a focusable trigger, such as a Button or Link, so keyboard users can reveal it. The tooltip itself never takes focus, so it has no focus ring.

| Key    | Action                                                   |
| :----- | :------------------------------------------------------- |
| Tab    | Moves focus to the trigger and opens its tooltip at once |
| Escape | Closes the tooltip and leaves focus on the trigger       |

## Screen readers

- The tooltip has role tooltip, and the trigger points to it with aria-describedby, so its text is read as a description.
- A tooltip describes; it does not name. Give every icon-only control its own aria-label, and let the tooltip repeat the same words.
- Keep tooltip content short and non-interactive.

## Touch

Tooltips never show on touch screens: a tap activates the trigger instead. Never rely on a tooltip for essential information.

## Target size

Tooltip triggers must be at least 24 x 24. For small info icons next to field labels, grow the hit area with padding, not the icon. The field info button is 16 x 16 today, below the minimum.

## Contrast

Use the tooltip tokens as they are. In forced colours mode, code keeps the text, the edge and the arrow readable.

## Reduced motion
