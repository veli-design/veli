# Pagination

<DocsTab id="overview">

Pagination moves people through a long list or table one page at a time, or adds the next set of items with Load more. Use the compact or numbered variants when people compare pages or come back to a place in the list, and Load more for browsing where position matters less. Never use it for the steps of a form.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/pagination.tsx"

## When to use

### Use pagination when

- A list or table is split into discrete pages. Pages keep long lists fast to load and give people a place to come back to.
- People step through pages with First, Previous, Next and Last.
- People need direct access to page numbers, to jump back to a page they remember or compare pages.
- People add the next set of results with a Load more button.

### Don't use pagination when

- People switch between named peer sections rather than numbered pages. Use Tabs.
- People move through the steps of a form. Use Continue and Back buttons.
- You would load more automatically as people scroll, with no button. Use the load more variant or page through the results instead.
- The list is short enough to show in full, roughly 20 items or fewer. Show the whole list.

<DocsAnatomy>

1. **First**

   A small transparent button that goes to page 1. Disabled on the first page. In code: onFirst.

2. **Previous**

   An icon-only small button with a 16 caret icon. Disabled on the first page. In code: onPrevious.

3. **Page**

   A small transparent button with the page number. Screen readers hear Page 3, and so on. In code: onChange.

4. **Current page**

   A small button in primary fill, marked as the current page with aria-current="page". In code: value or defaultValue.

5. **Ellipsis**

   Stands for pages left out. It is a button named Show hidden pages that opens a Hidden pages menu. In code, siblingCount and boundaryCount set which pages show.

6. **Next**

   Mirrors Previous. Disabled on the last page. In code: onNext.

7. **Last**

   Goes to the last page. Disabled on the last page. In code: maxValue and onLast.

8. **Page count**

   Page 2 of 13, shown by variant button instead of page numbers and announced politely when it changes.

9. **Viewed count**

   You've viewed 12 of 42 items, centred above the bar. A status message, so screen readers announce it. In code: loadedCount and totalCount.

10. **Progress bar**

4 high and rounded. Fills from the start edge in proportion to the items loaded, labelled by the count. In code it has role progressbar. 11. **Load more**

a medium transparent button at full width. Shows a spinner while loading and turns disabled once everything has loaded. In code: onLoadMore and isLoading.

</DocsAnatomy>

## Content guidelines

### Built-in labels

Pagination supplies its own labels in English and Dhivehi from the VeliProvider language. Keep them as they ship, so paging is the same on every service. Only the landmark or group name can be changed, with aria-label.

| Label                      | English                      | Dhivehi                        |
| :------------------------- | :--------------------------- | :----------------------------- |
| Landmark name              | Pagination                   | ޕޭޖިނޭޝަން                     |
| First                      | First                        | ފުރަތަމަ                       |
| Previous                   | Previous                     | ފަހަތަށް                       |
| Next                       | Next                         | ކުރިއަށް                       |
| Last                       | Last                         | ފަހުގެ                         |
| Page count                 | Page 5 of 20                 | ޞަފްޙާ 5 / 20                  |
| Page button name           | Page 3                       | ޞަފްޙާ 3                       |
| Ellipsis button            | Show hidden pages            | ފޮރުވިފައިވާ ޞަފްޙާތައް ދައްކާ |
| Ellipsis menu              | Hidden pages                 | ފޮރުވިފައިވާ ޞަފްޙާތައް        |
| Load more button and group | Load more                    | އިތުރަށް ދައްކާ                |
| Viewed count               | You've viewed 12 of 42 items | 42 ތަކެތިން 12 ތަކެތި ބަލާފައި |

Next and Previous are only for paging through content, never for form steps.

### Place it below the results

Place one pagination directly below the results it controls. Add a second one above the results only on long pages.

### Name each pagination by its list

Keep the default name Pagination when a page has one. When a page has two, name each after the list it moves through.

| Do                | Don't                                                                           |
| :---------------- | :------------------------------------------------------------------------------ |
| Pagination        | Pagination navigation (repeats the role, which screen readers already announce) |
| Application pages | Pages (doesn't say which list when there are two)                               |

### Name the load more group

Name the load more group after its list with aria-label, because by default the group and its button are both called Load more.

| Do                | Don't                                                                     |
| :---------------- | :------------------------------------------------------------------------ |
| More applications | Load more (same as the button inside it, and says nothing about the list) |

### Write the result count

Write the result count above the list, with the range, the total and the plural noun, in the active language. When the list shows everything loaded so far, write the count. Use tabular figures for numbers that change in place.

| Do                                   | Don't                                                     |
| :----------------------------------- | :-------------------------------------------------------- |
| Showing 21 to 40 of 120 applications | Showing 21-40 of 120 (a hyphen for the range and no noun) |
| Showing 1 to 20 of 1,250 payments    | 120 result(s) (bracketed plural)                          |
| Showing 1 application                | Showing results (no numbers)                              |

In Dhivehi, use Latin digits, keep numbers left to right, and write the count natively.

### Page titles

When each page of a paginated list has its own URL, add the page number to the page title.

| Do                                       | Don't                                                                  |
| :--------------------------------------- | :--------------------------------------------------------------------- |
| Your applications, page 2 of 5 \| gov.mv | Your applications \| gov.mv (every page of results has the same title) |

## Behaviour

- **Buttons, not links**: every control is a button (type="button") that changes the page through onChange. None navigates or changes the URL by itself, and pagination in a form doesn't submit it.
- **Your app loads each page**: pagination doesn't slice data. Slice local data or fetch the selected page yourself. For load more, update loadedCount only after the items are added.
- **Controlled or uncontrolled**: control the page with value and onChange, or set the starting page with defaultValue. maxValue, the total page count, must be at least 1.
- **Hidden pages**: in variant explicit, the ellipsis opens a menu of the pages left out; choosing one goes to that page.
- **Keep the page in the URL**: keep the page number in the URL, such as ?page=2, and treat an invalid page number as page 1. Add a history entry for each new page and restore the scroll position on Back.
- **Move focus after paging**: after people choose another page, move focus to the heading of the results and bring it into view. After Load more, move focus to the first new item.
- **Keep results visible while loading**: keep the current results on screen with aria-busy on the results region, or show Skeleton rows; don't empty the list first.
- **Failed loads**: when a page or the next set fails to load, keep pagination where it is, keep the items already shown, and show the error with Try again in the results area. Don't show an empty state.
- **Point at the results**: give the results region an id and a name, and pass the id to pagination with aria-controls.

## Responsive

Pagination must fit at 320px without horizontal scrolling. Variant explicit is about 572 wide at siblingCount 1 and boundaryCount 1 with page numbers up to 20; variant button is about 350. When the numbered controls don't fit, use variant button or loadmore, or lower siblingCount. The row wraps onto more lines when it runs out of room, and each line stays centred. The load more layout is 264 wide by default and shrinks to its container; set another width with className. Prefer variant button or loadmore on touch-first pages.

## Load more

<div className="preview mb-4 grid-cols-1 rounded-lg border p-4">
  <PaginationLoadMoreDemo client:load />
</div>

```tsx
const [items, setItems] = useState(initialItems);
const [isLoading, setLoading] = useState(false);
const [error, setError] = useState<string | null>(null);

async function loadMore() {
  setLoading(true);
  setError(null);
  try {
    const nextItems = await fetchNextItems();
    setItems((current) => [...current, ...nextItems]);
  } catch {
    setError('Could not load more items. Please try again.');
  } finally {
    setLoading(false);
  }
}

// Render items in your list above these controls.
<>
  {error && <p role="alert">{error}</p>}
  <Pagination
    variant="loadmore"
    loadedCount={items.length}
    totalCount={totalItems}
    onLoadMore={loadMore}
    isLoading={isLoading}
    aria-controls="results"
  />
</>;
```

Load more uses item counts, without `value`, `maxValue`, or page callbacks. Update `loadedCount` only after items are successfully appended. `isLoading` uses Veli Button’s loading indicator and disables repeat requests while keeping its label and dimensions stable. The status announces the displayed count; the progress bar reflects its proportion of the known total.

The button is disabled when every item is loaded or `totalCount` is zero. Counts are rounded down and clamped to nonnegative integers; `loadedCount` cannot exceed `totalCount`. The layout is 264px wide by default and shrinks to its container. Override its width with `className` if needed.

## Right-to-left languages

## Accessibility and themes

Page variants render a named navigation landmark; load more renders a named group. Use a unique `aria-label` when displaying multiple controls. Numbered navigation marks the selected button with `aria-current="page"`. Tab moves between controls, Enter or Space activates a button, arrow keys move through ellipsis menus, and Escape closes the menu.

All buttons use `type="button"`, so embedding Pagination in a form does not submit it. Pass `aria-controls` on the root to reference your results region. Keep appended items in reading order and announce fetch errors in your application. For page replacement, manage result focus in the application when needed.

Use [VeliProvider](/docs/components/provider/) for system, light, or dark themes. The load-more progress width transition and Button press scaling are disabled under reduced motion; the loading indicator follows the shared Button behavior.

## API Reference

`PaginationProps` is a discriminated union: choose the props for your `variant`. Standard root HTML and ARIA attributes are also accepted, except `children` and the native `onChange`. Pagination owns its internal composition.

| Shared prop  | Type                                   | Default    | Description                                     |
| :----------- | :------------------------------------- | :--------- | :---------------------------------------------- |
| `variant`    | `'button' \| 'explicit' \| 'loadmore'` | `'button'` | Chooses page navigation or incremental loading. |
| `aria-label` | `string`                               | Localized  | Accessible name of the navigation or group.     |
| `className`  | `string`                               | —          | Additional classes on the root.                 |

### Page navigation props

Used by `button` and `explicit` (`PaginationPageProps`).

| Prop            | Type                     | Default  | Description                                          |
| :-------------- | :----------------------- | :------- | :--------------------------------------------------- |
| `value`         | `number`                 | —        | Controlled current page, starting at 1.              |
| `defaultValue`  | `number`                 | `1`      | Initial uncontrolled page.                           |
| `maxValue`      | `number`                 | Required | Total pages, normalized to an integer of at least 1. |
| `onChange`      | `(page: number) => void` | —        | Called only when a different page is requested.      |
| `onFirst`       | `(page: number) => void` | —        | Called after `onChange` for the First button.        |
| `onPrevious`    | `(page: number) => void` | —        | Called after `onChange` for the Previous button.     |
| `onNext`        | `(page: number) => void` | —        | Called after `onChange` for the Next button.         |
| `onLast`        | `(page: number) => void` | —        | Called after `onChange` for the Last button.         |
| `siblingCount`  | `number`                 | `1`      | Adjacent visible pages in explicit mode.             |
| `boundaryCount` | `number`                 | `1`      | Visible pages at each end in explicit mode.          |

`value` is clamped to the available pages without firing callbacks. Range counts are normalized to nonnegative integers. Boundary buttons do not fire callbacks when disabled.

### Load-more props

Required when `variant="loadmore"` (`PaginationLoadMoreProps`).

| Prop          | Type         | Default  | Description                                                    |
| :------------ | :----------- | :------- | :------------------------------------------------------------- |
| `loadedCount` | `number`     | Required | Number of items currently displayed.                           |
| `totalCount`  | `number`     | Required | Known total number of available items.                         |
| `onLoadMore`  | `() => void` | Required | Requests the next batch; does not change counts automatically. |
| `isLoading`   | `boolean`    | `false`  | Pending request state that prevents repeat activation.         |

How pagination works with keyboards and screen readers, and what you still need to do.

## Keyboard

| Key                        | Action                                               |
| :------------------------- | :--------------------------------------------------- |
| Tab                        | Moves focus to the next enabled control              |
| Shift + Tab                | Moves focus to the previous enabled control          |
| Enter or Space             | Activates the focused control                        |
| Enter, Space or Down arrow | Opens the hidden pages menu from the ellipsis button |
| Up and Down arrows         | Move through the hidden pages in the menu            |
| Escape                     | Closes the menu                                      |

Disabled controls at the ends are skipped.

## Screen readers

- Variants button and explicit render a navigation landmark named Pagination. Variant loadmore renders a group named Load more, not a landmark.
- When a page has two paginations, give each a different aria-label. Name the load more group after its list.
- Icon-only controls and the ellipsis menu have built-in names in English and Dhivehi.
- In variant explicit, the current page is marked with aria-current="page".
- The page count in variant button announces its updates politely.
- In variant loadmore, the viewed count is a status message and the progress bar is labelled by it.
- Announce fetch errors in your application, and write your own result count as a status message that stands alone: Showing 21 to 40 of 120 applications.

## Focus

Controls show the Button focus ring on keyboard focus and fall back to a Highlight outline in forced colours mode. After a page change, move focus to the results heading; after Load more, to the first new item.

## Current page

Screen readers hear the current page through aria-current="page". On screen, the current page differs from the other pages only by its primary fill. A fill is a change of colour, so on its own it does not meet the rule that a current state needs a cue besides colour, such as a border, a shape or a weight change. See "Missing or unverified".

## Target size

Page controls are 36px tall, above the 24px minimum but under the 44px recommended for touch. Prefer variant button or loadmore on touch-first pages.

## Reduced motion

When people prefer reduced motion, the progress transition and the press scaling are turned off. Nothing extra is needed from you.

## Right to left

Set the language with VeliProvider (language dv). Labels, control order and carets follow it, and numbers stay left to right. Write your own result count in Dhivehi with Latin digits.
