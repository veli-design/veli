# Alert

<DocsTab id="overview">

An alert shows a message about the page or task in front of people, such as a status, a deadline or a problem to fix. It stays on the page until people close it or the issue is solved, and it never times out. Use it for messages people need to notice and often act on.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/alert.tsx"
  storybook="https://storybook.veli.design/?path=/docs/permit-review-in-progress--docs"

## When to use

### Use an alert when

- A message about the page or a task needs to stay visible, such as a status, a deadline or an outage.
- Something went wrong and people can fix it, such as a failed submission.
- People can act on the message right away, with one or two actions.
- A short confirmation should stay in context after a save or a payment.
- A message is inserted after an action and must be announced, such as a failed save.

### Don't use an alert when

- The message is short-lived feedback after an action. Use Toast.
- People must decide before they can continue. Use Modal.
- The message is about one field. Use the field error message.
- You only need a status label in a table or a card. Use Badge.
- You would need more than two actions. Use a page or a Modal instead.

<DocsAnatomy>

1. **Container**

   the alert surface, with the background, a border on light alerts, 24 radius and 16 padding. Screen readers treat it as a status message by default, or as an urgent alert when live is set to alert. In code it is Alert.

2. **Leading icon**

   a 20px icon in the Fill weight. Each intent has its own default icon; you can turn it off or swap it. It is decorative, so screen readers skip it. In code it is leadingIcon.

3. **Title**

   a short summary of what happened. In code it is Alert.Title.

4. **Description**

   optional detail and the next step. In code it is Alert.Description.

5. **Primary action**

   an optional main action, a secondary fill button at size sm. In code it goes in Alert.Actions.

6. **Secondary action**

   an optional lighter action, such as Remind me later, a secondary ghost button at size sm. In code it goes in Alert.Actions.

7. **Close button**

   an optional icon-only ghost button that dismisses the alert. Screen readers announce it as Dismiss alert. In code it is Alert.CloseButton.

</DocsAnatomy>

On high contrast alerts, the action buttons and the close button use the onHighContrast treatment.

## Content guidelines

### Title

Write up to 6 words that state the subject or outcome. Write success titles in the past tense. Put the most important words first and keep the fix for the description. Don't end the title with a full stop.

| Do                        | Don't                                          |
| :------------------------ | :--------------------------------------------- |
| Payment received          | Attention (says nothing about what happened)   |
| Permit review in progress | Error 502 (a code, not a message)              |
| Payment received          | Payment Received. (title case and a full stop) |

### Description

Write 1 or 2 sentences that add to the title and say what to do, each ending with a full stop. Don't repeat the title. Leave the description off when the title says it all.

| Do                                                                        | Don't                                                                                              |
| :------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------- |
| Upload a new photo by 30 November 2026 to continue your passport renewal. | Your application could not be processed due to a validation issue. (says nothing about what to do) |

### Action labels

Start with a verb that says what happens, in 1 to 3 words. Give an alert at most 2 actions, with the main action first and the lighter action second. Never use OK, Yes, No, Submit, Dismiss or Click here: the close button closes the alert.

| Do                                  | Don't                                                  |
| :---------------------------------- | :----------------------------------------------------- |
| Renew licence                       | Click here (no verb for the result)                    |
| Track application                   | OK (says nothing about what happens)                   |
| Renew licence, then Remind me later | Renew licence, then Dismiss (repeats the close button) |

### Wording by intent

Match the words to the intent. Don't use a danger or warning intent for routine information.

| Intent   | Pattern                                   | Example                                                                      |
| :------- | :---------------------------------------- | :--------------------------------------------------------------------------- |
| Positive | The thing and what happened               | Draft saved                                                                  |
| Info     | The subject and the date                  | Service hours change on 1 November 2026                                      |
| Warning  | The consequence and the date              | Your permit expires on 21 October 2027                                       |
| Danger   | What failed, what it means and what to do | Payment not taken. Your card was not charged. Try again or use another card. |

| Do                                                                           | Don't                                                          |
| :--------------------------------------------------------------------------- | :------------------------------------------------------------- |
| Payment not taken. Your card was not charged. Try again or use another card. | Something went wrong (says neither what failed nor what to do) |

### Plain language

Say what people can do, not what the system did. Avoid codes and jargon. If support needs a code, add it at the end as a reference people can quote.

| Do                                                               | Don't                                                   |
| :--------------------------------------------------------------- | :------------------------------------------------------ |
| We cannot take online payments right now. Try again after 14:00. | Gateway timeout (504) (a system code with no next step) |

### Dates and references

Give exact dates for deadlines. For planned downtime, give the start and end with weekday, date and 24-hour time, and say what will not work. Show reference numbers exactly as issued and keep them on one line.

| Do                                                                                                         | Don't                                                                    |
| :--------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------- |
| Upload it by 30 November 2026.                                                                             | Upload it soon. (no date to act on)                                      |
| Online payments are unavailable from 22:00 on Friday 30 October 2026 to 06:00 on Saturday 31 October 2026. | Payments are down tonight for maintenance. (no times and a vague reason) |
| Application PR-20418                                                                                       |                                                                          |

### Status words

Use the shared status words, each with its own intent everywhere: Approved and Paid are positive; Pending and Unpaid are cautious; Action needed and Expired are warning; Rejected, Overdue and a failed payment are danger. Never recolour a status for one service.

| Do                                 | Don't                                                         |
| :--------------------------------- | :------------------------------------------------------------ |
| Application WP-2026-04817 approved | Application WP-2026-04817 accepted (not a shared status word) |

### Outages

During an unplanned outage, show a warning alert with appearance highContrast at the top of every page. Title it Some services are unavailable, and say what does not work, that saved answers are safe and when the next update will be posted, with a link to the status page. Update the time each time the status changes.

### Dhivehi copy

Write Dhivehi copy natively rather than translating word for word, and keep it as short as the English, because Thaana lines are taller.

- Use **light** for most messages, inline with the page content. It has a tinted background with a subtle border and neutral text.
- Use **highContrast** sparingly, for an urgent message about the whole page that must not be missed, placed at the top of the page. It has a solid background with light text.
- Show at most one high contrast alert in a view. Use the light appearance for the other alerts in the view.
- On high contrast alerts, actions are secondary buttons with the high contrast treatment. Never put a primary button on the coloured surface.
- highContrast is visual emphasis only. It does not respond to the operating system contrast settings and does not replace forced colours support.

<DocsFigure
  src="/images/docs/alert/alert-icon-1.webp"

- Keep the default icon for the intent. Each intent has its own icon shape, so the status reads without colour.
- Swap it only when another icon says the same thing more clearly, such as a clock for a waiting state.
- Use icons in the Fill weight at 20px. In code, pass the icon element to leadingIcon.
- The five alert icons (info, check circle, warning circle, warning triangle and warning octagon) are the preferred swaps.

## Behaviour

- **Placement**: put the alert at the top of the page or section it is about, close to the content it refers to.
- **Persistence**: alerts stay until people close them or the problem is solved. They never time out; use Toast for timed messages.
- **Dismiss**: the close button calls onDismiss. Without isVisible, the alert hides itself, and changing defaultVisible after mount does not show it again. To show it again, control it with isVisible and onDismiss.
- **Actions**: buttons in Alert.Actions never dismiss the alert on their own. When an action resolves the message, hide the alert with isVisible or remove it from the page.
- **Several alerts**: stack them 16 apart with the most severe first. Show one high contrast alert at most.
- **Width**: the alert fills its container. Set the width on the container. Text wraps and the alert grows in height; it never truncates the title or description.
- **Error summary**: the form error summary is a danger alert in the light appearance, titled There is a problem, and not dismissible. Pass role="group" so it is not a live region; moving focus to it does the announcing. Never stack another banner above it.

## Colour modes

Alerts follow the Light and Dark mode of the page; no extra work is needed. Appearance is independent of the page theme. Light alerts become a dark tint. High contrast alerts move from the 800 step to the 1000 step in Dark mode, which is bright there, so the text turns dark and the high contrast buttons flip with it.

| cautious | `light/cautious/bg` (yellow/300), `light/cautious/icon` (yellow/800)   | `highContrast/cautious/bg` (yellow/800 in Light, yellow/1000 in Dark)   | yellow/100, yellow/200                 |
| warning  | `light/warning/bg` (orange/300), `light/warning/icon` (orange/800)     | `highContrast/warning/bg` (orange/800 in Light, orange/1000 in Dark)    | orange/100, orange/200                 |

| Part        | Light                            | High contrast                                                                  |
| :---------- | :------------------------------- | :----------------------------------------------------------------------------- |
| Border      | `border/base/subtle`             | None                                                                           |
| Title       | `text/base/emphasis`             | `highContrast/{intent}/foreground`                                             |
| Description | `text/base/strong`               | `highContrast/{intent}/description`                                            |
| Icon        | `light/{intent}/icon`            | `highContrast/{intent}/foreground`                                             |
| Actions     | Secondary fill and ghost buttons | Secondary fill and ghost buttons with `button/onHighContrast/secondary` tokens |

Map on-colour surfaces to these tokens, never to fixed white or black, and don't override them with raw colours.

## Motion

Alert has no enter or exit animation, so it appears and disappears at once. The buttons inside keep their own press feedback, which respects reduced motion.

## Intents and appearances

Choose `neutral` for general information, `info` for contextual guidance, `positive` for success, `cautious` for attention before continuing, `warning` for a developing problem, and `danger` for failure or urgent risk.

`light` uses a tinted background with neutral title and description colours. `highContrast` uses a solid background with contrasting text and icons. Appearance is independent of the page's light, dark, or system theme; both follow the page theme automatically.

## Layouts

The alert fills its container. Select its layout explicitly for the available space:

| Layout    | Content and actions                                                                              |
| :-------- | :----------------------------------------------------------------------------------------------- |
| `default` | Title, optional description, and up to two actions on one row.                                   |
| `stacked` | The same content with full-width actions stacked vertically. Use in narrow columns or on mobile. |
| `compact` | Title and one optional inline action. Omit the description and secondary action.                 |

## Actions and dismissal

Compose `Alert.Actions` with small Veli Buttons. Use `intent="secondary"` and `appearance="fill"` for the primary action, and `appearance="ghost"` for an optional secondary action. On `highContrast`, set `highContrast` on those Buttons (or let `Alert.Actions` and `Alert.CloseButton` apply it to direct Veli Buttons).

<div className="preview mb-4 rounded-lg border p-4">
  <AlertDismissibleDemo client:load />
</div>

```tsx
'use client';

import { useState } from 'react';
import { InfoIcon } from '@phosphor-icons/react';
import { Alert } from '@veli-design/react/alert';
import { Button } from '@veli-design/react/button';

export default function PermitAlert({ onTrack }: { onTrack: () => void }) {
  const [visible, setVisible] = useState(true);

  return (
    <Alert
      intent="info"
      appearance="highContrast"
      layout="stacked"
      leadingIcon={<InfoIcon size={20} weight="fill" />}
      isVisible={visible}
      onDismiss={() => setVisible(false)}
    >
      <Alert.Title>Permit review in progress</Alert.Title>
      <Alert.Description>You will receive an email when processing completes.</Alert.Description>
      <Alert.Actions>
        <Button
          type="button"
          size="sm"
          intent="secondary"
          appearance="fill"
          highContrast
          onPress={onTrack}
        >
          Track application
        </Button>
        <Button
          type="button"
          size="sm"
          intent="secondary"
          appearance="ghost"
          highContrast
          onPress={() => setVisible(false)}
        >
          Remind me later
        </Button>
      </Alert.Actions>
      <Alert.CloseButton />
    </Alert>
  );
}
```

Actions retain their application callbacks and do not dismiss automatically. On `highContrast`, direct Veli Buttons inside `Alert.Actions` (including fragments) and `Alert.CloseButton` use Button’s `highContrast` styles. Other controls keep their own styling.

With `isVisible`, the parent owns visibility: `onDismiss` requests dismissal, but the alert remains until the parent updates the prop. Without `isVisible`, `defaultVisible` initializes internal state and the close button hides the alert automatically. Changing `defaultVisible` after mount does not reset it; remount an uncontrolled alert to show it again. Alerts never time out.

## Announcements

The default `live="status"` uses a polite status role. Use `live="alert"` for newly inserted urgent feedback that needs an assertive announcement. `role` deliberately overrides the role selected by `live`. These choices do not change the visual appearance.

```tsx
import { Alert } from '@veli-design/react/alert';

export default function AlertAnnouncementDemo() {
  return (
    <Alert live="alert" intent="danger">
      <Alert.Title>Unable to submit your application</Alert.Title>
    </Alert>
  );
}
```

## API Reference

### Alert

| Prop             | Type                                                                       | Default     | Description                                                  |
| :--------------- | :------------------------------------------------------------------------- | :---------- | :----------------------------------------------------------- |
| `intent`         | `'neutral' \| 'info' \| 'positive' \| 'cautious' \| 'warning' \| 'danger'` | `'neutral'` | Semantic message treatment.                                  |
| `appearance`     | `'light' \| 'highContrast'`                                                | `'light'`   | Surface and foreground treatment, independent of page theme. |
| `layout`         | `'default' \| 'stacked' \| 'compact'`                                      | `'default'` | Explicit content and action arrangement.                     |
| `leadingIcon`    | `ReactNode`                                                                | -           | Optional decorative 20px icon.                               |
| `children`       | `ReactNode`                                                                | -           | Compound parts and application content.                      |
| `isVisible`      | `boolean`                                                                  | -           | Controlled visibility.                                       |
| `defaultVisible` | `boolean`                                                                  | `true`      | Initial uncontrolled visibility.                             |
| `onDismiss`      | `() => void`                                                               | -           | Called when the close button is pressed.                     |
| `live`           | `'alert' \| 'status'`                                                      | `'status'`  | Chooses the live-region role.                                |
| `role`           | `AriaRole`                                                                 | -           | Overrides the role selected by `live`.                       |
| `className`      | `string`                                                                   | -           | Root layout or visual overrides.                             |

Standard `div` attributes, including `id`, `dir`, `lang`, `aria-label`, `aria-describedby`, and event handlers, pass through to the root. The native `title` attribute is excluded; compose the message with `Alert.Title`.

### Compound parts

| Part                | Props                                       | Description                                                                      |
| :------------------ | :------------------------------------------ | :------------------------------------------------------------------------------- |
| `Alert.Title`       | `children: ReactNode`, `className?: string` | English semibold title; Dhivehi medium title.                                    |
| `Alert.Description` | `children: ReactNode`, `className?: string` | Regular description with its own colour token. Omit for compact.                 |
| `Alert.Actions`     | `children: ReactNode`, `className?: string` | Layout-aware row or stack. Consumers configure Button semantics and appearances. |
| `Alert.CloseButton` | `aria-label?: string`, `className?: string` | Optional 36px dismiss Button with a localized accessible name.                   |

## Accessibility

- Give every alert a clear title; colour and icons supplement the message.
- The alert itself is not focusable and never moves focus automatically. Its actions and close button participate in the normal tab order.
- Icons are hidden from assistive technology. Buttons need accessible names and retain visible keyboard focus.
- The close button supports Enter and Space. Its default name is “Dismiss alert” in English and “އެލާޓް ލައްޕާ” in Dhivehi; override `aria-label` when needed.
- Include a close button only when dismissal is meaningful. The application owns any necessary focus destination after a focused alert is removed.

## RTL, language, and motion

Use `VeliProvider language="dv"` for Dhivehi typography and RTL direction. The icon moves to the right, the close button to the left, and the primary action appears to the right of the secondary action. English content can also inherit `dir="rtl"` without switching fonts.

## Migration

The revised appearances replace `subtle`, `outline`, and `emphasis`. Change `subtle` to `light` and `emphasis` to `highContrast`. `outline` has no direct equivalent; choose the new treatment appropriate to the message. On high-contrast Alerts, use secondary `fill` and `ghost` Buttons with `highContrast` instead of transparent or colour overrides, and select `stacked` where the previous wrapping row was relied upon.

How the alert works with screen readers, keyboards and colour, and what you still need to do.

## Screen readers

- An alert is a polite status message by default (role status, live="status"), which suits banners that are always visible.
- Use live="alert" only when the alert is inserted or updated after an action and must be announced at once. Never use it on an alert that is on the page when it loads.
- The role prop overrides live, so an alert with a role set is not a live region. Use role="group" for the error summary.
- Put the most important words first in an inserted alert. It is read once and not repeated.
- The leading icon is decorative and hidden from screen readers. The title must carry the meaning on its own.

## Keyboard

The alert itself is not focusable and never moves focus. Its actions and close button are buttons in the normal tab order.

| Key            | Action                                             |
| :------------- | :------------------------------------------------- |
| Tab            | Moves focus to the next action or the close button |
| Shift + Tab    | Moves focus to the previous action or close button |
| Enter or Space | Activates the focused action or close button       |

## Focus

- Don't move focus to an alert when it appears.
- Buttons inside show the Veli focus ring when focused from the keyboard.
- When the close button removes an alert that had focus, move focus to a logical place, such as the heading of the section the alert was in. Veli leaves the focus destination to the app; without one, keyboard users lose their place.

## Close button name

The close button is labelled Dismiss alert in English and އެލާޓް ލައްޕާ in Dhivehi. When several dismissible alerts share a page, name each close button with aria-label, such as Dismiss permit review alert. Never name it X or Close button.

## Target size

The close button is a 36px ghost button and the action buttons are 36 high, larger than the 24px minimum target size.

## Contrast

Colour supports the message but never replaces it: each intent has its own icon shape and the title states the message. Use the alert tokens as they are. On high contrast alerts, use the high contrast button treatment so text and the focus ring stay readable on the coloured surface.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction, the Dhivehi fonts and the Dhivehi dismiss label. Pass Dhivehi titles, descriptions and action labels yourself, and wrap names and reference numbers in bdi or an element with dir="auto".
