# Modal

<DocsTab id="overview">

A modal is a dialog that sits above the page and blocks it until people act or close it. Use it for a confirmation, a short form or a focused task that must be finished before people carry on, such as cancelling an appointment.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/modal.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-modal--docs"
/>

## When to use

### Use a modal when

- People must confirm a decision before it happens, such as deleting or submitting.
- A short task belongs to the current page, such as changing one detail.
- People must read something and acknowledge it before going on.
- The task can be finished without leaving the page.

### Don't use a modal when

- The message is feedback after an action. Use Toast.
- The message is about the page and needs no answer. Use Alert.
- The content is long or has several steps. Use a full page.
- People only need a hint next to a control. Use Tooltip or Popover.
- The action is routine and can be reversed, such as saving or moving between steps. Don't ask for confirmation.

<DocsAnatomy>

1. **Overlay**

   Black at 60% with a 6px background blur, the same in Light and Dark mode. It blocks the page. Clicking it closes the modal unless isDismissable is false. In code it is ModalOverlay.

2. **Panel**

   The dialog surface, with the `components/modal/bg-solid` fill, radius 32 and a small shadow. The size sets the maximum width; the height grows with the content up to 90% of the viewport, then the panel scrolls. In code it is Modal.

3. **Title**

   Names the dialog for screen readers, so every modal needs one, or a label set with aria-label. In code it is Modal.Title.

4. **Close button**

   An icon-only secondary ghost button with a cross icon that closes the modal. Its accessible name is Close dialog, localised in Dhivehi. In code it is Modal.CloseButton.

5. **Description**

   An optional line under the title. When it is present, a divider closes the header. In code it is Modal.Description.

6. **Header divider**

   A subtle divider under the header. It shows only when there is a description.

7. **Content**

   The body, such as text, a short form or a list, with 16 padding top and bottom. In code it is Modal.Content.

8. **Footer divider**

   A subtle divider above the actions. It is always shown in the footer.

9. **Start actions**

   An optional group on the start edge for a secondary route, such as Back. Leave it off at xs and sm. In code it is the first button group in Modal.Footer.

10. **End actions**

the main action and its alternative, on the end edge. The main action is the filled button. In code it is the second button group in Modal.Footer.

</DocsAnatomy>

## Content guidelines

### Title

Say what is being decided or done, as a question or a task, on one line. End it with a question mark only when it asks something. People often read only the title and the buttons before they choose.

| Do                                  | Don't                                             |
| :---------------------------------- | :------------------------------------------------ |
| Cancel this appointment?            | Are you sure? (doesn't say what is being decided) |
| Withdraw application WP-2026-04817? | Confirm (doesn't say what is being decided)       |
| Change phone number                 | Warning (names a tone, not the task)              |
| Change phone number                 | Change Phone Number. (title case and a full stop) |

### Description

The description is optional. Add one sentence of context the title can't hold, and leave it out of xs confirmations.

| Do                                            | Don't                                                                           |
| :-------------------------------------------- | :------------------------------------------------------------------------------ |
| We send a code to the new number to check it. | Please fill in the form below. (says nothing the form doesn't, and uses please) |

### Body

Say what will happen and whether it can be undone, in 1 or 2 sentences, in people's own words.

| Do                                                                              | Don't                                                                   |
| :------------------------------------------------------------------------------ | :---------------------------------------------------------------------- |
| Your passport renewal appointment on 21 October 2026 at 10:00 will be released. | This action is irreversible. (legal tone, and doesn't say what is lost) |

### Action labels

Name the action with a verb and an object, using the same verb and object as the title: Delete this draft application?, Delete draft. Never use Yes, No, OK or Submit on its own.

| Do           | Don't                                |
| :----------- | :----------------------------------- |
| Delete draft | Yes (needs the body to make sense)   |
| Keep draft   | No (needs the body to make sense)    |
| Send code    | OK (says nothing about what happens) |
| Remove file  | Submit (no object)                   |

### Cancel, close and keep

Cancel stops the task and discards what was entered. Close hides a modal with no unsaved input. Back returns with answers kept. When the task itself is a cancellation, label the safe choice Keep.

| Do                                         | Don't                            |
| :----------------------------------------- | :------------------------------- |
| Keep appointment beside Cancel appointment | Cancel beside Cancel appointment |

### Forms

For a modal that holds a form, set isDismissable=&#123;false&#125; so a click outside can't discard answers, and ask before closing with unsaved changes. Use the title Leave without saving?, the body "You have changes that have not been saved." and the actions Leave without saving and Keep editing.

| Do                    | Don't                                                  |
| :-------------------- | :----------------------------------------------------- |
| Leave without saving? | Unsaved changes! (no question and an exclamation mark) |

### Opening button

Add an ellipsis to the label of a button that opens a modal needing more input, using the single character …. A confirmation needs none.

| Do                  | Don't                                                                    |
| :------------------ | :----------------------------------------------------------------------- |
| Change appointment… | Delete draft... (three full stops, and a confirmation needs no ellipsis) |

### Close button name

Keep the built-in name Close dialog. Override it with aria-label only to add context, in both languages.

| Do           | Don't                                              |
| :----------- | :------------------------------------------------- |
| Close dialog | X (not a name)                                     |
|              | Close modal window (names the role and the widget) |

### Dhivehi copy

Write Dhivehi copy natively rather than transliterating, and keep it as short as the English, because Thaana lines are taller.

## Behaviour

- **Opening**: Modal.Trigger wraps the opener and the modal and owns the open state. Pass any open-state controls to the trigger, not to Modal. For routing, asynchronous checks or several triggers, control it with isOpen and onOpenChange.
- **Closing**: the close button, Escape and a click on the overlay close the modal. isDismissable=&#123;false&#125; stops outside clicks; isKeyboardDismissDisabled stops Escape. Turn these off only when the modal has a visible closing action.
- **Actions**: buttons with slot="close" close the modal when pressed. Run the action first if it can fail, then close, so an error has somewhere to show.
- **Action order**: put the main action and its alternative in the end group of the footer, with the main action last, at the end edge, as the filled button. Use the start group only for a secondary route, such as Back, and leave it off at xs and sm.
- **Focus return**: when the modal closes, focus goes back to the control that opened it.
- **Scrolling**: the panel grows with its content up to 90% of the viewport height, then scrolls inside. The page behind does not scroll.
- **No stacking**: don't open a modal from inside another, or stack modals. Show the next step in the same modal, close the first before opening the second, or use a full page.
- **Narrow screens**: the modal reflows at 320 wide. It fills the width inside the 16 viewport padding and scrolls inside its 90% height cap. Let a table inside it scroll in its own frame.

## Usage

<div className="preview mb-4 rounded-lg border p-4">
  <ModalUsageDemo client:visible />

```tsx
<Modal.Trigger>
  <Button>Open modal</Button>
  <Modal>
    <Modal.Header>
      <Modal.Title>Edit profile</Modal.Title>
      <Modal.CloseButton />
    </Modal.Header>
    <Modal.Content>
      <p>Update your profile details and save when done.</p>
    </Modal.Content>
    <Modal.Footer>
      <Button slot="close" intent="secondary" appearance="transparent">
        Cancel
      </Button>
      <Button slot="close">Save changes</Button>
    </Modal.Footer>
  </Modal>
</Modal.Trigger>
```

`Modal.Trigger` owns open state and restores focus to the opener. Use controlled `isOpen` / `onOpenChange` when routing or async guards manage visibility.

## Dismiss

Pass `isDismissable={false}` and `isKeyboardDismissDisabled` when the user must pick an explicit action. Omit `Modal.CloseButton` for the same flows.

  <ModalDismissDemo client:visible />

```tsx

  <Modal.Header>
    <Modal.Title>Confirm destructive action</Modal.Title>
  </Modal.Header>
  <Modal.Content>
    <p>Outside click and Escape are disabled. Choose an explicit action.</p>
  </Modal.Content>
  <Modal.Footer>
    <Button slot="close" intent="secondary" appearance="transparent">
      Cancel
    </Button>
    <Button slot="close" intent="danger">
      Delete
    </Button>
  </Modal.Footer>
</Modal>
```

## API Reference

Modal is a Veli compound dialog on React Aria [`Modal`](https://react-spectrum.adobe.com/react-aria/Modal.html) / [`Dialog`](https://react-spectrum.adobe.com/react-aria/Dialog.html). Props below follow that stack.

### Modal

Veli-specific props for the dialog surface.

| Prop               | Type                                             | Default | Description                                    |
| :----------------- | :----------------------------------------------- | :------ | :--------------------------------------------- |
| `size`             | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl' \| 'full'` | `'md'`  | Max width of the panel.                        |
| `aria-label`       | `string`                                         | -       | Accessible name when `Modal.Title` is omitted. |
| `aria-labelledby`  | `string`                                         | -       | ID of an external accessible name.             |
| `overlayClassName` | `string`                                         | -       | Class on the backdrop overlay.                 |
| `className`        | `string`                                         | -       | Layout class on the modal panel.               |

### ModalOverlay

React Aria’s headless [`ModalOverlay`](https://react-spectrum.adobe.com/react-aria/Modal.html#modaloverlay). These props pass through. The React Aria docs cover the rest, except the exclusions below.

| Prop                        | Type                        | Default | Description                      |
| :-------------------------- | :-------------------------- | :------ | :------------------------------- |
| `isOpen`                    | `boolean`                   | -       | Controlled open state.           |
| `defaultOpen`               | `boolean`                   | -       | Uncontrolled initial open state. |
| `onOpenChange`              | `(isOpen: boolean) => void` | -       | Called when open state changes.  |
| `isDismissable`             | `boolean`                   | `true`  | Allows click-outside dismissal.  |
| `isKeyboardDismissDisabled` | `boolean`                   | `false` | Disables Escape to close.        |

Not forwarded from `ModalOverlay`:

| Prop        | Why                                                |
| :---------- | :------------------------------------------------- |
| `children`  | Veli owns the compound composition.                |
| `className` | Replaced by Veli `className` / `overlayClassName`. |

### Composition

Assemble the dialog with `Modal.Trigger`, `Modal.Header`, `Modal.Title`, `Modal.Description`, `Modal.CloseButton`, `Modal.Content`, and `Modal.Footer`.

| Part                | Notes                                                              |
| :------------------ | :----------------------------------------------------------------- |
| `Modal.Trigger`     | Wraps the opener and modal; manages open state and focus return.   |
| `Modal.Title`       | Dialog heading and accessible name.                                |
| `Modal.Description` | Optional subtitle; shows the header divider when present.          |
| `Modal.CloseButton` | Optional dismiss control. Default `aria-label` is localized.       |
| `Modal.Footer`      | Action row. Place start- and end-edge groups as separate children. |

### Modal.CloseButton

| Prop         | Type     | Default              | Description                     |
| :----------- | :------- | :------------------- | :------------------------------ |
| `aria-label` | `string` | Localized Close name | Accessible name for the button. |

## Accessibility

- Provide one dialog name: `Modal.Title`, `aria-label`, or `aria-labelledby`.
- Focus is trapped while open and restored to the trigger on close when using `Modal.Trigger`.
- Escape and outside click dismiss when `isDismissable` allows it.

The backdrop uses hard black at 60% opacity with uniform 6px blur in both light and dark modes.

## RTL and Language

The overlay inherits `lang` and `dir` from `VeliProvider`. Title, body, and footer alignment follow `dir`. On `lang="dv"`, `Modal.CloseButton` defaults to `ލައްޕާ`.

<DocsTab id="accessibility">

How the modal works with keyboards, screen readers and focus, and what you still need to do.

## Keyboard

| Key            | Action                                                    |
| :------------- | :-------------------------------------------------------- |
| Tab            | Moves to the next control inside the modal only           |
| Shift + Tab    | Moves to the previous control inside the modal only       |
| Escape         | Closes the modal, unless isKeyboardDismissDisabled is set |
| Enter or Space | Activates the focused button                              |

Turn off Escape and outside clicks only when the modal has a visible closing action, so focus can always leave.

## Screen readers

- The panel is a dialog, so screen readers announce it as a dialog with its title. Modal.Title renders a level 2 heading.
- Every modal needs a name: Modal.Title, aria-label or aria-labelledby.
- While the modal is open, content outside it is hidden from assistive technology.
- On phones, React Aria adds visually hidden Dismiss buttons at the start and end of the modal, so screen reader users can close it without Escape.

## Focus

- Focus moves into the modal when it opens and is trapped there. It returns to the opener on close.
- When a destructive confirmation opens, put focus on the safe action, the first field or the dialog itself, never on the destructive button. By default, focus goes to the dialog itself.
- Buttons inside show the Veli focus ring when focused from the keyboard.

## Close button name

The icon-only close button is named Close dialog, and ލައްޕާ in Dhivehi. Override it with aria-label only to add context, in both languages.

## Target size

The close button is 36 and the footer buttons are 44 high, above the 24px minimum target size.

## Contrast

A danger action says what it does in its label, so the meaning does not rely on red. Use the modal and button tokens as they are.

## Reduced motion

With reduced motion, the overlay and panel appear without transition. Nothing extra is needed from you.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction of the overlay, panel and dialog, and the Dhivehi close label. Pass Dhivehi titles, content and action labels yourself.
