# Divider

<DocsTab id="overview">

A divider separates related content with a thin line, so a long section reads as clear groups. Use it between rows of a list or summary, or with a short label such as Or between two alternative actions. With a click handler it can also act as an expand control that shows or hides more content.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/divider.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-divider--docs"

## When to use

### Use a divider when

- Related content blocks need a subtle boundary: between the rows of a list or summary, or between a heading and its content. Use a horizontal divider with appearance subtle, the default, and no text.
- Two alternative actions need an Or between them. Use a divider with text.
- Inline items, such as tabs or metadata, need a separator. Use a vertical divider and let it stretch to the row height.
- A long section should start collapsed and people can reveal more. Use an expandable divider with a label that says what the click does.

### Don't use a divider when

- Spacing alone separates the content. Use more space instead of a line.
- The content needs its own container. Use a card.
- The content should collapse under a title. Use an accordion.
- The items are views of the same content. Use tabs.
- A new section needs a heading. Use a heading and the document structure, not a divider alone.

<DocsAnatomy>

1. **Start line**

   A 1px line that fills the space before the caption, in the appearance colour. It is decorative, so screen readers skip it. A line-only divider is this line at full width; a vertical one stretches to its row.

2. **Icon**

   Optional, off by default, and only for an expandable divider. A 16px caret in a circle before the text, in `icon/base/muted`. It turns 180 degrees while aria-expanded is true. It is decorative. In code it is showIcon.

3. **Text**

   Optional caption, horizontal dividers only. Caption regular in `text/base/muted`, 6 from the lines and the icon. It also names the separator for screen readers. In code it is text.

4. **End line**

   Matches the start line. The two lines share the space left after the icon and text.

</DocsAnatomy>

## Content guidelines

### Captions

Divider captions take 1 to 3 words, make sense read alone, and are never a heading. Use sentence case and no full stop.

| Do               | Don't                                                                     |
| :--------------- | :------------------------------------------------------------------------ |
| Or               | OR (all caps)                                                             |
| Or continue with | Or sign in with your email address instead. (a sentence with a full stop) |
|                  | Applicant details and documents (a heading written as divider text)       |
|                  | See below (means nothing without the layout)                              |

### Always set the text

Set the text in every divider that shows text. The design file default, Or continue with, is a placeholder.

### Expandable divider labels

Say what the click does and swap the text with the state. The aria-label changes with the state and contains the visible text.

| Do                               | Don't                                                         |
| :------------------------------- | :------------------------------------------------------------ |
| Show more information            | More (does not say what changes)                              |
| Show less information            | Click to expand (names the gesture, not the result)           |
| aria-label Show more information | aria-label Toggle section (does not contain the visible text) |

### Dhivehi copy

Divider has no built-in strings: the caption and the expandable aria-label come from props. Pass Dhivehi text for both on Dhivehi pages.

## Appearances

Appearance sets the line colour. In code, appearance defaults to subtle. Use the least prominent line that still separates the content clearly, and one appearance for the same kind of break across a page.

| :--------------- | :--------------------- | :-------------------------------------------------------------- |

- **Horizontal**, the default, between stacked content. It fills the available width.
- **Vertical** (orientation vertical) between inline items, such as tabs or metadata. It stretches to the height its container gives it, 24 minimum, so place it in a container with an explicit height. A vertical divider ignores text and showIcon. In Figma the vertical variant is 70 high by default: set it to fill the height of its row.

## Expandable divider

<DocsFigure
  src="/images/docs/divider/divider-expandable-1.webp"
  darkSrc="/images/docs/divider/divider-expandable-1-dark.webp"
  alt='Use Expandable: a heading Permit information, the text "Expand to read additional information." and a muted divider with a caret in a circle and the caption Show more information.'
  width="758"
  height="784"
  caption="An expandable divider, collapsed."
/>

- Pass onClick to make a horizontal divider a full-width native button. You must give it aria-label, aria-expanded and aria-controls; showIcon is optional. Without a non-empty aria-label, onClick throws an error. Code does not require aria-expanded, so check it yourself.
- The divider only toggles. Your app shows and hides the content and owns the expanded state.
- Keep the content in the page, hidden with the hidden attribute while collapsed, and point aria-controls at its id.
- Turn on showIcon only on an expandable divider. The caret turns 180 degrees while aria-expanded is true.

## States

| State    | When                                    | Visual change                                                                         |
| :------- | :-------------------------------------- | :------------------------------------------------------------------------------------ |
| Default  | No interaction                          | Line in the appearance colour                                                         |
| Focus    | Keyboard focus on an expandable divider | 2px `border/focus` ring with a 2px offset. In forced colours, a 2px Highlight outline |
| Expanded | aria-expanded true                      | Caret turned 180 degrees                                                              |

A plain divider has no interaction and does not take focus. There is no hover or disabled state.

## Expandable content

Use `onClick` when a long section should start collapsed and let the reader reveal more. The Divider renders a button only when `onClick` is supplied. The caller controls the content, state, `aria-expanded`, and `aria-controls`; the component rotates its caret to point upward when `aria-expanded` is true, but does not render or animate the content panel.

<div className="preview mb-4 rounded-lg border p-4">
  <DividerExpandableDemo client:visible />
</div>

```tsx
import * as React from 'react';
import { Divider } from '@veli-design/react/divider';

function MoreDetails() {
  const [expanded, setExpanded] = React.useState(false);

  return (
    <>
      <p>Short summary of the section.</p>
      <div id="additional-details" hidden={!expanded}>
        <p>Additional details are shown here.</p>
      </div>
      <Divider
        text={expanded ? 'Show less' : 'Show more'}
        showIcon
        appearance="muted"
        aria-label={expanded ? 'Show less' : 'Show more'}
        aria-expanded={expanded}
        aria-controls="additional-details"
        onClick={() => setExpanded((current) => !current)}
      />
    </>
  );
}
```

## API Reference

| Prop          | Type                                                   | Default        | Description                                                                                            |
| :------------ | :----------------------------------------------------- | :------------- | :----------------------------------------------------------------------------------------------------- |
| `appearance`  | `'subtle' \| 'muted' \| 'strong' \| 'emphasis'`        | `'subtle'`     | Selects the semantic border color.                                                                     |
| `orientation` | `'horizontal' \| 'vertical'`                           | `'horizontal'` | Sets the divider direction. Text and the optional icon are supported on horizontal dividers.           |
| `text`        | `React.ReactNode`                                      | —              | Optional caption displayed between the horizontal line segments.                                       |
| `showIcon`    | `boolean`                                              | `false`        | Shows the 16px `CaretCircleDown` icon beside the caption.                                              |
| `onClick`     | `(event: React.MouseEvent<HTMLButtonElement>) => void` | —              | Makes a horizontal divider a full-width native button. The caller owns the content and expanded state. |
| `aria-label`  | `string`                                               | —              | Required with `onClick`; supplies a non-empty accessible name for the button.                          |
| `className`   | `string`                                               | —              | Adds layout or visual overrides.                                                                       |

Standard ARIA attributes and DOM event attributes are forwarded to the rendered separator or button. Use `appearance` to select a visual treatment; Divider does not expose generic `variant` or CSS `style` props. `elementType`, `isDecorative`, `render`, and `slot` are not supported by Divider's public API.

## Accessibility

Without `onClick`, Divider keeps separator semantics. Use the native horizontal or vertical orientation to describe the content boundary.

With `onClick`, the full horizontal row is a native button and supports pointer, Enter, and Space activation. A non-empty `aria-label` is required, including when it has visible `text`.

For expandable content, update `aria-expanded` with the caller's state and point `aria-controls` at the controlled content. Keep the controlled content in the DOM or use an appropriate hidden state.

Divider does not own the content panel or its animation. The caret rotation uses motion-safe Veli transition tokens; if the caller animates the content, respect `prefers-reduced-motion`.

The caption uses the muted text token; appearances use semantic border tokens and follow system, light, and dark themes. Layout follows the surrounding writing direction.

<DocsTab id="accessibility">

How the divider works with screen readers and keyboards. A plain divider is a separator; an expandable divider is a native button.

## Keyboard

A plain divider has no interaction and does not take focus. An expandable divider is a native button in the tab order.

| Key            | Action                                         |
| :------------- | :--------------------------------------------- |
| Tab            | Moves focus to the expandable divider          |
| Enter or Space | Runs onClick, which shows or hides the content |

## Screen readers

- A plain divider has the separator role, with its orientation. The decorative line segments around the text are hidden from assistive technology.
- A divider with text adds a hidden separator named by the text.
- An expandable divider is a button named by its aria-label. You must pass aria-expanded and aria-controls so screen readers announce the state and the content it controls.
- The icon is decorative and hidden.
- Back up the grouping a divider shows with spacing or headings, so the line is not the only cue that content belongs together.

## Focus

Keyboard focus on an expandable divider shows a 2px ring in `border/focus` with a 2px offset. In forced colours it becomes a 2px Highlight outline.

## Hidden content

Content an expandable divider controls stays in the page, hidden with the hidden attribute while collapsed, so it stays out of the reading order and aria-controls points to an element that exists.

## Contrast

Subtle lines can fall below 3:1 and disappear in forced colours or at high zoom. That is why the line must never be the only cue: use spacing or headings as well.

## Reduced motion

When the user prefers reduced motion, the caret turns without the animation. If you animate the content you show, apply the same preference.

## Right to left

Set the language with VeliProvider (language dv). The order of icon and text mirrors and the Dhivehi caption style applies. Pass Dhivehi text and aria-label yourself.

</DocsTab>
