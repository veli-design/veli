# Accordion

<DocsTab id="overview">

An accordion stacks related sections under short titles, so a long page stays easy to scan. People open only the sections they need. Use it for supporting detail such as FAQs, eligibility rules or fees, not for content everyone must read.

<DocsResources
  source="https://github.com/veli-design/veli/blob/main/packages/react/src/accordion.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-accordion--docs"
/>

## When to use

### Use an accordion when

- Content splits into clear, related sections that people scan by title.
- People need one section open at a time, or several at once, such as FAQs, eligibility rules or fees.
- You need to shorten a long page on small screens without hiding its structure.
- The content is secondary or supporting, not the main task on the page.

### Don't use an accordion when

- People must read all the content to finish a task. Show it on the page instead.
- There is only one section. Use a disclosure link or show the content directly.
- All content must stay visible for comparison. Show the sections on the page, or use a table for structured data.
- Panels would hold primary actions or form steps. Use separate pages.
- You need a loading placeholder. Accordion has no skeleton mode, so compose Skeleton pieces instead.

<DocsAnatomy>

1. **Header**

   The row that opens and closes the panel. It shows the hover and pressed fills and the focus ring. It is 56 high at size lg and 44 at size md. In code it is AccordionHeader, a level 3 heading by default.

2. **Title**

   A short, unique title for the section. Avoid titles that wrap. In code it is the AccordionHeader children.

3. **Indicator**

   A decorative 16px icon in a 20 x 24 box. The default caret turns 180 degrees when the item opens. With alignment left it follows the title; with alignment right it leads. You can swap in a custom icon through the icon slot.

4. **Content panel**

   The animated panel around the content. Its inset lines the body text up with the title. In code it is AccordionPanel.

5. **Description**

   Body content of any length. Keep interactive elements here, not in the header. In code it is the AccordionPanel children.

6. **Divider**

   The bottom border of each header and panel pair. It sits 2 below the content, matching the item's 2 top padding, so stacked items look evenly spaced. In code it is AccordionItem.

</DocsAnatomy>

## Content guidelines

### Titles

Use sentence case and 1 to 4 words, usually nouns. Don't end a title with punctuation. Keep titles under 65 characters and make each title unique within the service.

| Do                       | Don't                                                                                             |
| :----------------------- | :------------------------------------------------------------------------------------------------ |
| Required documents       | Here you can find all of the information about your permit application (wraps onto several lines) |
| Fees and processing time | Documents You Need (title case)                                                                   |
| Documents you need       | Fees: (end punctuation)                                                                           |

### Front-load keywords

Start each title with the word people scan for. Avoid starting every title with the same word.

| Do                               | Don't                                                    |
| :------------------------------- | :------------------------------------------------------- |
| Fees, Documents, Processing time | Licence fees, Licence documents, Licence processing time |

### Parallel titles

Write titles in the same form, such as all nouns, or all questions for FAQs.

| Do                                      | Don't                                             |
| :-------------------------------------- | :------------------------------------------------ |
| Who can apply, Documents you need, Fees | Who can apply?, Documents, How much does it cost? |

### FAQ titles

When titles are FAQ questions, write the question people ask, in sentence case, ending with a question mark. A question may run past 4 words when a shorter one would be unclear.

| Do                                  | Don't                                         |
| :---------------------------------- | :-------------------------------------------- |
| Who can apply for a fishing permit? | Eligibility? (not the question people ask)    |
| How long does renewal take?         | WHO CAN APPLY (all caps and no question mark) |

### Panel content

Keep each panel to one topic. Use short paragraphs of 5 sentences or fewer, lists or key-value rows. Avoid long unbroken text.

### Key-value rows

Put the label first and the value after it. Write amounts as MVR 250 and dates as 21 October 2026, and show reference numbers exactly as issued.

| Do                               | Don't     |
| :------------------------------- | :-------- |
| Fee: MVR 250                     | Rf. 250/- |
| Processing time: 10 working days | 21st Oct  |

### No actions in the header

The whole header opens and closes the panel. Put buttons and links inside the panel, never in the title row.

### Dhivehi copy

Accordion has no built-in text. Every title, panel and accessible name comes from your content, so pass Dhivehi titles and panel content yourself when the language is Dhivehi. Write Dhivehi natively rather than translating word for word, and leave room for text to grow by 30 to 50 percent.

## Alignment

Alignment left places the indicator after the title. Alignment right places it before the title, pointing toward it when collapsed. Both follow reading direction, so they mirror in Dhivehi. Use alignment right when the design calls for the indicator on the leading side.

## Custom indicator

Replace the caret through the icon slot when another icon reads better for the content.

- Use a 16px icon. It sits in the same 20 x 24 box as the caret.
- The icon is decorative. The title must describe the section on its own.
- Custom icons don't rotate on their own. Use the item's expanded state to change them, such as turning a plus 45 degrees to make a cross.
- Respect reduced motion in any custom icon animation.

## Behaviour

- **Open and close**: click or tap anywhere on the header to open or close the item. The default caret turns 180 degrees to show the state.
- **One or many open**: by default only one item is open at a time. Opening another closes the previous one. Set allowsMultipleExpanded to let several stay open.
- **Default open items**: open items on load with defaultExpandedKeys. For controlled state, use expandedKeys with onExpandedChange.
- **Item ids**: give every item an id. defaultExpandedKeys and expandedKeys must use these ids.
- **Keep the header in place**: opening an item doesn't move its header. Content expands below it and the scroll position stays, so people keep their place.
- **Header and panel match**: when you override size, alignment or flushed on one header, apply the same values to its panel.

## Motion

| What moves                   | Duration    | Easing      |
| :--------------------------- | :---------- | :---------- |
| Panel height                 | Normal      | Ease in out |
| Built-in indicator rotation  | Normal      | Ease in out |
| Hover and pressed background | Fast (80ms) | Ease out    |

With reduced motion turned on, all of these transitions are turned off: the panel opens and closes at once and the indicator changes without turning.

## Single vs. multiple expanded

By default only one panel is open at a time. Pass `allowsMultipleExpanded` to let several stay open.

<div className="preview mb-4 rounded-lg border p-4">
  <AccordionVariantsDemo client:load />
</div>

For full control over markup, compose the parts directly:

```tsx
<Accordion defaultExpandedKeys={['overview']}>
  <AccordionItem id="overview">
    <AccordionHeader>Overview</AccordionHeader>
    <AccordionPanel>Summary content.</AccordionPanel>
  </AccordionItem>
  <AccordionItem id="history">
    <AccordionHeader>Submission history</AccordionHeader>
    <AccordionPanel>Tracked applications.</AccordionPanel>
  </AccordionItem>
</Accordion>
```

## Controlled expansion

Use stable item IDs. Supply `expandedKeys` with `onExpandedChange` to control the open sections.

```tsx
const [expandedKeys, setExpandedKeys] = useState<Set<string | number>>(new Set(['overview']));

<Accordion items={items} expandedKeys={expandedKeys} onExpandedChange={setExpandedKeys} />;
```

Import `useState` from React. Item keys are strings or numbers.

Use `md` for compact sections and `lg` for larger text. `alignment="left"` places the indicator after the label; `alignment="right"` places it before the label. Both layouts follow the reading direction. `flushed` reduces the outer inset; it does not remove all padding.

## Custom indicator

The `icon` slot is decorative and has a 20 × 24px wrapper. Use a 16px icon. Custom icons do not rotate automatically: use the item's render state to choose their appearance.

```tsx
<Accordion>
  <AccordionItem id="details">
    {({ isExpanded }) => (
      <>
        <AccordionHeader
          level={2}
          icon={<Plus size={16} className={isExpanded ? 'rotate-45' : undefined} />}
        >
          Details
        </AccordionHeader>
        <AccordionPanel>Section content.</AccordionPanel>
      </>
    )}
  </AccordionItem>
</Accordion>
```

Import `PlusIcon` from `@phosphor-icons/react`. Keep interactive elements inside the panel, not inside the header button.

## API Reference

### Veli

| Prop               | Type                           | Default  | Description                                                            |
| :----------------- | :----------------------------- | :------- | :--------------------------------------------------------------------- |
| `items`            | `readonly AccordionItemData[]` | -        | Data-driven sections. When supplied, takes precedence over `children`. |
| `children`         | `ReactNode`                    | -        | Composed Accordion parts.                                              |
| `size`             | `'md' \| 'lg'`                 | `'md'`   | Trigger and panel text size.                                           |
| `alignment`        | `'left' \| 'right'`            | `'left'` | Trailing or leading indicator, respectively.                           |
| `flushed`          | `boolean`                      | `false`  | Reduces horizontal insets.                                             |
| `className`        | `string`                       | -        | Classes merged onto the group.                                         |
| `itemClassName`    | `string`                       | -        | Classes merged onto each data-driven item.                             |
| `triggerClassName` | `string`                       | -        | Classes merged onto each data-driven trigger button.                   |
| `panelClassName`   | `string`                       | -        | Classes merged onto each data-driven panel.                            |

`AccordionItemData` contains `id: string | number`, `label: ReactNode`, and `content: ReactNode`.

### DisclosureGroup

React Aria's headless [DisclosureGroup](https://react-spectrum.adobe.com/react-aria/DisclosureGroup.html#props). These props pass through.

| Prop                     | Type                       | Default | Description                    |
| :----------------------- | :------------------------- | :------ | :----------------------------- |
| `allowsMultipleExpanded` | `boolean`                  | `false` | Allows several open panels.    |
| `defaultExpandedKeys`    | `Iterable<Key>`            | -       | Initially open item IDs.       |
| `expandedKeys`           | `Iterable<Key>`            | -       | Controlled open item IDs.      |
| `onExpandedChange`       | `(keys: Set<Key>) => void` | -       | Called when expansion changes. |

React Aria's `children` and `className` render functions are replaced by Veli's `ReactNode` children and string class names. `isDisabled` is not supported by Veli's Accordion. Other group props, including DOM attributes and `style`, pass through.

### Composition

| Component         | Props                                                                       | Description                                                                                                                                                  |
| :---------------- | :-------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AccordionItem`   | React Aria `Disclosure` props except `isDisabled`; string `className`       | Supports `id`, `isExpanded`, `defaultExpanded`, `onExpandedChange`, and render-function children. Group expansion state takes precedence when present.       |
| `AccordionHeader` | `children`, `icon`, `level`, `size`, `alignment`, `flushed`, `className`    | `level` defaults to `3`. Heading attributes pass to the heading; `className` styles its trigger button. Size, alignment, and flushed inherit from the group. |
| `AccordionPanel`  | `children`, `size`, `alignment`, `flushed`, `className`, `contentClassName` | Panel attributes pass through. `className` styles the animated outer panel; `contentClassName` styles its inner content. Variants inherit from the group.    |

Header and panel children are React nodes. Panel `className` is a string, not a React Aria render function. If overriding the header's size, alignment, or flushed setting, apply the same overrides to its panel.

How the accordion works with keyboards, screen readers and reduced motion, and what you still need to do. Each header is a native button inside a heading, so it follows the standard disclosure pattern.

## Keyboard

Every header is a native button, so it joins the normal tab order. There is no arrow-key navigation between headers.

| Key            | Action                                          |
| :------------- | :---------------------------------------------- |
| Tab            | Moves focus to the next header                  |
| Shift + Tab    | Moves focus to the previous header              |
| Enter or Space | Opens or closes the panel of the focused header |

## Screen readers

- Each header renders a button inside a heading, so screen readers list the headers with the other headings on the page.
- The button reports whether its panel is open (aria-expanded) and which panel it controls (aria-controls).
- Each panel is a group labelled by its header.
- Titles are read as written. Keep them meaningful and unique so they make sense out of context.
- The indicator icon is decorative and hidden from assistive technology.

## Focus

- Keyboard focus shows the Veli focus ring around the header. It appears for keyboard focus only, not on click.
- Never remove the ring or replace it with a colour change.
- State is never shown by colour alone: the indicator turns and the panel appears or disappears.

## Hidden content

Content in a collapsed panel can't be focused and is hidden from assistive technology. Never put errors, required information or confirmations inside a closed panel. Show them on the page, outside the accordion, or open the item that holds them.

Collapsed panels use the browser's hidden until found behaviour where it is supported, so find in page can reveal and open a collapsed panel.

## Target size

The md header is 44px tall. That is above the 24 x 24 minimum target size and meets the 44 recommended for touch. Don't reduce the header padding.

## Contrast

Use the accordion's text, icon and background tokens as they are. Don't override them with custom colours.

## Heading level

Each header is a level 3 heading by default, which suits an accordion placed under a level 2 section. Set level on AccordionHeader so the headers fit the page outline. Data-driven items use the same default.

## Reduced motion

When the user prefers reduced motion, the panel opens and closes without the height transition and the indicator does not turn. Nothing extra is needed from you, unless you add a custom indicator animation: apply the same preference to it.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction and the language, so screen readers can switch to a Dhivehi voice. Alignment and padding follow the reading direction automatically. Pass Dhivehi titles and panel content yourself: the accordion has no built-in text.
