# Accordion

<DocsTab id="overview">

An accordion stacks headers that each reveal a panel of content. Use it to shorten long pages by hiding detail until it is needed: FAQs, service requirements, submission history. This page covers when to use it and how to write for it. Design, Code and Accessibility have their own tabs.

## When to use

When to use an accordion, and when to use something else.

### Use an accordion when

- Content can be split into clear, related sections that users scan by title.
- Users need only one or two sections at a time, e.g. FAQs, application details, settings groups.
- You need to shorten a long page on small screens without hiding the structure.
- Content is secondary or supporting, not the main task on the page.

### Don’t use an accordion when

- Users must read all the content to finish a task. Show it on the page instead.
- There is only one section. Use a disclosure link or show the content directly.
- Users need to compare content across sections side by side. Use tabs or a table.
- Panels would hold primary actions or form steps. Use a stepper or separate pages.

1. **Header · AccordionHeader**

   A heading (h3 by default) that wraps a full-width button. The button opens and closes the panel and receives the hover and pressed backgrounds.

2. **Title · header children**

   Short, unique title for the section. Avoid titles that wrap.

3. **Indicator · icon slot**

   Decorative 16px icon in a 20 × 24 box. The default caret rotates when expanded. It trails the title with left alignment and leads it with right alignment. Replace it through the `icon` prop.

4. **Content panel · AccordionPanel**

   Animated outer panel (`className`) around the inner content (`contentClassName`). Its inset lines the body text up with the title.

5. **Description · panel children**

   Body content of any length. Keep interactive elements here, not in the header.

6. **Divider · AccordionItem**

   Bottom border of each AccordionItem, one header and panel pair. Separates stacked items.

</DocsAnatomy>

## Content guidelines

Keep headers to one line. Write them as topics, not questions, unless the page is an FAQ. Panels can hold paragraphs, lists, links and small tables. Put interactive controls in the panel, never in the header. Open the most important section by default when there is one.

## Motion

Panels animate their height and built-in indicators rotate using the normal motion duration and ease-in-out. Hover and pressed colour feedback use the fast duration (80ms) and ease-out. With reduced motion enabled, these transitions are disabled. Apply the same preference to any custom indicator animation.

## Single vs. multiple expanded

By default only one panel is open at a time. Pass `allowsMultipleExpanded` to let several stay open.

For full control over markup, compose the parts directly:

```tsx
<Accordion defaultExpandedKeys={['overview']}>
  <AccordionItem id="overview">
    <AccordionHeader>Overview</AccordionHeader>
    <AccordionPanel>Summary content.</AccordionPanel>
  </AccordionItem>
  <AccordionItem id="history">
    <AccordionHeader>Submission history</AccordionHeader>
    <AccordionPanel>Tracked applications.</AccordionPanel>
  </AccordionItem>
</Accordion>
```

## Controlled expansion

Use stable item IDs. Supply `expandedKeys` with `onExpandedChange` to control the open sections.

```tsx
const [expandedKeys, setExpandedKeys] = useState<Set<string | number>>(new Set(['overview']));

<Accordion items={items} expandedKeys={expandedKeys} onExpandedChange={setExpandedKeys} />;
```

Import `useState` from React. Item keys are strings or numbers.

## Custom indicator

The `icon` slot is decorative and has a 20 × 24px wrapper. Use a 16px icon. Custom icons do not rotate automatically: use the item's render state to choose their appearance.

```tsx
<Accordion>
  <AccordionItem id="details">
    {({ isExpanded }) => (
      <>
        <AccordionHeader
          level={2}
          icon={<Plus size={16} className={isExpanded ? 'rotate-45' : undefined} />}
        >
          Details
        </AccordionHeader>
        <AccordionPanel>Section content.</AccordionPanel>
      </>
    )}
  </AccordionItem>
</Accordion>
```

Import `PlusIcon` from `@phosphor-icons/react`. Keep interactive elements inside the panel, not inside the header button.

## API Reference

### Veli

| Prop               | Type                           | Default  | Description                                                            |
| :----------------- | :----------------------------- | :------- | :--------------------------------------------------------------------- |
| `items`            | `readonly AccordionItemData[]` | -        | Data-driven sections. When supplied, takes precedence over `children`. |
| `children`         | `ReactNode`                    | -        | Composed Accordion parts.                                              |
| `size`             | `'md' \| 'lg'`                 | `'md'`   | Trigger and panel text size.                                           |
| `alignment`        | `'left' \| 'right'`            | `'left'` | Trailing or leading indicator, respectively.                           |
| `flushed`          | `boolean`                      | `false`  | Reduces horizontal insets.                                             |
| `className`        | `string`                       | -        | Classes merged onto the group.                                         |
| `itemClassName`    | `string`                       | -        | Classes merged onto each data-driven item.                             |
| `triggerClassName` | `string`                       | -        | Classes merged onto each data-driven trigger button.                   |
| `panelClassName`   | `string`                       | -        | Classes merged onto each data-driven panel.                            |

`AccordionItemData` contains `id: string | number`, `label: ReactNode`, and `content: ReactNode`.

### DisclosureGroup

React Aria's headless [DisclosureGroup](https://react-spectrum.adobe.com/react-aria/DisclosureGroup.html#props). These props pass through.

| Prop                     | Type                       | Default | Description                    |
| :----------------------- | :------------------------- | :------ | :----------------------------- |
| `allowsMultipleExpanded` | `boolean`                  | `false` | Allows several open panels.    |
| `defaultExpandedKeys`    | `Iterable<Key>`            | -       | Initially open item IDs.       |
| `expandedKeys`           | `Iterable<Key>`            | -       | Controlled open item IDs.      |
| `onExpandedChange`       | `(keys: Set<Key>) => void` | -       | Called when expansion changes. |

React Aria's `children` and `className` render functions are replaced by Veli's `ReactNode` children and string class names. `isDisabled` is not supported by Veli's Accordion. Other group props, including DOM attributes and `style`, pass through.

### Composition

| Component         | Props                                                                       | Description                                                                                                                                                  |
| :---------------- | :-------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AccordionItem`   | React Aria `Disclosure` props except `isDisabled`; string `className`       | Supports `id`, `isExpanded`, `defaultExpanded`, `onExpandedChange`, and render-function children. Group expansion state takes precedence when present.       |
| `AccordionHeader` | `children`, `icon`, `level`, `size`, `alignment`, `flushed`, `className`    | `level` defaults to `3`. Heading attributes pass to the heading; `className` styles its trigger button. Size, alignment, and flushed inherit from the group. |
| `AccordionPanel`  | `children`, `size`, `alignment`, `flushed`, `className`, `contentClassName` | Panel attributes pass through. `className` styles the animated outer panel; `contentClassName` styles its inner content. Variants inherit from the group.    |

Header and panel children are React nodes. Panel `className` is a string, not a React Aria render function. If overriding the header's size, alignment, or flushed setting, apply the same overrides to its panel.

How the Accordion works with keyboards, screen readers and reduced-motion settings, and what a page author still has to do. The component is built on React Aria Disclosure.

## Keyboard

Every header is a native button, so it joins the normal tab order. There is no arrow-key roving; that keeps behaviour predictable inside long forms.

| Key                | Action                                                   |
| ------------------ | -------------------------------------------------------- |
| `Tab`              | Moves focus to the next header or focusable element.     |
| `Shift + Tab`      | Moves focus to the previous header or focusable element. |
| `Enter` or `Space` | Toggles the panel of the focused header.                 |

## Screen readers

Each header renders a button inside a heading, with `aria-expanded` reflecting the open state and `aria-controls` pointing at its panel. The panel is a region labelled by its header. Titles are announced verbatim. Write them as topics so they make sense out of context. The indicator icon is decorative and hidden from assistive technology.

## Focus and disabled

The focus ring uses the shared focus tokens and appears on keyboard focus. Accordion and AccordionItem do not support `isDisabled`. Keep required information visible instead of relying on a disabled accordion header. State is never conveyed by colour alone: the indicator changes orientation and the panel itself appears or disappears.

## Hidden content

Content in a collapsed panel can’t be focused and is hidden from assistive technology. Never put errors, required information or confirmations inside a closed panel.

## Target size

The single-line `md` header is 44px tall, and `lg` is 56px tall. Keep the provided header padding so the full-width button remains easy to activate.

## Contrast

Text, icons and backgrounds use the shared semantic tokens in light and dark themes. Check contrast again if you override colours; keep focus and expanded states distinguishable without relying on colour alone.

## Heading level

Set `level` on AccordionHeader so the headers fit the page outline. The default is 3, which suits an accordion placed under an h2 section. Data-driven items use the same default.

## Reduced motion

When the user prefers reduced motion, the panel opens and closes without the height transition and the indicator changes orientation without animating. Apply the same preference to any custom indicator animation.

## Dhivehi and right-to-left

Use `VeliProvider language="dv"` for Dhivehi. The same Accordion component follows the provider’s language and reading direction, with MV A Waheed for headers and MV Faseyha for body text. There is no separate AccordionDv code component.

Logical padding and indicator placement mirror automatically. Keep meaningful, concise titles and check translated text at both sizes. See [Right-to-left languages](#right-to-left-languages) for the existing interactive example and code.
