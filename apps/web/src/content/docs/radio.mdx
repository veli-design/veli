# Radio

<DocsTab id="overview">

A radio lets people choose one option from a short list, where every option stays visible. Use radios in a group of two or more, inside a RadioGroup that holds the selected value. Once people choose, one radio in the group is always on: they can choose another, but not turn it off again.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/radio.tsx"

## When to use

### Use a radio when

- People must compare a small set of visible options and choose exactly one.
- There are 2 to 6 options.
- People must answer a yes or no question. Use two radios, Yes then No, so a skipped answer is clearly different from No.
- The value belongs to one group. Always put the radios inside a RadioGroup.

### Don't use a radio when

- People can choose more than one option. Use a [checkbox](/docs/components/checkbox/).
- The list is long and people would rather search or type into it. Use a [combobox](/docs/components/combobox/).
- The choice is a single on or off setting. Use a [switch](/docs/components/switch/) or a [checkbox](/docs/components/checkbox/).
- People switch between views of the same content. Use [tabs](/docs/components/tabs/).

## Content guidelines

### Group label

Every group needs a label that asks the question, in sentence case, ending with a question mark. On a page that asks one question, the question is the page heading and the group label at once.

| Do                                    | Don't                                            |
| :------------------------------------ | :----------------------------------------------- |
| Where will you collect your passport? | Collection office: (not a question, and a colon) |
| Do you have a previous passport?      |                                                  |

### Options

Write short, parallel phrases that don't overlap, in sentence case and without a full stop. Use a logical order, such as alphabetical, by size or by frequency, and put the most common option first. Add None of these or I do not know when it is a valid answer.

| Do                                          | Don't                                                                           |
| :------------------------------------------ | :------------------------------------------------------------------------------ |
| Under 1 year, 1 to 4 years, 5 years or more | In person and At the counter (two options that mean the same thing)             |
| Collect it in person, By post               | I would like to collect it in person. (long, and a full stop)                   |
| None of these, I do not know                | Other (please specify) (please, and brackets; ask a follow-up question instead) |

### Description

Add one short line only when people need it to choose. Leave off the full stop, and don't put links in labels, descriptions or errors.

| Do                              |
| :------------------------------ |
| Sent to your registered address |

### Error message

Say what to do, in the words of the question, starting with Choose. Use one sentence with no full stop and no please, and never show only Required.

| Do                                         | Don't                                                     |
| :----------------------------------------- | :-------------------------------------------------------- |
| Choose where to collect your passport      | Please select an option. (please, select and a full stop) |
| Choose yes if you have a previous passport | Required (does not say what to do)                        |

### Yes or no questions

Ask a yes or no question that people must answer with two radios, Yes then No, such as Do you have a previous passport? Use a checkbox only for a single statement people opt into.

### No default when none fits

If no option should be chosen by default, leave every radio off and say so in the question. A preselected answer is easy to submit without reading, and hides whether people really chose it.

### Gender

When a service needs gender, use the gender field pattern, built as a RadioGroup, and keep the labels and help gender neutral.

### Dhivehi copy

Radio and RadioGroup have no built-in text apart from Optional on FieldLabel. Pass every label, description and error in English and Dhivehi, and write your own errors instead of the browser's. Write Dhivehi natively rather than transliterating, and keep it as short as the English, because Dhivehi lines are taller.

| Disabled | isDisabled                           | Muted circle and text; skipped by the arrow keys              |

A read-only RadioGroup (isReadOnly) can be focused and its answer heard, but not changed. Use it, not isDisabled, for answers that can't be changed here, such as gender prefilled from the National Registry. It looks the same as default.

## Behaviour

- **Choosing**: clicking the circle or the label selects the radio and turns the others off.
- **Arrow keys select**: arrow keys select each radio they pass, so never navigate or submit when the value changes.
- **Controlled or uncontrolled**: pass value with onChange to RadioGroup, or defaultValue to start with one chosen.
- **Groups**: RadioGroup holds one value and stacks radios 12 apart, in a column by default. Its orientation prop only changes what screen readers announce; a row of very short options, or a responsive grid, needs layout classes on the root.
- **Validation**: check a required group when people submit. Outside a Veli Form, validationBehavior native blocks submission with the browser's message; inside one it is aria and doesn't block. Either way, set isInvalid with your own errorMessage.
- **Error summary**: after a submit with errors, show the error summary, There is a problem, with a link for each error in page order. The link for a radio group goes to its first radio. While the summary shows, add Error: to the start of the page title.
- **Field parts or props, not both**: RadioGroup has no label prop, so put FieldLabel inside it. You can also use FieldDescription and FieldError inside the group, but then don't pass description or errorMessage on the group as well, or the help and error show twice.
- **Group only**: a radio is not a standalone toggle. It only works as one option of a RadioGroup.
- **Styling**: Radio takes no style overrides. Its className only sets the outer layout.

## Usage

Place a `FieldLabel` inside the group, or provide `aria-label` or `aria-labelledby`.

<div className="preview mb-4 rounded-lg border p-4">
  <RadioUsageDemo client:load />
</div>

```tsx
<RadioGroup name="contact" defaultValue="email">
  <FieldLabel>Contact method</FieldLabel>
  <Radio value="email">Email</Radio>
  <Radio value="sms">SMS</Radio>
</RadioGroup>
```

## Sizes

`md` has a 16px control and 8px selected indicator. `lg` has a 24px control and 14px indicator. `xl` keeps the 24px control and 14px indicator, with body-lg labels and body-md helper/error text. The label and helper text wrap while the control keeps its size.

<div className="preview mb-4 rounded-lg border p-4">
  <RadioSizesDemo client:load />
</div>

```tsx
<RadioGroup aria-label="Choices" defaultValue="one">
  <Radio size="md" value="one">
    Medium
  </Radio>
  <Radio size="lg" value="two">
    Large
  </Radio>
  <Radio size="xl" value="three">
    Extra large
  </Radio>
</RadioGroup>
```

## Descriptions and validation

Use group `description` and `errorMessage` for shared guidance. When the group is invalid, its error replaces the description. Alternatively, compose `FieldDescription` and `FieldError` inside the group; choose one message approach per slot.

An option's `description` and `errorMessage` are associated with that option. Its `isInvalid` controls local error visibility; group `isInvalid`, `isRequired`, and `validate` control validation.

<div className="preview mb-4 rounded-lg border p-4">
  <RadioMessagesDemo client:load />
</div>

```tsx
<RadioGroup isInvalid errorMessage="Choose a contact method.">
  <FieldLabel>Contact method</FieldLabel>
  <Radio value="email" description="Receive a message in your inbox.">
    Email
  </Radio>
  <Radio value="sms">SMS</Radio>
</RadioGroup>
```

For required forms, set `name` and `isRequired` on the group. `validationBehavior="native"` blocks invalid submission; `"aria"` exposes validation without blocking it. A native reset restores an uncontrolled group's `defaultValue`; reset controlled state in the application.

## Disabled and read only

`isDisabled` prevents focus and selection and excludes the control from form submission. Group `isReadOnly` keeps its value and allows focus while preventing changes. Individual radios may also be disabled.

## API Reference

Radio and RadioGroup are Veli components on React Aria's [radio components](https://react-spectrum.adobe.com/react-aria/RadioGroup.html), which manage native `<input type="radio">` elements. Props below follow that stack.

### Radio

Veli-specific props for an option inside RadioGroup.

| Prop           | Type                    | Default | Description                                                   |
| :------------- | :---------------------- | :------ | :------------------------------------------------------------ |
| `size`         | `'md' \| 'lg' \| 'xl'`  | `'md'`  | Control and label size.                                       |
| `children`     | `ReactNode`             | -       | Visible option label.                                         |
| `description`  | `ReactNode`             | -       | Helper text associated with this option.                      |
| `errorMessage` | `ReactNode`             | -       | Local error shown when option `isInvalid` is true.            |
| `isInvalid`    | `boolean`               | `false` | Shows the option's local error; group validation is separate. |
| `className`    | `string`                | -       | Layout classes on the root label.                             |
| `ref`          | `Ref<HTMLLabelElement>` | -       | Forwarded to the root label.                                  |

### RadioGroup

Veli-specific props for the composed group.

| Prop           | Type                  | Default | Description                                               |
| :------------- | :-------------------- | :------ | :-------------------------------------------------------- |
| `description`  | `ReactNode`           | -       | Shared helper text.                                       |
| `errorMessage` | `ReactNode`           | -       | Shared error text; replaces the description when invalid. |
| `className`    | `string`              | -       | Layout classes on the root group.                         |
| `ref`          | `Ref<HTMLDivElement>` | -       | Forwarded to the root group.                              |

### React Aria Radio

React Aria's headless option props pass through. Its documentation covers the remaining accessible-label, focus, hover, and DOM props, except the exclusions below.

| Prop         | Type                                  | Default | Description                              |
| :----------- | :------------------------------------ | :------ | :--------------------------------------- |
| `value`      | `string`                              | -       | Required unique value inside RadioGroup. |
| `isDisabled` | `boolean`                             | `false` | Disables this option.                    |
| `autoFocus`  | `boolean`                             | `false` | Focuses this option on mount.            |
| `inputRef`   | `RefObject<HTMLInputElement \| null>` | -       | Ref for the native radio input.          |

### React Aria RadioGroup

React Aria's headless group props pass through. Selection, form values, and validation belong to the group.

| Prop                 | Type                           | Default      | Description                                               |
| :------------------- | :----------------------------- | :----------- | :-------------------------------------------------------- |
| `children`           | `ReactNode` or render function | -            | Options and fields; render functions receive group state. |
| `value`              | `string \| null`               | -            | Controlled selection.                                     |
| `defaultValue`       | `string \| null`               | -            | Uncontrolled initial selection.                           |
| `onChange`           | `(value: string) => void`      | -            | Called when selection changes.                            |
| `isDisabled`         | `boolean`                      | `false`      | Disables all options.                                     |
| `isReadOnly`         | `boolean`                      | `false`      | Allows focus while preventing selection changes.          |
| `isRequired`         | `boolean`                      | `false`      | Requires a selection.                                     |
| `isInvalid`          | `boolean`                      | `false`      | Marks the group invalid.                                  |
| `name`               | `string`                       | -            | Native form field name.                                   |
| `form`               | `string`                       | -            | ID of the owning form.                                    |
| `validate`           | `function`                     | -            | Custom validation of the selected value.                  |
| `validationBehavior` | `'native' \| 'aria'`           | `'native'`   | Native blocking or ARIA validation.                       |
| `orientation`        | `'vertical' \| 'horizontal'`   | `'vertical'` | Announced orientation; use classes for row layout.        |

Not forwarded from React Aria:

| Prop                      | Why                                                              |
| :------------------------ | :--------------------------------------------------------------- |
| `style`                   | Not supported on Radio or RadioGroup.                            |
| `className`               | Replaced by Veli's string layout `className` on the root.        |
| Radio `children`          | Veli owns the control; children provide the visible label.       |
| RadioGroup `label`        | Compose FieldLabel, or use `aria-label` / `aria-labelledby`.     |
| RadioGroup `errorMessage` | Replaced by Veli's message content; functions are not supported. |

### Native radio input

React Aria manages the native input's checked state and keyboard behavior. The option's `value` and the group's `name` and `form` reach that input; `inputRef` accesses it. Set selection through RadioGroup rather than adding a separate `checked` prop to Radio. Internal control and indicator slots remain private.

## Accessibility

Give each option visible label content or `aria-label`/`aria-labelledby`. Tab enters the selected option; arrow keys move selection, skipping disabled options, and Space selects the focused option. Helper and error text describe the input without becoming its name. The focus ring is visible for keyboard use and selection remains visible in forced colors.

Hover colors update immediately. Press and release animate the border and selected indicator over the fast motion token (80ms). Reduced motion disables those transitions.

## RTL and Language

Use the same locale and direction as the surrounding UI. Dhivehi typography follows `lang="dv"`; the label stays beside its control in RTL. Wrap a localized subtree in React Aria's `I18nProvider` when it differs from the application locale so horizontal arrow keys follow that direction.

How radios work with keyboards, screen readers and touch, and what you still need to do. Radio and RadioGroup use React Aria radio semantics around native radio inputs.

## Keyboard

| Key         | Action                                                                                                                  |
| :---------- | :---------------------------------------------------------------------------------------------------------------------- |
| Tab         | Moves into the group on the selected radio, or the first radio when none is selected. Tab again leaves the group        |
| Shift + Tab | Moves to the previous focusable element, leaving the group                                                              |
| Arrow keys  | Move to the next or previous radio and select it, skipping disabled radios. Left and Right follow the reading direction |
| Space       | Selects the focused radio                                                                                               |

The group is a single tab stop: only one radio in it can be reached with Tab.

## Screen readers

- A native radio input sits inside the label, so the label text is the radio's accessible name. Give every option visible label text, or aria-label when there is none.
- The group is a radio group named by the FieldLabel inside it. Every group needs a label.
- Each radio is read as selected or not selected, with its position in the group.
- Descriptions and errors describe the input without becoming part of its name. The group's error message is announced with the group.
- The circle and dot are decorative and hidden from assistive technology.

## Focus

- The focus ring shows on keyboard focus only, outside the circle, so nothing shifts.
- Arrow keys move focus and selection together inside a RadioGroup.
- State is never shown by colour alone: the dot and the border show it.

## Disabled

isDisabled on a radio or the whole group mutes it, skips it with the arrow keys and leaves it out of form submission. For answers people need to hear but can't change here, use isReadOnly on the group instead.

## Target size

The label is part of the control, so the whole row selects the radio. Keep radios at least 12 apart, as RadioGroup does, or use size lg on touch screens.

## Contrast

Use the radio's border, dot and text tokens as they are. Don't override them with custom colours.

## Forced colours

In Windows contrast themes the circle, dot and focus ring switch to system colours, so selection stays visible.

## Reduced motion

When the user prefers reduced motion, the border and dot change without a transition. Nothing extra is needed from you.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction and the language, mirrors the layout and makes the arrow keys follow the direction. Pass Dhivehi labels, descriptions and errors yourself.
