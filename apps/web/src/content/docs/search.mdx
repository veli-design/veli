# Search

<DocsTab id="overview">

Search lets people find something by typing a word or phrase, such as a service, a record or a person. Use it above a list or page that is too long to scan. The field has a leading search icon and shows a clear button once it holds a value. Your service owns the querying and shows the results.

## When to use

### Use search when

- People enter a query that filters or searches content, such as an item in a long list, table or page.
- The list narrows as people type, or updates when they press Enter.
- A menu or select holds more options than people can scan.
- The query needs a one-action clear control once it holds a value.

### Don't use search when

- The field collects text that is not a search, such as a form answer. Use [Input](/docs/components/input/).
- People choose from a short list. Use [Select](/docs/components/select/).
- People must search a fixed list of options and select a value. Use [Combobox](/docs/components/combobox/).

<DocsAnatomy>

1. **Field**

   The typing area, 36, 44 or 52 high by size. The default appearance has a bottom line; outline has a border all round.

2. **Search icon**

   A 16 icon (20 at lg) before the text. Decorative, so screen readers skip it.

3. **Text**

   The placeholder in `text/base/inactive` until people type, then the value. Body sm regular (body md at lg). In code it is placeholder and value.

4. **Clear button**

   A 16 cross icon (20 at lg). It shows when there is a value and the field is not read only or disabled. Screen readers call it Clear search. Code shows it automatically; in Figma it is showClear.

5. **Line**

   The bottom line of the default appearance, 1.5 at rest and 2 when active. The outline appearance uses a border instead.

</DocsAnatomy>

In code you can also pass a label above the field and a description below it. The error message replaces the description while the field is invalid. Without a visible label, give the field an aria-label or aria-labelledby that names the search.

## Content guidelines

### Placeholder

Use the placeholder to say what a search covers. Write it in sentence case, with no end punctuation and no ellipsis. Code shows Search as the placeholder when you set none; replace it with placeholder, or pass an empty string to leave it out.

| Do                  | Don't                                                     |
| :------------------ | :-------------------------------------------------------- |
| Search services     | Type here (says only to type, not what can be found)      |
| Search applications | Type to search... (says only to type, and ends with dots) |
| Filter councils     |                                                           |

### Label

Never let the placeholder be the only name. Pass label, or an aria-label naming the search when a heading already makes its purpose clear.

| Do              | Don't                                          |
| :-------------- | :--------------------------------------------- |
| Search services | Search (the default placeholder is not a name) |
| Find a service  |                                                |

### Value

Show exactly what people typed. Don't change or format it.

### No results

Show the no results message below the field or in the list, not as an error. Repeat the search term exactly as typed, in single curly quotes, and suggest one next step. When filters hide every result, say so and offer one action: No applications match these filters. Clear filters.

| Do                                                                         | Don't                                                 |
| :------------------------------------------------------------------------- | :---------------------------------------------------- |
| No results for 'pasport'. Check the spelling or search for something else. | No data (doesn't say what was searched or what to do) |

Write the quotes around the search term as curly single quotes in the product.

### Result count

After a search, announce the number of results in a polite live region. Search doesn't announce results itself.

| Do                | Don't                                      |
| :---------------- | :----------------------------------------- |
| 12 services found | Loading... (says nothing about the result) |

### Built-in strings

| String            | English      | Dhivehi       |
| :---------------- | :----------- | :------------ |
| Placeholder       | Search       | ހޯދާ          |
| Clear button name | Clear search | ހޯދުން ފޮހެލާ |

The clear button name has no override prop. Don't rename it per page. Search has no Optional text and no info tooltip.

### Dhivehi copy

Write Dhivehi placeholders natively rather than translating word for word, and keep them as short as the English.

## Behaviour

- **Typing**: control the query with value and onChange, or start with defaultValue. onChange also runs with an empty string when the field is cleared or the form is reset.
- **Enter**: with onSubmit, Enter calls it with the query instead of submitting the parent form. Without onSubmit, Enter follows native form submission. Phones show a search key (enterKeyHint search).
- **Clear**: the clear button empties the field, runs onClear and returns focus to the text. Clearing doesn't submit the form.
- **Escape**: empties a field that holds a value and runs onClear. When the field is already empty, Escape passes to the parent, such as a dialog.
- **Click target**: clicking anywhere in the field moves focus to the text.
- **Read only**: isReadOnly keeps the field focusable and the value selectable, and hides the clear button. Use it for a query people can see but not change here.
- **Disabled**: isDisabled blocks typing, hides the clear button and removes the field from the tab order.
- **Your service owns the rest**: debouncing, fetching, result messages and autocomplete belong to your page. Show no results and network failures in the results area.
- **Keep the search in the URL**: keep search terms in the URL, and replace the history entry while people type rather than adding one per keystroke.
- **Autofocus**: autofocus only the main search on a search page on desktop. Avoid autofocus on mobile.
- **Width**: the field fills its container. Set the width through the surrounding layout.
- **Text size on phones**: text in a field should be at least 16px on phones, so iOS Safari doesn't zoom the page on focus. Search text is 14px at sm and md and 16px at lg, so use size lg on phones.

## Controlled values

Use `defaultValue` for an uncontrolled initial query, or `value` and `onChange` to own the query. `onChange` receives a string, including an empty string when cleared. Clearing does not submit the form.

<div className="preview mb-4 rounded-lg border p-4">
  <SearchControlledDemo client:visible />
</div>

```tsx
'use client';

import { useState } from 'react';
import { Search } from '@veli-design/react/search';

export function SearchControlledDemo() {
  const [query, setQuery] = useState('');

  return (
    <div className="w-[320px] max-w-full space-y-3">
      <Search
        appearance="outline"
        label="Search services"
        value={query}
        onChange={setQuery}
        description="Filter services as you type."
      />
      <p className="type-body-sm-regular text-base-muted">Query: {query || 'None'}</p>
    </div>
  );
}
```

Set `name` to include the query in native form submission. Submit handling belongs to the parent form. Form reset restores the initial query; controlled consumers receive the reset value through `onChange`.

## Using Search in Veli forms

Search follows Veli's [form handling conventions](/docs/patterns/forms/), just like Input and TextArea. Veli `Form` defaults to `validationBehavior="aria"`, which Search inherits so your form library owns validation. Use `validationBehavior="native"` on the form when you want browser constraint validation to block submission. Named errors supplied through `Form`'s `validationErrors` also reach Search.

<div className="preview mb-4 rounded-lg border p-4">
  <SearchFormDemo client:visible />
</div>

```tsx
'use client';

import { useState } from 'react';
import { Button } from '@veli-design/react/button';
import { Form } from '@veli-design/react/form';
import { Search } from '@veli-design/react/search';

export function SearchFormDemo() {
  const [submitted, setSubmitted] = useState('');

  return (
    <Form
      className="w-[320px] max-w-full"
      validationBehavior="native"
      onSubmit={(event) => {
        event.preventDefault();
        setSubmitted(String(new FormData(event.currentTarget).get('query')));
      }}
    >
      <Search
        label="Find a service"
        name="query"
        isRequired
        pattern="[A-Za-z ]+"
        description="Enter a service name using letters and spaces."
        errorMessage="Enter a service name using letters and spaces."
      />
      <div className="flex gap-3">
        <Button type="submit">Search</Button>
        <Button type="reset" appearance="ghost" onPress={() => setSubmitted('')}>
          Reset
        </Button>
      </div>
      <p className="type-body-sm-regular text-base-muted" role="status">
        {submitted ? `Submitted query: ${submitted}` : 'No query submitted.'}
      </p>
    </Form>
  );
}
```

With React Hook Form, spread the `Controller` field object (`name`, `value`, `onChange`, `onBlur`, `ref`) onto Search and pass `isInvalid` and `errorMessage` from `fieldState`. With TanStack Form, pass `field.state.value`, `field.handleChange`, and `field.handleBlur`, using Veli's form error helpers for messages. Initialize controlled queries to `''`. Both modes support clearing; `onChange` receives the query string rather than a DOM event.

## Search events

Without `onSubmit` on Search, Enter follows native parent-form submission. With `onSubmit`, Enter invokes that callback with the query instead of submitting the parent form; it is a search request event, not a validated form submission. For forms that must validate before submitting, handle `onSubmit` on the parent `Form` instead. `onClear` runs when the clear button or Escape clears a nonempty editable query. Both also trigger `onChange('')`. Escape on an empty query does not trigger clearing.

<div className="preview mb-4 rounded-lg border p-4">
  <SearchEventsDemo client:visible />
</div>

```tsx
'use client';

import { useState } from 'react';
import { Search } from '@veli-design/react/search';

export function SearchEventsDemo() {
  const [submitted, setSubmitted] = useState('');

  return (
    <div className="w-[320px] max-w-full space-y-3">
      <Search
        aria-label="Search documents"
        placeholder="Search documents"
        onSubmit={setSubmitted}
        onClear={() => setSubmitted('')}
      />
      <p className="type-body-sm-regular text-base-muted" role="status">
        {submitted
          ? `Requested query: ${submitted}`
          : 'Press Enter to request a search; Escape clears the query.'}
      </p>
    </div>
  );
}
```

Debouncing, fetching, cancellation, result messages, and autocomplete remain application concerns. Empty queries are valid unless you opt into required or custom validation. No results and network failures should be represented in the results experience rather than automatically marking the field invalid.

## Validation

`description` supplies accessible helper text. When invalid, `errorMessage` replaces it. Use `isInvalid` for externally managed errors, or React Aria’s validation props for form validation.

## API Reference

Search composes React Aria [`SearchField`](https://react-aria.adobe.com/SearchField) with a native `<input type="search">`.

### Search

| Prop                    | Type                     | Default     | Description                                           |
| :---------------------- | :----------------------- | :---------- | :---------------------------------------------------- |
| `appearance`            | `'default' \| 'outline'` | `'default'` | Underline or pill shell.                              |
| `size`                  | `'sm' \| 'md' \| 'lg'`   | `'md'`      | 36px, 44px, or 52px field height.                     |
| `label`                 | `ReactNode`              | -           | Optional visible label associated with the input.     |
| `showRequiredIndicator` | `boolean`                | `true`      | Show the shared required indicator when required.     |
| `description`           | `ReactNode`              | -           | Accessible helper text below the field.               |
| `errorMessage`          | `ReactNode`              | -           | Replaces helper text when invalid.                    |
| `className`             | `string`                 | -           | Layout class on the root, such as width or margin.    |
| `ref`                   | `Ref<HTMLInputElement>`  | -           | Forwarded to the inner input for focus or inspection. |

### SearchField

React Aria’s [`SearchField` props](https://react-aria.adobe.com/SearchField#api) pass through, subject to the exclusions below.

| Prop                 | Type                                                              | Default                                   | Description                                                                |
| :------------------- | :---------------------------------------------------------------- | :---------------------------------------- | :------------------------------------------------------------------------- |
| `value`              | `string`                                                          | -                                         | Controlled query.                                                          |
| `defaultValue`       | `string`                                                          | -                                         | Uncontrolled initial query.                                                |
| `onChange`           | `(value: string) => void`                                         | -                                         | Query change, clear, or form reset.                                        |
| `onSubmit`           | `(value: string) => void`                                         | -                                         | Enter-triggered query callback; replaces parent-form submission for Enter. |
| `onClear`            | `() => void`                                                      | -                                         | Clear button or Escape clears a nonempty editable query.                   |
| `isDisabled`         | `boolean`                                                         | `false`                                   | Prevents interaction and native form submission of this field.             |
| `isReadOnly`         | `boolean`                                                         | `false`                                   | Prevents edits; permits focus and selection.                               |
| `isInvalid`          | `boolean`                                                         | `false`                                   | Marks the field invalid.                                                   |
| `isRequired`         | `boolean`                                                         | `false`                                   | Requires a query.                                                          |
| `validate`           | `(value: string) => ValidationError \| true \| null \| undefined` | -                                         | Custom React Aria validation.                                              |
| `validationBehavior` | `'native' \| 'aria'`                                              | Inherited from Form, otherwise `'native'` | Native form validation or ARIA-only feedback.                              |
| `name`               | `string`                                                          | -                                         | Native form field name.                                                    |
| `form`               | `string`                                                          | -                                         | ID of the associated form.                                                 |
| `autoFocus`          | `boolean`                                                         | `false`                                   | Focuses on mount.                                                          |
| `aria-label`         | `string`                                                          | -                                         | Accessible name when there is no visible label.                            |
| `aria-labelledby`    | `string`                                                          | -                                         | IDs of elements supplying the accessible name.                             |
| `aria-describedby`   | `string`                                                          | -                                         | Additional accessible description IDs.                                     |

Not forwarded from `SearchField`:

| Prop         | Why                                          |
| :----------- | :------------------------------------------- |
| `children`   | Search owns its composition.                 |
| `style`      | Not supported.                               |
| `className`  | Replaced by the root layout class.           |
| `type`       | Fixed to `search`.                           |
| `spellCheck` | Applied directly to the inner input instead. |

## Accessibility, language, and motion

- Provide `label`, `aria-label`, or `aria-labelledby`; use `aria-labelledby` for a visible external label.
- Tab reaches the input and, when present, the clear button. Enter or Space activates the clear button. Keyboard focus is visible on the shell.
- Clicking unused space in the shell focuses the input. Disabled fields cannot receive focus; read-only fields remain focusable.
- The provider localizes the default placeholder and clear-button name to English or Dhivehi. On `lang="dv"` inputs, entered text uses MV Faseyha; RTL layout mirrors the search and clear icons. The magnifying glass and cross retain their shapes.
- Background, stroke, and clear-button transitions respect reduced-motion preferences.

## Migration

Replace `variant` with `appearance`; the values and default are unchanged. The old prop is removed.

```tsx
// Before
<Search variant="outline" aria-label="Search services" />
// After
<Search appearance="outline" aria-label="Search services" />
```

How search works with keyboards and screen readers, and what you still need to do. It is built on the React Aria SearchField with a native search input.

## Keyboard

| Key            | Action                                                                      |
| :------------- | :-------------------------------------------------------------------------- |
| Tab            | Moves focus to the field, then to the clear button when it shows            |
| Enter          | In the field, runs onSubmit, or submits the parent form                     |
| Escape         | Empties a field that holds a value; on an empty field, passes to the parent |
| Enter or Space | On the clear button, empties the field and returns focus to the text        |

A disabled field is skipped by Tab. A read-only field stays focusable.

## Screen readers

- **Name**: give every Search a name. Pass label, or aria-label or aria-labelledby when there is no visible label. The placeholder is a hint, not a name.
- **Search icon**: decorative and hidden from screen readers.
- **Clear button**: named Clear search, in English and Dhivehi.
- **States**: disabled, read-only and invalid states are exposed to assistive technology.
- **Description and error**: description and errorMessage are linked to the field.
- **Results**: Search doesn't announce results. Announce the result count yourself in a polite live region, such as 12 services found.

## Landmark

When a search covers the site or a whole section, wrap it and its button in a search landmark (a form with role search, or the search element). Give each one a distinct name if the page has more than one.

## Focus

Keyboard focus shows a 2px ring in `border/focus` with a 2px offset around the field. It appears for keyboard focus only; a click shows the active state instead, with the pressed fill and a 2px line or border. With the ring, the outline appearance drops its border, so the two never stack. Clicking anywhere in the field, outside the text, moves focus to the text.

## Target size

The clear button measures 16 x 16 at sm and md and 20 x 20 at lg, below the 24 x 24 minimum target. See "Missing or unverified".

## Contrast

| Element                                           | Light  | Dark   | Minimum |
| :------------------------------------------------ | :----- | :----- | :------ |
| Value text, `text/base/strong` on `bg-default`    | 11.8:1 | 10.3:1 | 4.5:1   |
| Read only value, `text/base/strong` on `bg-hover` | 11.2:1 | 9.3:1  | 4.5:1   |
| Placeholder, `text/base/inactive` on `bg-default` | 2.7:1  | 2.3:1  | 4.5:1   |
| Icons, `icon/base/muted` on `bg-default`          | 5.2:1  | 4.6:1  | 3:1     |
| Line or border, `stroke-default` on `bg-default`  | 3.23:1 | 2.83:1 | 3:1     |

The placeholder is below 4.5:1, so never put information people need only in the placeholder. In dark mode the line or border is 2.83:1 on the field fill, below 3:1. Against the page it is 3.06:1 in Light and 3.23:1 in Dark.

## Right to left

Set the language with VeliProvider (language dv). The field and its icons mirror, and the built-in strings switch to Dhivehi. Set dir to auto on the field so Latin queries read left to right.
