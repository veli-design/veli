# Toast

<DocsTab id="overview">

A toast gives brief feedback about something people just did, or about a background task that finished or failed: a short message at the edge of the screen. Screen readers announce it without moving focus, and it closes on its own or when people close it. Every toast goes through one shared queue and appears in one toast region.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/toast.tsx"

## When to use

### Use a toast when

- People need a brief confirmation of their own action that needs no reply and is not tied to a place on the page.
- A small in-page action is done and its result is not on screen, such as Draft saved or Reference number copied.
- A background task finished or failed while people were doing something else, such as a file upload.
- App events need to reach people one after another. Send them through the shared toast queue.

### Don't use a toast when

- The message belongs with page content or must stay visible. Use Alert.
- People must decide before they continue. Use Modal with clear actions.
- A form has validation errors. Use the error summary and field error messages.
- People must keep the information, such as a reference number, deadline or amount due. Show it on the page or in an Alert, and use the toast only to confirm the action.
- The change is already visible, such as a switch turning on. Let the change confirm itself.
- The message is a tip, reminder or announcement unrelated to what people just did. Put news in an Alert on the relevant page.
- The message ends a transaction, such as an application or payment. Use a confirmation page with a clear heading.

<DocsAnatomy>

1. **Container**

   The toast surface, with a tinted or solid background, a 1px border on subtle toasts, 24 radius, 16 padding and a medium shadow, because a toast sits above the page. It is at most 384 wide. In code it is Toast.

2. **Leading icon**

   A 20px icon in the Fill weight. Each intent has its own shape, so the intent never depends on colour alone. You can turn it off or swap it. It is decorative, so screen readers skip it. In code it is leadingIcon and showLeadingIcon.

3. **Title**

   Required. It says what happened in up to 6 words, with no full stop, and names the toast for screen readers. In code it is title.

4. **Description**

   Optional. One or two sentences that add to the title and say what to do. In code it is description.

5. **Main action**

   Optional. A secondary fill button, size xs, with a verb-first label. In code it is the first item in actions.

6. **Second action**

   Optional lighter action, a secondary ghost button, size xs. Two actions at most. In code it is the second item in actions.

7. **Close button**

   An icon-only ghost button that closes the toast. Screen readers announce it as Close notification. Keep it on every toast. In code it is showCloseButton.

8. **Timeout progress**

   An optional bar that counts down a timed toast and follows the bottom corners. It is decorative, so it is hidden from screen readers, and it is hidden with reduced motion. In code it is showProgress.

</DocsAnatomy>

On emphasis toasts, the action buttons and the close button use the high contrast treatment.

## Content guidelines

Toasts are read aloud once, so every word counts.

### Title

Write up to 6 words that say what happened, in the past tense, with no full stop. Put the key words first. No exclamation marks and no praise.

| Do                      | Don't                                                                         |
| :---------------------- | :---------------------------------------------------------------------------- |
| Draft saved             | Success! (says nothing about what happened)                                   |
| Payment not taken       | Your application draft has now been saved. (a long sentence with a full stop) |
| Reference number copied | Done (means nothing without the screen)                                       |

### Description

Write 1 or 2 sentences that add to the title and say what to do, each ending with a full stop. Don't repeat the title, and never show an error code on its own.

| Do                                                | Don't                                                       |
| :------------------------------------------------ | :---------------------------------------------------------- |
| Draft saved. You can come back to it for 30 days. | Draft saved. Your draft has been saved. (repeats the title) |

### Action labels

Give a toast at most 2 actions, each a verb in 1 to 3 words, with the main action first. Never use OK, Dismiss or Retry: the close button closes the toast, and Try again repeats a failed action. Offer Undo for reversible actions, such as Draft deleted.

| Do               | Don't                                 |
| :--------------- | :------------------------------------ |
| Undo             | Retry (use Try again)                 |
| Try again        | Dismiss (duplicates the close button) |
| View application | OK                                    |

### Wording by intent

Match the words to the intent. Keep sorry for failures the service caused.

| Intent   | Pattern                       | Example                                                  |
| :------- | :---------------------------- | :------------------------------------------------------- |
| Positive | The thing and what happened   | Draft saved                                              |
| Info     | The subject and the date      | Service hours change on 1 November 2026                  |
| Warning  | The consequence and the date  | Permit expires on 21 October 2027                        |
| Danger   | What failed and what it means | Payment not taken. Your card was not charged. Try again. |

| Do                                                       | Don't                                                        |
| :------------------------------------------------------- | :----------------------------------------------------------- |
| Payment not taken. Your card was not charged. Try again. | Oops! Something went wrong (vague, playful and no next step) |

### Numbers and dates

Use exact dates and 24-hour times, such as 21 October 2026, 14:30. Write amounts as MVR 250. Show references exactly as issued and on one line. A relative date such as Today always comes with the exact date.

| Do                          | Don't                                                            |
| :-------------------------- | :--------------------------------------------------------------- |
| Refund of MVR 250 requested | Appointment moved to tomorrow (relative date with no exact date) |

### Status words

When a toast reports a status, use the standard word and its intent everywhere: Approved and Paid are positive, Pending is cautious and Rejected is danger.

### Dhivehi copy

Write Dhivehi copy natively rather than word for word, and keep it as short as the English, because Thaana lines are taller. Keep the built-in close button name. Under Dhivehi, pass a Dhivehi aria-label to ToastRegion so the region name is Dhivehi too.

- Use **subtle**, the default, for most toasts. It has a tinted background with a subtle border and neutral text, the same surface as a light Alert.
- Use **emphasis** for high-salience feedback that people must not miss, such as a failed payment. It has a solid background with light text, the same surface as a high contrast Alert. If every toast is emphasised, none stands out.
- Use one appearance for toasts that appear together.

## Behaviour

- **Timing**: give a toast with no action a timeout of 5000 ms or more, and longer for longer text. Toasts with an action, errors and warnings have no timeout and stay until people close them. In code, omit timeout or set it to 0 to keep a toast open.
- **Pause on hover and focus**: the timer pauses while people hover over or focus the toast region, so they have time to read and act.
- **Actions**: an action closes the toast after it runs, unless dismissOnPress is false. Give actions stable ids when their labels can change.
- **One queue**: create one toast queue and share it across the app. Set maxVisibleToasts, such as 3; the rest wait in the queue. The default shows every toast. For a bulk action, show one summary toast, such as 5 files removed.
- **Repeated events**: when the same event happens again while its toast is showing, close the earlier toast before adding the new one, so people see one toast per event.
- **Width**: toasts are at most 384 wide and the region stays inside the screen insets. Text wraps and the toast grows in height.

## Tokens

Toast uses the Alert component tokens for each intent and appearance. Names leave out the `components/alert/` prefix.

| Intent   | Subtle: background, icon                                               | Emphasis: background                                                    | Emphasis: foreground, description |
| :------- | :--------------------------------------------------------------------- | :---------------------------------------------------------------------- | :-------------------------------- |

## Motion

A toast enters from the edge it is placed on: from the end edge for end placements, the start edge for start placements, and from the top or bottom for centred placements. The timeout progress bar shrinks as the timer runs.

With reduced motion turned on, toasts appear and leave without entry and exit transitions, and the progress bar is hidden.

## Usage

<div className="preview mb-4 rounded-lg border p-4">
  <ToastUsageDemo client:load />
</div>

```tsx
const queue = createToastQueue<VeliToastContent>({ maxVisibleToasts: 3 });

function AppShell({ children }) {
  return (
    <>
      <ToastRegion queue={queue} placement="bottom-end" />
      {children}
    </>
  );
}

queue.add(
  { title: 'Application saved', description: 'Your draft has been stored.', intent: 'positive' },
  { timeout: 5000 },
);
```

`placement` follows the screen's logical start and end. Use a timeout of at least 5000 ms for auto-dismiss messages. Omit `timeout` or set it to `0` when the message should remain until dismissed.

## Appearances

`subtle` uses the same light surface as Alert, and `emphasis` uses Alert's high-contrast surface. The default is `subtle`. Choose an intent to match the message: `neutral`, `info`, `positive`, `cautious`, `warning`, or `danger`. On `emphasis`, secondary actions and the close control use Button `highContrast` (onHighContrast) styles.

Each toast shows a leading icon for its intent. Pass `leadingIcon` to replace that icon, or set `showLeadingIcon` to `false` to hide it.

  <ToastAppearancesDemo client:load />
</div>

```tsx
queue.add({ title: 'Draft saved', intent: 'positive', appearance: 'subtle' });
queue.add({ title: 'Draft saved', intent: 'positive', appearance: 'emphasis' });
```

## Actions

Actions dismiss the toast after `onPress` returns unless `dismissOnPress` is `false`. Give actions unique `id` values when their order can change. Accent actions use Button's filled accent treatment.

<div className="preview mb-4 rounded-lg border p-4">
  <ToastActionsDemo client:load />
</div>

```tsx
queue.add({
  title: 'File deleted',
  actions: [
    { id: 'undo', label: 'Undo', intent: 'accent', onPress: restoreFile },
    {
      id: 'details',
      label: 'View details',
      appearance: 'ghost',
      dismissOnPress: false,
      onPress: showDetails,
    },
  ],
});
```

To hide the default close button, set `showCloseButton: false` and provide another way to dismiss the message, such as an action or timeout.

## Timeout progress

`showProgress` displays a decorative countdown when a positive timeout is supplied. The timer pauses while the region is hovered or focused.

## API Reference

Toast is a Veli notification built on React Aria's [Toast](https://react-aria.adobe.com/Toast), `ToastRegion`, and `ToastQueue`. Props below follow that stack.

### ToastRegion

Veli's region positions and renders queued notifications.

| Prop        | Type                                                                              | Default        | Description                     |
| :---------- | :-------------------------------------------------------------------------------- | :------------- | :------------------------------ |
| `queue`     | `ToastQueue<T>`                                                                   | -              | Required shared queue instance. |
| `placement` | `'top' \| 'bottom' \| 'top-start' \| 'top-end' \| 'bottom-start' \| 'bottom-end'` | `'bottom-end'` | Logical screen position.        |
| `children`  | `ReactNode \| ({ toast }) => ReactElement`                                        | Default Toast  | Custom queued-toast rendering.  |
| `className` | `string \| (state) => string`                                                     | -              | Additional region classes.      |
| `style`     | `CSSProperties \| ((state) => CSSProperties \| undefined)`                        | -              | Region styles.                  |

Region styling callbacks can read `visibleToasts`, `isHovered`, `isFocused`, and `isFocusVisible`. The default renderer expects `VeliToastContent`; use custom `children` for another content type.

### VeliToastContent

The content passed to `queue.add()`.

| Prop              | Type                                                                       | Default     | Description                                                                              |
| :---------------- | :------------------------------------------------------------------------- | :---------- | :--------------------------------------------------------------------------------------- |
| `title`           | `ReactNode`                                                                | -           | Required primary message.                                                                |
| `description`     | `ReactNode`                                                                | -           | Supporting content, including numeric values.                                            |
| `intent`          | `'neutral' \| 'info' \| 'positive' \| 'cautious' \| 'warning' \| 'danger'` | `'neutral'` | Semantic color treatment.                                                                |
| `appearance`      | `'subtle' \| 'emphasis'`                                                   | `'subtle'`  | Surface treatment. `subtle` matches Alert light. `emphasis` matches Alert high contrast. |
| `leadingIcon`     | `ReactNode`                                                                | -           | Replaces the default intent icon.                                                        |
| `showLeadingIcon` | `boolean`                                                                  | `true`      | Shows the default intent icon when `leadingIcon` is omitted.                             |
| `actions`         | `VeliToastAction[]`                                                        | -           | Actions in supplied order.                                                               |
| `showCloseButton` | `boolean`                                                                  | `true`      | Includes the close button in the default composition.                                    |
| `showProgress`    | `boolean`                                                                  | `false`     | Shows the countdown for a positive timeout.                                              |

### VeliToastAction

| Prop             | Type                                               | Default       | Description                                   |
| :--------------- | :------------------------------------------------- | :------------ | :-------------------------------------------- |
| `id`             | `React.Key`                                        | -             | Unique stable identity for reordered actions. |
| `label`          | `ReactNode`                                        | -             | Required action content.                      |
| `onPress`        | `() => void`                                       | -             | Action handler.                               |
| `dismissOnPress` | `boolean`                                          | `true`        | Closes the toast after the handler returns.   |
| `intent`         | `'primary' \| 'secondary' \| 'accent' \| 'danger'` | `'secondary'` | Button treatment.                             |
| `appearance`     | `'fill' \| 'transparent' \| 'ghost'`               | `'fill'`      | Button surface; accent always uses fill.      |

### Toast

Used by `ToastRegion` or in a custom region renderer.

| Prop              | Type                                                       | Default                         | Description                                                              |
| :---------------- | :--------------------------------------------------------- | :------------------------------ | :----------------------------------------------------------------------- |
| `toast`           | `QueuedToast<T>`                                           | -                               | Required queue entry.                                                    |
| `intent`          | `ToastIntent`                                              | Queued intent or `'neutral'`    | Overrides the queued intent.                                             |
| `appearance`      | `ToastAppearance`                                          | Queued appearance or `'subtle'` | Overrides the queued appearance.                                         |
| `leadingIcon`     | `ReactNode`                                                | Queued icon                     | Overrides the queued leading icon.                                       |
| `showLeadingIcon` | `boolean`                                                  | Queued value or `true`          | Overrides whether the default intent icon is shown.                      |
| `children`        | `ReactNode \| (state) => ReactNode`                        | Default composition             | Replaces the leading icon, content, actions, close button, and progress. |
| `className`       | `string \| (state) => string`                              | -                               | Additional toast classes.                                                |
| `style`           | `CSSProperties \| ((state) => CSSProperties \| undefined)` | -                               | Styles merged with Toast's transition styles.                            |

Toast callbacks can read `toast`, `isFocused`, and `isFocusVisible`. With custom `children`, you choose which parts to include; `showCloseButton` controls only the default composition.

### React Aria Toast and ToastRegion

Both wrappers inherit React Aria's labeling, global DOM, and `render` props. For the full definitions, see [React Aria Toast](https://react-aria.adobe.com/Toast#api). Common supported props include:

| Prop               | Type     | Default                           | Description                                                |
| :----------------- | :------- | :-------------------------------- | :--------------------------------------------------------- |
| `aria-label`       | `string` | Localized region count            | Accessible name for ToastRegion.                           |
| `aria-labelledby`  | `string` | Toast title ID                    | References an accessible label; overrides the Toast title. |
| `aria-describedby` | `string` | Toast description ID (if present) | References an accessible description.                      |

Toast is named by its title through `aria-labelledby`, which takes precedence over `aria-label`. Set `aria-labelledby` to reference another label when needed. ToastRegion uses a localized notification count unless `aria-label` is supplied.

Not passed through unchanged:

| Prop          | Why                                                                                   |
| :------------ | :------------------------------------------------------------------------------------ |
| `lang`, `dir` | Set from `VeliProvider`; local values do not override them.                           |
| `children`    | Veli supplies default rendering and allows replacement as described above.            |
| `className`   | Merged with Veli's classes.                                                           |
| `style`       | Toast merges transition styles; ToastRegion passes the supplied styles to React Aria. |
| `id`, `ref`   | Not declared by Veli's wrapper public types.                                          |

### ToastContent, ToastActions, and ToastTimeoutProgress

These parts render the queued content, actions, and countdown inside a `Toast`.

| Prop        | Type             | Default | Description                     |
| :---------- | :--------------- | :------ | :------------------------------ |
| `toast`     | `QueuedToast<T>` | -       | Required queue entry.           |
| `className` | `string`         | -       | Additional classes on the part. |

### ToastCloseButton

| Prop         | Type     | Default          | Description                      |
| :----------- | :------- | :--------------- | :------------------------------- |
| `aria-label` | `string` | Localized string | Accessible close-button name.    |
| `className`  | `string` | -                | Additional close-button classes. |

The close control is an icon-only ghost Button. On `emphasis` toasts it sets `highContrast` so the control uses onHighContrast secondary styles. The parts expose only the props listed above. They do not inherit the underlying React Aria content/button props, native attributes, `children`, `style`, or refs as public props.

### createToastQueue

`createToastQueue<T>(options)` returns a React Aria queue with Veli's default update behavior.

| Prop               | Type                   | Default          | Description                                             |
| :----------------- | :--------------------- | :--------------- | :------------------------------------------------------ |
| `maxVisibleToasts` | `number`               | `Infinity`       | Maximum visible notifications.                          |
| `wrapUpdate`       | `(fn, action) => void` | Veli transitions | Custom update wrapper; call `fn` to deliver the update. |

`action` is `'add'`, `'remove'`, or `'clear'`. A custom wrapper takes precedence over Veli's default motion behavior.

Options for `queue.add(content, options)`:

| Prop      | Type         | Default | Description                                                    |
| :-------- | :----------- | :------ | :------------------------------------------------------------- |
| `timeout` | `number`     | -       | Auto-dismiss delay in milliseconds; omitted or `0` stays open. |
| `onClose` | `() => void` | -       | Called when this toast closes; not called by `clear()`.        |

`add()` returns a key for `close(key)`. `clear()` removes all entries. `pauseAll()` and `resumeAll()` control visible timers; `visibleToasts` exposes the visible entries, and `subscribe(fn)` returns an unsubscribe function.

## Accessibility

- Use a clear title and include supporting information in `description`.
- React Aria announces notifications and provides focus management. `F6` and `Shift+F6` navigate toast regions.
- Keep messages with actions open until dismissed. If the close button is hidden, provide an action or timeout to remove the toast.
- With reduced motion, Veli skips entry/exit transitions and hides decorative progress. A custom `wrapUpdate` controls its own motion behavior.

## RTL and Language

`VeliProvider language="dv"` supplies Dhivehi typography, RTL direction, and a localized close label. Text and actions align to the reading start; the close button sits at the reading end. Logical start/end placements reverse in RTL. Use `<bdi>` to isolate Latin references in Dhivehi messages.

How the toast works with screen readers, keyboards and timing, and what you still need to do.

## Screen readers

- Each toast is a non-modal alert dialog named by its title and described by its description. Its content is announced when it appears, and focus stays where it was.
- Keep the title and description short and put the key words first. The message is read once and not repeated.
- The toast region is a landmark named with the number of notifications, such as 1 notification., so people can find it in the landmark list.
- The leading icon and the timeout progress bar are decorative and hidden from screen readers.
- Never put information people need to complete or understand a task only in a toast.

## Keyboard

| Key            | Action                                                           |
| :------------- | :--------------------------------------------------------------- |
| F6             | Moves focus to the toast region from anywhere in the app         |
| Shift + F6     | Moves focus to the toast region, going backwards through regions |
| Tab            | Moves through each toast's actions and close button              |
| Enter or Space | Activates the focused action or close button                     |

## Focus

- A toast never takes focus when it appears.
- A toast must never cover the focused element. Place the region clear of the main action, sticky bars and the keyboard.
- A focused toast and the focused region show the Veli focus ring. Buttons inside show their own focus ring.

## Timing

Keep an auto-dismissing toast on screen for at least 5 seconds, and longer for longer text. Toasts with actions, errors or warnings have no timeout. The timer pauses while people hover over or focus the region, so they have time to read and act.

## Target size

The close button is 36 and the actions are 28 high, so both have hit areas of at least 24 x 24.

## Contrast

The title states the outcome, so the intent never depends on colour. Each status intent also has its own icon shape. Use the toast tokens as they are, and use the high contrast button treatment on emphasis toasts.

## Reduced motion

With reduced motion, toasts appear and leave without transitions and the progress bar is hidden. Nothing extra is needed from you unless you pass a custom wrapUpdate to the queue: it then controls its own motion and must respect the same preference.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction, the Dhivehi fonts and the Dhivehi close button name. Pass a Dhivehi aria-label to ToastRegion so the region name is Dhivehi too, and pass Dhivehi titles, descriptions and action labels yourself.
