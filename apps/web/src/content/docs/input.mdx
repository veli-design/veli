# Input

<DocsTab id="overview">

An input lets people type a short answer on one line, such as a name, an email address or a phone number. Use it whenever a form needs a short value that people type rather than pick. Each input comes with a visible label, and can add helper text, a validation message and small accessories at the start or end of the field.

## When to use

### Use an input when

- The answer is short and fits on one line, such as a name or an ID card number.
- People type the value rather than pick it.
- The value is text, an email address, a URL, a phone number or a similar single-line value.
- The field needs a visible label, helper text, a validation message, or leading and trailing content.

### Don't use an input when

- The answer may run to several lines. Use [Text area](/docs/components/textarea/), with its resize and character count.
- People choose from a fixed list. Use [Select](/docs/components/select/).
- The answer is a date. Use [Date picker](/docs/components/date-picker/), or [Date field](/docs/components/date-field/) for a date people know by heart, such as a date of birth.
- The field is for a password or a search. Use [Password input](/docs/components/password-input/) or [Search](/docs/components/search/), which have built-in show and clear behaviour.
- The form is still loading. Input has no skeleton mode, so compose [Skeleton](/docs/components/skeleton/) pieces instead.

<DocsAnatomy>

1. **Label**

   names the field. In code it is label.

2. **Info icon**

   a 16px button that opens a tooltip with extra help. In code it is infoTooltip.

3. **Optional**

   the word Optional after the label. It switches to Dhivehi with the page language. In code it is isOptional. It is hidden when the field is required.

4. **Required indicator**

   an asterisk after the label. In code it shows with isRequired; set showRequiredIndicator to false to hide it.

5. **Field**

   the typing area, 36, 44 or 52 high with a 10 corner radius. The default appearance has an underline; the outline appearance has a border. In code it is appearance.

6. **Text**

   the placeholder until people type, then the value. In code it is placeholder and value.

7. **End content**

   an optional 20px icon at the end of the field. While the field is invalid, a warning icon shows here instead. In code it is endContent.

8. **Helper text**

   one sentence below the field. The error message replaces it while the field is invalid. In code it is description.

</DocsAnatomy>

## Content guidelines

### Labels

Name the value, not the action. Write labels as a short noun phrase in sentence case, with no colon at the end. On a one-question page the label may be the question.

| Do             | Don't                                                      |
| :------------- | :--------------------------------------------------------- |
| Email address  | Enter your email: (names the action and ends with a colon) |
| ID card number | NIC                                                        |

### Placeholders

Use a placeholder, if at all, for one of three things: a format example, such as 7XX XXXX or name@example.mv; what a search covers, such as Search services; or a short prompt on an empty choice, such as Choose an atoll. Write it in sentence case with no end punctuation. Never put the label or instructions in the placeholder: it disappears when people type and its text is low contrast.

| Do                                              | Don't                                                       |
| :---------------------------------------------- | :---------------------------------------------------------- |
| 7XX XXXX                                        | Enter your phone number (an instruction in the placeholder) |
| A visible label, Email address, above the field | Email address as the placeholder with no label              |

### Helper text

Add helper text only when the label needs context: where to find the value, what format it takes or why it is needed. Keep it to one sentence with no full stop. When a value has a format people may not know, show an example that starts with "For example": For example, A900101. If the field has a length limit, say it before people type: You can enter up to 50 characters. Don't put links in helper text, and use infoTooltip only for extra detail.

| Do                                      | Don't                                                                                        |
| :-------------------------------------- | :------------------------------------------------------------------------------------------- |
| The number on the front of your ID card | Please enter your ID card number here. (repeats the label, says please and adds a full stop) |

### Error messages

Say what is wrong and how to fix it, in one specific sentence with no full stop, using the words of the label. When the answer is missing, write Enter followed by the thing. When the format is wrong, show the right one. Set errorMessage for every check the input runs, in English and Dhivehi, instead of showing the browser's own messages.

| Do                                          | Don't                                   |
| :------------------------------------------ | :-------------------------------------- |
| Enter an email address like name@example.mv | Invalid input (doesn't say what to fix) |
| Enter your ID card number                   | Required                                |

Use these templates for other errors:

- **Length**: Full name must be 100 characters or less.
- **Range**: Amount must be between MVR 10 and MVR 5,000.
- **Duplicate**: say what already exists and what to do: You have already applied for this permit. Your reference is WP-2026-04817.
- **Mismatch**: say what must match and how to fix it.
- **Not found**: say what was searched and how to check it: We could not find an application with the reference WP-2026-04871. Check the reference and try again.
- **Codes**: Enter the code we sent you. Never repeat a password, code or other sensitive value in a message.

### Optional and required

Mark whichever is rarer in the form. When most fields are required, label the optional ones with isOptional. When most are optional, mark the required ones with isRequired and say once above the form: Fields marked with \* are required. Never mark one field both ways. The input hides Optional when a field is required. In a form that marks optional fields, set showRequiredIndicator to false, because the asterisk shows on every required field by default.

### Units and amounts

Show units and prefixes, such as MVR or kg, outside the value in startAddon or endAddon, so people type the number only, and still name the value in the label. In amount inputs, accept MVR, Rf, the rufiyaa sign, commas and spaces as typed. Write amount errors in MVR.

| Do                                                  | Don't                                                                                 |
| :-------------------------------------------------- | :------------------------------------------------------------------------------------ |
| Label "Amount paid", MVR in startAddon, value 1,250 | Value typed as MVR 250 (people must type the currency and validation has to strip it) |
| Amount must be MVR 10 or more                       | Enter amount in MVR without commas (makes people format the value)                    |
|                                                     | Amount must be numeric (technical, with no range)                                     |

### IDs, phone numbers and addresses

- Label the national ID number "ID card number" and show it exactly as issued: A900101.
- In phone fields, accept spaces, hyphens and a leading +960, 960 or 00960. Don't use input masks or reformat the number while people type.
- Ask for an address in Maldivian order: house or building name, road, island or city, then postcode.
- Write email addresses in full and in lower case. Use name@example.mv in visible format hints.

### Built-in strings

Input has two built-in strings, and both switch to Dhivehi with the page language:

| String                        | English          | Dhivehi           |
| :---------------------------- | :--------------- | :---------------- |
| Optional, shown by isOptional | Optional         | އިޚްތިޔާރީ        |
| Info button name              | More information | އިތުރު މަޢުލޫމާތު |

Optional can't be reworded. Override the info button name with infoTooltipAriaLabel so it says what the help is about: More information about ID card number.

### Dhivehi copy

Write Dhivehi labels, helper text and errors natively rather than translating word for word, and keep them as short as the English, because Dhivehi lines are taller and phrases often longer.

## Sizes

Input has three sizes. Size sets the field height, padding and text styles. In code, size defaults to md.

- Use **sm** (36 high) in dense layouts, such as filters, tables and toolbars.
- Use **md** (44 high), the default, for forms.
- Use **lg** (52 high, with larger text) for short forms that need to stand out, such as sign-in, and for kiosks.

## Behaviour

- **Typing**: the value updates as people type. Control it with value and onChange, or start with defaultValue.
- **Click target**: clicking anywhere in the field, outside the text, moves focus to the text.
- **Read only**: isReadOnly keeps the field focusable and selectable but blocks changes. Use it, not isDisabled, for a prefilled value that can't be edited here.
- **Disabled**: isDisabled blocks typing and removes the field from the tab order.
- **Validation**: check the value when people submit, then again as they edit so the error clears once fixed. isInvalid or a failed check shows errorMessage below the field and a warning icon at the end. Never silently block or strip keystrokes, such as refusing letters in a phone field, and keep every answer when people go back, refresh or hit an error.
- **Input types**: type email, password, tel and url keep the value left to right in Dhivehi, and phones show a matching keyboard.
- **Autocomplete and keyboards**: set autoComplete on fields for people's own details, such as type email with autoComplete email, and type tel with autoComplete tel. Use inputMode numeric for an ID card number or a code, never type number. Turn spellCheck and autoCapitalize off for codes, reference numbers, email addresses and ID card numbers.
- **Accept common formats**: trim spaces, ignore spaces and dashes in phone and ID card numbers, and accept upper or lower case in ID card numbers, such as a123456.
- **Paste, Enter and password managers**: never block pasting. Enter submits the form from a single-line field. Keep password managers off fields that aren't for signing in, with a specific autocomplete token or autocomplete off.
- **Autofocus**: autofocus only the single main input of a page on desktop, such as Search on a search page. Avoid autofocus on mobile.
- **One-time codes**: use one input with autoComplete one-time-code and inputMode numeric, so a pasted code fills it. Say where the code went, showing only the last 4 digits of the phone number, and how long it lasts. Offer Send a new code after a short wait, such as 30 seconds.
- **Width**: the input fills the width it is given. Constrain the parent, not the field, and lay forms out in one column with fields sized to the expected answer.
- **Text size on phones**: field text is at least 16px on mobile so iOS Safari doesn't zoom the page on focus. Sizes sm and md use 14px text, so use size lg or set 16px text on phones.

- In Dhivehi the layout mirrors. The label, Optional and asterisk read from the right, and the end icon moves to the left.
- The field keeps its height (36, 44 or 52). The taller Dhivehi line overflows, centred. The label row, with its 8 below, grows to 36 at sm and md and 40 at lg, against 28, 28 and 32 in English (Storybook). See Missing or unverified.
- Email, password, phone and URL values stay left to right. Set dir to ltr on other fixed formats, such as an ID card number or a reference like WP-2026-04817, and to auto on free text. Labels stay in the page direction.
- Optional and the info button name switch to Dhivehi.
- In code, wrap the form in VeliProvider with language set to dv.
- In Figma, design Dhivehi forms with inputDv. It has the same variants as input, mirrored, with the Dhivehi text styles and strings.

## Tokens

Fill, line and text per state. Line is the underline in the default appearance and the border in outline. Fill and line names are written `text-input/...` and leave out the `components/` prefix.

| State     | Fill                                                   | Line                                                                                    | Text and icon                                                  |
| :-------- | :----------------------------------------------------- | :-------------------------------------------------------------------------------------- | :------------------------------------------------------------- |
| Default   | `text-input/bg-default`                                | Underline `text-input/stroke-default` 1.5; outline border `text-input/stroke-default` 1 | Placeholder `text/base/inactive`                               |
| Hover     | `text-input/bg-hover`                                  | Underline `text-input/stroke-hover` 1.5; outline border `text-input/stroke-hover` 1.5   | As default                                                     |
| Active    | `text-input/bg-pressed`                                | Underline `text-input/stroke-pressed` 2; outline border `text-input/stroke-pressed` 2   | Value `text/base/strong`                                       |
| Focus     | `text-input/bg-pressed`                                | Underline `text-input/stroke-pressed` 2 plus the focus ring; outline has the ring only  | Value `text/base/strong`                                       |
| Filled    | `text-input/bg-default`; outline `text-input/bg-hover` | Underline `text-input/stroke-default` 1.5; outline border `text-input/stroke-default` 1 | Value `text/base/strong`                                       |
| Error     | `text-input/bg-default`                                | Underline `text-input/stroke-error` 1.5; outline border `text-input/stroke-error` 1     | Value `text/base/strong`; message and icon `text/danger/muted` |
| Read only | `text-input/bg-hover`                                  | None                                                                                    | Value `text/base/strong`                                       |
| Disabled  | `text-input/bg-hover`                                  | None                                                                                    | `text/disabled`; label `text/base/muted`                       |

| Part              | Token               |
| :---------------- | :------------------ |
| Label             | `text/base/DEFAULT` |
| Optional          | `text/base/subtle`  |
| Required asterisk | `text/danger/muted` |
| Helper text       | `text/base/muted`   |
| Focus ring        | `border/focus`      |

Token names leave out the `semantics/` prefix. Override these tokens, not raw colours, when theming.

## Accessibility

- Give the field a visible `label`, or pass `aria-label` / `aria-labelledby` when the label is hidden.
- `description` is the accessible helper. On error, `errorMessage` replaces it.
- The error icon and slot icons are decorative. Put any meaning they carry in `errorMessage` or `description`.
- If `action` is interactive, render a button or link so it has its own accessible name.

## RTL and Language

On `lang="dv"` pages, entered text uses `MV_Faseyha`. In RTL, the label row, slots, and error icon follow `dir`. Values for `type="email"`, `"url"`, `"tel"`, and `"password"` stay left-to-right in the Latin font so addresses and numbers keep their order. Their Dhivehi placeholders stay right-aligned.

How the input works with keyboards and screen readers, and what you still need to do. Input is built on the React Aria TextField, which wraps a native input element, so it follows the standard text field pattern.

## Keyboard

| Key         | Action                                                                                           |
| :---------- | :----------------------------------------------------------------------------------------------- |
| Tab         | Moves focus to the field, then to the info button and any slot buttons, which are separate stops |
| Shift + Tab | Moves focus back                                                                                 |
| Enter       | Submits the form from a single-line field                                                        |

A disabled input is skipped by Tab. A read-only input stays in the tab order so people can select and copy its value.

## Screen readers

- **Label**: give every field a visible label. It is linked to the field, so it is read as the field's name. Never replace it with aria-label or the placeholder.
- **Description and error**: description and errorMessage are linked to the field, so people hear the help and the error with it. errorMessage replaces the description while the field is invalid.
- **States**: required, disabled, read-only and invalid states are exposed to assistive technology.
- **Required**: isRequired tells screen readers the field is required. The asterisk is visual only.
- **Optional**: Optional is visible text outside the label, so screen readers don't announce it when people move to the field, only when they read the page.
- **Icons**: the warning icon is decorative and hidden from assistive technology, because the message says the same. Icons you pass to the slots are decorative too: hide them yourself, and put any meaning they carry in the label, description or errorMessage.
- **Header action**: if action is interactive, render a real Button or Link so it has its own accessible name. Never use styled text.

## Errors

Errors show a message and a warning icon as well as the red line, so they never rely on colour alone. Show the same words in the error summary at the top of the form.

## Target size

The minimum target size is 24 x 24, and 44 is recommended for touch. The md field is 44px tall and the lg field 52px, so both reach the touch size. Size sm is 36px, which passes the minimum; keep it to dense layouts on larger screens. Use lg on kiosks. The info button is 16 x 16, below the 24 x 24 minimum; see Missing or unverified.

## Contrast

The value, label, helper text and error text meet the 4.5:1 text minimum: helper text in `text/base/muted` measures 4.96:1 in light and 5.23:1 in dark. The field line measures 3.06:1 in light and 3.23:1 in dark against the page, and 3.23:1 in light but 2.83:1 in dark against the field fill, below 3:1; see Missing or unverified. The placeholder (2.1:1 to 2.7:1) and Optional (3.0:1 to 3.4:1) fall below 4.5:1, so never put information people need in either. Put it in the label or the helper text.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction and the language, and switches Optional and the info button name to Dhivehi. Email, URL, telephone and password values stay left to right. Set dir to ltr on other fixed-format fields, such as an ID card number, and dir to auto on free text. Pass Dhivehi labels, helper text and errors yourself.
