# Table

<DocsTab id="overview">

A table shows a set of records that share the same attributes, one record per row and one attribute per column, so people can scan, compare, sort, select or open them. Typical uses are a person's applications, payments, permits or a data access log.

<DocsResources
  source="https://github.com/veli-design/veli/blob/main/packages/react/src/table.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-table--docs"
/>

## When to use

### Use a table when

- People scan or compare records across columns, such as payments made or applications submitted.
- People check a history or log over time, such as who accessed their data.
- Rows need sorting, selection, opening, resizing or reordering.
- Every record has the same attributes, one per column.

### Don't use a table when

- The content isn't naturally tabular. Use a list or a card.
- You want to lay out a page or put form fields side by side. Use the page layout grid for placement and Field for form questions.
- It shows the details of one record, such as one application's answers. Show them as label and value pairs in a card or on the record's page.
- People answer a form question, such as choosing one service. Use Radio for one choice, Checkbox for several, or Select and Combobox for long lists.
- A wide table would be the only view on phones and people need every column to understand each record. Show each record as a card.

<DocsAnatomy>

1. **Frame**

   Radius 16 with a 1px `border/base/subtle` line on `bg/surface/raised`. It scrolls sideways when the columns are wider than the frame. In code it is Table, inside an automatic frame.

2. **Header row**

   The column headers and the line under them. Turn on stickyHeader to keep it in view while the body scrolls. In code it is Table.Header.

3. **Column header**

   A short noun that names the data. In code it is Table.Column.

4. **Sort caret**

   A 14px caret on the sorted column only, pointing up for ascending and down for descending. In code it comes from allowsSorting and sortDescriptor.

5. **Column resizer**

   A 17 wide target with a 1px line at the end of a resizable column. In code it is Table.ColumnResizer.

6. **Drag handle**

   24 x 24 with a 16px drag icon in `icon/base/muted`. Rows drag only from here. In code it comes from dragAndDropHooks.

7. **Selection checkbox**

   Checkbox md, Select all in the header and one per row, with toggle selection. In code it comes from selectionMode multiple.

8. **Row header cell**

   The cell that identifies the row, such as the reference number. In code it is isRowHeader on its column.

9. **Cell**

   Holds text, a number, a badge or a button. In code it is Table.Cell.

10. **Row**

one record, with hover, selected, focus and disabled states. In code it is Table.Row. 11. **Row action**

one button or link, or a menu button when there are more actions, in the last column. 12. **Row divider**

a 1px `border/base/subtle` line under each row. The last row has none; the frame line closes the table.

</DocsAnatomy>

## Content guidelines

### Table name

Name every table with a visible heading it is labelled by. If there is no heading, use aria-label. Leave out the word table.

| Do                     | Don't                                                       |
| :--------------------- | :---------------------------------------------------------- |
| Your applications      | Table (repeats the role and says nothing about the content) |
| Payments in 2026       | Data Grid 1 (title case and meaningless)                    |
| Who accessed your data |                                                             |

### Column headers

Write short nouns of 1 to 3 words that name the data, in sentence case, with no colon or full stop. Put units and currency in the header, such as Amount (MVR) or Size (MB), so cells hold just the number. Short headers keep columns narrow, and screen readers repeat them before each cell.

| Do               | Don't                                  |
| :--------------- | :------------------------------------- |
| Reference number | What is your reference?                |
| Submitted        | Date submitted:                        |
| Amount (MVR)     | DATE SUBMITTED (all caps)              |
|                  | Amt (unclear abbreviation in a header) |

### Sortable headers

Keep a sortable header to the column name only. Don't add Sort by, arrows or the direction in words; the caret shows the sort and screen readers announce it.

| Do        | Don't                                                     |
| :-------- | :-------------------------------------------------------- |
| Submitted | Sort by date submitted (an instruction instead of a name) |

### Dates and times

Use short forms such as Oct only in table cells and other places where space truly requires it, never in sentences, headings or buttons.

| Do                 | Don't                                                |
| :----------------- | :--------------------------------------------------- |
| 21 Oct 2026        | 10/21/2026 (numeric dates are ambiguous)             |
| 21 Oct 2026, 09:00 | 21st Oct, 2026 9am (ordinal, comma and 12-hour time) |

### Amounts

Put MVR in the header and the number in the cell, aligned to the inline end. Match decimals in a column: when one amount has laari, show 2 decimals on all of them.

| Do                                 | Don't                                   |
| :--------------------------------- | :-------------------------------------- |
| Fee (MVR): 250.00, 1,500.00, 12.50 | 250 MVR (code after the amount)         |
| No fee                             | MVR 0.00 (write Free or No fee)         |
|                                    | MVR 250, 1500 and Rf 75.5 in one column |

### Status words

Show the status word as text in a badge in the status column, using the shared status words. Each word keeps one intent everywhere: In review is info, Action needed is warning, Approved is positive.

| Do            | Don't                       |
| :------------ | :-------------------------- |
| In review     | A coloured dot with no word |
| Action needed | Processing                  |

### References and places

Show references exactly as issued, usually in the row header column. Use the agreed spelling for places.

| Do                | Don't                                       |
| :---------------- | :------------------------------------------ |
| WP-2026-04817     | wp 2026 04817 (changed case and separators) |
| A900101           |                                             |
| Lh. Naifaru, Malé | K. Male (not the agreed spelling)           |

### Empty cells

| Do             | Don't                                |
| :------------- | :----------------------------------- |
| Not provided   | - (ambiguous and read aloud as dash) |
| None           | N/A (abbreviation)                   |
| Not applicable |                                      |

### Empty and no results

Replace the default No results found. Never leave it on a table that never had data or failed to load. Say why the table is empty and what to do next, with at most one action. After a search, repeat the term and suggest one next step.

| Do                                                                                      | Don't                                                      |
| :-------------------------------------------------------------------------------------- | :--------------------------------------------------------- |
| No applications yet. Applications you start will appear here. Start an application.     | No results found. (generic, and suggests a search failed)  |
| You have nothing to do. We will tell you when an application needs your attention.      | Nothing here! (vague, with an exclamation mark)            |
| No results for ‘WP-2026-0481’. Check the reference number or search for something else. | Search returned 0 rows. (system wording with no next step) |
| No payments match these filters. Clear filters.                                         |                                                            |

### Row actions

Start with a verb, 1 to 3 words. Extend the accessible name of repeated controls with the row.

| Do                                          | Don't                                         |
| :------------------------------------------ | :-------------------------------------------- |
| View application                            | Details (no verb)                             |
| Download receipt                            | Click here (says nothing about the result)    |
| Menu button named Actions for WP-2026-04817 | Actions on every row, with no row in the name |
|                                             | Three unnamed icon buttons in every row       |

### Dhivehi copy

Headers, cells and custom empty content come from your content, so pass them in the active language. Write Dhivehi natively rather than transliterating, and keep headers as short as the English, because Thaana renders wider. Pass the empty message in the active language through emptyMessage or renderEmptyState.

| Mode              | In code                   | What people see                                                                 |
| :---------------- | :------------------------ | :------------------------------------------------------------------------------ |
| None (default)    | selectionMode none        | No selection. Rows can still open a record                                      |
| Multiple, toggle  | selectionMode multiple    | A checkbox in every row and Select all in the header                            |
| Single            | selectionMode single      | One row at a time, shown by the row tint, with no checkbox                      |
| Multiple, replace | selectionBehavior replace | Selecting a row replaces the selection, like a file manager, with no checkboxes |

Use the default toggle selection for multiple selection in service tables, so every row shows a checkbox people can see and tap. Replace behaviour depends on modifier keys and gives no visible cue that rows can be selected. With multiple selection, show the number selected and the bulk actions above the table, such as 3 selected, and keep the actions out of the way until something is selected.

## Sorting

<DocsFigure
  src="/images/docs/table/table-sorting-1.webp"
  darkSrc="/images/docs/table/table-sorting-1-dark.webp"
  alt="Three small tables with the columns Reference and Submitted, and the rows WP-2026-04817, 21 Oct 2026 and BL-3051, 14 Oct 2026. Sortable, not sorted: no caret. Ascending: a caret pointing up after Submitted. Descending: a caret pointing down. Each has its note below it."
  width="2400"
  height="756"
  caption="A sortable column that is not sorted, ascending and descending."
/>

- Only the column the table is sorted by shows a caret. A sortable column that is not sorted keeps the caret space empty.
- The caret points up for ascending (A to Z, smallest or oldest first) and down for descending (newest first).
- Sorting is controlled: set allowsSorting on the columns, pass sortDescriptor and onSortChange, and sort the items yourself.
- Load a sortable table already sorted in the order that fits the task, and show that sort on its header: newest first for histories, nearest deadline first for tasks. Most people never change the sort. Keep the sort column and direction in the URL.

- **Status column**: the status word in a badge, with the intent that word always has.
- **Amounts**: the currency in the header and only the number in the cell, aligned to the inline end.
- **One row action**: a button or link in the last column, its accessible name extended with the row, such as View WP-2026-04817.
- **Several row actions**: a menu button in the last column, named with the row, such as Actions for WP-2026-04817.
- **First use**: replace No results found. Say why the table is empty and what to do next, with at most one action. In code: renderEmptyState.
- **No results**: after a search, repeat the term and suggest one next step. When filters hide every row, offer Clear filters. In code: emptyMessage.
- **Reorderable rows**: rows drag from their handle. Also offer Move up and Move down, because dragging can't be the only way. In code: dragAndDropHooks.
- **Resizable columns**: a resizer at the end of each resizable column. Give those columns a width and a minimum width. In code: Table.ResizableContainer and Table.ColumnResizer.
- **Sticky header**: stickyHeader keeps the header row in view while the body scrolls. It is off by default and needs a bounded scrolling ancestor, such as a Table.ResizableContainer with a maximum height.

| State    | When                                             | Visual change                                                                      |
| :------- | :----------------------------------------------- | :--------------------------------------------------------------------------------- |
| Default  | No interaction                                   | No fill                                                                            |
| Hover    | Pointer over a row or a sortable header          | Fill `brand/neutral/alpha/100`                                                     |
| Focus    | Keyboard focus on a row, cell or sortable header | 2px `border/focus` ring inside the edge                                            |
| Selected | Row in selectedKeys                              | Fill `components/button/primary/subtle/default`, checkbox on with toggle selection |
| Disabled | Row in disabledKeys                              | Text `text/disabled`. The row can't be focused, selected or opened                 |
| Empty    | The body has no rows                             | Empty message in `text/base/muted`, default No results found.                      |

- **Disabled rows**: keyboard navigation skips them. Show why in the row itself, for example a status of Expired or Cancelled, not in a tooltip. With disabledBehavior selection, rows keep their row actions and only selection is blocked. Select all skips disabled rows.
- **Loading**: Table has no loading state of its own. Keep the header row visible and show Skeleton rows or Loading text in the body. Show the empty state only after the data has loaded. If loading fails, show an error with Try again, never the empty state.

## Behaviour

- **Opening a record**: make the identifying cell a link to the record page, or use row actions (onRowAction) with VeliProvider navigate. Row actions run on Enter, double click or tap.
- **Removing rows**: confirm in a modal before withdrawing an application, or delete a draft at once and offer Undo in a toast. Never delete from one tap. Then move focus to the next row.
- **Reordering**: rows drag only from their handle. Offer Move up and Move down actions, or a position field, as well. Update your items in onReorder; the table does not own their order.
- **Search, filters and pages**: put search, active filters as tags and the result count above the table, and pagination below it. Table has none of these built in.
- **Long tables**: use pagination for more than about 50 rows. Keep the page number, filters and search terms in the URL, and return people to the same place when they go back.
- **Narrow screens**: keep the identifying column first and the status column next to it, and let the table scroll inside its frame. Don't hide the scrollbar.
- **Dense dashboards**: dashboards may use tight rows and many columns, as long as text meets contrast, targets are at least 24 x 24 and the table scrolls inside its own frame.
- **Row height**: rows have no fixed height. Long text wraps and the row grows.

- Select all, Select row, the move row label and the default empty message follow the language. The sort announcements, the resizer and the drag announcements come from React Aria and may stay English.

## Sorting

Sorting is controlled: set `allowsSorting` on individual columns, provide `sortDescriptor` and `onSortChange`, and sort the items yourself. Keep numeric and date values in their original types when comparing; formatted dates should not be sorted lexically.

<div className="preview mb-4 rounded-lg border p-4">
  <TableSortingDemo client:visible />
</div>

```tsx
import { useState } from 'react';
import { Table, type SortDescriptor } from '@veli-design/react/table';

export default function SortableTable() {
  const [sort, setSort] = useState<SortDescriptor>({ column: 'name', direction: 'ascending' });
  const rows = [
    { id: 'tourism', name: 'Tourism licence', status: 'Approved' },
    { id: 'fishing', name: 'Fishing permit', status: 'Pending' },
    { id: 'business', name: 'Business registration', status: 'Rejected' },
  ];
  const items = [...rows].sort((a, b) => {
    const column = sort.column as 'name' | 'status';
    const result = a[column].localeCompare(b[column]);
    return sort.direction === 'descending' ? -result : result;
  });
  return (
    <Table aria-label="Permit applications" sortDescriptor={sort} onSortChange={setSort}>
      <Table.Header>
        <Table.Column id="name" isRowHeader allowsSorting>
          Name
        </Table.Column>
        <Table.Column id="status" allowsSorting>
          Status
        </Table.Column>
      </Table.Header>
      <Table.Body items={items}>
        {(item) => (
          <Table.Row id={item.id}>
            <Table.Cell>{item.name}</Table.Cell>
            <Table.Cell>{item.status}</Table.Cell>
          </Table.Row>
        )}
      </Table.Body>
    </Table>
  );
}
```

## Row actions and reordering

Pass `onRowAction={(key) => openPermit(key)}` for activation. Enter activates the focused row. Pointer activation depends on selection behavior: toggle selection separates selection from actions, while replace selection uses double-click for an action. `TableRow` also accepts React Aria link props such as `href`; use the provider router for client-side navigation.

For reordering, import `useDragAndDrop` from the Table entry point, supply `getItems` and `onReorder`, and pass the returned `dragAndDropHooks` to `Table`. Update your items in `onReorder`; the component does not own their order. Header and row drag cells are inserted automatically. The Drag And Drop story in the linked Storybook covers the complete controlled collection.

## Responsive layout and sticky headers

The automatic rounded frame scrolls horizontally when the table is wider than its container. Use `className="min-w-[640px]"` on `Table` when columns should retain their width on small screens. Table has one density; there are no public size or appearance variants.

`stickyHeader` needs a bounded scrolling ancestor. Use `TableResizableContainer className="max-h-64 overflow-auto"` as that frame, even when columns are not resizable. The container replaces the automatic frame, so borders do not nest. `Table.className` targets the table element; container classes target the frame.

## API Reference

Table composes [React Aria Table](https://react-spectrum.adobe.com/react-aria/Table.html) with Veli styling. Each part accepts the corresponding React Aria props except `style` and state-based `className`; Veli exposes a string `className`. `TableHeader` and `TableRow` accept static React children rather than React Aria collection-renderer children. Use dynamic items on `TableBody` and return a row with explicit cells. `TableColumn` and `TableCell` retain render-function children.

### Table

| Prop                                  | Type                               | Default    | Description                                      |
| :------------------------------------ | :--------------------------------- | :--------- | :----------------------------------------------- |
| `aria-label`, `aria-labelledby`       | `string`                           | —          | Required accessible table name.                  |
| `stickyHeader`                        | `boolean`                          | `false`    | Sticky header cells within a scrolling ancestor. |
| `selectionMode`                       | `'none' \| 'single' \| 'multiple'` | `'none'`   | Row selection mode.                              |
| `selectionBehavior`                   | `'toggle' \| 'replace'`            | `'toggle'` | Checkbox toggle or row replacement selection.    |
| `selectedKeys`, `defaultSelectedKeys` | `'all' \| Iterable<Key>`           | —          | Controlled or initial selected rows.             |
| `onSelectionChange`                   | `(keys: Selection) => void`        | —          | Selection updates.                               |
| `disabledKeys`                        | `Iterable<Key>`                    | —          | Disabled row keys.                               |
| `disabledBehavior`                    | `'selection' \| 'all'`             | `'all'`    | Disable selection only or all interactions.      |
| `disallowEmptySelection`              | `boolean`                          | `false`    | Prevent clearing the final selection.            |
| `sortDescriptor`                      | `SortDescriptor`                   | —          | Column key and ascending/descending direction.   |
| `onSortChange`                        | `(sort: SortDescriptor) => void`   | —          | Request a new sort; caller orders items.         |
| `onRowAction`                         | `(key: Key) => void`               | —          | Row activation.                                  |
| `dragAndDropHooks`                    | `DragAndDropHooks`                 | —          | Hooks from `useDragAndDrop`.                     |
| `className`                           | `string`                           | —          | Classes merged onto the table, not its frame.    |

Other declared React Aria root props, including keyboard/focus handlers, `id` and ARIA attributes, are forwarded. There is no root `size`, `appearance` or `allowsSorting` prop.

### Composition

Each part is available as a named export and on `Table`: `TableHeader` / `Table.Header`, `TableColumn` / `Table.Column`, `TableBody` / `Table.Body`, `TableRow` / `Table.Row`, `TableCell` / `Table.Cell`, `TableResizableContainer` / `Table.ResizableContainer`, and `TableColumnResizer` / `Table.ColumnResizer`.

| Part                      | Props                                                                                                          | Purpose                                                                                                                                       |
| :------------------------ | :------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- |
| `TableHeader`             | `children`, `className`                                                                                        | Explicit columns; inserts selection/drag columns when enabled.                                                                                |
| `TableColumn`             | `id`, `isRowHeader`, `allowsSorting`, `children`, `width`, `defaultWidth`, `minWidth`, `maxWidth`, `className` | Column identity, accessible row heading, sorting and width constraints. Children may be a render function receiving column state.             |
| `TableBody<T>`            | `items`, `children`, `emptyMessage`, `renderEmptyState`, `className`                                           | Static rows or an item renderer. Undefined `emptyMessage` uses the localized fallback.                                                        |
| `TableRow<T>`             | `id`, `textValue`, `href`, `children`, `onPointerDownCapture`, `onDragStartCapture`, `className`               | Row identity and content. Set `textValue` for complex content used in typeahead/drag announcements. Pointer drags start from the handle cell. |
| `TableCell`               | `children`, `textValue`, `className`                                                                           | Cell content; render-function children receive cell state.                                                                                    |
| `TableResizableContainer` | `children`, `onResizeStart`, `onResize`, `onResizeEnd`, `className`                                            | Scroll frame and column resize callbacks (width maps keyed by column id).                                                                     |
| `TableColumnResizer`      | `aria-label`, `className`                                                                                      | Focusable resize handle with React Aria keyboard/pointer behavior.                                                                            |

`Selection`, `SortDescriptor`, `SortDirection`, and `useDragAndDrop` are re-exported from the same entry point. Custom classes are merged with defaults for each part.

## Accessibility and motion

- Give the table an accessible name and mark a meaningful column `isRowHeader` so row selection and drag announcements identify the row.
- Arrow keys navigate the grid. Space selects when selection is enabled; Enter activates row actions. Focus rings identify rows, sortable headers, cells and resize handles.
- Select-all skips disabled rows. `disabledBehavior="selection"` preserves row actions while blocking selection.
- Focus a resize handle and press Enter to begin, use Left/Right to resize, and Enter to finish or Escape to cancel. Direction follows the provider locale.
- Focus a drag handle and press Enter to begin moving, arrow keys to choose a drop target, Enter to drop, or Escape to cancel. Keep a pointer alternative through the visible handle.
- Row feedback uses colour transitions and disables those transitions under `prefers-reduced-motion: reduce`. No entrance or layout animation is added by Table.

How the table works with keyboards and screen readers, and what you still need to do. Table is a React Aria grid, so sorting, selection, resizing and drag semantics come built in.

## Keyboard

The table is one Tab stop. Tab moves on to the next control after the table.

| Key                       | Action                                                                   |
| :------------------------ | :----------------------------------------------------------------------- |
| Arrow keys                | Move between rows and cells. Left and Right follow the reading direction |
| Home or End               | Move to the first or last cell in the row                                |
| Ctrl or Cmd + Home or End | Move to the first or last row                                            |
| Page Up or Page Down      | Move by a page                                                           |
| Typing                    | Jumps to the row whose text starts with the typed letters                |
| Space                     | Toggles selection of the focused row, with toggle selection              |
| Enter                     | Runs the row action, or sorts a focused sortable header                  |
| Shift + arrow             | Extends the selection, with multiple selection                           |
| Ctrl or Cmd + A           | Selects all rows, with multiple selection                                |
| Escape                    | Clears the selection                                                     |

Column resizer: Enter starts resize mode, arrow keys change the width, and Enter or Escape ends it. Drag handle: Enter starts the drag, Tab moves between drop targets, arrow keys choose the position, Enter drops and Escape cancels.

When the table scrolls inside its frame, check that keyboard users can reach every column and that the focused cell scrolls into view.

## Screen readers

- The table renders a native table element with role grid. Give it an accessible name that says what it lists: a visible heading it is labelled by (aria-labelledby), or aria-label.
- Mark the identifying column as the row header with isRowHeader. Screen readers announce it with each cell, and each row checkbox is named from it, such as Select row Tourism licence.
- Sortable headers set aria-sort on the sorted column. React Aria announces the new sort.
- Selected rows set aria-selected, and disabled rows aria-disabled.
- The sort caret is decorative and hidden from assistive technology.
- Name repeated row actions with the row: Actions for WP-2026-04817.

## Disabled

Disabled rows can't be focused, selected or activated, and keyboard navigation skips them. Their faded text falls below the contrast minimum, which WCAG allows for content that can't be used. Show why the row is disabled as visible text in the row.

## Target size

Sort headers, checkboxes, drag handles, resizers and row actions are at least 24 x 24, also in dense tables. The drag handle is 24 x 24 and the resizer 17 wide by the header height.

## Contrast

Status is a word, never colour alone. Use the table's text, border and fill tokens as they are.

## Reduced motion

When the user prefers reduced motion, row colour transitions are turned off. Nothing extra is needed from you.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction, so the first column sits on the right and arrow keys follow it. Never set dir on the table element. Pass Dhivehi headers, cells and the empty message yourself.
