# Tabs

<DocsTab id="overview">

Tabs split one page into sections that people switch between without leaving it. Use them when the sections are related and people only need one at a time. Each tab either shows a panel on the same page or, as a link tab, opens a peer page.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/tabs.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-tabs--docs"

## When to use

### Use tabs when

- People switch between related content sections in the same context, such as Overview, Documents and History.
- Each tab shows a panel, or opens a peer page through href.
- There are 2 to 7 sections, each with a short label. Put any extra tabs in More.

### Don't use tabs when

- People must go through steps in order. Show one step at a time instead, as a question page.
- People need to compare sections side by side. Show the sections on the page together.
- The options perform actions rather than show content or navigate. Use buttons or a menu.
- Sections are long and people read down the page. Use an accordion.
- A section would need tabs of its own. Use headings inside the panel, an accordion, or separate pages.
- They would be the main navigation of a site or service. Use the site's header navigation.

<DocsAnatomy>

1. **Leading**

   Optional 16px icon before the label, on every tab or on none. In code it is item.leading.

2. **Label**

   One or two words that name the section. The selected tab uses the medium weight in `text/base/strong`. In code it is item.label.

3. **Trailing**

   Optional content after the label, such as a badge counter for new or waiting items. In code it is item.trailing.

4. **Tab**

   One section, 36, 44 or 48 high with radius 8. Hover and pressed add a fill. In code, each item in items.

5. **More**

   An optional tab after the last visible tab that opens a menu of the tabs you put in overflowItems. Turn it on with showMore; its label is moreLabel, More by default.

6. **Indicator**

   A 2px line in `tabs/border-active` under the selected tab. It slides to the tab people select.

7. **Border**

   A 2px line in `tabs/border-inactive` under the whole list. It hugs the tab group; pass tabListClassName w-full for a full-width line. When the tabs are wider than their container, the row scrolls sideways.

</DocsAnatomy>

The selected panel sits 16 below the list. Only the selected panel shows.

## Content guidelines

### Labels

Name each section with a short noun of 1 or 2 words, not an instruction. Use sentence case and no full stop.

| Do        | Don't                                               |
| :-------- | :-------------------------------------------------- |
| Overview  | View your documents (an action, not a section name) |
| Documents | FEES (all caps)                                     |
| Fees      | Fees. (full stop on a label)                        |
| Pricing   | About this service (three words where one will do)  |
| Services  | How much it costs (a sentence, not a label)         |

### Order

Put the most used section first and keep the order of tabs the same everywhere. People find tabs by position as well as by label.

### Number of tabs

Show 2 to 7 tabs. Code needs at least 2; put the rest in More.

### Link tab labels

For link tabs, make each label match the heading of the page it opens. People check they arrived where the tab said.

| Do        | Don't                                          |
| :-------- | :--------------------------------------------- |
| Documents | Files (opens a page headed Uploaded documents) |

### Panel headings

Start each panel with a heading that matches the tab label, at the level below the page section heading, so screen reader users can find it.

| Do        | Don't                                                   |
| :-------- | :------------------------------------------------------ |
| Documents | Uploaded files (does not match the tab label Documents) |

### Counts

Use a badge count in the trailing slot only for new or waiting items, such as unread messages. Cap it at 99+ and give it an accessible name that says what it counts.

| Do                 | Don't                                          |
| :----------------- | :--------------------------------------------- |
| Messages, 3 unread | Messages 3 (read without saying what 3 counts) |

### Tab list name

Always pass listAriaLabel: a short noun phrase that says what the tabs switch between, without the word tabs.

| Do                  | Don't                                                       |
| :------------------ | :---------------------------------------------------------- |
| Service sections    | Tabs (the English default; names the role, not the content) |
| Application details | Navigation tabs (role word in the name)                     |

### Dhivehi copy

Tabs has three built-in strings. The More label is translated by VeliProvider (އިތުރު in Dhivehi); keep it. The tab list name defaults to Tabs in both languages, so always pass listAriaLabel in the active language. The More menu name, More tabs, has no prop and stays English under language dv. Pass Dhivehi labels and panels yourself.

- **Section tabs** (items with panel) switch panels on one page. The panels sit 16 below the list.
- **Link tabs** (items with href) make each tab its own page. Selection follows the current page: drive selectedKey from the route and leave page content outside the tabs. Wire VeliProvider navigate, or a per-item render prop for framework link components.

Keep the selected tab in the URL. Link tabs do this through href; for section tabs, use a query parameter. Back, refresh and shared links then return to the same tab.

- Pass extra tabs as overflowItems. They show in a menu behind a More tab after the last visible tab.
- Overflow is not automatic: you choose which tabs go in More. Use it to keep the visible row within narrow widths.
- When a tab from the More menu is selected, the More tab shows its label in the selected style, with the indicator under it. In Figma there is no selected More variant: set moreLabel.
- The menu items use the same leading and trailing content as the tabs.

## Leading and trailing

Use leading for an icon, on every tab or on none. The label already names the tab, so the icon is decorative and hidden from screen readers. Use trailing for a badge counter, only for new or waiting items such as unread messages. Icons in tabs are 16px.

## Behaviour

- **One panel at a time**: only the selected panel shows.
- **Activation**: by default, moving focus with the arrow keys also selects the tab (automatic activation). Link tabs default to manual activation.
- **Slow panels**: set keyboardActivation manual on tabs whose panels load data or take time to show, so arrow keys only move focus and Enter or Space selects.
- **Link tabs never navigate on focus**: don't set keyboardActivation automatic when items have href, or moving focus would open a new page.
- **Selection**: controlled with selectedKey and onSelectionChange, or uncontrolled with defaultSelectedKey. The first enabled tab is selected by default.
- **Narrow widths**: the tab bar scrolls sideways inside its own row, and the underline hugs the tab group.

## Usage

<div className="preview mb-4 rounded-lg border p-4">
  <TabsUsageDemo client:visible />

```tsx
const items = [
  { id: 'overview', label: 'Overview', panel: 'Summary content.' },
  { id: 'services', label: 'Services', panel: 'Service list.' },
  { id: 'pricing', label: 'Pricing', panel: 'Fees and schedules.' },
];

<Tabs listAriaLabel="Service sections" items={items} />;
```

Size with `sm`, `md`, or `lg`. Use `leading` and `trailing` for icons or badges. The underline hugs the tab group; when tabs are wider than the container, the bar scrolls horizontally. Pass `tabListClassName="w-full"` for a full-width underline.

## Overflow

Pass additional tabs as `overflowItems` to collapse them behind a localized More menu.

```tsx
<Tabs
  listAriaLabel="Workspace sections"
  items={items}
  overflowItems={[
    { id: 'billing', label: 'Billing', panel: 'Invoices.' },
    { id: 'integrations', label: 'Integrations', panel: 'Connected apps.' },
  ]}
/>
```

## Navigation

Pass `href` on an item to render that tab as a link. Drive selection from the current route and leave page content outside Tabs. When any item has an `href`, Tabs defaults `keyboardActivation` to `'manual'`. Wire client-side navigation through [`VeliProvider`](/docs/components/provider/) `navigate`, or a per-item `render` prop for framework `Link` components.

```tsx
<Tabs
  listAriaLabel="Team sections"
  selectedKey={pathname}
  onSelectionChange={() => {}}
  items={[
    { id: '/team/overview', label: 'Overview', href: '/team/overview' },
    { id: '/team/members', label: 'Members', href: '/team/members' },
  ]}
/>
```

Omit `panel` for route-driven tabs; Tabs still renders a visually hidden panel so `aria-controls` resolves.

## API Reference

Tabs is built on React Aria [`Tabs`](https://react-spectrum.adobe.com/react-aria/Tabs.html). Props below follow that stack.

### Tabs

Veli-specific props for the composed control.

| Prop               | Type                      | Default  | Description                                                            |
| :----------------- | :------------------------ | :------- | :--------------------------------------------------------------------- |
| `items`            | `[TabsItem, TabsItem, …]` | -        | Tabs to show. At least two.                                            |
| `overflowItems`    | `TabsItem[]`              | -        | Additional tabs collapsed into the More menu.                          |
| `size`             | `'sm' \| 'md' \| 'lg'`    | `'sm'`   | Tab padding and label typography.                                      |
| `listAriaLabel`    | `string`                  | `'Tabs'` | Accessible name for the tab list.                                      |
| `tabListClassName` | `string`                  | -        | Class on the underline bar. Use `"w-full"` for a full-width underline. |
| `tabClassName`     | `string`                  | -        | Class merged onto each visible tab.                                    |
| `panelClassName`   | `string`                  | -        | Class merged onto each visible panel.                                  |
| `className`        | `string`                  | -        | Layout class on the root (width, margin, flex/grid).                   |

### React Aria Tabs

React Aria’s headless [`Tabs`](https://react-spectrum.adobe.com/react-aria/Tabs.html#props). These props pass through. The React Aria docs cover the rest, except the exclusions below.

| Prop                 | Type                         | Default                | Description                                                |
| :------------------- | :--------------------------- | :--------------------- | :--------------------------------------------------------- |
| `selectedKey`        | `Key`                        | -                      | Controlled selected tab.                                   |
| `defaultSelectedKey` | `Key`                        | first enabled          | Uncontrolled initial tab.                                  |
| `onSelectionChange`  | `(key: Key) => void`         | -                      | Called when the active tab changes.                        |
| `keyboardActivation` | `'automatic' \| 'manual'`    | `'manual'` with `href` | When to select on focus.                                   |
| `isDisabled`         | `boolean`                    | `false`                | Disables the whole tab list.                               |
| `disabledKeys`       | `Iterable<Key>`              | -                      | Keys of tabs to disable. Prefer `isDisabled` on each item. |
| `orientation`        | `'horizontal' \| 'vertical'` | `'horizontal'`         | Tab list orientation.                                      |

Not forwarded from React Aria `Tabs`:

| Prop        | Why                                                |
| :---------- | :------------------------------------------------- |
| `children`  | Replaced by Veli’s `items` / `overflowItems`.      |
| `style`     | Not supported.                                     |
| `className` | Replaced by Veli’s layout `className` on the root. |

### TabsItem

| Prop         | Type               | Description                                         |
| :----------- | :----------------- | :-------------------------------------------------- |
| `id`         | `string \| number` | Stable tab key.                                     |
| `label`      | `ReactNode`        | Visible tab label.                                  |
| `panel`      | `ReactNode`        | Optional panel content. Omit for route-driven tabs. |
| `leading`    | `ReactNode`        | Content before the label.                           |
| `trailing`   | `ReactNode`        | Content after the label.                            |
| `isDisabled` | `boolean`          | Prevents selection.                                 |
| `href`       | `string`           | Renders the tab as a link.                          |
| `render`     | `RenderProps`      | Escape hatch for framework `Link` components.       |

Link DOM props (`target`, `rel`, `hrefLang`, `download`, `ping`, `referrerPolicy`, `routerOptions`) are also accepted on each item. `overflowItems` uses the same shape; panels still come from those items.

`TabsOverflow` is also exported for advanced composition inside an active React Aria tab list. Prefer `overflowItems` on `Tabs`.

## Accessibility

- Provide `listAriaLabel` so the tab list has an accessible name.
- Arrow keys move focus between visible tabs. Home and End jump to the first and last enabled tab.
- With automatic activation, focus also selects the tab. Link tabs default to manual activation.
- Disabled tabs are skipped. Overflow tabs are selected from the More menu.

## RTL and Language

How tabs work with keyboards, screen readers and reduced motion, and what you still need to do. Tabs follow the React Aria tabs pattern: each tab is linked to its panel.

## Keyboard

Tab moves into the list on the selected tab. The More tab is a separate stop after the list.

| Key                 | Action                                                                                 |
| :------------------ | :------------------------------------------------------------------------------------- |
| Tab                 | Moves into the list on the selected tab, then on to the More tab and the panel         |
| Left or Right arrow | Moves to the previous or next tab, wrapping at the ends. Follows the reading direction |
| Home or End         | Moves to the first or last enabled tab                                                 |
| Enter or Space      | Selects the focused tab, with manual activation, or opens the More menu                |

With automatic activation, moving focus also selects the tab. Disabled tabs are skipped.

## Screen readers

- The list has role tablist and each tab role tab, with aria-selected and aria-controls pointing to its panel. Each panel has role tabpanel and is labelled by its tab.
- Always pass listAriaLabel. The default name is Tabs in both languages and only names the role.
- The More tab is a button that opens a menu named More tabs; its items are radio menu items.
- Start each panel with a heading that matches the tab label, so screen reader users can navigate by heading once the panel opens.
- Link tabs still render a visually hidden panel, so aria-controls resolves.

## Focus

- Keyboard focus shows a 2px ring in `border/focus` around the tab. It appears for keyboard focus only, not on click.
- From the selected tab, Tab moves into the panel. The panel takes focus itself only when it has no focusable content; otherwise Tab goes to its first control.
- The selected tab is not shown by colour alone: it is also medium weight and has the indicator.

## Disabled

A disabled tab can't be selected and the arrow keys skip it. Prefer isDisabled on each item.

## Target size

Size sm is 36 high, md 44 and lg 48. Use md or lg on pages used mostly on phones.

## Contrast

The Figma page gives these contrast ratios on `bg/surface/base` and `bg/surface/raised`, showing the lower of the two. Use the tabs text, fill and indicator tokens as they are. Don't override them with custom colours.

| Element                            | Light  | Dark   | Minimum |
| :--------------------------------- | :----- | :----- | :------ |
| Label, `text/base/DEFAULT`         | 7.4:1  | 7.3:1  | 4.5:1   |
| Label on the pressed fill          | 6.3:1  | 6.1:1  | 4.5:1   |
| Selected label, `text/base/strong` | 11.2:1 | 11.1:1 | 4.5:1   |
| Indicator, `tabs/border-active`    | 3.1:1  | 7.2:1  | 3:1     |

The pressed fill is measured at its token alpha, as code renders it.

## Reduced motion

When the user prefers reduced motion, the indicator and fill transitions are turned off. Nothing extra is needed from you.

## Right to left

Set the language with VeliProvider (language dv). The tab row, indicator and More caret follow the direction, the arrow keys follow the reading direction, and the More label becomes އިތުރު. Pass Dhivehi labels, panels and listAriaLabel yourself.
