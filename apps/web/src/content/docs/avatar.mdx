# Avatar

<DocsTab id="overview">

An avatar shows who a person, agency or service is at a glance, as a photo, initials or an icon. Use it next to a name in lists, comments and account menus, so people can recognise who did what. An avatar only shows identity: it takes no action and never replaces the name.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/avatar.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-avatar--docs"
/>

## When to use

### Use an avatar when

- A person, agency or service needs a compact visual identity next to its name.
- You need to show who owns, submitted or acted on an item.
- People recognise others faster by photo or initials than by name alone.

### Don't use an avatar when

- The identity must be conveyed in text. Show the full name or label next to the avatar; never rely on the avatar alone.
- You want to show status, role or priority. Use Badge, and never encode status in the avatar colour.
- You need a product image, logo or illustration. Use an image.
- People need to select or remove a person in a group. Use Tags.

<DocsAnatomy>

1. **Container**

   a circle filled with the appearance colour (`components/avatar/<appearance>`). Its diameter is the size: 60, 52, 44, 36, 28, 20 or 16. In code it is Avatar.

2. **Initials**

   one or two glyphs from the name, centred. Sizes 20 and 16 show one glyph. In code it is initials.

3. **Icon**

   a person icon for a person or a buildings icon for an agency, filled and centred. The icon box scales with the size, from 32 at size 60 down to 12 at size 28 and below. It is decorative and hidden from assistive technology. In code it is type icon or agencyIcon.

4. **Image**

   a photo cropped to the circle. Appearance has no effect on image avatars. In code it is src and alt.

5. **Image border**

   a 1px border (`components/avatar/img-border`) that keeps light photo edges visible on light backgrounds. Image avatars only.

</DocsAnatomy>

## Content guidelines

### Initials

Pass the full name to initials; code derives the glyphs. It takes the first letters of the first two words, or the first two letters of a one-word name: Aishath Mariyam becomes AM, and Aishath Shiuna Ibrahim becomes AS.

| Do                         | Don't                                                        |
| :------------------------- | :----------------------------------------------------------- |
| initials="Aishath Mariyam" | initials="A.M." (full stops render as glyphs; pass the name) |

In Figma, initials aren't derived. Type them yourself: two capital letters, or one at sizes 20 and 16.

### Alternative text

Set alt to the person's or agency's full name. Never use words like avatar, profile picture or photo.

| Do                     | Don't                                                         |
| :--------------------- | :------------------------------------------------------------ |
| Aishath Mariyam        | Avatar (names the image, not the person)                      |
| Maldives Immigration   | Profile picture of Aishath (role words and a partial name)    |
| Aishath Shiuna Ibrahim | Profile picture of user (describes the image, not the person) |

When the name is shown next to the avatar, hide the avatar from assistive technology with aria-hidden="true", so the name isn't read twice.

### Alternative text in Dhivehi

Always pass alt, in Dhivehi too. Without it, icon and image avatars fall back to the English word User and agency icon avatars to Agency, even under VeliProvider language dv. Initials avatars use the initials string. Pass the Dhivehi spelling of the name under language dv, such as ޝިހާމް ހުސައިން.

| Do                                                        | Don't                                                                     |
| :-------------------------------------------------------- | :------------------------------------------------------------------------ |
| alt="Hassan Ibrahim", in Dhivehi script under language dv | No alt in a Dhivehi interface (screen readers hear the English word User) |

### Photos

Use a square photo with the face centred. The image is cropped to a circle, so keep the subject inside the safe centre.

### Presence

When you show whether a person is available, show the presence word as text, or as the aria-label of a status dot, never through the avatar colour. Use Online with the positive intent, Away with cautious, Busy with danger and Offline with neutral.

## Types

Choose the type by what the avatar represents and what data you have.

<DocsFigure
  src="/images/docs/avatar/avatar-types-1.webp"

  alt="Four examples labelled type image, initials, icon and agencyIcon: a photo of a person, a blue initials avatar MJ, a neutral person icon avatar and a green agency avatar with a buildings icon."
  width="2400"
  height="552"
  caption="Image, initials, icon and agency icon."
/>

| Type           | Use it for                                                                                                              |
| :------------- | :---------------------------------------------------------------------------------------------------------------------- |
| image          | A photo of the person, when a reliable photo exists, such as the signed-in user's profile                               |
| initials       | A person with a known name but no photo. Pass the full name                                                             |
| icon (default) | A person whose name isn't available, such as an anonymous or unknown user                                               |
| agencyIcon     | An agency, such as Ministry of Economic Development. A person icon or initials make an agency look like a named officer |

Content resolves in this order: a loadable src shows the image; otherwise initials show when they are set, even if type is icon; otherwise the icon or agency icon shows.

## Appearances

Appearance sets the background and glyph colour of initials and icon avatars. Image avatars ignore it. In code, appearance defaults to blue.

<DocsFigure
  src="/images/docs/avatar/avatar-appearances-1.webp"

- Use **neutral** for unknown users and system entities.
- Give a person or agency the same appearance everywhere, for example by deriving it from a stable id.
- Appearance is decorative. It carries no status, role or priority.

## Behaviour

<DocsFigure
  src="/images/docs/avatar/avatar-fallback-1.webp"
  darkSrc="/images/docs/avatar/avatar-fallback-1-dark.webp"
  alt="Three steps. Step 1, src loads: a photo avatar. Step 2, src fails, initials set: a blue initials avatar MJ. Step 3, no src or initials: a person icon avatar and an agency icon avatar."
  width="2400"
  height="456"
  caption="What the avatar shows when the image or initials are missing."
/>

- **Fallback**: a loadable src shows the image. When it fails to load, the avatar falls back to initials when they are supplied, otherwise to the icon for the type. Design every screen that shows a photo avatar so it also looks right with initials or the icon, and pass the name through initials with every image avatar.
- **Not interactive**: an avatar is a div with no built-in action. To make it do something, wrap it in a button or a link and give that control an accessible name.
- **Status dot**: to show presence, place an xs Badge dot 2px inside the bottom end corner of the avatar with a 2px ring in the surface colour.

## API Reference

| Prop         | Type                                                                                                               | Default  | Description                                                                                 |
| :----------- | :----------------------------------------------------------------------------------------------------------------- | :------- | :------------------------------------------------------------------------------------------ |
| `type`       | `'image' \| 'initials' \| 'icon' \| 'agencyIcon'`                                                                  | `'icon'` | Preferred content when `src` and `initials` do not resolve first.                           |
| `appearance` | `'blue' \| 'neutral' \| 'emerald' \| 'yellow' \| 'orange' \| 'magenta' \| 'indigo' \| 'teal' \| 'green' \| 'lime'` | `'blue'` | Surface and content color.                                                                  |
| `size`       | `'60' \| '52' \| '44' \| '36' \| '28' \| '20' \| '16'`                                                             | `'44'`   | Diameter in pixels; scales icon and initials.                                               |
| `initials`   | `string`                                                                                                           | -        | Name or initials; takes priority over `type` when set. Sizes `16` and `20` show one glyph.  |
| `src`        | `string`                                                                                                           | -        | Image URL; takes priority when loadable. On error, falls back to `initials` when available. |
| `alt`        | `string`                                                                                                           | -        | Accessible name for every content type.                                                     |

All other `div` attributes are supported.

## Accessibility

- Pass a meaningful `alt` for every avatar.
- Without `alt`, initials fall back to the `initials` string; agency icons to `"Agency"`; otherwise `"User"`.
- Avatar is a non-interactive `div`. Wrap it in a button or link when it should be actionable.

## RTL and Language

With `VeliProvider` set to Dhivehi (`language="dv"`), Latin `initials` sources map to Thaana glyphs, including digraphs such as `SH` → `ޝ`.

<DocsTab id="accessibility">

How the avatar works with screen readers and what you still need to do. An avatar is a static image of an identity, so the work is in its name.

## Screen readers

- Every avatar renders an image with alt text, including initials and icon avatars, where the image is visually hidden. The glyphs and icons themselves are hidden from assistive technology.
- Pass alt as the full name of the person or agency. Without alt, initials avatars use the initials string, agency icons use Agency and the rest use User.
- When the name is shown next to the avatar, add aria-hidden="true" to the avatar so the name isn't read twice.

## Focus

An avatar isn't focusable and has no keyboard behaviour. To make it act, wrap it in a Button or a Link with an accessible name. Attach any Tooltip to that wrapper, not to the avatar.

## Contrast

Initials are text, so each appearance needs 4.5:1 against its background. Measured in Storybook at size 44 on the base surface, every appearance gives about 5.8:1 to 6.2:1 in light and dark themes. Appearance colour carries no meaning, so nothing is lost for people who can't tell the colours apart.

## Right to left

Set the language with VeliProvider (language dv). Latin initials then map to Thaana glyphs. Pass alt in Dhivehi yourself: the fallback names User and Agency stay English.

</DocsTab>
