# Skeleton

<DocsTab id="overview">

Skeleton is a plain placeholder shape with a soft shimmer, shown where content will appear while it is fetched. Compose several Skeletons in the shape of the final layout, such as Table rows, a Card or a form, so nothing moves when the content arrives. Skeleton is hidden from screen readers, so announce the loading state separately with a status message.

## When to use

### Use Skeleton when

- The shape of the content is known and takes up real space, such as a list of applications, a Table of payments, a Card or a form loading saved answers, and the load may take longer than about 300 ms.
- A page, or a part of it such as a form or a list, needs a loading state. Compose several Skeleton pieces together.
- You need a loading state for a component that has no skeleton mode, such as Accordion, Input, Avatar or Button. Compose Skeleton pieces in its shape.

### Don't use Skeleton when

- Only an indeterminate indicator or a pending label is needed. Use Spinner or Loading text.
- Content loads in under about 300 ms. Show nothing.
- Content is already on screen and only refreshing.
- A Button started the action. Use Button isLoading or isPending. The Button keeps its label as its accessible name and keeps its width; the label is hidden while the Spinner shows.
- Loading failed or there is nothing to show. Show what could not load with a Try again action, or the empty state, where the Skeletons were.

1. **Block**

   A block in `bg/skeleton` with the md corner radius, 6. className sets its size and shape and can change the radius, such as rounded-full for an Avatar. In code it is Skeleton.

2. **Shimmer**

   A white highlight, 65 percent in Light and 8 percent in Dark, that sweeps across the block. It is removed under reduced motion. In code it is a private part of Skeleton.

Compose several Skeletons in the shape of the part they replace. A form field, for example, is a label line, a block the height of the field and a help line.

## Content guidelines

### Status message

Skeleton has no text or built-in strings. The words come from the status message beside it. Name the activity and its object, and don't add an ellipsis.

| Do                        | Don't                                                   |
| :------------------------ | :------------------------------------------------------ |
| Loading your applications | Loading... (typed ellipsis and no object)               |
| Loading payment history   | Loading content (too general when the content is known) |

### When the content arrives

Announce the result in a status message that makes sense on its own, such as 12 applications.

### Both languages

Write the status message in English and Dhivehi. Keep every string in your language files.

## Shapes

Match each Skeleton to the size and corner radius of the part it stands for, so the page stays still when content arrives and the shapes read as the parts they replace.

| Part                 | Size                          | Radius     | Classes                              |
| :------------------- | :---------------------------- | :--------- | :----------------------------------- |
| Label line           | 76 x 8                        | xs (2)     | `h-2 w-[76px] rounded-xs`            |
| Input field, md      | 44 high, full width           | field (10) | `h-11 w-full rounded-field`          |
| Text area, md        | at least 146 high, full width | field (10) | `min-h-[146px] w-full rounded-field` |
| Pill search field    | 44 high, full width           | full       | `h-11 w-full rounded-full`           |
| Avatar, default size | 44 x 44                       | full       | `size-11 rounded-full`               |

A field Skeleton is a label line, a gap of 8, a block the height of the field, a gap of 4, then a help line. Text lines are 10 high with 8 between them, and the last line is shorter. Storybook and the Figma specs give the same values.

Size Skeleton pieces with layout classes rather than inventing one-off loading components, so they stay on the same spacing and radius tokens as the real components.

| Radius | Token            | Value           | Use                                                                   |
| :----- | :--------------- | :-------------- | :-------------------------------------------------------------------- |
| md     | `radius/DEFAULT` | 6               | The default. For blocks that stand in for Buttons and other md shapes |
| field  | `radius/field`   | 10              | For blocks that stand in for fields, such as Input and Text area      |
| xs     | `radius/xs`      | 2               | For text lines                                                        |
| lg     | `radius/lg`      | 8               | For larger blocks, such as an image or a chart                        |
| full   | `radius/full`    | Half the height | For Avatars, pills and pill Search                                    |

- **Text content**: bars of different lengths with the last line shorter, and only as many lines as the text usually has. Text lines are 10 high.
- **List items**: one row per item, with an Avatar circle, two lines and a status shape. Show as many rows as the list usually has.
- **Field**: a label line, a block the height of the field and a help line. Input, Select and Date picker have no skeleton prop.
- **Table rows**: Skeleton rows inside the Table area with the header row already in place, 3 to 5 rows.
- Keep the page heading, navigation, filters and working controls real while the list or Table area shows Skeletons.

## Behaviour

- **Shimmer loops until removed**: a light highlight sweeps across each Skeleton for 1500 ms, then rests for 500 ms, and repeats for as long as the Skeleton is on screen. Skeleton never stops by itself.
- **Timing**: wait about 150 to 300 ms before showing Skeletons, then keep them for about 300 to 500 ms once shown, so fast responses never flash a loader.
- **Swap in one step**: replace the Skeletons in the same place with the content, the empty state or what could not load, all at once.
- **When loading fails**: show what could not load with a Try again action where the Skeletons were.
- **Fill the slot**: a Skeleton fills its intended slot. Constrain its width and height in the surrounding layout.
- **Reflow like the real layout**: build Skeleton layouts with the same responsive classes as the real layout, so they reflow with it from 320 px. A Table that becomes stacked cards on phones gets stacked card Skeletons.
- **Nothing real inside**: never put text, links, buttons or other content inside a Skeleton. Place Skeletons beside real content and controls.

## Language and direction

<DocsFigure
  src="/images/docs/skeleton/skeleton-rtl-1.webp"

- Skeleton shapes are direction-neutral. Use logical utilities, such as ms-auto for end-aligned cells, so the composition mirrors.
- The shimmer follows the text direction: it sweeps from left to right in English and from right to left under dir rtl.
- Under language dv, size text lines and their gaps to the Dhivehi line height, which is taller: Body md is 17px on a 186 percent line height in Dhivehi against 16px on 150 percent in English. Skeletons sized for English lines make a Dhivehi page grow when the text arrives.

## Tokens

| Part              | Token                                                                | Reduced motion | Notes                                     |
| :---------------- | :------------------------------------------------------------------- | :------------- | :---------------------------------------- |
| Fill              | `bg/skeleton`                                                        | Same           | Neutral 300 in Light, neutral 400 in Dark |
| Shimmer highlight | White, 65 percent in Light and 8 percent in Dark, faded at the edges | Removed        | No token. Figma draws the Light value.    |
| Corner radius     | `radius/DEFAULT` (6) unless className changes it                     | Same           |                                           |

Token names leave out the `semantics/` prefix.

## Motion

| What moves        | Duration                                      | Easing | Reduced motion                      |
| :---------------- | :-------------------------------------------- | :----- | :---------------------------------- |
| Shimmer highlight | 2s loop: sweeps for 1500 ms, rests for 500 ms | Linear | Removed; only the static fill stays |

## Accessibility

Each `Skeleton` sets `aria-hidden="true"` because placeholders are decorative. Wrap the loading region in a live status element when you need to announce progress:

```tsx
<div aria-busy="true" aria-label="Loading form">
  <Skeleton className="h-11 w-full" />
</div>
```

| Input field (md)  | `h-11 w-full`              |

| Pill search field | `h-11 w-full rounded-full` |
| Avatar            | `size-10 rounded-full`     |

## Composition

Build component-specific placeholders by stacking `Skeleton` elements:

```tsx
function InputFieldSkeleton() {
  return (
    <div className="flex w-full flex-col items-start">
      <div className="flex w-full items-center pb-2">
        <Skeleton className="h-2 w-[76px] rounded-xs" />
      </div>
      <Skeleton className="h-11 w-full" />
      <div className="flex w-full items-center pt-1">
        <Skeleton className="h-2 w-[76px] rounded-xs" />
      </div>
    </div>
  );
}
```

How Skeleton works with screen readers, focus and reduced motion. Skeleton is decorative; the loading state is announced by a status message.

## Screen readers

- Every Skeleton renders with aria-hidden, so assistive technology skips the placeholders. Skeleton announces nothing by itself.
- When Skeletons stand in for content, also set a status message or aria-busy on the real container, such as Loading your applications. Put the status message in a role status region present from load.
- Remove aria-busy with the Skeletons, and announce when the content has loaded or failed.
- Anything inside a Skeleton is hidden too. Hidden focusable content can be reached with the keyboard but has no name or role, and hidden text is never read.

## Focus

Skeleton is not focusable and has no keyboard interaction. Focus stays where it was when content replaces the Skeletons.

## Reduced motion

When the user prefers reduced motion, the shimmer highlight and its animation are removed and only the `bg/skeleton` fill stays. Nothing extra is needed from you.

## Text resize

Build Skeleton layouts with the same responsive classes as the real layout, so they reflow with it at 400 percent zoom and narrow widths.

## Right to left

The shimmer follows the direction set by VeliProvider (language dv). Use logical utilities so the composition mirrors, and size text lines to the Dhivehi line height.
