# Badge

<DocsTab id="overview">

A badge shows a short status, a category or a count at a glance. Use it next to the item it describes, in tables, cards, lists and headings, so people can see where things stand without reading a sentence. Badges are labels only: people can't click, select or remove them.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/badge.tsx"
  storybook="https://storybook.veli.design/?path=/docs/components-badge--docs"
/>

## When to use

### Use a badge when

- A short status needs to be seen at a glance, such as Approved, Pending or Rejected.
- Items in a list, table or card need a category or type.
- A count of new or unread items belongs next to a control or a heading. Use the counter.
- A person or service needs a presence indicator, such as the status dot on an avatar.

### Don't use a badge when

- People can select or remove the label. Use Tags.
- People should act on it, such as opening or filtering something. Use a button or a link.
- The message needs a sentence or explains what to do. Use Alert, which has a title and a description.
- The message is short-lived feedback after an action. Use Toast.

<DocsAnatomy>

1. **Container**

   the outer shape. It sets the height, padding, corner radius and the appearance colours. It is not interactive. In code it is Badge, rendered as a span.

2. **Leading icon**

   an optional 16px icon before the label, 12px at size sm. It is decorative, so screen readers skip it. Counters and dots never show it. In code it is leadingIcon.

3. **Label**

   the status or category text, on one line. It truncates with an ellipsis when the badge runs out of room. In code it is the Badge children.

4. **Count**

   in counter mode a number replaces the label. Values above max show as max+, such as 99+. In code it is count and max. Counters only.

</DocsAnatomy>

## Content guidelines

### One or two words

Name the state or the category in 1 or 2 words, so the badge reads at a glance. The row or card around it already names the item.

| Do        | Don't                                                                            |
| :-------- | :------------------------------------------------------------------------------- |
| Approved  | Application approved by officer (4 words; the row already names the application) |
| In review | Your application is waiting for review by an officer (a sentence)                |

### Sentence case

Capitalise the first word only. Don't use all caps or title case.

| Do        | Don't                |
| :-------- | :------------------- |
| In review | IN REVIEW (all caps) |

### No punctuation

Don't add full stops, colons or exclamation marks, and don't put a field label inside the badge.

| Do   | Don't                                             |
| :--- | :------------------------------------------------ |
| Paid | Paid! (exclamation mark)                          |
| Paid | Status: Paid (colon and a label inside the badge) |

### Status, not action

A badge says what something is, not what to do. Actions belong in a button.

| Do            | Don't                                                            |
| :------------ | :--------------------------------------------------------------- |
| Action needed | Upload documents (an instruction in a label people can't act on) |

### Status words and intents

Use the shared status words, and give each word the same intent everywhere. Never recolour a status for one service.

| Status        | Intent   | Use it when                                                                                                       |
| :------------ | :------- | :---------------------------------------------------------------------------------------------------------------- |
| Draft         | neutral  | An application is started but not submitted                                                                       |
| Submitted     | info     | The agency has received it but not started checking                                                               |
| In review     | info     | The agency is checking it                                                                                         |
| Action needed | warning  | The person must do something before it can continue                                                               |
| Approved      | positive | The agency has said yes                                                                                           |
| Rejected      | danger   | The agency has said no                                                                                            |
| Cancelled     | neutral  | It was stopped before a decision                                                                                  |
| Expired       | warning  | A licence, permit, document, payment link or draft is no longer valid                                             |
| Paid          | positive | The full amount has been received                                                                                 |
| Unpaid        | cautious | A payment is due but its deadline has not passed                                                                  |
| Overdue       | danger   | A payment or task has passed its deadline                                                                         |
| Pending       | cautious | The service can't yet say whether an application is submitted or in review, or a payment is waiting to go through |

Pair the badge with the detail people need next to it, such as the date and reference number for Submitted, the reason for Rejected, or the amount and deadline for Unpaid.

| Do                                 | Don't                                                                                |
| :--------------------------------- | :----------------------------------------------------------------------------------- |
| In review                          | Processing (not a shared status word; use In review)                                 |
| Approved, with the positive intent | Approved, with the green intent (green is a category colour with no success meaning) |

### Presence words

Keep Online, Away, Busy and Offline for whether a person or a service is available, never for an application, payment or document. Show Online with positive, Away with cautious, Busy with danger and Offline with neutral.

### Numbers in counters

Show counters in digits only and cap them at 99+. Put the subject next to the counter or in its accessible name, such as 5 notifications, and give the exact count in the accessible name or a detail view.

| Do  | Don't                                                              |
| :-- | :----------------------------------------------------------------- |
| 5   | five (a word)                                                      |
| 99+ | 5 new (words belong in the accessible name or next to the counter) |
| 99+ | 12840 (a wide counter)                                             |

Hide the counter when the count is zero, unless zero means something to people.

### Fees

Write Free when a service never charges, and No fee when a fee usually applies but not to this person.

| Do     | Don't                       |
| :----- | :-------------------------- |
| Free   | MVR 0 (looks like an error) |
| No fee | N/A (says nothing)          |

### Dhivehi labels

Badge has no built-in text: labels, counts and status dot names all come from your content. Write Dhivehi labels natively rather than translating word for word, and keep them as short as the English. Pass Dhivehi aria-label values for dots and counters too, such as އޮންލައިން for Online.

## Intents

Badge has eleven intents. The first six carry a status meaning. The other five are category colours with no status meaning. Choose by meaning, not by colour. In code, intent defaults to neutral.

  width="2400"
  height="1984"
  caption="The eleven intents, each in outline, subtle and emphasis."
/>

| Intent   | Meaning                                                                     | Examples                  |
| :------- | :-------------------------------------------------------------------------- | :------------------------ |
| neutral  | The default. States and metadata with no judgement                          | Draft, Offline            |
| info     | Worth noticing, no action needed                                            | New, In review            |
| positive | Success and completed states                                                | Approved, Paid, Online    |
| cautious | Waiting, where nothing is wrong yet                                         | Pending, Away             |
| warning  | Needs attention before it becomes a problem                                 | Expiring soon, Incomplete |
| danger   | Errors, failures and blocked states                                         | Rejected, Failed, Busy    |
| magenta  | Category colour, no status meaning                                          |                           |
| indigo   | Category colour, no status meaning                                          |                           |
| brand    | Category colour in the Veli brand teal, for labels about the product itself |                           |
| green    | Category colour, no status meaning. Not the same as positive                |                           |
| lime     | Category colour, no status meaning                                          |                           |

- Use category colours to tell groups apart. Keep category colours and status intents apart within one set of badges.
- Colour only adds to the word. The label always says the status in text.

## Appearances

Every intent comes in three appearances. In code, appearance defaults to outline. From most to least emphasis: emphasis, subtle, outline.

<DocsFigure
  src="/images/docs/badge/badge-appearances-1.webp"
  darkSrc="/images/docs/badge/badge-appearances-1-dark.webp"
  alt="Three info badges with a leading icon and the text Label: outline with a blue border and no fill, subtle with a light blue background, and emphasis with a solid blue background and white text."
  width="2400"
  height="536"
  caption="Outline, the default, subtle and emphasis."
/>

- Use **outline**, a border with no fill, for metadata and long lists of badges.
- Use **subtle**, a tinted background, for statuses that should stand out in a row.
- Use **emphasis**, a solid background with inverted text, for the one status that matters most on a view.

Use one appearance and one size for badges that sit together, such as a column in a table, and let the intent carry the difference. All three appearances keep a 1px border (transparent on subtle and emphasis), so they are the same size.

| Size         | Height    | Icon | Use it for                                                                 |
| :----------- | :-------- | :--- | :------------------------------------------------------------------------- |
| md (default) | 28        | 16   | Most layouts: cards, page headers and table rows with comfortable spacing  |
| sm           | 20        | 12   | Dense tables, inside other components such as Tags, and next to small text |
| xs           | 8 x 8 dot | None | Next to an avatar or a name where a label would crowd the layout           |

The xs dot has no label or icon and ignores children. Give it an aria-label. Keep one size within a group of badges.

## Counter

The counter is a numeric pill for unread items, notifications and results. In code, pass counter or count; passing count turns counter mode on. In Figma, use BadgeCounter.

<DocsFigure
  src="/images/docs/badge/badge-counter-1.webp"
  darkSrc="/images/docs/badge/badge-counter-1-dark.webp"
  alt="Five counter examples: 5 in an outline danger md circle, 42 in an outline info sm pill, 99+ in an outline neutral md pill for a count of 128, 7 in an emphasis danger sm circle, and a red 5 counter sitting on the top end corner of a round bell icon button."
  width="2400"
  height="520"
  caption="Counters at md and sm, a capped count and a counter on an icon button."
/>

- A counter shows a number only. Put the subject next to it or in the accessible name.
- Values above max show as max+. The default max is 99, so 128 shows as 99+. Keep max at 99 unless the layout needs fewer digits.
- One digit fills the minimum width and shows as a circle. More digits grow the pill.
- Counters never show a leading icon.
- When a counter sits on an icon, put the icon in a button or another padded control. A bare icon leaves too little room and the counter covers the glyph.

## Leading icon

An optional leading icon before the label reinforces the status. The label must still make sense without it. Use a 16px icon at md and a 12px icon at sm. Vary status icons by shape for each intent, not only by colour. Labels, not icons, carry the meaning, so the icon is hidden from screen readers.

## Behaviour

- **Not interactive**: a badge is a span. It takes no focus and has no hover or pressed state. Wrap it in a button or a link when it should act.
- **Width and truncation**: a badge hugs its label and stays on one line. It never grows wider than its container; the label truncates with an ellipsis.
- **Counter cap**: a count above max shows as max+. The minimum width keeps one digit a circle; more digits grow the pill.
- **Counter on an icon button**: place the counter 2px outside the top end corner of the icon button (-top-0.5 -end-0.5) and hide it from screen readers with aria-hidden. Put the count in the button's aria-label. In Dhivehi the counter moves to the top left.
- **Status dot on an avatar**: place the dot 2px inside the bottom end corner of the avatar (bottom-0.5 end-0.5) with a 2px ring in the surface colour (ring-2 ring-bg-surface-base), so it stays visible on any photo. Add the ring in the layout; the component has none.
- **Empty values**: never render an empty badge. Show a defined value or hide the badge.

- In Dhivehi the layout mirrors. The leading icon sits on the right of the label, and badges in a row run right to left.

- In Figma, design Dhivehi screens with BadgeDv. It has the same appearances, intents and sizes as Badge. Counters and dots use BadgeCounter in both languages.

## Accessibility

- Label badges expose their text through the rendered label.
- `size="xs"` status dots are `aria-hidden` unless you pass `aria-label` or `aria-labelledby`.
- Counter badges should include `aria-label` when the count is not clear from visible text alone.
- When a counter overlays an icon button, put the count in the button’s `aria-label` and mark the badge `aria-hidden`.
- Badge is a non-interactive `span` by default. Wrap it in a button or link when it should be actionable.

## RTL and Language

In RTL, the leading icon and label follow `dir`. Localized label copy is fine; status dots still need an `aria-label` in the active language.

How the badge works with screen readers and colour, and what you still need to do. A badge is static text, so most of the work is in the label and the accessible names you pass.

## Screen readers

- Assistive technology reads the label text, so it must make sense on its own. Write status words that stand alone, such as In review, not a colour or a code.
- The leading icon is hidden from assistive technology.
- A status dot (xs) is hidden from assistive technology unless it has an aria-label. Give every dot that carries meaning an aria-label in the active language, such as Online or އޮންލައިން.
- Add an aria-label to a counter when the number alone is unclear, such as 5 notifications.
- When a counter sits on an icon button, put the count in the button's aria-label, such as Notifications, 5 unread, and mark the badge aria-hidden, so the count is announced once. Don't name only the icon, such as Bell.

## Count changes

When a count updates while the page is open, announce the change through a polite live region elsewhere on the page. Don't make the badge itself a live region.

## Focus

Badges are not in the tab order and have no focus ring. Don't add tabindex to a badge. If a badge should open or filter something, use a button or a link instead.

## Contrast

- Label and count text meets 4.5:1 in every intent and appearance. Measured in Storybook on the base surface, it is 7.3:1 or more in light and dark themes.
- Intent colour supports the label but never replaces it. A status dot needs visible text nearby or an aria-label.
- A status dot is a graphic that carries meaning, so it needs 3:1 against what is behind it. Only emphasis dots reach this (7.3:1 or more on the base surface). Outline and subtle dots measure below 2:1, so use the emphasis appearance for dots, as the Storybook examples do.
- On a photo, keep the 2px ring in the surface colour around the dot.

## Target size

A badge is not a target. A counter on an icon needs the icon inside a padded control, such as an icon button, so the counter doesn't cover the glyph or the hit area.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction, so the icon, the order of badges and the counter position mirror automatically. Pass Dhivehi labels and Dhivehi aria-label values yourself: the badge has no built-in text.
