# Button

<DocsTab id="overview">

A button starts an action: it submits a form, saves changes, confirms a step or opens a modal. Use it when people need to do something on the current view. Four intents set its emphasis and meaning, and it covers destructive, icon-only, disabled and loading actions. To go to another page, use Link.

## When to use

### Use a button when

- People trigger an immediate action on the current view: submit, save, confirm or open a modal.
- The action must work the same with keyboard, touch and screen readers.
- The action can become disabled or busy while it runs.
- You need a compact icon-only action that has an accessible name, such as close or edit in a toolbar.

### Don't use a button when

- The action navigates to another page. Use Link, or a button rendered as a link (as="a" with href) when it must look like a button.
- You switch between views of equal weight. Use Tabs.
- More than one primary action would compete on the same view. Keep one primary and give the other buttons the secondary intent or a lower appearance.
- The control stays on or off. Use Switch or Checkbox.

1. **Container**

   The button root. It is pill shaped, takes its padding from the size, and shows the hover, pressed, focus and disabled styling. In code it is Button.

2. **Leading icon**

   Optional. A 12 to 20px icon before the label, inside a fixed icon box. It is decorative, so screen readers skip it. In code it is an icon in children, before the label.

3. **Label**

   The action text and the accessible name. Verb first, on one line. In code it is the children.

4. **Trailing icon**

   Optional. An icon after the label, usually a direction arrow. Pass the mirrored arrow in Dhivehi. In code it is an icon in children, after the label.

</DocsAnatomy>

## Content guidelines

### Verb first

Start every label with a verb that says what happens when it is pressed. Describe exactly what the action does, no more and no less.

| Do            | Don't                                                                    |
| :------------ | :----------------------------------------------------------------------- |
| Save changes  | OK (says nothing about the result)                                       |
| Pay and renew | Licence renewal (reads as a heading, not an action)                      |
| Delete file   | Click here to book your appointment now (too long and starts with Click) |

Never label an action OK, Yes, No, Submit, Dismiss, Click here or Here on its own.

### Sentence case

Capitalise the first word and proper nouns only. No all caps and no title case.

| Do         | Don't                   |
| :--------- | :---------------------- |
| Save draft | Save Draft (title case) |

### Keep it short

Use 1 to 3 words. If a label wraps, shorten it or let the button group wrap instead. Clarity wins over the limit: Sign in with eFaas is 4 words and approved.

| Do               | Don't                                   |
| :--------------- | :-------------------------------------- |
| Book appointment | Click here to book your appointment now |

### Punctuation

No full stops and no exclamation marks. Add an ellipsis, the single … character, only when the action opens a further step that needs more input, such as Rename… opening a dialog. Never add one to a loading label.

| Do      | Don't                                                              |
| :------ | :----------------------------------------------------------------- |
| Rename… | Submit application! (exclamation mark)                             |
|         | Saving... (ellipsis on a loading label, typed as three full stops) |

### While the action runs

Keep the label while the action runs and set isPending. Don't relabel it Loading, Please wait or Paying…, and don't add a Spinner beside it. Say what is happening and the outcome in a separate status message.

| Do                           | Don't                                                              |
| :--------------------------- | :----------------------------------------------------------------- |
| Pay and renew, shown pending | Paying… (changes the name and adds an ellipsis to a loading label) |

### Standard labels

Name the same action the same way across a journey and across services.

| Do                 | Don't                                    |
| :----------------- | :--------------------------------------- |
| Continue           | Proceed (use Continue for the next step) |
| Sign in with eFaas | Login (use Sign in)                      |
| Pay MVR 250        |                                          |
| Save and continue  |                                          |

- **Continue, Back, Next**: Continue moves to the next step of a form or journey. Back returns to the previous step without losing answers. Next and Previous are only for paging through content, never for form steps.
- **Save**: Save stores changes and stays on the page. Save and continue only when the button both saves and moves on. Save draft when people can leave and come back later.
- **Submit**: only with what is being submitted, on the final step: Submit application. Never Submit on its own.
- **Send**: for messages, feedback, codes and documents: Send code again.
- **Pay**: for the action that takes money, with the amount when it is known: Pay MVR 250.
- **Apply and Renew**: Apply for something new, Renew to extend something people already have.
- **Delete and Remove**: Delete when something is destroyed and can't be got back: Delete draft. Remove when it leaves a list but still exists: Remove file. Destructive actions use the danger intent.
- **Edit and Change**: Edit opens something for editing: Edit address. Change sits next to each answer on a check your answers page, named Change phone number.
- **Download and Upload**: Download a file with its type and size when known: Download receipt (PDF, 120 KB). Upload sends a file from the device: Upload passport photo.
- **Cancel, Close and Back**: Cancel stops a task and discards what was entered. Close hides something with no unsaved input. When the task itself is a cancellation, label the safe choice Keep: Keep appointment beside Cancel appointment.
- **Done and Confirm**: Done finishes a task with nothing left to save. Confirm only with an object: Confirm payment. A confirmation button repeats the title's verb and object: title Delete this draft application?, button Delete draft.
- **Search, Clear and Try again**: Search runs a search. Clear says what it clears: Clear filters. After a failure, Try again repeats the action; never Retry.
- **eFaas**: write eFaas with a lower case e. The sign-in button reads Sign in with eFaas. In Dhivehi the name is written އީފާސް.

### Destructive actions

Label a destructive action with the verb and the thing that will be lost: Delete draft application, Withdraw application, Remove passport-copy.pdf. Use the danger intent only on the button that performs the destructive action, with a clear Cancel next to it.

| Do          | Don't                       |
| :---------- | :-------------------------- |
| Delete file | Continue with intent danger |

### Repeated buttons

The accessible name contains the visible label, ideally starting with it. When the same label repeats, add the object after it.

| Do                                                            | Don't                          |
| :------------------------------------------------------------ | :----------------------------- |
| Visible Edit beside the home address, named Edit home address | Several buttons all named Edit |

Name a Copy button with its object, Copy reference number, and confirm with a short status message: Reference number copied.

### No links in buttons

Don't put links inside a button label.

### Built-in text

Button has one built-in string: Loading (ލޯޑުވަނީ in Dhivehi), the name of the progressbar shown while it loads. There is no prop to change it, so write icon-only names that still read well followed by Loading, such as Delete file.

### Dhivehi labels

Write Dhivehi labels natively rather than translating word for word or spelling English words in Thaana. Keep them as short as the English, because Dhivehi lines are taller and phrases are often longer.

## Intents

Four intents set the emphasis and meaning of a button. Choose by what the action does, not by colour. In code, intent defaults to primary.

- **Primary**: the main action on a view. Use one per view. In a form, make the submit button primary: Enter in a field submits through the button with type="submit", whatever its intent.
- **Secondary**: supporting actions beside a primary, such as Cancel or Back. Secondary uses neutral colours so it never competes.
- **Danger**: destructive or irreversible actions. Name what is lost and use danger only on the button that does it, with Cancel beside it.
- **Accent**: highlighted or promotional actions, such as a featured service. Accent is fill only. Use it at most once per page.

- **Fill**: a solid background. Highest emphasis, for the single most important action in a group.
- **Transparent**: a tinted background with no border. Medium emphasis, for secondary actions that still need a surface.
- **Ghost**: no background until hover. Lowest emphasis, for inline and toolbar actions.

Rank buttons in a group by appearance, fill then transparent then ghost, within one intent. Don't mix intents to rank buttons. Ghost and transparent buttons keep the full height of their size, so rows of mixed appearances stay aligned.

## Icon only

An icon-only button is a square button with a single icon, fully rounded. In code, set iconOnly and give the button an aria-label. In Figma, turn showLabel off.

<DocsFigure
  src="/images/docs/button/button-icononly-1.webp"
  darkSrc="/images/docs/button/button-icononly-1-dark.webp"

- The icon is the same size as in a text button of that size: 20, 20, 16, 16 and 12px from xl to xs. Button sizes an icon placed directly in its children, so pass it without its own size.
- The accessible name comes from aria-label, written verb first, as a visible label would be.
- Prefer a text label when space allows. Use icon-only for a compact, well-known action such as close or edit in a toolbar, never for an action such as Renew licence.

## Icons

Place icons before or after the label as children. An icon beside a visible label is decorative, so hide it from assistive technology. Prefer a visible label when space allows.

| Do                                    | Don't                                 |
| :------------------------------------ | :------------------------------------ |
| Download receipt with a download icon | An icon-only button for Renew licence |
| Close as an icon-only button          |                                       |

## High contrast

Secondary buttons have a high-contrast version for coloured surfaces at step 800 or darker, such as the Alert high-contrast colours or a brand surface. It is off by default. In code, set highContrast on each secondary button; in Figma, turn on onHighContrast.

- Only secondary fill, transparent and ghost have a high-contrast version. Don't put primary, danger or accent buttons on a high-contrast surface. Use secondary fill with high contrast as the main action.
- Don't use high contrast on mid tones, from 500 to 700. Light text fails there; use a light surface and the normal buttons.
- Don't use high contrast on light surfaces, such as gov.mv accent or a 100 to 300 tint. Use the normal secondary buttons.
- On a brand surface at step 800 or darker, both high-contrast secondary buttons and an accent fill button work. Accent fill keeps the main action on brand; high contrast keeps the actions neutral.
- In Dark mode the teal brand surface stays at step 700. A high-contrast secondary fill button still works there (3.3:1 against the surface, label 18:1), but transparent and ghost labels drop to 3.3:1, so use secondary fill on teal brand.
- A high-contrast Alert uses a secondary fill main action and secondary ghost for the second action and the close button, all with high contrast on. On mobile the actions stack and fill the width.
- High contrast changes only the colours, focus ring and disabled look. Size, state, label and icons stay the same. Let the setting set the colours; don't recolour buttons by hand, because overrides break in Dark mode and drift from code.
- In code, the high-contrast colours need the Veli tokens package 0.10.0 or later.

## Behaviour

- **Press feedback**: pressing shows the pressed background and a ripple that grows from the pointer position, tinted per intent and appearance. The pressed background stays while the ripple plays. The whole button responds, including padding and icons.
- **Loading**: isLoading and isPending are the same. Both ignore repeat presses. The button keeps its label as its accessible name and keeps its width; the label is hidden while the Spinner shows. A pending submit button also stops native form submission, including Enter from a field. Keep the visible content mounted while loading so the width and accessible name stay.
- **Width and wrapping**: text buttons hug their label. Long labels wrap and the button grows; icon-only buttons stay square. Use a w-\* class for a fixed or full width.
- **Submit buttons**: set type="submit" on the button that submits a form. Button defaults to type="button", so Enter in a single-line field submits only through a submit button. Keep it enabled until pressed, then show it pending with its label until the request finishes.
- **Disabled**: avoid disabled buttons. Keep the action enabled and say what is missing when it is pressed, or show the reason as text beside it: Upload your ID card to continue. Don't disable submit before the form is valid, and don't explain the reason in a Tooltip.
- **Link mode**: when navigation must look like a button, render it as a link with as="a" and href. A disabled or loading link button keeps its anchor and label but drops href. Never navigate from a plain button.
- **Destructive actions**: never delete or cancel from a single tap with no way back. Give every destructive action a confirmation step, such as a Modal, or an Undo.

## Disabled and Loading

Use `isDisabled` for an unavailable action. Use `isLoading` while work is in progress: it displays a spinner, marks the button busy, and prevents repeat activation while retaining keyboard focus. React Aria's `isPending` uses the same loading behavior. Set either prop while the operation is pending, then clear it when the operation completes or fails.


Loading submit and reset buttons cancel their native action, including Enter from a form field. This does not block submission through another button or a programmatic form submission; guard the form handler too when the entire form must stay locked.

## Upgrading existing buttons

- Loading buttons now retain focus and use `aria-disabled` and `data-pending` instead of native `disabled`. Update any `:disabled` selectors used specifically for loading; use `isDisabled` when the action must leave the tab order.
- `isPending` now shows the same spinner as `isLoading`, with the original label kept as the accessible name.
- Spacing follows the Figma content and padding model. Check tightly sized action groups and translated labels. Explicit `h-*` and `size-*` classes still override the default dimensions.
- `size={null}` resolves to `md`. Accent buttons always use the fill appearance.

## Navigation

Use `as="a"` and `href` for a destination. `as` selects the HTML element; `intent` and `appearance` still control its styling. The same Button styles wrap a native anchor, so Enter follows the link and Space retains browser scrolling behavior. Modifier clicks, middle clicks, context-menu actions, `target`, `rel`, and `download` keep native link behavior.

<div className="preview mb-4 rounded-lg border border-base-subtle bg-surface-raised p-4">
  <ButtonNavigationDemo client:visible />

```tsx
<Button
  as="a"
  href="https://www.mindco.mv/"
  target="_blank"
  rel="noopener noreferrer"
>
  Open Link
</Button>

<Button as="a" href="/account" isDisabled>Account</Button>
<Button as="a" href="/account" isLoading>Account</Button>
```

Disabled and loading links retain their anchor and label, remove `href`, and block activation. Loading links retain focus and their label width. Use `ButtonProps<'a'>` for typed navigation wrappers; the default `ButtonProps` remains the action-button type. Link mode accepts an anchor ref and React Aria Link interaction props; button-only form attributes are excluded. Its `slot` belongs to React Aria LinkContext; it does not consume ButtonContext action slots.

### Client routing

A native anchor can use client routing. For links that only need navigation, pass `navigate` and (when needed) `useHref` to `VeliProvider`. `routerOptions` belongs to that provider contract. Map push/replace and route prefixes in the application; Veli does not infer framework options. This path has no automatic router prefetch.

```tsx
<Button as="a" href="/account">
  Account
</Button>
```

Declare React Aria's application-level `RouterConfig.routerOptions` before passing options, and handle them in `navigate`. For example, a Next App Router provider can use `navigate={(href, options) => options?.replace ? router.replace(href, options) : router.push(href, options)}`. The Pages Router equivalent uses `next/router` and its `router.push(href, undefined, options)` / `router.replace(href, undefined, options)` signatures. Configure `useHref` for the browser-visible base path if the application requires one, including external/hash exclusions. Prefer the Next Link composition below when Next should own that mapping.

Pass routing to the existing `VeliProvider`, even if the application has an outer React Aria provider. Veli bridges its hook and component router contexts; an independently installed hook provider can otherwise use a different context.

### Router Link composition

Pass the router's real Link through `render`. Put its destination and framework options on that Link; Button's `href` is optional when you supply a renderer. This preserves typed routes and avoids framework dependencies or router adapters in Veli.

Both Next App Router and Pages Router use `next/link`:

```tsx
'use client';

import NextLink from 'next/link';
import { Button } from '@veli-design/react/button';

<Button
  as="a"
  isLoading={isSaving}
  render={(props) => <NextLink {...props} href="/account" prefetch={false} replace />}
>
  Account
</Button>;
```

Next owns base paths, URL objects, typed routes, and options such as `scroll`, `onNavigate`, and Pages Router `as`, `shallow`, and `locale`. App Router `prefetch={false}` disables viewport and hover prefetch. Pages Router disables viewport prefetch but still prefetches on hover. Prefetch runs in production.

TanStack Router keeps its registered route, params, and search types directly on its Link:

```tsx
import { Link as RouterLink } from '@tanstack/react-router';

<Button
  as="a"
  render={(props) => (
    <RouterLink {...props} to="/posts/$postId" params={{ postId: '42' }} preload="intent" />
  )}
>
  Read post
</Button>;
```

React Router uses the same pattern:

```tsx
import { Link as RouterLink } from 'react-router';

<Button as="a" render={(props) => <RouterLink {...props} to="/account" replace />}>
  Account
</Button>;
```

Keep framework-specific behavior on the router Link. For downloads, use a native `<Button as="a" href="/report.pdf" download>`. A router’s `reloadDocument` option may navigate programmatically and lose browser download behavior; it is not a substitute for a native download link. React Router data prefetch depends on its data/framework setup; `BrowserRouter` alone does not provide it.

### Composition contract

`render` owns navigation and URL mapping. Button supplies React Aria link interactions, styles/content, and the anchor ref; a surrounding `VeliProvider` does not navigate or rewrite the renderer's destination. To use provider routing, omit `render`.

Return one anchor-producing component and forward the generated props/ref/children. Set its destination after spreading `props`. Do not wrap a Button in a Link or nest anchors. Navigation `onClick` runs on the native anchor click and can cancel navigation with `event.preventDefault()`. Use it for activation analytics or cancellation (or Next's `onNavigate`). React Aria's keyboard `onPress` completes on keyup; a router can unmount the link after Enter's earlier native click. Do not use `onPress` to navigate a second time.

While disabled, loading, or pending, Button renders a destination-free anchor itself and **does not call `render`**. This also applies to inherited `LinkContext` state and prevents the router Link from starting prefetch. Requests started before becoming inactive are not canceled. Put shared classes, accessible names, `target`, and test IDs on Button so they also apply to the inactive anchor. Root replacements retain pending focus, but refs receive normal detach/attach notifications; do not assume DOM identity across state changes. The action-button renderer is unchanged.

React Aria Link styled as a Button is the semantic model. Veli uses `useLink` so disabled/loading mode can retain an anchor ref and pending focus; React Aria Components Link changes to a span when disabled. Both modes share Button styling and content. A general `Slot`/`asChild` API would still need the same event, ref, and inactive-state contract.

Official references: [React Aria Link](https://react-aria.adobe.com/Link), [Next App Link](https://nextjs.org/docs/app/api-reference/components/link), [Next Pages Link](https://nextjs.org/docs/pages/api-reference/components/link), [TanStack custom links](https://tanstack.com/router/latest/docs/framework/react/guide/custom-link), and [React Router Link](https://reactrouter.com/api/components/Link).

Button uses the shared compact button spinner by default while keeping its size, accessible label and pending behavior. Use `loadingIndicator` only when supplying a custom decorative pending visual.

```tsx
<Button isPending={isSaving} onPress={handleSave}>
  Save changes
</Button>
```

## API Reference

Button uses React Aria [`Button`](https://react-aria.adobe.com/Button) for actions and [`useLink`](https://react-aria.adobe.com/Link/useLink) for navigation. Select the semantic mode with `as`; the mode determines the required props, native element, and ref type.

### Rendering modes and types

| Mode       | Native contract                                                                                            |
| :--------- | :--------------------------------------------------------------------------------------------------------- |
| Action     | Omit `as` or use `as="button"`. Renders `<button>` with a `Ref<HTMLButtonElement>`. `href` is unavailable. |
| Navigation | Use `as="a"` with `href` or an explicit `render`. Renders `<a>` with a `Ref<HTMLAnchorElement>`.           |

`ButtonProps` defaults to the action type. Use its generic argument for navigation wrappers or components that accept both modes:

```tsx
import type { ButtonProps } from '@veli-design/react/button';

type ActionProps = ButtonProps;
type NavigationProps = ButtonProps<'a'>;
type EitherModeProps = ButtonProps<'button' | 'a'>;
```

An icon-only button requires `iconOnly: true` and a non-empty `aria-label` or `aria-labelledby` in either mode. The types enforce the label requirement; development builds also check it. A spinner-only button needs an accessible name when it has no children.

### Veli Button

These props apply in both modes. Defaults describe a standalone Button; supported React Aria context props can supply inherited values.

| :----------------- | :--------------------------------------------------------- | :--------------- | :--------------------------------------------------------------------------------------------------------------------------- |

These interaction props are available in both modes except where noted. The React Aria [Button](https://react-aria.adobe.com/Button) and [Link](https://react-aria.adobe.com/Link) references cover their respective event behavior, subject to Veli's exclusions below.

| Prop                          | Type                                   | Default | Description                                                                                                                          |

| `onPressEnd`                  | `(event: PressEvent) => void`          | -       | Called when a press ends, including cancellation. Does not necessarily mean activation.                                              |
| `onPressUp`                   | `(event: PressEvent) => void`          | -       | Action mode only. Called when a press is released over the control, even if it started elsewhere.                                    |

### Composition and render state

The optional `render` callback replaces the native root while retaining the generated content, styling, event handlers, and ref. It has a mode-specific signature:

| Mode       | Callback type                                                                                          | Default           |
| :--------- | :----------------------------------------------------------------------------------------------------- | :---------------- |
| Action     | `(props: ComponentPropsWithRef<'button'>, state: ButtonRenderProps) => ReactElement`                   | Native `<button>` |
| Navigation | `(props: ComponentPropsWithRef<'a'>, state: LinkRenderProps & { isPending: boolean }) => ReactElement` | Native `<a>`      |

`ComponentPropsWithRef` and `ReactElement` are React types; `ButtonRenderProps` and `LinkRenderProps` are React Aria Components types. The generated `props` include children, ref, events, and accessibility attributes. Preserve them on the replacement root. In link mode, the renderer runs only while enabled; see [Composition contract](#composition-contract).

The callback receives these observed states. They are not props for forcing visual state:

| State            | Type      | Modes      | Meaning                                                                                     |
| :--------------- | :-------- | :--------- | :------------------------------------------------------------------------------------------ |
| `isHovered`      | `boolean` | Both       | A mouse or pen is hovering over the control.                                                |
| `isPressed`      | `boolean` | Both       | A pointer or keyboard press is in progress.                                                 |
| `isFocused`      | `boolean` | Both       | The control has focus.                                                                      |
| `isFocusVisible` | `boolean` | Both       | The control should show its keyboard focus indicator.                                       |
| `isDisabled`     | `boolean` | Both       | Action disabled state. Navigation renderers run only while enabled, so receive false.       |
| `isPending`      | `boolean` | Both       | Action pending state. Navigation renderers run only while enabled, so receive false.        |
| `isCurrent`      | `boolean` | Navigation | `aria-current` marks the current destination. `false` and `'false'` do not mark it current. |

### Unsupported props and forms

| Prop or form                                                            | Support or alternative                                                                                             |
| :---------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------- |
| Function-valued `children`                                              | Supply `ReactNode` children; use `render` for root composition.                                                    |
| Function-valued `className`, or `style`                                 | Supply string `className` values. Inline style props are excluded.                                                 |
| `disabled`                                                              | Use `isDisabled`; anchors have no native disabled behavior.                                                        |
| `variant`                                                               | Use `intent` and `appearance` for styling.                                                                         |
| `asChild`, `elementType`, or `as="link"`                                | Select the supported mode with `as="button"` or `as="a"`; use the mode-specific `render` contract for composition. |
| `onPressUp` / `onPressChange` in navigation mode                        | Not supported by the installed `useLink` hook. Use `onPressStart` / `onPressEnd`, or read `isPressed` in `render`. |
| `href` without `as="a"`                                                 | Select navigation mode explicitly.                                                                                 |
| Button form attributes in navigation mode                               | Use an action Button for submit/reset behavior.                                                                    |
| `isHovered`, `isPressed`, `isFocused`, `isFocusVisible`, or `isCurrent` | Read callback state; use `aria-current` for the current destination and a ref or `autoFocus` to move focus.        |

## Accessibility

- Give each button a clear action label. Icon-only and spinner-only buttons require `aria-label` or `aria-labelledby`.
- Decorative icons should be hidden from assistive technology with `aria-hidden="true"`.
- Enter and Space activate a focused action button. Use `onPress` so keyboard, touch, and pointer actions share one handler. In link mode, Enter follows the destination and Space retains browser scrolling behavior.
- Keep focus on the action while asynchronous work is pending, and announce the outcome using an accessible status or error message.
- The loading spinner stops rotating when reduced motion is requested. A spinner is not a substitute for a meaningful action name.

## RTL and Language

Use `VeliProvider language="dv"` to set Dhivehi language and RTL direction. Button typography follows the language, and the icon/label order follows `dir`. Load the fonts described in [Typography](/foundations/typography/).

Button does not translate labels or mirror arbitrary children. Localize the label and accessible name, and use a left-facing forward arrow in RTL. Direction-neutral icons, such as Plus, stay unchanged.

How the button works with keyboards, screen readers and touch, and what you still need to do. Button renders a native button, or a native link in link mode.

## Keyboard

| Key            | Action                                                                             |
| :------------- | :--------------------------------------------------------------------------------- |
| Tab            | Moves focus to the next enabled button                                             |
| Shift + Tab    | Moves focus to the previous enabled button                                         |
| Enter or Space | Activates the focused button                                                       |
| Enter          | Follows a button in link mode (as="a"). Space doesn't activate it, as for any link |

Disabled buttons are skipped. Loading buttons stay in the tab order.

## Screen readers

- The visible label is the accessible name. Write it verb first so it makes sense on its own.
- Icon-only buttons need aria-label or aria-labelledby with verb-first text: Delete file, not Trash icon. In code the types require it and development builds warn when it is missing.
- A Tooltip is never the only name of an icon-only button. Use the same text in its Tooltip.
- An icon beside a visible label is decorative: hide it with aria-hidden. On an icon-only button the icon carries the meaning, so the button needs a name.
- While loading, the button sets aria-busy and aria-disabled, so assistive technology announces the wait while focus stays on the button. Its progressbar is named Loading (ލޯޑުވަނީ in Dhivehi). On an icon-only button that name joins the accessible name, so write names that read well followed by Loading.
- A loading button with no visible content still needs aria-label.
- Announce the result of the action in a status or error message.

- Keyboard focus shows the Veli focus ring: a 2px gap in `bg/surface/base`, then a 2px ring in `border/focus`, following the pill shape. It sits outside the button, so focusing doesn't change its size or move neighbours.
- The ring appears on keyboard focus only, not on a pointer press.
- In forced colours mode the ring becomes a 2px outline.
- On high-contrast surfaces the ring keeps a transparent gap so the surface shows, and stays visible.
- Never remove the ring or replace it with a colour change alone.

## Disabled

isDisabled blocks every interaction and removes the button from the tab order, so people using a keyboard or screen reader may not find it or learn why it is unavailable. Prefer an enabled button that explains what is missing when pressed, or show the reason as text next to it. Don't use a Tooltip to say why a control is disabled.

## Target size

Every size is at least 24px tall, which meets the 24 x 24 minimum target size. Size md is 44px tall, the recommended size for primary actions on touch screens. Use sm and xs only in dense desktop toolbars and table rows.

## Contrast

Use the intent and appearance tokens as they are, and the high-contrast treatment on strong colours. Don't override them with custom colours. The button label carries the meaning; don't rely on the colour of the button or the surface alone. On a high-contrast surface at step 800 in Light mode, high-contrast secondary buttons measure at least 16:1 for fill text and icons, 6.3:1 for transparent, 5.2:1 for ghost and 5.2:1 for the focus ring.

## Reduced motion

When people prefer reduced motion, the press scale and the ripple are removed and the loading spinner stops rotating. Nothing extra is needed from you.

## Right to left

Set the language with VeliProvider (language dv). It sets the direction and the language, so screen readers can switch to a Dhivehi voice and the built-in Loading name is read in Dhivehi. Pass Dhivehi labels and accessible names yourself, and pass a left arrow for a forward action.
