# PasswordInput

<DocsTab id="overview">

A password input lets people type a password with its characters hidden, and show it with the eye button to check what they typed. Use it to sign in and to create or change a password, where it can also show the rules a new password must meet and whether two entries match. Citizens sign in with eFaas, so a password input is for staff systems and services that still keep their own password.

## When to use

### Use a password input when

- People sign in to a staff system or a service that still keeps its own password.
- People create a new password and need to see the rules as they type.
- Policy requires people to repeat a new password, and the form must say whether the two match. Otherwise prefer one field with the eye button.
- The value is secret and should stay hidden from people nearby, such as a PIN. For a PIN that is not a sign-in password, set autoComplete to off or a specific token so password managers don't offer to save it.

### Don't use a password input when

- The value isn't secret, such as an email address or a National ID number. Use [Input](/docs/components/input/).
- People enter a one-time code sent by SMS. Use [Input](/docs/components/input/) with autoComplete one-time-code and inputMode numeric, so people can check the digits as they copy them.
- People look something up, such as a service or a form. Use [Search](/docs/components/search/).
- People turn a sign-in option on or off, such as staying signed in. Use a [Checkbox](/docs/components/checkbox/), not ticked by default, and never offer it on a kiosk.
- Citizens sign in to a service. Use a [Button](/docs/components/button/) labelled Sign in with eFaas.

<DocsAnatomy>

1. **Label**

   Names the field. Body sm regular at sm and md, body md regular at lg, in `text/base/DEFAULT`. In code it is label.

2. **Required indicator**

   An asterisk in `text/danger/muted`. The field is required by default; set showRequiredIndicator to false to hide the asterisk and keep it required. In code it is isRequired.

3. **Text**

   Dots for the password, or the placeholder in `text/base/inactive` before people type. The value is `text/base/strong`. It always reads left to right in the Latin font. In code it is placeholder and value.

4. **Field**

   36, 44 or 52 high with a 10 radius (`radius/field`), in Dhivehi too. The default appearance has an underline; outline has a border. In code it is appearance.

5. **Visibility toggle**

   An eye button that shows or hides the password. Screen readers announce it as Show password or Hide password. In code it is showVisibilityToggle, on by default.

6. **Requirement icon**

   A circle in `icon/danger/subtle` while a rule is not met, a check in a circle in `icon/success/subtle` once it is. 16 px. In code it is requirements.

7. **Requirement**

   Each rule, in `text/danger/muted` until it is met, then `text/success/muted`. Caption regular, body sm at lg. In code it is requirements.

8. **Status icon**

   Replaces the visibility toggle while the field is invalid. Decorative, so screen readers skip it. In code it is isInvalid.

9. **Message**

   Feedback below the field, such as Passwords do not match or Passwords match, in `text/danger/muted` or `text/success/muted`. It replaces the helper text. In code it is errorMessage, or feedbackMessage with feedbackTone.

</DocsAnatomy>

## Content guidelines

### Labels

Name what goes in the field: Password to sign in, New password and Confirm password when people create one. Use the same words across the service, in sentence case with no colon.

| Do               | Don't                                                                 |
| :--------------- | :-------------------------------------------------------------------- |
| Password         | Enter your password: (an instruction with a colon)                    |
| New password     | Re-type Password (title case and a different word for the same thing) |
| Confirm password |                                                                       |

### Placeholder

The built-in placeholder is Enter Password, in title case. Pass placeholder="Enter password", or leave the placeholder out. Never put the password rules in the placeholder; show them with requirements.

### Requirement labels

Write each rule as a short condition in sentence case that people can check as they type. Don't use the built-in rule labels, which are in title case and force character mixes.

| Do                               | Don't                                                      |
| :------------------------------- | :--------------------------------------------------------- |
| At least 12 characters           | 8+ Character (symbol, singular and title case)             |
| Not a commonly used password     | Special Character (title case, and a forced character mix) |
| Not found in a known data breach |                                                            |

### Match messages

Use these messages under the confirm field.

| Do                     | Don't                                                     |
| :--------------------- | :-------------------------------------------------------- |
| Passwords match        | Password match (singular subject with a plural verb form) |
| Passwords do not match | Invalid input. (vague, with a full stop on one sentence)  |

### Error messages

Say what is wrong and how to fix it. Never say which part of a sign-in was wrong, and never repeat a password in a message, a URL, a log or analytics.

- Missing: Enter a password, or Enter your password on a sign-in form.
- Too short: Password must be 12 characters or more.
- Too common: Choose a password that is harder to guess.
- Mismatch: Passwords do not match. Enter the same password in both fields.
- When sign-in is locked after failed attempts, say when people can try again and how to get help now.

Show the same message next to the field and in the error summary at the top of the page, with the same words.

| Do                                                                     | Don't                                                                                               |
| :--------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------- |
| Check your username and password and try again, or reset your password | The password is incorrect. Try again or reset it. (tells someone guessing that the username exists) |
| Enter your password                                                    | Invalid (gives no fix)                                                                              |

### Built-in strings

| String             | English           | Dhivehi             |
| :----------------- | :---------------- | :------------------ |
| Placeholder        | Enter Password    | ޕާސްވޯޑް ލިޔުއްވާ   |
| Eye button, hidden | Show password     | ޕާސްވޯޑް ދައްކާ     |
| Eye button, shown  | Hide password     | ޕާސްވޯޑް ފޮރުވާ     |
| Default rule       | 8+ Character      | 8+ އަކުރު           |
| Default rule       | Lowercase letter  | ކުޑަ އަކުރެއް       |
| Default rule       | Uppercase letter  | ބޮޑު އަކުރެއް       |
| Default rule       | Number            | ނަންބަރެއް          |
| Default rule       | Special Character | ޚާއްޞަ ކެރެކްޓަރެއް |

Override the placeholder with placeholder. The eye button names can't be changed. Replace the default rules by passing your own requirements, with labels in English and Dhivehi.

### Dhivehi copy

Write Dhivehi labels, rules and messages natively rather than translating word for word, and keep them as short as the English.

- Use **lg** (52 high) for short forms that need to stand out, such as sign-in. The label and password use Body md, and messages and rules use Body sm.

## Behaviour

- **Show and hide**: the eye button switches the value between dots and text. Control it with isRevealed and onRevealedChange, or start with defaultRevealed. Turn the button off with showVisibilityToggle set to false.
- **Live checklist**: with requirements set, each rule turns green with a check as soon as it is met. On an empty field the checklist stays hidden unless showRequirementsWhenEmpty is set. requirements set to true uses the default rules; you can also pass your own array of rules.
- **Choose your own rules**: ask for a minimum length, such as at least 12 characters, and block common or breached passwords on the server. Don't require arbitrary character mixes, such as a symbol, a capital and a number: pass your own requirements instead of the defaults.
- **Success**: once every rule is met, the field turns green on its own. Set isSuccess to show it yourself, such as on a confirm field that matches.
- **Message row**: the checklist or feedback row takes the place of the description and error text. When requirements show, put any other help above the field or in the form text.
- **While invalid**: a decorative status icon replaces the eye button, so people can't reveal the password they need to fix. The message shows below the field.
- **Required by default**: isRequired is true. Set isRequired to false for an optional password. There is no Optional text and no info tooltip.
- **Real checks stay on the server**: the checklist only checks the rules you pass. Keep password validation in your app logic; the exported helpers getDefaultPasswordRequirements, resolvePasswordRequirements and arePasswordRequirementsMet evaluate the same rules outside the field.
- **Autocomplete and paste**: set autoComplete so password managers can fill the field: current-password, the default, for signing in and new-password for creating or changing a password. Give the field a stable name and never block paste.
- **Width**: the field fills the width it is given. Constrain the parent, not the field.
- **Text size on phones**: text in a field should be at least 16px on phones, so iOS Safari doesn't zoom the page on focus. Password input text is 14px at sm and md and 16px at lg, so use size lg on phones.

## Tokens

Fill, line and text per state. Line is the underline in the default appearance and the border in outline. Names leave out the `components/text-input/` prefix.

| State        | Fill                             | Line                                                                         | Text and icon                                                                                                       |
| :----------- | :------------------------------- | :--------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------ |
| Default      | `bg-default`                     | Underline `stroke-default` 1.5; outline border `stroke-default` 1            | Placeholder `text/base/inactive`; eye button `icon/base/muted`                                                      |
| Hover        | `bg-hover`                       | Underline `stroke-hover` 1.5; outline border `stroke-hover` 1.5              | As default                                                                                                          |
| Active       | `bg-pressed`                     | Underline `stroke-pressed` 2; outline border `stroke-pressed` 2              | Password `text/base/strong`; eye button `icon/base/muted`                                                           |

## Requirement checklist

Pass `requirements` to render the built-in checklist, which updates live as the user types. Pass `true` for the default rules, or an array of `PasswordRequirement` objects to customize them. The checklist stays hidden on an empty field unless `showRequirementsWhenEmpty` is set. When every rule is met, the field applies success styling.

<div className="preview mb-4 rounded-lg border p-4">
  <PasswordInputRequirementsDemo client:visible />
</div>

```tsx

```

The helpers `getDefaultPasswordRequirements`, `resolvePasswordRequirements`, and `arePasswordRequirementsMet` are exported alongside the component for validating values outside the field.

## Match and mismatch

Use `feedbackMessage` with `feedbackTone` for confirm-password copy. `feedbackTone="success"` (or `isSuccess`) applies the success shell. A checklist or feedback row replaces the helper and error text.

## Accessibility

- Give the field a visible `label`, or pass `aria-label` / `aria-labelledby` when the label is hidden.
- `description` is the accessible helper. On error, `errorMessage` replaces it.
- The visibility toggle is in the tab order and uses a localized Show/Hide password name. When the field is invalid, the toggle is replaced by a decorative status icon that is not a tab stop.

## RTL and Language

In RTL, the label, helper, checklist, feedback, and field chrome follow `dir`. Padding mirrors, and the visibility control or invalid icon sits on the trailing edge. The entered value stays left-to-right with English typography metrics, aligned to the start edge, so passwords keep their character order. On `lang="dv"` pages, labels, helpers, default requirement copy, and the empty placeholder use Dhivehi; the value keeps English type.

How the password input works with keyboards and screen readers, and what you still need to do. It is built on the React Aria TextField with a native password input and a native button for the eye.

## Keyboard

| Key            | Action                                           |
| :------------- | :----------------------------------------------- |
| Tab            | Moves focus to the field, then to the eye button |
| Shift + Tab    | Moves focus back                                 |
| Enter or Space | On the eye button, shows or hides the password   |
| Enter          | In the field, submits the form                   |

While the field is invalid, the status icon that replaces the eye button is not a tab stop. A disabled field and its eye button are skipped.

## Screen readers

- **Label**: give every field a visible label. When there is none, pass aria-label or aria-labelledby.
- **Eye button**: named Show password or Hide password, so screen readers say what it will do, and it reports its pressed state. The names switch to Dhivehi in a Dhivehi form.
- **States**: required, disabled, read-only and invalid states are exposed to assistive technology.
- **Description and error**: description and errorMessage are linked to the field and read with it.
- **Status icon**: the icon that replaces the eye button on an invalid field is decorative and hidden. The message below carries the meaning.
- **Checklist**: link the checklist to the field so it is read on focus, and announce met rules politely at most once per change, never on every keystroke. See "Missing or unverified": Storybook does not link it yet.

## Focus

Keyboard focus shows a 2px ring in `border/focus` with a 2px offset around the field, and around the eye button when it has focus. It appears for keyboard focus only; a click shows the active state instead, with the pressed fill and a 2px underline or border. With the ring, the outline appearance drops its border, so the two never stack. Clicking anywhere in the field, outside the text, moves focus to the text.

## Colour alone

Each rule is written out as text with its own icon, a check or a circle, so met and unmet rules never rely on red and green alone. Match and success also show the green fill and a message or ticked rules, because the success line on its own is low contrast in light mode.

## Target size

The eye button measures 20 x 20, below the 24 x 24 minimum target. See "Missing or unverified".

## Contrast

In both modes, on `bg/surface/base` and `bg/surface/raised`: the password is 10.3:1 or more (10.8:1 or more on the success fill), the label 7.3:1 or more, the checklist and messages 4.9:1 or more, the eye button 4.6:1 or more, the checklist and status icons 3.0:1 or more, and the default line 3.06:1 in Light and 3.23:1 in Dark against the page. Against the field fill the line is 3.23:1 in Light but 2.83:1 in Dark, below 3:1. The placeholder (2.3:1 to 2.7:1) never holds anything people need. In light mode the success line is 2.5:1 to 2.8:1 against the page, so success always comes with the green fill and a message.

## Right to left

Set the language with VeliProvider (language dv). The label, messages and checklist follow the direction; the password stays left to right. Pass Dhivehi labels and your own rule labels yourself.
