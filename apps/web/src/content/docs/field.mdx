# Field

<DocsTab id="overview">

Field is the set of parts that give a form control its label, help text and error message when the control has no built-in ones, such as a radio group, a checkbox group or a custom control. The other Veli fields (Input, Text area, Select, Combobox, Date picker, Password input and Drop zone) carry the same three parts as props, so the content rules on this page apply to them too.

## When to use

### Use Field parts when

- A RadioGroup or CheckboxGroup needs a visible label, description or error message. Put FieldLabel, FieldDescription and FieldError inside the group.
- A custom or native control needs a label and messages. Use Field, FieldLabel and FieldControl, or useFieldControlProps.
- You need to show form library validation errors. Render them through FieldError inside the group.
- One question needs several controls, such as island, house name and road for an address. Use FieldSet with FieldLegend, so the legend names the whole set.

### Don't use Field parts when

- The control already has label, description and errorMessage props, such as Input, Text area, Select or Combobox. Use those props instead.
- The group already passes description or errorMessage. Use the props or the parts, not both, or the text shows twice.
- You only need to name a single RadioGroup or CheckboxGroup. Don't wrap it in FieldSet; put FieldLabel inside the group.
- The help is too long for one sentence. Use a [popover](/docs/components/popover/) opened by a button next to the label.

<DocsAnatomy>

1. **Label**

   names the group or control. For a radio or checkbox group, write the question being asked. Put it inside the group so it names the group. In code it is FieldLabel.

2. **Info icon**

   a 16 x 16 icon button that opens a tooltip with a short hint. Input, Select and Text area add it after the label with infoTooltip. FieldLabel has none, so a group uses a popover next to the label for longer help.

3. **Optional**

   built-in text after the label, in `text/base/subtle`. It switches to Dhivehi with the language and hides when the field is required. In code it is isOptional.

4. **Description**

   one line of help under the label. In code it is FieldDescription.

5. **Required indicator**

   the asterisk after the label, in `text/danger/muted`. It is hidden from screen readers; the group is announced as required instead. In code it is isRequired, and showRequiredIndicator hides it.

6. **Error message**

   says what is wrong and how to fix it, at the end of the group. Several errors show as a list. In code it is FieldError, with children or errors.

</DocsAnatomy>

For custom layouts, Field also has layout parts: Field, FieldSet, FieldLegend, FieldGroup, FieldContent, FieldTitle, FieldSeparator and FieldControl.

## Content guidelines

### Labels

A label names the value people give, in sentence case and with no colon. A RadioGroup or CheckboxGroup label asks the question, ending with a question mark. Every field needs a visible label; never let a placeholder be the label.

| Do                                    | Don't                                                     |
| :------------------------------------ | :-------------------------------------------------------- |
| ID card number                        | Enter your ID card number (an instruction, not the value) |
| Where will you collect your passport? | Atoll: (colon)                                            |
| How should we contact you?            | Collection point: (a noun with a colon)                   |
|                                       | PLAN (all caps)                                           |

Call the card a National ID card in running text and the number on it an ID card number in labels. Never write NIC, NID, IC or National Identity Card Number.

### Descriptions

Add help only when the label needs context, as one short sentence with no full stop. Say where to find the value, what format it takes or why it is needed. When a value has a format people may not know, give an example starting with For example. For a CheckboxGroup, write Choose all that apply. Don't put links in a description.

| Do                                      | Don't                                                                       |
| :-------------------------------------- | :-------------------------------------------------------------------------- |
| The number on the front of your ID card | Please fill in this field carefully. (please, adds nothing and a full stop) |
| For example, A900101                    | Click here to find your number (a link and Click here)                      |
| Choose all that apply                   |                                                                             |

For help that is too long for a description, use a [popover](/docs/components/popover/) opened by a button next to the label.

### Error messages

Say what is wrong and how to fix it, in the words of the label. For a missing answer, start with Enter for text and Choose for choices. Use one sentence with no full stop, no please and no blame.

| Do                                    | Don't                                             |
| :------------------------------------ | :------------------------------------------------ |
| Enter your ID card number             | Invalid input (generic, gives no fix)             |
| Choose where to collect your passport | Please choose a plan. (please and a full stop)    |
| Enter a date after 21 October 2026    | You forgot to enter your name (blames the person) |

Show the same wording next to the field and in the error summary, one message per field at a time: the one that blocks progress first. After a submit with errors, show the error summary, titled There is a problem.

Messages from a form library or schema follow the same rules. FieldError shows them as written and lists them when there are several.

### Required and optional

Mark whichever is rarer in the form. Use isOptional on FieldLabel to add Optional when most fields are required, or isRequired to show the asterisk when most are optional, with a line such as Fields marked with \* are required.

| Do                                 |
| :--------------------------------- |
| Phone number Optional              |
| Fields marked with \* are required |

### Legends

Write a FieldLegend as the question when the set asks one thing, or as a short heading for a set of separate questions. On a page that asks one question, the legend can be the page heading.

| Do                    | Don't                                        |
| :-------------------- | :------------------------------------------- |
| What is your address? | Section 2 (says nothing about the questions) |
| Contact details       |                                              |

### Dhivehi copy

FieldLabel has one built-in string, Optional, which switches to އިޚްތިޔާރީ when the language is Dhivehi and can't be reworded. Pass every label, description and error in English and Dhivehi yourself. Write Dhivehi natively rather than translating word for word, and keep it as short as the English.

## Behaviour

- **Inside the group**: put FieldLabel inside the RadioGroup or CheckboxGroup it names. A label beside the group can't name it.
- **Pass the group state**: pass the group's isRequired and isDisabled render state to the FieldLabel inside it, so the asterisk and the muted style match the group.
- **Show errors after submit**: show FieldError after people submit, not while they type. Veli Form shows errors without blocking submission, so set the errors from your submit handler.
- **Errors stand alone**: RadioGroup, CheckboxGroup and the shared fields replace the description with the error while invalid, so write errors that make sense without the help. This applies to the description prop; a FieldDescription child is not removed for you, so hide it yourself while the group is invalid. A single Checkbox keeps both.
- **Several errors**: FieldError renders several errors as a list and renders nothing when there are none. Text you pass as children wins over the errors value.
- **Form libraries**: pass React Hook Form, TanStack Form or Standard Schema errors into FieldError errors.
- **Props or parts, not both**: don't pass description or errorMessage on a group that also uses FieldDescription or FieldError.
- **Wrapping**: labels and messages wrap; never truncate them. They follow the layout and orientation of the group they sit in, and must stay readable at 200 percent text size.

## Validation

When the group is invalid, render `FieldError` inside it. Do not also pass `errorMessage` on the group, or the text shows twice. The same rule applies to `description` vs `FieldDescription`.

<div className="preview mb-4 rounded-lg border p-4">
  <FieldValidationDemo client:visible />
</div>

```tsx
<RadioGroup isInvalid>
  <FieldLabel>Plan</FieldLabel>
  <Radio value="basic">Basic</Radio>
  <Radio value="pro">Pro</Radio>
  <FieldError>Choose a plan to continue.</FieldError>
</RadioGroup>
```

`FieldError` also accepts an `errors` value from React Hook Form, TanStack Form, or Standard Schema issues. See [Forms](/patterns/forms/).

## API Reference

Field primitives are thin wrappers over React Aria [`Label`](https://react-spectrum.adobe.com/react-aria/Label.html) and [`Text`](https://react-spectrum.adobe.com/react-aria/Text.html). Inside `RadioGroup` / `CheckboxGroup`, those slots wire `aria-labelledby` and `aria-describedby` on the group.

### FieldLabel

| Prop                    | Type                   | Default     | Description                                                  |
| :---------------------- | :--------------------- | :---------- | :----------------------------------------------------------- |
| `size`                  | `'sm' \| 'md' \| 'lg'` | `'md'`      | Label typography size.                                       |
| `isOptional`            | `boolean`              | `false`     | Shows localized Optional. Hidden when the field is required. |
| `isDisabled`            | `boolean`              | Field state | Overrides disabled label styling for built-in controls.      |
| `isRequired`            | `boolean`              | Field state | Overrides required state for built-in controls.              |
| `showRequiredIndicator` | `boolean`              | `true`      | Shows `*` when a surrounding `Field` is required.            |
| `htmlFor`               | `string`               | -           | Optional override for standalone label association.          |

React Aria [`Label`](https://react-spectrum.adobe.com/react-aria/Label.html#props) props pass through except:

| Prop        | Why                             |
| :---------- | :------------------------------ |
| `className` | Replaced by Veli label classes. |
| `style`     | Not supported.                  |

### FieldDescription

| Prop         | Type                   | Default     | Description                                              |
| :----------- | :--------------------- | :---------- | :------------------------------------------------------- |
| `size`       | `'sm' \| 'md' \| 'lg'` | `'md'`      | Helper typography size.                                  |
| `isDisabled` | `boolean`              | Field state | Overrides disabled helper styling for built-in controls. |

Renders React Aria `Text` with `slot="description"`.

### FieldError

| Prop     | Type                   | Default | Description                                                             |
| :------- | :--------------------- | :------ | :---------------------------------------------------------------------- |
| `errors` | `unknown`              | -       | Form-library or Standard Schema errors. Ignored when `children` is set. |
| `size`   | `'sm' \| 'md' \| 'lg'` | `'md'`  | Error typography size.                                                  |

Renders React Aria `Text` with `slot="errorMessage"`. Multiple `errors` messages render as a list. Renders nothing when there is no message.

### Other exports

`Field`, `FieldSet`, `FieldLegend`, `FieldGroup`, `FieldContent`, `FieldTitle`, `FieldSeparator`, `FieldControl`, and `useFieldControlProps` support native or custom controls.

## Accessibility

- Put `FieldLabel` inside the group. A label beside the group cannot name it.
- Prefer a visible `FieldLabel` over `aria-label` when the label is shown.
- Use either group `description` / `errorMessage` props or `FieldDescription` / `FieldError` children — not both.
- Do not wrap a single radio or checkbox group in `FieldSet` / `FieldLegend` only to name it.

## RTL and Language

Label, description, and error follow the page `dir`. With `isOptional`, FieldLabel shows the localized Optional string from the Veli language (`en` / `dv`).

How the field parts name and describe controls for assistive technology, and what you still need to check.

## Screen readers

- FieldLabel is a React Aria label. Inside a RadioGroup or CheckboxGroup it names the group, so screen readers read the question when people enter it.
- FieldDescription and FieldError are linked to the group as its description, so they are read after the name.
- FieldSet and FieldLegend use the native fieldset and legend, so the legend names every control in the set.
- The required asterisk and Optional sit outside the label text, so neither is part of the accessible name. isRequired is still announced as required, but Optional is not announced.
- Prefer a visible FieldLabel to aria-label. Use aria-labelledby only when a visible heading already names the group.

## Errors

Show every error in text, next to the control and in the error summary. Never show an error with colour, an icon or a border alone.

## Custom controls

When you wire a custom control with FieldControl or useFieldControlProps, check in the accessibility tree that it has the right role, the FieldLabel text as its name, and the description and error as its description.

| Description        | 4.96:1 light, 5.23:1 dark |

Values are on `bg/surface/base` and `bg/surface/raised`; the description figures are measured on the page in Storybook. Optional is below the 4.5:1 text minimum. Disabled text is exempt. Use the field text tokens as they are. Don't override them with custom colours.
