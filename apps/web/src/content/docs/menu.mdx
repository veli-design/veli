# Menu

<DocsTab id="overview">

A menu shows a short list of actions or choices when people open it from a button. Use it to keep secondary actions out of the way, such as editing, downloading or deleting a record. A menu can group items into sections, keep a selection, show descriptions and shortcut hints, and open nested submenus.

  source="https://github.com/veli-design/veli/blob/main/packages/react/src/menu.tsx"

## When to use

### Use a menu when

- A button opens a compact list of secondary actions, such as edit, download or delete.
- People choose one or more options from a popover, such as a view or a sort order.
- The actions need sections, separators, descriptions, shortcut hints or nested submenus.

### Don't use a menu when

- One main action can be shown directly. Use a Button instead of hiding it in a menu.
- People fill in a form value from a list. Use Select.
- The options take people to other pages. Use Link or Tabs.
- People switch between persistent content panels. Use Tabs.
- The panel holds fields or other controls. Use Popover.

   A 16px check in `icon/primary/default` on a selected item, when the menu allows selection. Turn it on with isSelected; showSelectionSlot keeps its space when the item is not selected. In code: selectionMode and selectedKeys on Menu.

   A 16px icon at the end, 20 at lg. In code: endIcon.

6. **Submenu caret**

   Shows that the item opens a nested menu. It points to the side the submenu opens on. In code: MenuSubmenuTrigger draws it.

7. **Description**

   An optional second line in `text/base/muted`. In code: description.

   A 1px line between groups, 12 in from each side. In code: MenuSeparator.

In code, a menu is MenuTrigger (the button that opens it), MenuPopover, Menu and its items. Figma has no menu popover component; build it from the frame on the Menu page.

## Content guidelines

### Item labels

Start with a verb and keep labels to 1 to 3 words, in sentence case, with no full stop. Put any detail in the description, not the label: menus are scanned, not read.

| Do            | Don't                                                        |
| :------------ | :----------------------------------------------------------- |
| Rename        | Record deletion (a noun, not an action)                      |
| Download copy | Click here to rename this file (long, and names the gesture) |
| Delete record | Copy download (vague)                                        |
| Edit details  | Edit Details (title case)                                    |

Never label an item OK, Yes, No, Submit or Dismiss on its own. Use the standard verbs: Edit or Change, Delete or Remove, Download or Upload, Sign out.

### Destructive items

Name the verb and the thing that will be lost: Delete record, not Delete. Use the danger intent, and don't rely on colour alone to show the risk. A danger item opens a confirmation Modal, or acts at once and offers Undo in a Toast. Never delete anything from a single press with no confirmation or undo.

| Do            | Don't  |
| :------------ | :----- |
| Delete record | Delete |

### Follow-up actions

Add an ellipsis only when the item opens a further step that needs more input, such as a dialog. Use the single ellipsis character, never three full stops.

| Do                  | Don't                         |
| :------------------ | :---------------------------- |
| Rename…             | Download copy… (acts at once) |
| Change appointment… | Rename... (three full stops)  |

### Descriptions

Write a description as one short sentence with no full stop, such as the reason an item is disabled.

| Do                                     | Don't                                                                                                                 |
| :------------------------------------- | :-------------------------------------------------------------------------------------------------------------------- |
| Requires admin permissions             | This option is not available to you at this time because you do not have the right permissions. (too long for a menu) |
| Update labels, metadata and visibility |                                                                                                                       |

### Section titles

Use a noun for the group.

| Do      | Don't                                                     |
| :------ | :-------------------------------------------------------- |
| View    | Change how you view things (a sentence, not a group name) |
| Account |                                                           |

### Icon-only triggers

Give an icon-only trigger an accessible name that starts with a verb and names the object when several exist. Add context when the trigger repeats on every row, and use the same text in its Tooltip.

| Do                                    | Don't                                      |
| :------------------------------------ | :----------------------------------------- |
| Show actions for record WP-2026-04817 | More (repeats on every row with no object) |
|                                       | Three dots (names the icon)                |

### Shortcuts

Write shortcuts with the key names as printed and a plus sign between them: Ctrl + K, Shift + Tab. Shortcut hints only show the keys; they don't register the shortcut.

### Dhivehi copy

Menu has no built-in visible text. Pass every label, description, section title and accessible name in English and Dhivehi. Write Dhivehi natively and keep it as short as the English.

- **Sections and separators**: group related actions with MenuSection and MenuSeparator.
- **Descriptions, icons and shortcuts**: give an item more context with description, startIcon, endIcon and shortcut. Shortcut takes a string, an array of keys or a KbdGroup.
- **Selection**: for a choice that stays selected, such as a view or a sort order, set selectionMode single on Menu with selectedKeys. The chosen item shows a check, and the other items keep its space. Use selectionMode multiple for several choices.
- **Submenus**: nest a MenuItem and a MenuPopover in MenuSubmenuTrigger. The caret is drawn for you.
- **Links**: an item with href renders as a link. Prefer Link when the options take people to other pages.

## Behaviour

- **Opening**: the menu opens from its trigger, 8 below it by default, and closes when people choose an item, press Escape or click outside.
- **Choosing**: an item runs its action and closes the menu. To keep the menu open after choosing, such as in a selection menu, set closeOnSelect to false on the item.
- **Width**: items fill the popover width. The popover is at least 224 wide and grows with the longest item. Cap the popover width with className when descriptions are long.
- **Submenus**: submenus stay open while the pointer moves diagonally toward them.
- **Overscroll**: keep scrolling inside the menu so it does not move the page behind.

<div className="preview mb-4 rounded-lg border p-4">

```tsx
<MenuTrigger>
  <Button intent="secondary" appearance="transparent">
    Actions
  </Button>
  <MenuPopover>
    <Menu>
      <MenuItem startIcon={<PencilSimple size={16} />}>Edit</MenuItem>
      <MenuItem startIcon={<DownloadSimple size={16} />} shortcut={['⌘', 'E']}>
        Export
      </MenuItem>
      <MenuSeparator />
      <MenuItem intent="danger" startIcon={<Trash size={16} />}>
        Delete
      </MenuItem>
    </Menu>
  </MenuPopover>
</MenuTrigger>
```

Pass `selectionMode` on `Menu` for single or multiple selection. Nest a trigger `MenuItem` and `MenuPopover` in `MenuSubmenuTrigger` for submenus — the caret is automatic and flips with reading direction.

## Appearances

Items support size, danger intent, description, icons, and shortcut. Shortcuts use [Kbd](/docs/components/kbd/): a string, a string array, or a custom `KbdGroup`.

## API Reference

Menu is a Veli composition on React Aria [`Menu`](https://react-spectrum.adobe.com/react-aria/Menu.html). Props below follow that stack.

### MenuItem

Veli-specific props for each item.

| Prop          | Type                              | Default     | Description                                             |
| :------------ | :-------------------------------- | :---------- | :------------------------------------------------------ |
| `size`        | `'sm' \| 'md' \| 'lg'`            | `'md'`      | Item height and typography.                             |
| `intent`      | `'default' \| 'danger'`           | `'default'` | Use `danger` for destructive actions.                   |
| `description` | `ReactNode`                       | -           | Secondary line beneath the label.                       |
| `startIcon`   | `ReactNode`                       | -           | Leading icon.                                           |
| `endIcon`     | `ReactNode`                       | -           | Trailing icon (separate from the submenu caret).        |
| `shortcut`    | `string \| string[] \| ReactNode` | -           | Shortcut hint; strings and arrays render as `Kbd` keys. |
| `className`   | `string`                          | -           | Classes merged onto the item.                           |

### React Aria MenuItem

React Aria’s headless [`MenuItem`](https://react-spectrum.adobe.com/react-aria/Menu.html#menuitem). These props pass through. The React Aria docs cover the rest, except the exclusions below.

| Prop            | Type      | Default | Description                                                      |
| :-------------- | :-------- | :------ | :--------------------------------------------------------------- |
| `id`            | `Key`     | -       | Item key for selection and `onAction`.                           |
| `isDisabled`    | `boolean` | `false` | Disables the item.                                               |
| `closeOnSelect` | `boolean` | -       | Whether selecting closes the menu; defaults per `selectionMode`. |

| `href`          | `string`  | -       | Renders the item as a link.                                      |

## Accessibility

- Give the menu an accessible name with `aria-label` or `aria-labelledby` when the trigger label alone is not enough.
- Disabled items use `isDisabled` and expose `aria-disabled`.
- Keyboard: arrows move focus; Home and End jump to the edges; typeahead matches labels; Enter or Space activates; Escape closes; Arrow Right / Left open and close submenus (mirrored in RTL).

## RTL and Language

`MenuPopover` inherits `lang` and `dir` from `VeliProvider`, so item alignment and the submenu caret follow reading direction. Shortcut keys keep `lang="en"` so modifier glyphs stay stable in Dhivehi.

How the menu works with keyboards, screen readers and assistive settings. Menu is built on React Aria Menu and follows the menu button pattern, with one difference for disabled items.

## Keyboard

| Key                        | Action                                                      |
| :------------------------- | :---------------------------------------------------------- |
| Enter, Space or Down arrow | On the trigger, opens the menu with focus on the first item |
| Up arrow                   | On the trigger, opens the menu with focus on the last item  |
| Down arrow and Up arrow    | Move between items                                          |
| Home and End               | Jump to the first and last item                             |
| Letters                    | Jump to the next item that starts with them                 |
| Enter or Space             | Activates the focused item                                  |
| Right arrow                | Opens a submenu. Left arrow in Dhivehi                      |
| Left arrow                 | Closes a submenu. Right arrow in Dhivehi                    |
| Escape                     | Closes the menu and returns focus to the trigger            |
| Tab                        | Closes the menu and moves on                                |

## Screen readers

- The trigger reports that it opens a menu and whether it is open. The menu is labelled by its trigger.
- Items are menu items. In a single selection menu they are radio items, and in a multiple selection menu checkbox items, each reporting whether it is checked.
- Disabled items report that they are disabled, but the arrow keys skip them, so keyboard and screen reader users may not hear them or their descriptions. The menu button pattern keeps disabled items focusable. Don't hide the only explanation of a disabled action inside the menu.
- Give the menu an aria-label when the trigger does not name the choices clearly, and give a MenuSection with no title an aria-label so the group is announced.
- Give an item whose content is not plain text, such as one with an icon or description, a textValue or aria-label.
- Leading icons are decorative when the label says the same thing.
- On phones, visually hidden Dismiss buttons at the start and end of the popover let screen reader users close it without Escape. They read Dismiss in English on Dhivehi pages.

## Focus

When the menu opens from the keyboard, focus moves into it and the arrow keys move between items. The focused item takes the `menu/hover` fill, not a ring. Focus returns to the trigger when the menu closes. The trigger button keeps its own focus ring while the menu is closed.

## Controls inside items

Don't put buttons, links, fields or other controls inside a menu item. Make each action its own item, or use a Popover for a small panel of controls.

## Target size

Every size is above the 24 x 24 minimum target. Size md is 44 high, which already meets the 44 recommended for touch. Size lg is 52 high and gives touch and roomy layouts more space. Size sm is 36 high, for dense tools on desktop.

## Contrast

Default labels meet contrast on every fill in Light and Dark. In Dark, default descriptions fall below 4.5:1 on hover and pressed, and danger labels fall just below on the pressed fill. Don't put information people need in descriptions: put it in the label or on the page. Never show risk with colour alone.

## Selected state

The selected item shows a check mark, a shape that survives forced colours, not colour alone.

## Zoom

Keep the menu inside the viewport at high zoom, and cap its width when descriptions are long.

## Right to left

VeliProvider sets the language and direction of the menu popover. It flips the submenu caret and the Left and Right arrow keys in Dhivehi. Pass every label in Dhivehi yourself.
