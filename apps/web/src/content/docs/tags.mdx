# Tags

<DocsTab id="overview">

Tags show a group of short labels that people select as filters, remove, or follow as links, such as the departments a search covers or the filters applied to a list. Use Tags for a few short choices and for active filters. Use Badge for a status, and Checkbox or Select when the options are long or many.

In code, compose a TagGroup with Tag children for a collection with arrow-key navigation, selection or removal. Use TagButton for a standalone action or filter, and TagDropdown for a selected filter that has sub-labels.

## When to use

### Use tags when

- You need a compact set of categories or metadata, such as the departments a search covers.
- People select, remove or follow labelled items, such as filters, saved topics or related pages.
- There are a few short choices. Set selectionMode to single or multiple when the tags act as filters or choices.
- You show the filters applied to a list. Put them above the results as removable tags in a group labelled Active filters, and add a Clear filters button when more than one is set.

### Don't use tags when

- A label only shows a status and there is nothing to do with it. Use Badge.
- The choices need long labels or explanations, or there are many to read and compare. Use a Checkbox group, or Select for one choice from many.
- It is a required question in a form with one answer. Use Radio, not single-selection tags.
- It is the main navigation of a site or service. Keep that in the header, and use Link for navigation lists.

<DocsAnatomy>

1. **Container**

   The pill, 28 to 44 high by size, with a full radius. Fill has a background; outline has a 1px border and no background at rest. In code it is Tag inside TagGroup, or TagButton on its own.

2. **Check**

   Shows before the label on a selected tag, so selection never relies on colour alone. The same size as the icons, 10 to 16. Drawn when the tag is selected.

3. **Leading content**

   An icon, an avatar glyph or a count badge before the label. It is hidden from assistive technology, so the label text must carry its meaning. In code it is leading.

4. **Label**

   One to three words in a medium weight. The label is essential text and must never be cut off, so keep it short. Code truncates it with an ellipsis when the tag reaches its width. In code it is the Tag children, or textValue for complex content.

5. **Remove button**

   A round button with a cross, 14 to 24 by size, named Remove and the tag text, such as Remove Tourism. Shown when TagGroup has onRemove; rename it with removeButtonLabel.

6. **Label part**

   Tag with a dropdown only. The selected tag itself. Its outer corners are half the height and its inner corners are 4 (`radius/sm`).

7. **Value**

   A 1px divider and the sub-labels picked. One shows its name; two or more show the count. Regular weight; it truncates.

8. **Caret part**

   Opens the menu of this tag's sub-labels. 24 to 40 wide by size, with its own hover, pressed, focus and open states.

</DocsAnatomy>

A TagGroup adds a group label above the tags, such as Departments, and a description or error below them. In code they are label, description and errorMessage on TagGroup.

## Content guidelines

### Group label

Name what the tags are, as a short noun phrase in sentence case.

| Do                | Don't                                                                              |
| :---------------- | :--------------------------------------------------------------------------------- |
| Departments       | Select departments: (an instruction with a colon; the description says what to do) |
| Preferred channel | Tags (names the component, not the content)                                        |
| Active filters    |                                                                                    |

### Description

Write one sentence, in active words, that says how many tags people can choose. Leave off the full stop.

| Do                             | Don't                                                                                            |
| :----------------------------- | :----------------------------------------------------------------------------------------------- |
| Choose one or more departments | Please click the departments you want to see. (Please, Click and a full stop)                    |
| Choose one channel             | Only one channel can be selected at a time. (passive, uses Select for choosing, and a full stop) |

### Errors

Say what to do, starting with Choose. Check a required group when people submit, and show the error in errorMessage.

| Do                             | Don't                                                                                            |
| :----------------------------- | :----------------------------------------------------------------------------------------------- |
| Choose at least one department | Select at least one department. (Select is for naming a button in running text, and a full stop) |
| Choose at least one department | Invalid selection (doesn't say how to fix it)                                                    |

### Tag labels

Write each label as 1 to 3 words, a noun or the value itself, unique in its group. Keep labels short, parallel and in a logical order.

| Do        | Don't                                                       |
| :-------- | :---------------------------------------------------------- |
| Tourism   | Show tourism results (an action; the label names the value) |
| Malé      | TOURISM (all caps)                                          |
| In review | Tourism. (end punctuation)                                  |

### Status filters

Label status filter tags with the shared status words, the same words the Badges in the list show, such as In review or Approved. Use one term for each status everywhere.

### Remove names

Keep the built-in remove button name, Remove and the tag text. Pass removeButtonLabel only when the tag text isn't enough, such as a tag with an icon or a count, or to add the object. Write Remove, not Delete, because the item still exists.

| Do                    | Don't                              |
| :-------------------- | :--------------------------------- |
| Remove Tourism        | Remove (identical on every tag)    |
| Remove Tourism filter | X (names the icon, not the action) |

### Empty state

When a group can be empty, pass renderEmptyState with text that says what is empty and what to do, or hide the group, as you do for active filters when none are set. Never leave the built-in No tags available. When filters hide every result, say so and offer Clear filters.

| Do                                            | Don't                                                                                   |
| :-------------------------------------------- | :-------------------------------------------------------------------------------------- |
| No saved topics. Topics you save appear here. | No tags available. (generic; talks about tags, not the content, and gives no next step) |

### Link tags

Name the page a link tag opens, so the label makes sense on its own, in a screen reader, a search result or a translated page.

### Dhivehi copy

Write Dhivehi labels natively rather than transliterating, and keep them as short as the English. The built-in empty state and remove names come in Dhivehi from VeliProvider; your labels and custom remove names are yours to translate.

## Appearances

Tags come in two appearances. In code, appearance defaults to fill. Set it once on TagGroup, or on one Tag to override it.

- **Fill**: a light neutral fill. A selected tag turns charcoal with inverted text and a check.
- **Outline**: a 1px border and no fill at rest. A selected tag gets a charcoal border, a light fill and a check. It is quieter; use it for long lists of tags or filters inside cards.

Use one appearance within a group.

- **Leading content**: an icon or an avatar glyph before the label, such as for a person. It scales with the tag size and is hidden from assistive technology. In code it is leading.
- **Leading count**: a counter Badge for unread or pending items. Because leading content is hidden, also put the count in the tag text, such as visually hidden text after the label, or in textValue.
- **Removable**: a remove button after the label. In code, onRemove on TagGroup. Removal requests don't update your data: remove the keys from items in onRemove.
- **Link**: a link tag goes to another page and can't be selected or removed. Name the destination page. In code, href on Tag inside a group, or TagButton as="a" when you need native anchor behaviour, such as copying the link address.
- **Field-like group**: a label, a description and an error. The error replaces the description. In code, label, description and errorMessage on TagGroup. TagGroup doesn't validate the selection itself; derive the error from your own state.
- **Active filters**: show the filters applied to a list above the results as removable tags in a group labelled Active filters. Add Clear filters when more than one is set.

Leading content works with selection, removal and links. Don't put a status Badge in the leading slot.

## Dropdown filter

Use TagDropdown when a selected filter has optional sub-labels.

<DocsFigure
  src="/images/docs/tags/tags-dropdown-1.webp"
  darkSrc="/images/docs/tags/tags-dropdown-1-dark.webp"
  alt="Six cards. tag not selected: a plain Tourism tag with no caret. showValue off: Tourism selected with a check and a separate caret part, and no value. Open: the caret turned up. One sub-label: Tourism, a divider and Resorts, then the caret. Two or more: Tourism, a divider and the count 2. True, no sub-labels: a selected Statistics tag with no caret."
  width="2400"
  height="1392"
  caption="A tag with a dropdown, from not selected to two sub-labels picked."
/>

- Before it is selected, a tag with sub-labels is a plain tag with no caret. A selected tag without sub-labels also stays a plain tag.
- It exists only on a selected tag that has sub-labels. The caret part, or Arrow Down on the tag, opens a menu of those sub-labels with multiple selection; the menu stays open while people choose.
- After the label, the value shows the sub-label name when one is picked and the count when two or more are. It shows nothing for an empty selection. In code, renderSelection controls this summary.
- Pressing the label deselects the filter and clears its sub-labels. Clearing the sub-labels in the menu leaves the parent selected.
- Dropdown tags have no remove button. Place TagDropdown next to standalone tags, not inside a TagGroup.

| State    | When                                                | Visual change                                                                                                              |
| :------- | :-------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| Default  | No interaction                                      | Fill: `fill/bg/default`. Outline: `outline/border/default`, no fill                                                        |
| Hover    | Pointer over the tag                                | The fill darkens one step (`fill/bg/hover`). Outline: the border darkens too, with a light fill                            |
| Pressed  | While the tag is pressed                            | The fill darkens again, and the tag grows slightly (scale 1.045) with a ripple, as Button does                             |
| Focus    | Keyboard focus                                      | A 2px ring in `border/focus`, 2 away from the tag                                                                          |
| Selected | Selected in a group with selectionMode              | Charcoal fill (fill) or charcoal border with a light fill (outline), inverted or strong text, and a check before the label |
| Disabled | isDisabled on the tag or the group, or disabledKeys | Disabled fill or border and muted text. The tag can't be focused or pressed                                                |

Selection never relies on colour alone: selected tags show a check and still read in forced colours. Avoid disabled tags. Say near the group why a tag is unavailable, or leave it out.

## Behaviour

- **Select**: with selectionMode single or multiple, pressing a tag selects or clears it. Use it when the tags act as filters or choices.
- **Filter without moving focus**: when people select or remove a filter tag, update the results and the count, keep focus in the group, and announce the new count once. Keep the filters in the URL.
- **Remove at once**: remove a filter tag without a confirmation, because selecting it again undoes it. Confirm only when removing a tag deletes saved data. For other reversible removals, offer Undo in a Toast.
- **Focus after removal**: when people remove the focused tag, focus moves to the next tag, or the previous one, or the group when it is empty.
- **Validate on submit**: check a required group when people submit the form, show the error in errorMessage, and check it again as people change the selection.
- **Wrapping and truncation**: tags wrap within the available width. Tag labels are essential text and must never be cut off: keep them short, or let the group wrap. Code truncates tag text with an ellipsis at the inline end when a tag reaches its width.
- **Small screens**: put a long set of filter tags behind a Filters button that opens a Modal, and keep the active filters as removable tags above the results.

Heights use `spacing/7` to `spacing/11`; side padding `spacing/2,5` to `spacing/5`; gaps `spacing/1` to `spacing/2,5`. Tags in a TagGroup sit 8 apart (`spacing/2`) and wrap to the next line. The group label, the tags and the description sit 6 apart (`spacing/1,5`).

A tag with a dropdown adds a caret part 24, 28, 32, 36 and 40 wide by size. It sits 1 from the label part in fill and 2 (`spacing/0,5`) in outline. The divider before the value is 1 wide and 8, 8, 10, 12 and 12 high, and the value sits one gap after it. The label part has the same padding and gaps as a tag of the same size, and no remove button.

## Corner radius

Tags use `radius/full` at every size. The two parts of a tag with a dropdown have outer corners of half the height (14, 16, 18, 20 and 22 by size; 16 is `radius/2xl`) and inner corners of 4 (`radius/sm`), because a full radius on one corner squashes the small inner corners. The remove button is a circle.

Use `TagButton` for an action, or supply `isSelected` and update it in `onPress` for a controlled filter. Use `TagButton as="a"` with `href` for native navigation. ## Dropdown filters

Use `TagDropdown` when a selected filter has optional sub-labels. Your application owns parent membership. Keep `TagDropdown` mounted with `isSelected` and `onSelect` to animate between the plain filter and split dropdown. Omitting `isSelected` preserves the selected-only mode. The label clears the sub-label selection and calls `onDeselect`; the separate arrow opens the multiple-selection menu. Clearing sub-labels in the menu leaves the parent selected.

<div className="preview mb-4 rounded-lg border p-4">
  <TagsDropdownDemo client:visible />
</div>

```tsx
import { useState } from 'react';
import type { Selection } from 'react-aria-components';
import { MenuItem } from '@veli-design/react/menu';
import { TagDropdown } from '@veli-design/react/tags';

const items = [
  { id: 'forms', label: 'Forms' },
  { id: 'permits', label: 'Permits' },
  { id: 'reports', label: 'Reports' },
];

function DocumentFilter() {
  const [selected, setSelected] = useState(false);
  const [selectedKeys, setSelectedKeys] = useState<Selection>(new Set());

  return (
    <TagDropdown
      isSelected={selected}
      onSelect={() => setSelected(true)}
      label="Documents"
      items={items}
      selectedKeys={selectedKeys}
      onSelectionChange={setSelectedKeys}
      onDeselect={() => setSelected(false)}
      renderSelection={(selection) => {
        const values = items.filter((item) => selection === 'all' || selection.has(item.id));
        return values.length === 1 ? values[0].label : values.length > 1 ? values.length : null;
      }}
    >
      {(item) => <MenuItem id={item.id}>{item.label}</MenuItem>}
    </TagDropdown>
  );
}
```

`renderSelection` controls the summary: show the selected sub-label for one item, a count for two or more, and nothing for an empty selection. Dropdown tags have no remove icon. Use `defaultSelectedKeys` for uncontrolled sub-labels, and `isOpen` / `onOpenChange` when the menu's open state needs to be controlled.

## Collections

Use `selectionMode="single"` or `"multiple"` for choices. Pass `onRemove` to show remove controls, and update the collection in that callback. An existing `Tag href` remains a link in the group; link tags are neither selectable nor removable. Disable individual tags with `disabledKeys` or `Tag isDisabled`, or the whole group with `TagGroup isDisabled`.

  <TagsVariantsDemo client:visible />
</div>

```tsx
<TagGroup
  label="Departments"
  selectionMode="multiple"
  defaultSelectedKeys={['tourism', 'fisheries']}
>
  <Tag id="tourism">Tourism</Tag>
  <Tag id="fisheries">Fisheries</Tag>
  <Tag id="transport">Transport</Tag>
  <Tag id="education">Education</Tag>
</TagGroup>
```

```tsx
import { useState } from 'react';
import { Tag, TagGroup } from '@veli-design/react/tags';

function SavedTopics() {
  const [topics, setTopics] = useState([
    { id: 'documents', label: 'Documents' },
    { id: 'forms', label: 'Forms' },
  ]);

  return (
    <TagGroup
      label="Saved topics"
      items={topics}
      onRemove={(keys) => setTopics((items) => items.filter((item) => !keys.has(item.id)))}
    >
      {(topic) => <Tag id={topic.id}>{topic.label}</Tag>}
    </TagGroup>
  );
}
```

Removal requests do not update your data: remove the requested keys from `items` in `onRemove`. An empty collection shows a localized message; customize it with `renderEmptyState`.

Link keys are ignored in supplied selections and excluded from selection callbacks, including range selection and select-all. When a collection contains links, select-all reports an explicit set of selectable non-link keys.

Collection links remain grid rows and navigate programmatically. Use `TagButton as="a"` when you need native anchor behavior such as a browser context menu or copying the link address. Use `onAction` for collection actions; avoid running an additional navigation handler alongside `href`.

Add decorative icons or badges with `leading`. Include meaningful leading information in `textValue` because the leading slot is hidden from assistive technology.

## Validation

A non-empty `errorMessage` replaces `description`. Tags do not validate selection automatically or expose `isInvalid`; derive the message from your application state.

```tsx
import { useState } from 'react';
import { Tag, TagGroup } from '@veli-design/react/tags';

function Departments() {
  const [selectedKeys, setSelectedKeys] = useState<Set<string | number>>(new Set());

  return (
    <TagGroup
      label="Departments"
      selectionMode="multiple"
      selectedKeys={selectedKeys}
      onSelectionChange={(keys) =>
        setSelectedKeys(new Set(keys === 'all' ? ['tourism', 'fisheries'] : keys))
      }
      description="Choose at least one department."
      errorMessage={selectedKeys.size === 0 ? 'Select a department to continue.' : undefined}
    >
      <Tag id="tourism">Tourism</Tag>
      <Tag id="fisheries">Fisheries</Tag>
    </TagGroup>
  );
}
```

## API Reference

The collection components compose React Aria [`TagGroup`, `TagList`, and `Tag`](https://react-spectrum.adobe.com/react-aria/TagGroup.html). Standalone actions use React Aria [`Button`](https://react-spectrum.adobe.com/react-aria/Button.html), navigation uses its link hooks, and dropdowns compose Veli [Menu](/docs/components/menu/). `Key` is `string | number`; `Selection` is `'all' | Set<Key>`.

### TagGroup

Veli props for the composed group. `items`, `children`, `renderEmptyState`, and `listClassName` configure its internal tag list.

#### Appearance

| Prop            | Type                                   | Default  | Description                               |
| :-------------- | :------------------------------------- | :------- | :---------------------------------------- |
| `appearance`    | `'fill' \| 'outline'`                  | `'fill'` | Default appearance for tags in the group. |
| `size`          | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'` | `'sm'`   | Default tag size.                         |
| `className`     | `string`                               | -        | Class merged onto the group root.         |
| `listClassName` | `string`                               | -        | Class merged onto the wrapping tag list.  |

#### Content and state

| Prop               | Type                                       | Default           | Description                                 |
| :----------------- | :----------------------------------------- | :---------------- | :------------------------------------------ |
| `label`            | `ReactNode`                                | -                 | Visible label above the list.               |
| `description`      | `ReactNode`                                | -                 | Helper text below the list.                 |
| `errorMessage`     | `ReactNode`                                | -                 | Replaces the helper when non-empty.         |
| `isDisabled`       | `boolean`                                  | `false`           | Disables all tags and remove controls.      |
| `items`            | `Iterable<T>`                              | -                 | Items for a dynamic collection.             |
| `children`         | `ReactNode \| ((item: T) => ReactNode)`    | -                 | Static tags or a renderer for `items`.      |
| `renderEmptyState` | `(state: TagListRenderProps) => ReactNode` | Localized message | Content shown when the collection is empty. |

#### Selection and interaction

These React Aria [`TagGroup`](https://react-spectrum.adobe.com/react-aria/TagGroup.html#props) props pass to the group. Veli excludes disabled tags and links when handling removal requests.

| Prop                     | Type                                | Default            | Description                                                      |
| :----------------------- | :---------------------------------- | :----------------- | :--------------------------------------------------------------- |
| `selectionMode`          | `'none' \| 'single' \| 'multiple'`  | `'none'`           | Whether and how many tags can be selected.                       |
| `selectionBehavior`      | `'toggle' \| 'replace'`             | `'toggle'`         | How multiple selection responds to interaction.                  |
| `selectedKeys`           | `'all' \| Iterable<Key>`            | -                  | Controlled selection.                                            |
| `defaultSelectedKeys`    | `'all' \| Iterable<Key>`            | -                  | Uncontrolled initial selection.                                  |
| `onSelectionChange`      | `(keys: 'all' \| Set<Key>) => void` | -                  | Called when selection changes.                                   |
| `disallowEmptySelection` | `boolean`                           | `false`            | Prevents clearing the last selected tag.                         |
| `disabledKeys`           | `Iterable<Key>`                     | -                  | Keys of tags to disable.                                         |
| `onRemove`               | `(keys: Set<Key>) => void`          | -                  | Enables removal and requests updates for enabled, non-link tags. |
| `onAction`               | `(key: Key) => void`                | -                  | Called when a tag performs an action.                            |
| `shouldSelectOnPressUp`  | `boolean`                           | `false`            | Selects on release rather than press down.                       |
| `escapeKeyBehavior`      | `'clearSelection' \| 'none'`        | `'clearSelection'` | Whether Escape clears selection.                                 |
| `aria-label`             | `string`                            | -                  | Accessible name when no visible label is used.                   |
| `aria-labelledby`        | `string`                            | -                  | ID of an element that labels the group.                          |

Other supported root DOM and ARIA props pass through. Not forwarded unchanged:

| Prop        | Why                                            |
| :---------- | :--------------------------------------------- |
| `children`  | Replaced by Veli's tag-list composition above. |
| `className` | Replaced by Veli's string class on the root.   |
| `style`     | Not supported.                                 |
| `ref`       | Not declared in the public wrapper types.      |

React Aria `TagList` is internal. Its arbitrary `style`, `slot`, `render`, and other list props are not exposed; use the four list props in the Veli table above. Native form-field props such as `name`, `isRequired`, `isInvalid`, and `validate` are not part of this group API.

### TagButton

`as` selects a discriminated prop type: omit it or use `as="button"` for an action or controlled filter; use `as="a"` for navigation. Both modes support the shared appearance and content props above, React Aria press, focus, and hover behavior, and `isDisabled`.

#### Action and filter (`as="button"`)

Renders a native `<button>` through React Aria Button.

| Prop         | Type                                                     | Default    | Description                                                                                           |
| :----------- | :------------------------------------------------------- | :--------- | :---------------------------------------------------------------------------------------------------- |
| `as`         | `'button'`                                               | `'button'` | Action or filter mode.                                                                                |
| `children`   | `ReactNode \| ((state: ButtonRenderProps) => ReactNode)` | -          | Label or button state renderer.                                                                       |
| `isSelected` | `boolean`                                                | -          | Controlled filter state; sets `aria-pressed` and shows the selected check. Omit for an action button. |
| `isDisabled` | `boolean`                                                | `false`    | Disables the button.                                                                                  |
| `isPending`  | `boolean`                                                | `false`    | React Aria pending state; prevents press actions.                                                     |
| `onPress`    | `(event: PressEvent) => void`                            | -          | Handles pointer, touch, and keyboard activation.                                                      |
| `type`       | `'button' \| 'submit' \| 'reset'`                        | `'button'` | Native button behavior.                                                                               |
| `ref`        | `Ref<HTMLButtonElement>`                                 | -          | Ref to the button element.                                                                            |

Other React Aria [Button props](https://react-spectrum.adobe.com/react-aria/Button.html#props), including supported native form, DOM, ARIA, press, focus, and hover props, pass through. `className` accepts a string; `style` is not exposed. `isSelected` has no uncontrolled counterpart. Navigation props such as `href`, `target`, and `rel` are not available in button mode.

#### Navigation (`as="a"`)

Renders a native `<a>` using React Aria's link, focus, and hover hooks. Supply `href` or a `render` callback that returns a compatible router anchor. Use `href` with React Aria `RouterProvider` for client-side navigation, or use `render` to integrate a router link directly.

| Prop           | Type                                                   | Default  | Description                                                           |
| :------------- | :----------------------------------------------------- | :------- | :-------------------------------------------------------------------- |
| `as`           | `'a'`                                                  | Required | Navigation mode.                                                      |
| `children`     | `ReactNode \| ((state: LinkRenderProps) => ReactNode)` | -        | Label or link state renderer.                                         |
| `href`         | `string`                                               | -        | Destination URL; required unless `render` supplies the router anchor. |
| `target`       | `string`                                               | -        | Browsing context for the destination.                                 |
| `rel`          | `string`                                               | -        | Link relationship metadata.                                           |
| `download`     | `boolean \| string`                                    | -        | Requests a download rather than navigation.                           |
| `aria-current` | `AriaAttributes['aria-current']`                       | -        | Identifies the current destination; does not add selection.           |
| `isDisabled`   | `boolean`                                              | `false`  | Prevents navigation and exposes the disabled state.                   |
| `onPress`      | `(event: PressEvent) => void`                          | -        | Handles activation.                                                   |
| `render`       | `(props, state) => ReactElement`                       | -        | Returns a compatible router anchor; required when `href` is omitted.  |
| `ref`          | `Ref<HTMLAnchorElement>`                               | -        | Ref to the anchor element.                                            |

Navigation mode accepts other supported React Aria [Link props](https://react-spectrum.adobe.com/react-aria/Link.html#props), including DOM, ARIA, press, focus, hover, and router props. It excludes `onPressUp`, `onPressChange`, `isSelected`, `aria-pressed`, `isPending`, and button submit/form props such as `type`, `name`, `value`, `form`, and `formAction`. `className` accepts a string; `style` is not exposed.

When disabled, navigation mode renders an anchor without `href` and suppresses a custom `render` callback so a router cannot navigate around the disabled state. Refs point to the rendered anchor in navigation mode and the rendered button in action mode.

```tsx
<TagButton as="a" href="/guidance" appearance="outline">
  Related guidance
</TagButton>

<TagButton as="a" render={(props) => <RouterLink {...props} to="/guidance" />}>
  Related guidance
</TagButton>
```

The custom router component must render an anchor and forward the native anchor props (including `children`) and ref. It receives `LinkRenderProps` as the second argument. A custom renderer owns navigation and URL mapping; avoid also navigating from `onPress` or `onClick`. Configure your router's navigation and URL handling on `RouterProvider` when using the `href` approach.

### TagDropdown

A parent filter with separate deselection and menu buttons while selected. Place it alongside standalone tags; it is not a `TagGroup` collection item.

#### Content

| Prop              | Type                                    | Default         | Description                                                              |
| :---------------- | :-------------------------------------- | :-------------- | :----------------------------------------------------------------------- |
| `label`           | `ReactNode`                             | Required        | Parent tag label.                                                        |
| `dropdownLabel`   | `string`                                | Localized label | Accessible name for the arrow and menu. Provide one for a complex label. |
| `items`           | `Iterable<T>`                           | -               | Dynamic menu collection.                                                 |
| `children`        | `ReactNode \| ((item: T) => ReactNode)` | Required        | `MenuItem` children or an item renderer.                                 |
| `renderSelection` | `(selection: Selection) => ReactNode`   | Required        | Summary of the selected sub-labels.                                      |

#### Selection and state

| Prop                  | Type                        | Default   | Description                                                                |
| :-------------------- | :-------------------------- | :-------- | :------------------------------------------------------------------------- |
| `selectedKeys`        | `'all' \| Iterable<Key>`    | -         | Controlled sub-label selection.                                            |
| `defaultSelectedKeys` | `'all' \| Iterable<Key>`    | Empty set | Initial uncontrolled sub-label selection.                                  |
| `onSelectionChange`   | `(keys: Selection) => void` | -         | Called when sub-labels change, including an empty set before `onDeselect`. |
| `isSelected`          | `boolean`                   | `true`    | Parent selection; keep mounted to animate the attached caret.              |
| `onSelect`            | `() => void`                | -         | Required when `isSelected` may be false; selects the parent.               |
| `onDeselect`          | `() => void`                | Required  | Removes parent membership in your application.                             |
| `disabledKeys`        | `Iterable<Key>`             | -         | Menu item keys that cannot be selected.                                    |
| `isDisabled`          | `boolean`                   | `false`   | Disables both buttons and keeps the menu closed.                           |
| `isOpen`              | `boolean`                   | -         | Controlled menu visibility.                                                |
| `defaultOpen`         | `boolean`                   | `false`   | Initial uncontrolled menu visibility.                                      |
| `onOpenChange`        | `(isOpen: boolean) => void` | -         | Called when menu visibility changes.                                       |

When `isSelected` is false, only the plain filter label is available; its caret is inert and hidden from assistive technology. The menu opens only for a selected, enabled parent, even if `isOpen` is true. Deselecting or disabling the parent closes the menu and requests `onOpenChange(false)`; when controlling `isOpen`, reflect that request in your state. The menu always uses multiple selection and stays open while choosing sub-labels. `TagDropdown` exposes the props above and the shared standalone appearance props; it does not forward arbitrary button, menu, popover, DOM, ARIA, `style`, or `ref` props.

### DOM structure

The group root and tag rows are `<div>` elements, with a grid for keyboard interaction. `TagButton` renders a `<button>` by default or an `<a>` with `as="a"`, and `TagDropdown` wraps its two buttons in a labelled `<span role="group">`. Selection is application state; include it in your form data explicitly when submitting.

## Accessibility

- Give the group a visible `label`, or use `aria-label` / `aria-labelledby`.
- Arrow keys navigate tags; selection follows `selectionMode`. Delete or Backspace removes enabled selected tags, or the focused tag when it is unselected.
- Clicking a remove control removes that tag without selecting it. Disabled tags remain in the collection during bulk removal.
- A selected disabled tag retains `aria-selected="true"` alongside `aria-disabled="true"`. Group link tags retain grid-row keyboard navigation and announce their destination through an accessible description; links are excluded from selection and removal.
- Standalone filters expose `aria-pressed`. In a selected `TagDropdown`, Tab reaches the label and arrow independently; Enter or Space activates the focused control. ArrowDown on either the selected label or arrow opens the menu and focuses its first enabled option. The menu supports arrow-key navigation and Escape to close. If external state deselects a focused open dropdown, focus returns to its label; if the whole dropdown becomes disabled, its labelled group receives programmatic focus without adding a tab stop.
- Plain and nested text supply the tag name automatically. Provide `textValue` for complex or function content, and a useful `removeButtonLabel` for custom removal wording.
- `description` is the accessible helper; a non-empty `errorMessage` replaces it. Focus remains visible in forced-colors mode, and reduced motion makes color changes immediate.

## RTL and Language

Use [VeliProvider](/docs/components/provider/) with `language="dv"` for Dhivehi and RTL, or `language="en"` for English and LTR. Dhivehi tags use `MV A Waheed`; labels and messages follow the provider typography. Leading content and removal controls follow the text direction.

Built-in empty messages, remove labels, and dropdown menu labels follow the provider language. Localize your visible tag content and custom remove labels in your application. Local `lang` and `dir` attributes do not change the built-in translated copy.

## Motion

Tag color changes, caret reshaping and summary transitions use `duration-normal` (200ms). Pressing a button or either dropdown segment grows the whole control over `duration-fast` (80ms), without a ripple. Collection additions/removals fade and scale while remaining rows slide into place; a summary slides in when it appears and fades when its text changes.

Keep stable item IDs and the dropdown mounted for continuous transitions. TagGroup owns motion within its collection; a surrounding layout owns transitions between standalone controls and the exit of any standalone control it unmounts. Reduced motion disables these decorative effects, including press growth.

How tags work with keyboards, screen readers and assistive technology, and what you still need to do. TagGroup follows the grid pattern from React Aria, with one row per tag.

## Keyboard

A TagGroup is one stop in the tab order. Arrow keys move between tags.

| Key                     | Action                                                                                     |
| :---------------------- | :----------------------------------------------------------------------------------------- |
| Tab                     | Moves focus into the group, to the last focused tag, and then out of it                    |
| Left Arrow, Right Arrow | Move to the previous or next tag. Mirrored in Dhivehi, so Left Arrow always moves left     |
| Home, End               | Move to the first or last tag                                                              |
| Space or Enter          | Selects or clears the focused tag, when selection is on. Follows a link tag                |
| Delete or Backspace     | Removes the selected tags, or the focused tag when it isn't selected, when onRemove is set |
| Escape                  | Clears the selection                                                                       |

Standalone TagButton filters are native buttons in the tab order. In a selected TagDropdown, Tab reaches the label and the caret separately, Enter or Space activates the focused part, and Down Arrow on either part opens the menu.

## Screen readers

- TagGroup renders a grid labelled by its label, with one row per tag. Give every group a visible label, or aria-label or aria-labelledby.
- Selected tags carry aria-selected. Disabled tags carry aria-disabled.
- The description and the error are linked to the group with aria-describedby.
- Plain text gives each tag its name. Give icon-only or complex tags textValue, and a useful removeButtonLabel.
- Leading icons and badges are hidden from assistive technology. Put any meaning, such as a count, in the label text or in textValue.
- Link tags in a group announce their destination through an accessible description, Link: and the address.
- Standalone filters (TagButton with isSelected) expose aria-pressed.
- When a filter changes the results, announce the new count once through a live region.

- Selection shows with a check as well as colour.

## Disabled

Disabled tags can't be focused, selected or removed, and their remove button is inert. A selected disabled tag keeps aria-selected. Say near the group why a tag is unavailable, or leave it out.

## Target size

The remove button is 14 to 24 wide, but its hit area is extended to at least 24 x 24 at every size. At xs and sm, leave space around it so neighbouring targets don't overlap. Use md or larger for removable tags on touch-first pages.

## Read-only tags

If the tags only show labels, with no selection, removal or links, check that the group adds no Tab stop that does nothing. If it does, show the labels as a plain list.
