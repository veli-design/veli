# Kbd

<DocsTab id="overview">

Kbd shows the name of a keyboard key, and KbdGroup shows a shortcut made of several keys, such as Ctrl K. Use them beside menu items, in tooltips, in help panels and in instructions that name a key. Kbd only displays keys; your app handles the shortcut.

## When to use

### Use Kbd when

- You document a keyboard key or shortcut, such as in a help panel.
- You show a shortcut beside a menu item or in a help hint.
- An instruction names a key people press, such as Press Enter to search.
- You show one key, such as Enter or Esc. For a combination, use KbdGroup with one Kbd per key.

### Don't use Kbd when

- The element must capture keyboard input. Kbd only displays keys; handle the keys in the app.
- The value is something people type or copy, such as a reference number, a code or a password. Show it as plain text, kept left to right, such as PR-20418.
- The layout is used only with touch, such as a phone view. Keep the action on its visible control, and show shortcuts in desktop layouts.
- The shortcut would be the only way to do something. Give the action a visible control, and list the shortcut in a menu or help panel.

1. **Key**

   20 high and at least 20 wide, with radius 4 and a translucent fill. Display only, so it never takes focus. In code it is Kbd, the native kbd element.

2. **Label**

   The key name as printed on the key, such as K, Enter or Shift, in Caption regular 12/16 on one line. In code it is the Kbd children.

3. **Icon**

   An optional 12 x 12 icon for a key printed as a symbol, such as Command. It is decorative, so hide it from screen readers with aria-hidden and name the key instead.

4. **Group**

   Holds the keys of one shortcut, 2 apart, modifiers first and the main key last. In code it is KbdGroup, with role group and an aria-label.

</DocsAnatomy>

## Content guidelines

### Key names as printed

Write the name printed on the key, and use the same name everywhere.

| Do    | Don't                                                          |
| :---- | :------------------------------------------------------------- |
| Ctrl  | control (not how the key is printed)                           |
| Enter | Return key (a role word, and the macOS name on a Windows hint) |
| K     |                                                                |

### Key order

Modifiers first and the main key last: Ctrl, Shift, F. Keep the same order in every hint.

| Do                         | Don't                                |
| :------------------------- | :----------------------------------- |
| Ctrl Shift F, one key each | Ctrl+Shift+F (three keys in one Kbd) |

### Running text

In a sentence, write the keys with a plus sign and non-breaking spaces: Ctrl + K, Shift + Tab. In UI, show them with Kbd and KbdGroup.

### Platform keys

Use ⌘ and ⌥ on macOS, and Ctrl and Alt on Windows and Linux. Don't use a slash to show both.

| Do     | Don't                                 |
| :----- | :------------------------------------ |
| ⌘ K    | Ctrl/⌘ K (two platforms in one label) |
| Ctrl K |                                       |

### Group names

Write a KbdGroup aria-label as the key names in words. Screen readers may skip or misread symbols such as ⌘.

| Do              | Don't                    |
| :-------------- | :----------------------- |
| Command K       | ⌘K (a symbol, not words) |
| Control Shift F |                          |

### Strings and Dhivehi

Kbd has no built-in text. Key labels come from its children and group names from aria-label; keep both in the language files with the rest of the screen. On Dhivehi screens keep the key names in English, with lang="en", because the keys are printed in Latin.

- **Letter or number**: such as K or 1.
- **Key name**: as printed on the key, such as Shift, Enter or Esc. Longer names such as Page Down widen the key without wrapping.
- **Symbol or icon**: a key printed as a symbol, such as ⌘, ⌥ or ⇧, or an arrow shown as a 12px icon. Hide the icon and name the key.
- **Combination**: one key each in a KbdGroup, modifiers first and the main key last.
- **In a menu**: a shortcut beside a menu item, display only.
- **In a tooltip**: an action and its keys in a small Tooltip, with the KbdGroup after the text and an 8 gap.

## Behaviour

- **Display only**: Kbd and KbdGroup don't register or handle shortcuts; the app wires them up. Shortcut hints in menus are display only too.
- **Modifier keys**: build shortcuts on a modifier key, such as Ctrl, ⌘ or Alt, rather than single letters.
- **Single keys**: a shortcut of one letter, number or symbol must work only while its component has focus, or people must be able to turn it off or change it.
- **Reserved keys**: never take over browser or screen reader keys, such as Ctrl + F, Ctrl + L, Tab or F6. Choose unused combinations and let people turn custom shortcuts off.
- **Dhivehi keyboards**: test shortcuts with the Dhivehi phonetic keyboard. Match the physical key with KeyboardEvent.code, or accept both characters: with that keyboard on, the K key types ކ.
- **Discoverable**: list shortcuts in menus or a help panel, and never make a shortcut the only way to do something.
- **No wrapping**: a KbdGroup stays on one line. Let the surrounding row wrap between groups on narrow screens.

## Variants

`KbdGroup` propagates its `variant` to direct `Kbd` children that do not already specify a variant. Nested wrappers are left unchanged. Both treatments use theme tokens and respond to the active light or dark theme; choose the treatment prescribed by the surrounding component.

## API Reference

### Kbd

Veli-specific props for a single keyboard key.

| Prop        | Type                      | Default     | Description                                    |
| :---------- | :------------------------ | :---------- | :--------------------------------------------- |
| `variant`   | `'default' \| 'inverted'` | `'default'` | Color treatment of the key.                    |
| `children`  | `ReactNode`               | —           | Latin key label or shortcut glyph (required).  |
| `className` | `string`                  | —           | Classes merged with the key's default styling. |

Latin keys use one size: 20px high, at least 20px wide, with 4px corners and 2px vertical / 4px horizontal padding. Longer labels such as `Page Down` expand without wrapping. Text uses 12px Caption Regular with a 16px line height; decorative icons are 12px.

### KbdGroup

Veli-specific props for composing keys into a shortcut.

| Prop        | Type                      | Default     | Description                                                                |
| :---------- | :------------------------ | :---------- | :------------------------------------------------------------------------- |
| `variant`   | `'default' \| 'inverted'` | `'default'` | Treatment propagated to direct `Kbd` children without an explicit variant. |
| `className` | `string`                  | —           | Classes merged with the group's default styling.                           |

The group uses a 2px gap and keeps its contents together. Allow a surrounding row to wrap between groups on narrow screens.

### React Aria forwarded props

Neither component wraps a React Aria primitive, so there are no forwarded React Aria props. They render native elements directly. Menu and Tooltip use their own React Aria integrations when consuming Kbd.

### Native `<kbd>` props

`Kbd` forwards `React.HTMLAttributes<HTMLElement>` to its `<kbd>` element. Common native props are listed below.

| Prop         | Type                       | Default   | Description                                                                                                                  |
| :----------- | :------------------------- | :-------- | :--------------------------------------------------------------------------------------------------------------------------- |
| `lang`       | `string`                   | `'en'`    | Native language tag for Latin labels. Keep the English default in Dhivehi interfaces; Dhivehi key typography is unsupported. |
| `dir`        | `'ltr' \| 'rtl' \| 'auto'` | Inherited | Direction of the key content.                                                                                                |
| `id`         | `string`                   | —         | Native element identifier.                                                                                                   |
| `title`      | `string`                   | —         | Additional text describing the key.                                                                                          |
| `aria-label` | `string`                   | —         | Accessible name, useful for an icon-only key.                                                                                |

Native `data-*`, other ARIA attributes, and DOM event handlers also pass through. The component does not register shortcuts or make the key focusable by default.

### Native `<div>` props

`KbdGroup` forwards `React.HTMLAttributes<HTMLDivElement>` to its group container.

| Prop         | Type                       | Default   | Description                                                           |
| :----------- | :------------------------- | :-------- | :-------------------------------------------------------------------- |
| `children`   | `ReactNode`                | —         | Keys and any additional group content.                                |
| `dir`        | `'ltr' \| 'rtl' \| 'auto'` | Inherited | Use `'ltr'` for modifier-first Latin shortcut order in an RTL layout. |
| `lang`       | `string`                   | Inherited | Language of group content; each Kbd still defaults to `'en'`.         |
| `role`       | `AriaRole`                 | `'group'` | Makes the container a nameable group by default.                      |
| `aria-label` | `string`                   | —         | Accessible name describing a key combination.                         |
| `id`         | `string`                   | —         | Native element identifier.                                            |

Native `data-*`, other ARIA attributes, and DOM event handlers also pass through.

## Language and direction

Kbd supports Latin key labels and shortcut glyphs only; Dhivehi labels and typography are not supported. Keys default to `lang="en"` so Latin labels retain Inter and the 12px/16px metrics inside a Dhivehi provider. Keep this default when the surrounding interface uses `language="dv"`. The native `lang` attribute still passes through for compatibility, but setting `lang="dv"` activates shared Dhivehi typography outside the supported key geometry.

Group direction inherits from the surrounding layout; use `dir="ltr"` to keep a Latin shortcut in modifier-first order in an RTL interface. The surrounding Menu can remain RTL.

```tsx
<div lang="dv" dir="rtl">
  <KbdGroup dir="ltr" aria-label="Control Shift P">
    <Kbd>Ctrl</Kbd>
    <Kbd>Shift</Kbd>
    <Kbd>P</Kbd>
  </KbdGroup>
</div>
```

Menu's string and array `shortcut` props already render Latin keys in an LTR group. For a small Tooltip, compose the label and an LTR `KbdGroup` with an 8px gap; large Tooltip designs do not include shortcuts.

## Accessibility and behavior

`Kbd` uses the native `<kbd>` element and is not focusable by default. Give a shortcut group an accessible name when its glyphs need explanation, and hide decorative SVG icons with `aria-hidden="true"`. For an icon-only standalone key, provide `aria-label` on the key.

Neither component handles key presses, adds motion, or changes the tab order. Implement any shortcut behavior on the application action separately, and use `aria-keyshortcuts` on that action when appropriate. Menu and Tooltip retain their own focus, dismissal, and reduced-motion behavior.

How keys and shortcuts work with screen readers and keyboards, and what you still need to do. Kbd is static text inside the native kbd element.

## Keyboard

Kbd and KbdGroup are not focusable and don't change the tab order. A shortcut is a faster way, not the only way: every action must still work from its visible control with the keyboard alone.

## Screen readers

- Kbd uses the native kbd element and KbdGroup has role group.
- Give a KbdGroup an aria-label when its keys alone don't explain the shortcut, such as icon keys: Command Shift K.
- Hide an icon inside a key with aria-hidden, and name the key instead, such as aria-label="Command key".
- Put aria-keyshortcuts on the control the shortcut runs, such as aria-keyshortcuts="Control+K" on the search button, so screen readers announce it there.

## Contrast

- Default keys: measured in Storybook in light mode on the base surface, the label is about 6.7:1. The key fill against the surface is only about 1.1:1, so the key shape is faint; the label carries the meaning.
- Inverted keys: the label is below 4.5:1. Measured in Storybook on the base surface it is about 2.2:1, and the Figma build measured about 3.0:1 on the primary Tooltip fill in light mode and 1.35:1 in dark mode. Don't rely on the inverted variant for important text until its tokens are reviewed.

## Right to left

Keys keep lang="en" on Dhivehi pages, so screen readers read the key names in English. Set dir="ltr" on each KbdGroup so the key order stays modifier first.
