title: Principles
description: The operating beliefs behind Veli—clarity, access, local context, and shared foundations.
---

## Clarity before novelty

Make the next action easy to understand. Familiar patterns, direct language, and visible system status matter more than a novel interaction.

- Keep one primary action clear in each task.
- Use labels that describe outcomes, not implementation details.
- Reveal complexity only when it becomes useful.

## Access is the baseline

Design for different needs from the start. Keyboard access, readable contrast, semantic structure, and resilient zoom behavior are part of the definition of done.

Accessibility should be tested throughout design and development, not added after a service is complete.

## Local language matters

English and Dhivehi are first-class product contexts. Layout, typography, icons, and reading order must work in both left-to-right and right-to-left interfaces.

Content should be written for the people using the service rather than translated literally from internal terminology.

## Use shared foundations

Build with traceable tokens and supported components before introducing local values. Shared foundations make behavior predictable and let improvements reach every service.

Create a local pattern only when the existing system cannot express a verified user need.
