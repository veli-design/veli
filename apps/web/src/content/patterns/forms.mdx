# Forms

Veli field components are built on react-aria-components and already accept the controlled props form libraries need: `name`, `value` / `onChange`, `onBlur`, `isInvalid`, and `isRequired`. For most fields you spread the library's field object directly. The `@tradenetcorp/veli-ui/form` subpath adds a `Form` wrapper and helpers that turn library or schema errors into field messages.

## Import

```tsx
import { Form, getErrorMessages, toErrorMessage } from '@tradenetcorp/veli-ui/form';
```

## React Hook Form

`Controller`'s `field` object (`name`, `value`, `onChange`, `onBlur`, `ref`) spreads directly onto `Input`, `TextArea`, `Select`, `ComboBox`, `RadioGroup`, `CheckboxGroup`, `DateField`, and `DatePicker`. For `Select` and `DatePicker`, pass `ref` as `triggerRef` so focus-on-error reaches the trigger button.

`Select` and `ComboBox` infer their key type from `value` / `onChange`. A `string | null` field therefore type-checks with no conversion. Hold dates as `DateValue` objects in form state (React Aria's recommendation); set `name` when a native submit should send an ISO 8601 string.

```tsx
import type { CalendarDate } from '@internationalized/date';
import { Controller, useForm } from 'react-hook-form';
import { Checkbox } from '@tradenetcorp/veli-ui/checkbox';
import { DatePicker } from '@tradenetcorp/veli-ui/date-picker';
import { Form } from '@tradenetcorp/veli-ui/form';
import { Input } from '@tradenetcorp/veli-ui/input';
import { Select, SelectItem } from '@tradenetcorp/veli-ui/select';

function ProfileForm() {
  const { control, handleSubmit } = useForm({
    defaultValues: {
      email: '',
      country: null as string | null,
      startDate: null as CalendarDate | null,
      terms: false,
    },
  });

  return (
    <Form onSubmit={handleSubmit(console.log)}>
      <Controller
        name="email"
        control={control}
        rules={{ required: 'Email is required' }}
        render={({ field, fieldState }) => (
          <Input
            {...field}
            label="Email"
            isInvalid={fieldState.invalid}
            errorMessage={fieldState.error?.message}
          />
        )}
      />
      <Controller
        name="country"
        control={control}
        render={({ field: { ref, ...field }, fieldState }) => (
          <Select
            {...field}
            triggerRef={ref}
            label="Country"
            isInvalid={fieldState.invalid}
            errorMessage={fieldState.error?.message}
          >
            <SelectItem id="mv">Maldives</SelectItem>
            <SelectItem id="sg">Singapore</SelectItem>
          </Select>
        )}
      />
      <Controller
        name="startDate"
        control={control}
        render={({ field: { ref, ...field } }) => (
          <DatePicker {...field} triggerRef={ref} label="Start date" />
        )}
      />
      <Controller
        name="terms"
        control={control}
        render={({ field }) => (
          <Checkbox
            name={field.name}
            isSelected={field.value}
            onChange={field.onChange}
            onBlur={field.onBlur}
          >
            I accept the terms
          </Checkbox>
        )}
      />
    </Form>
  );
}
```

If a form must store dates as ISO `yyyy-MM-dd` strings, convert with `parseDate` and `.toString()` from `@internationalized/date`.

`TagGroup` accepts a `string[]` as `selectedKeys`. Write selections back with `onSelectionChange={(keys) => keys !== 'all' && field.onChange([...keys].map(String))}`.

If you use React Hook Form's `disabled` option, also pass `isDisabled={field.disabled}`. Veli fields read `isDisabled`, not the DOM `disabled` attribute.

## TanStack Form

Wire each `form.Field` render prop to the field's props directly. Veli fields call `onChange` with the value itself, not a DOM event, so `field.handleChange` can be passed as-is — including on `Select` when the field stores a `string | null`.

Show errors only once the field is touched (`isTouched && !isValid`), so users aren't shown errors while typing their first value. TanStack marks every field as touched on submit, so a submit attempt still reveals all errors. `toErrorMessage` turns the field's `errors` array into a message.

```tsx
import { useForm } from '@tanstack/react-form';
import * as z from 'zod';
import { Form, toErrorMessage } from '@tradenetcorp/veli-ui/form';
import { Input } from '@tradenetcorp/veli-ui/input';
import { Select, SelectItem } from '@tradenetcorp/veli-ui/select';

const schema = z.object({
  fullName: z.string().trim().min(1, 'Name is required'),
  country: z
    .string()
    .nullable()
    .refine((value) => value !== null, 'Country is required'),
});

function TanStackExample() {
  const form = useForm({
    defaultValues: { fullName: '', country: null as string | null },
    validators: { onChange: schema },
    onSubmit: ({ value }) => console.log(value),
  });

  return (
    <Form
      onSubmit={(event) => {
        event.preventDefault();
        void form.handleSubmit();
      }}
    >
      <form.Field name="fullName">
        {(field) => {
          const isInvalid = field.state.meta.isTouched && !field.state.meta.isValid;
          return (
            <Input
              label="Full name"
              name={field.name}
              value={field.state.value}
              onChange={field.handleChange}
              onBlur={field.handleBlur}
              isInvalid={isInvalid}
              errorMessage={toErrorMessage(field.state.meta.errors)}
            />
          );
        }}
      </form.Field>
      <form.Field name="country">
        {(field) => (
          <Select
            label="Country"
            name={field.name}
            value={field.state.value}
            onChange={field.handleChange}
            onBlur={field.handleBlur}
            isInvalid={field.state.meta.isTouched && !field.state.meta.isValid}
            errorMessage={toErrorMessage(field.state.meta.errors)}
          >
            <SelectItem id="mv">Maldives</SelectItem>
            <SelectItem id="sg">Singapore</SelectItem>
          </Select>
        )}
      </form.Field>
    </Form>
  );
}
```

## Schema validation and error messages

Any [Standard Schema](https://standardschema.dev/) validator (Zod, Valibot, ArkType) works with both libraries: pass it to TanStack's `validators`, or to React Hook Form through `@hookform/resolvers`. TanStack runs the validator at the point you choose:

| Option                | Runs                       |
| :-------------------- | :------------------------- |
| `validators.onChange` | On every change            |
| `validators.onBlur`   | When a field loses focus   |
| `validators.onSubmit` | Only when the form submits |

With a schema, a TanStack field's `state.meta.errors` holds issue objects (`{ message, path }`), not strings, so they can't be passed to `errorMessage` as-is. Convert them with:

- `toErrorMessage(errors)` returns the first message, for a field's `errorMessage` prop.
- `getErrorMessages(errors)` returns every unique message, for rendering a list.

Both accept strings, `{ message }` objects (React Hook Form's `fieldState.error`, Standard Schema issues), and arrays of either.

```tsx
<Input
  label="Title"
  isInvalid={field.state.meta.isTouched && !field.state.meta.isValid}
  errorMessage={toErrorMessage(field.state.meta.errors)}
/>
```

## Checkbox groups

`CheckboxGroup` holds a `string[]` value, so it takes a form field directly in both libraries. Give each `Checkbox` a `value`. `RadioGroup` and `CheckboxGroup` show `description` and `errorMessage` below the group.

```tsx
<form.Field name="channels">
  {(field) => (
    <CheckboxGroup
      aria-label="Notification channels"
      name={field.name}
      value={field.state.value}
      onChange={field.handleChange}
      onBlur={field.handleBlur}
      isInvalid={field.state.meta.isTouched && !field.state.meta.isValid}
      errorMessage={toErrorMessage(field.state.meta.errors)}
    >
      <Checkbox value="email">Email</Checkbox>
      <Checkbox value="sms">SMS</Checkbox>
    </CheckboxGroup>
  )}
</form.Field>
```

With React Hook Form, spread `{...field}` and pass `isInvalid` / `errorMessage` from `fieldState`.

## Array fields

For a list of repeated inputs, use TanStack's `mode="array"` field and address each item with bracket notation. `pushValue` and `removeValue` add and remove items. React Hook Form's equivalent is `useFieldArray`.

```tsx
<form.Field name="emails" mode="array">
  {(emailsField) => (
    <>
      {emailsField.state.value.map((_, index) => (
        <form.Field key={index} name={`emails[${index}].address`}>
          {(field) => (
            <Input
              label={`Email ${index + 1}`}
              name={field.name}
              value={field.state.value}
              onChange={field.handleChange}
              onBlur={field.handleBlur}
            />
          )}
        </form.Field>
      ))}
      <Button type="button" onPress={() => emailsField.pushValue({ address: '' })}>
        Add email
      </Button>
    </>
  )}
</form.Field>
```

## Reset and submitting from outside the form

Call `form.reset()` (TanStack) or `reset()` (React Hook Form) to restore default values. To place the submit button outside the `<Form>` element, for example in a card footer or modal actions, give the form an `id` and point the button at it with `form`:

```tsx
<Form id="profile-form" onSubmit={/* ... */}>{/* fields */}</Form>

<Button type="submit" form="profile-form">
  Save
</Button>
<Button type="button" intent="secondary" appearance="transparent" onPress={() => form.reset()}>
  Reset
</Button>
```

## Controlled values without a form library

When you keep field values in your own state (for example a schema-driven renderer), pass `value` and `onChange` yourself. String-oriented stores map like this:

| Field kind        | Stored value                 | Veli wiring                                                      |
| :---------------- | :--------------------------- | :--------------------------------------------------------------- |
| Text / number     | `string`                     | `value` + `onChange(string)` on `Input`                          |
| Select / combobox | `string \| null`             | `value` + `onChange` (key type inferred as `string \| null`)     |
| Boolean           | `"true"` / `"false"` strings | `isSelected={value === 'true'}`, write back `"true"` / `"false"` |
| Date              | `yyyy-MM-dd` string          | `parseDate(value)` in, `date?.toString() ?? null` out            |
| Validation        | your own error string        | `isInvalid={error != null}` and `errorMessage={error}`           |

Example select wired from a string enum:

```tsx
import { Select, SelectItem } from '@tradenetcorp/veli-ui/select';

<Select
  name={field.name}
  label={field.label}
  value={field.value}
  onChange={(key) => updateValue(field.id, key)}
  isRequired={field.required}
  isInvalid={Boolean(error)}
  errorMessage={error}
>
  {field.options.map((option) => (
    <SelectItem key={option} id={option}>
      {option}
    </SelectItem>
  ))}
</Select>;
```

For dates stored as ISO strings:

```tsx
import { parseDate } from '@internationalized/date';
import { DatePicker } from '@tradenetcorp/veli-ui/date-picker';

<DatePicker
  name={field.name}
  label={field.label}
  value={field.value ? parseDate(field.value) : null}
  onChange={(date) => updateValue(field.id, date?.toString() ?? null)}
/>;
```

For booleans stored as strings, read with `value === 'true'` and write `"true"` / `"false"` on change.
