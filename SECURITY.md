# Security policy

## Supported versions

Security fixes are prioritised for the latest published versions of
`@veli-design/react`, `@veli-design/tokens` and `@veli-design/cli`, and
the latest distributed versions of Veli Blocks. Older versions are not
guaranteed to receive backported fixes. Consumers of copied Blocks should
apply relevant updates to their own code.

Please report vulnerabilities in older versions too if you are unsure
whether the current release is affected.

## Reporting a vulnerability

Report suspected vulnerabilities in Veli privately using
[GitHub private vulnerability reporting](https://github.com/veli-design/veli/security/advisories/new).
Do not disclose security-sensitive details in public issues, pull requests
or discussions.

Include the affected package, Block or repository area, its version or
commit, a description of the issue and its potential impact, and any
information needed to help maintainers assess it safely. Do not include
credentials, personal data or other sensitive information.

## Scope

This policy covers the Veli codebase, its published packages, distributed
Blocks, and Veli-maintained build and distribution infrastructure.
Ordinary defects, feature requests and non-security accessibility issues
should follow the normal contribution and issue-reporting process.

Vulnerabilities specific to applications that consume Veli should be
reported to the maintainers of those applications.

## Response and disclosure

We aim to acknowledge reports within five working days. The Veli maintainers will assess
the report privately, engage security specialists when necessary,
communicate next steps and coordinate disclosure with the reporter
when appropriate. Remediation timing depends on the
severity, complexity and impact of the issue.

Please allow time for investigation and remediation before publishing
details. Avoid testing that disrupts services or accesses data without
permission.
