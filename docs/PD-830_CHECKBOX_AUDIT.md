# PD-830 Checkbox public release audit

Audited against the current [🏝️ Checkbox page](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=305-8759) on 12 October 2026. The issue's supplied node `1078:2986` currently resolves to the Tooltip page, so the Checkbox page and its live variant sets were used. The rendered baseline was the existing [Storybook on port 6006](http://localhost:6006/?path=/story/components-checkbox--sizes); changes were checked in the isolated [Storybook on port 6007](http://localhost:6007/?path=/story/components-checkbox--states-audit) and the [built website preview](http://localhost:4322/docs/checkbox/).

## 13 October 2026 spec recheck

The live [English](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=305-8760) and [Dhivehi](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5085-391) sets each still contain 51 variants. The invalid row shows off and on, with description and explanatory error text, at `md`, `lg`, and `xl`. For example, [English md off invalid](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=305-8768) and [Dhivehi xl off invalid](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5219-124918) are explicit. There is no indeterminate + invalid variant in either set. The new [overview example](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5280-16858) shows a CheckboxGroup in a form, but no group or read-only component variant. The [guidelines](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5086-23381) still say read-only has no separate look.

In [Basim's PD-830 reply](https://linear.app/onegov/issue/PD-830/audit-checkbox-for-public-release), he confirmed that the check/dash should stay white in dark mode and that a read-only design state is needed. The former is now implemented in `checkbox.tsx`; the latter still needs a Figma treatment before code can reproduce it. The issue assignee confirmed the invalid state is needed for required consent and group validation, including explanatory text. The current code and docs already support those cases.

## Findings

The [Narrow layout story](http://localhost:6007/?path=/story/components-checkbox--narrow-layout) exposed one additional code defect after review: when the label wrapped, the box was centered against both lines. The control slot now aligns with the first line in English LTR and Dhivehi RTL. The story checks the rendered positions in both languages; Figma does not provide a narrow-width frame for comparison.

### 3. Designer questions and proposed Figma additions

The current [Figma and code gaps](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5086-23619) page already calls out several of these mismatches. They are left unchanged pending a design decision.

1. In the [English](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=305-8760) and [Dhivehi](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5085-391) variant sets, add or explicitly rule out **indeterminate + invalid** for `md`, `lg`, and `xl` (six language/size scenarios). The current [`States audit`](http://localhost:6007/?path=/story/components-checkbox--states-audit) renders them using the existing code state model.
2. Dark check/dash color is resolved: Basim confirmed white, and [`checkbox.tsx`](../packages/ui/src/checkbox.tsx) now keeps it white. The [Figma gap notes](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5086-23619) still propose Figma-side changes for unchecked background, indeterminate fill, unchecked pressed border, checked pressed mark scale, `md` hover label color, disabled `md` label/description gap, and label end padding. Verify those updates in Figma before changing code.
3. Basim said a read-only design state is needed, but the [guidelines](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5086-23381) still say it has no separate look and neither component set contains it. Add its visual treatment before implementing a new code appearance. The [new overview](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5280-16858) shows a group example; group validation and narrow/wrapping examples would complete the spec. Rename residual Radio layers within the Checkbox variants if they are intended to be published for developer inspection.
