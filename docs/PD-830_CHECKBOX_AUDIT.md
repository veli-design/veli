### 3. Designer questions and proposed Figma additions

The current [Figma and code gaps](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5086-23619) page already calls out several of these mismatches. They are left unchanged pending a design decision.

1. In the [English](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=305-8760) and [Dhivehi](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5085-391) variant sets, add or explicitly rule out **indeterminate + invalid** for `md`, `lg`, and `xl` (six language/size scenarios). The current [`States audit`](http://localhost:6007/?path=/story/components-checkbox--states-audit) renders them using the existing code state model.
2. Specify dark and system appearance, especially the check/dash color. The light variants use a white mark; the current [`checkbox.tsx`](../packages/ui/src/checkbox.tsx) uses the inverted semantic token, which renders near black in dark mode. Review unchecked background, indeterminate fill, unchecked pressed border, checked pressed mark scale, `md` hover label color, disabled `md` label/description gap, and label end padding against the [Figma gap notes](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5086-23619).
3. Add rendered group, narrow/wrapping, and read-only scenarios to the [Checkbox page](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=305-8759); clarify whether `readOnly` needs a visual state. The [guidelines](https://www.figma.com/design/4h7LJTwcIvXiwx5a1hQJqk/Veli-Design-System?node-id=5086-23381) define behavior, but the component sets do not show these cases. Rename residual Radio layers within the Checkbox variants if they are intended to be published for developer inspection.
